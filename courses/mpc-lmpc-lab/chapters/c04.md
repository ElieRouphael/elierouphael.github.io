## The controller, assembled {#assembled}

**The task.** Drive the 1:10-scale car of lab [[b04]] around its 20.19 m track, half-width 0.4 m, as fast as it will go, starting from nothing better than four laps of a noisy path follower at 0.8 m/s. The plant is the dynamic bicycle model with Pacejka tyres, integrated at 1 ms and sampled every 0.1 s; the state is $x = (v_x, v_y, r, e_\psi, s, e_y)$ and the input $u = (\delta, a)$, as in lab [[b04]]. Nothing in the controller knows the tyre law. It knows the Frenet kinematics, which lab [[b03]] derived, and it has the stored laps.

**The idea.** Learning MPC for a repeated task, chapter [[a13]]: at every sample solve a short-horizon problem whose terminal ingredients, the set where the plan may end and the price of ending there, come from the laps already driven. Lab [[b02]] ran it on the linear cart, where chapter [[a12]]'s proof makes the convex hull of stored states a safe set and chapter [[a13]]'s argument makes the barycentric value a terminal cost. The car is nonlinear, so every ingredient is made *local*: the model is refitted around the plan, the safe set is the hull of stored states near the plan's end, and the guarantees become what Part 7 says they become.

::: table
| Ingredient | What it is here | Where the course taught it |
|---|---|---|
| Prediction model | An affine time-varying model $x_{k+1} = A_k x_k + B_k u_k + c_k$, refitted at every step of the horizon from the last four laps by lab B4's local regression | [[b04]], [[a01]], [[a02]] |
| Terminal set | The convex hull of 48 stored states, 12 from each of the 4 fastest laps, nearest in progress to the plan's predicted end | [[a12]] |
| Terminal cost | The barycentric mixture of those states' costs-to-go, counted in samples to the finish line | [[a13]] |
| Stage cost | None on the state; an input-rate penalty $\Delta u_k^\top \mathrm{diag}(5, 50)\,\Delta u_k$ for smoothness | [[a05]] |
| Constraints | The lane $|e_y| \le 0.4$, a speed box, the input bounds, all on every predicted state | [[a05]], [[b03]] |
| Online problem | One QP in 28 inputs and 48 weights, solved by the interior-point method | [[a04]] |
| Receding horizon | Apply the first input, measure, shift the plan, refit, solve again | [[a06]] |
| Lap-to-lap learning | Each successful lap joins the database; faster laps replace slower ones in the safe set | [[b02]] |
| Fallback | If the QP is infeasible, replay the fastest stored lap's input from the nearest stored state | [[b04]], exercise 11 |
:::

::: define What makes racing LMPC different from the cart's
**In plain words:** the same loop, with every piece recomputed around where the car is and where its plan ends, because a nonlinear car has no single linear model and no global convex safe set. The lap time enters only through the terminal value: the controller never tracks a reference line, it minimises the number of samples it expects to need to reach the finish, as learned from the laps that already did.

**More precisely:** the terminal cost of chapter [[a13]], $V_c(x_N) = \lambda^\top J$ with $x_N = S^\top \lambda$, where $J_r$ is the number of samples lap $i$ still needed from its state $s_r$ to cross the finish line (negative for states just beyond it); the safe set $S$ holds only states near the plan's end, so that the hull is small enough for the local model to be trusted inside it; and the dynamics along the horizon are the local affine model of lab [[b04]] evaluated along the previous plan, so that the problem stays a QP.

- Lap :: One crossing of the finish line to the next; laps after the first start where the previous one ended (a flying start).
- Cost-to-go :: Samples to the finish line of the lap that visited the state: $T_i - k$ for the $k$-th state of a lap of $T_i$ samples.
- Local safe set :: $4 \times 12$ stored states, chosen by progress $s$, with the lap's own first 40 states shifted by one lap length standing in for the lap after the line.
- Plan :: The 14-step predicted trajectory; the next step's model is linearised along it, shifted by one.
:::

## The model layer: a time-varying model along the plan {#model}

Chapter [[a02]] stacked an LTI model over a horizon; lab [[b04]] fitted an affine model to the car at one operating point and showed that along a 14-step horizon its matrices move. The controller combines the two. Given the previous plan $(\bar x_0, \bar u_0), \dots, (\bar x_{N-1}, \bar u_{N-1})$, where $\bar x_0$ is the measured state and the $\bar u_k$ are the last solution's inputs shifted by one, it fits

$$x_{k+1} = A_k x_k + B_k u_k + c_k, \qquad (A_k, B_k, c_k) = \mathrm{fit}(\bar x_k, \bar u_k), \qquad \bar x_{k+1} = A_k \bar x_k + B_k \bar u_k + c_k,$$

one local regression per step, each with the structured rows for $v_x, v_y, r$ from the 7 nearest transitions of each of the 4 most recent laps and the exact Frenet rows linearised at $\bar x_k$. Then it stacks them exactly as chapter [[a02]] did for a constant model, with the matrices now indexed by step:

$$x_k = \Phi_k x_0 + \Gamma_k U + d_k, \qquad \Phi_{k+1} = A_k \Phi_k, \quad \Gamma_{k+1} = A_k \Gamma_k + B_k E_k, \quad d_{k+1} = A_k d_k + c_k,$$
%narrow x_k = \Phi_k x_0 + \Gamma_k U + d_k, \\ \Phi_{k+1} = A_k \Phi_k, \quad \Gamma_{k+1} = A_k \Gamma_k + B_k E_k, \\ d_{k+1} = A_k d_k + c_k

where $E_k$ picks $u_k$ out of the stacked $U$ and the affine constants accumulate in $d_k$. Every predicted state is then affine in $U$ and every constraint on it is a row of the QP, as in chapter [[a05]].

**Why along the previous plan, not the stored lap.** At the first sample of the first learned lap there is no previous plan; the controller takes the fastest stored lap's inputs from the nearest stored state as the guess. From then on the shifted solution is the guess: the plan the optimiser found a tenth of a second ago is the best available picture of where the car will be, and the local model is only trustworthy near data it was fitted on, which the plan's states are if the plan resembles a stored lap. Over the twenty laps the model layer never ran out of data at a horizon state until lap 20, where 10 of 1106 local fits fell back to the nearest seven transitions with a widened bandwidth, lab [[b04]]'s support fallback: by then the car was going where no stored lap had gone.

## The safe-set layer: forty-eight states near the end of the plan {#safeset}

Chapter [[a12]] stored every state of every successful run. On the track that would be thousands of states in six dimensions, and, worse, a hull spanning the whole lap would ask the local model to be valid across it. The racing controller keeps a *local* convex safe set:

$$S = \bigcup_{i \in \text{4 fastest laps}} \{ \text{the 12 stored states of lap } i \text{ nearest in } s \text{ to } \hat s_N \}, \qquad \hat s_N = \text{the progress of the plan's predicted end},$$
%narrow S = \bigcup_{i \in \text{4 fastest}} \{ 12 \text{ states of lap } i \text{ nearest in } s \text{ to } \hat s_N \}

48 states in all, with their costs-to-go $J_r$ in samples. Nearest in progress, not in the full state: the terminal state must land in their hull, and states one or two metres ahead on the track are the ones a 1.4 s horizon can reach.

**Counting to the finish line.** A lap of $T_i$ samples gives its $k$-th state the cost $J = T_i - k$: how many samples that lap still needed. Minimising $\lambda^\top J$ at the end of the plan is minimising the expected remaining lap time, in tenths of a second, as the stored laps experienced it. There is no reference line and no speed target anywhere in the cost; the car goes faster because the states of faster laps carry smaller costs, and chapter [[a13]]'s LP mixes them.

**The finish line is not a wall.** Near the end of a lap the plan's end lies beyond $s = L$, where a lap's own stored states run out. Each lap's first 40 states are appended with $s + L$ and cost-to-go $-k$: the lap after the line, represented by the same lap's start, so that crossing the line is worth exactly what it costs and the plan may look through it. Without this the car would brake before the line, which is lab [[b02]]'s plateau in a different guise: a terminal value that is pessimistic where the data end.

**Fastest four, most recent four.** The safe set takes the four fastest successful laps, so a slow early lap drops out as soon as four better ones exist; the model takes the four most recent successful ones, whose operating points are closest to the current car. Lap 19, which left the track, counts as unsuccessful for both and is never stored, which is chapter [[a12]]'s rule that only successful runs certify anything.

## The cost: lap time through the terminal value, smoothness through rates {#cost}

$$\min_{U, \lambda}\ \sum_{k=0}^{N-1} (u_k - u_{k-1})^\top \begin{pmatrix} 5 & 0 \\ 0 & 50 \end{pmatrix} (u_k - u_{k-1}) + \lambda^\top J,$$

with $u_{-1}$ the input applied at the previous sample. The rate penalty is the only stage cost: it stops the steering from chattering between samples and keeps the acceleration from flipping between its bounds, and it is cheap enough, on a scale where $J$ counts samples, that the lap time dominates. The constraints are the lane on every predicted state, $|e_{y,k}| \le 0.4$, a speed box $0.1 \le v_{x,k} \le 4$ that keeps the affine model from being asked about a stopped or an absurd car, the input bounds $|\delta_k| \le 0.5$, $|a_k| \le 10$, and the terminal ingredients

$$x_N = S^\top \lambda, \qquad \mathbf 1^\top \lambda = 1, \qquad 0 \le \lambda \le 1 .$$

Six equality rows tie the plan's end to the hull of the 48 stored states, one row makes the weights a mixture. With $x_N$ affine in $U$ these are linear equalities in $(U, \lambda)$: the problem is a QP, exactly the structure of chapter [[a13]]'s LMPC problem with the matrices of lab [[b04]] in place of $A$ and $B$.

## The QP, and a fallback rule {#qp}

Seventy-six variables, 28 inputs and 48 weights; 56 inequality rows for the lane and the speed box, 56 input bounds and 96 weight bounds stacked by the solver, 7 equalities. The interior-point method of chapter [[a04]] solves it in 16 to 35 iterations, about 8 ms each on the author's laptop, which is comfortably inside the 100 ms sample. A lap is 80 to 220 such problems; the twenty laps are 2376 of them.

The orange plan starts at the car and ends on the circled terminal point, which is a mixture of two or three stored states, the enlarged dots: Carathéodory's theorem (chapter [[a13]]) promises a representation with at most seven points in six dimensions, and the LP's optimum uses far fewer. At sample 25 of lap 3 the car is at $s = 2.83$ m at 1.22 m/s; the plan ends at $s = 4.52$ m with a learned value of 141.0 samples, chosen among candidates worth 136 to 243.

**When the QP is infeasible.** The guess may be wrong enough, or the car may have gone where no stored state is reachable within the lane, for the equality and lane rows to be incompatible. The solver then reports a failure (its residual does not fall, chapter [[a04]] Part 8), and the controller applies the rule of lab [[b04]]'s exercise 11: replay the input of the fastest stored lap at the stored state nearest the car in $(s, e_y)$, an input known to have kept a car inside the lane from nearly here, and rebuild the guess from that lap. On the first eighteen laps the rule was never needed; lap 19 needed it 49 times.

**What happened.** The first learned lap already cuts the seed time by 8.5 s: with no state cost at all, the terminal value alone pulls the car towards the states of the seed laps that were closest to the line, and the plan may drive the input to its bounds between them. Each lap then widens the envelope: the fastest stored speed grows by about 0.1 m/s a lap because the terminal state must stay in the hull of stored states, and only the stored states can raise it. Eighteen laps improve on every lap before them, the gains shrinking from 3.6 s to 0.1 to 0.3 s as the car approaches what its tyres allow in the corners. The inputs stayed inside their bounds on every lap by construction, and the lane was respected on every lap but one, with the largest offset rising from 0.18 m to 0.36 m as the controller learned to use the width of the track.

**Lap 19.** At 2.98 m/s, going where no stored lap had been, the local model's prediction and the car parted ways: the plan was feasible, the car arrived somewhere else, and from there no plan satisfied both the lane rows and the terminal equality. The QP was infeasible at 49 of 93 samples; the fallback replayed the fastest lap's inputs, the car ran 0.92 m from the centreline, more than twice the half-width, and came back. The lap was not stored. Lap 20, from the same database as lap 18 plus nothing, drove 7.9 s, the fastest of all, with 10 local fits short of data. Part 7 says why none of this contradicts a theorem, and why it is the honest end of the course.

## What is guaranteed, and what the car does not give {#guarantees}

Chapter [[a12]] proved that the convex hull of stored states is control invariant, and chapter [[a13]] that the barycentric value decreases along a stored mixture, so that the LMPC of lab [[b02]] is recursively feasible and its iteration cost never increases. Both proofs use linearity exactly once, at the line

$$f\Big(\sum_r \lambda_r s_r,\ \sum_r \lambda_r u_r\Big) = \sum_r \lambda_r f(s_r, u_r),$$

which says that the mixture of stored states driven by the mixture of stored inputs lands on the mixture of stored successors. For the bicycle model it is false: the tyre forces are nonlinear in the slip angles, and chapter [[a12]]'s one-dimensional counter-example, $f(x, u) = x^2 + u$, already breaks it. The racing controller has no certificate of recursive feasibility and no non-increasing lap time. What it has instead:

1. **A local convexification.** The 48 states span a short stretch of track and a narrow band of speeds, within which the car's dynamics are close to affine, and the local model is fitted on exactly those transitions. The hull is approximately invariant in the sense that a mixed input from a mixed state lands near the mixed successor, with an error of the order of the model's one-step error, 0.01 to 0.02 in the velocities on lab [[b04]]'s held-out lap.
2. **An empirical learning curve.** Eighteen monotone laps are an observation, as lab [[b02]] insisted its curves were, not a theorem. The curve bends when the model's error grows faster than the gains shrink.
3. **A fallback that is itself data.** The replayed input is one that kept a car in the lane from nearly the same state; it is not a proof either, and on lap 19 the car still left the track by half a metre before the replayed inputs brought it back. A real car would want a hard brake-and-hold law with its own invariant set, the layered fallbacks of lab [[b06]].

What transfers from the theory is the mechanism, not the certificate: the terminal set gives the optimiser somewhere safe to end, the terminal value tells it which end is cheap, the receding horizon corrects the model's errors at every sample, and the data improve both ingredients with every lap. What does not transfer is the word "guaranteed". Robust learning MPC, with the model error bounded and the constraints tightened by it, is where that word comes back, and chapter [[c01]] shows the linear version of the tool.

## The learning curve, and a bound it will not reach {#curve}

The lap times fall as $21.9, 18.3, 16.6, \dots, 8.3$ s, each gain smaller than the last. Lab [[b02]]'s double integrator converged in three iterations because its terminal value, once the data reached the optimal path, was exact; here the terminal value is only as good as the fastest stored lap, and each lap can be faster than the stored ones only by what the model lets the optimiser dare between stored states. That is why the fastest speed climbs in steps of about 0.1 m/s: the gain per lap is the width of the model's trust region, not the distance to the optimum.

**The planner's number.** Lab [[b03]]'s centreline speed planner, run on the same scaled track with the tyres' peak friction coefficient 0.8 and the input bound $|a| \le 10$, needs 4.43 s for a lap at 2.20 to 7.85 m/s. The fastest learned lap takes 7.9 s at 1.60 to 2.99 m/s, half the planner's speed on average and 30 percent of it at $s = 9.5$ m. The two are different problems. The planner has no lateral dynamics: it allows the speed that pure friction permits at each curvature, with no tyre slip, no yaw inertia, no steering bound, and it drives the centreline, where the learned car uses up to 0.34 m of the 0.4 m half-width to straighten its line. The planner is an optimistic bound for a car that could instantly take any lateral acceleration up to $0.8g$; the learned controller is a real closed loop on a car whose tyres saturate, and it has driven 20 laps. Where the planner says the straights allow 7.85 m/s, the learned car reaches 3 m/s because no stored lap has gone faster, and the gap on the straights is the clearest picture of what more laps would buy before the corners, not the data, became the limit.

## The code behind it {#code}

The chapter's controller lives in its numbers script, `code/c04_numbers.py`, which also carries a copy of the track, the car and lab B4's local regression from the course package's racing module so that it runs alone. Its solve function is the QP of Parts 2 to 5 in forty lines; read it against the linear `LMPCController.solve` below it, which it generalises.

```python
    def solve(self, x0, u_prev, U_guess, model):
        """One Learning MPC step: linearise along the guess, build the QP in (U, lambda), solve it."""
        n, m = 6, 2
        A_list, B_list, c_list, xbar, fallbacks = [], [], [], np.asarray(x0, float).copy(), 0
        for k in range(N):                                   # the LTV model along the guessed trajectory
            A, B, c, fb = model.fit(xbar, U_guess[k]); fallbacks += fb
            A_list.append(A); B_list.append(B); c_list.append(c)
            xbar = A @ xbar + B @ U_guess[k] + c
        P, Gm, d = [np.eye(n)], [np.zeros((n, m * N))], [np.zeros(n)]
        for k in range(N):                                   # x_{k+1} = A_k x_k + B_k u_k + c_k, stacked in U
            Gk = A_list[k] @ Gm[k]; Gk[:, m * k:m * k + m] += B_list[k]
            P.append(A_list[k] @ P[k]); Gm.append(Gk); d.append(A_list[k] @ d[k] + c_list[k])
        base = [P[k] @ x0 + d[k] for k in range(N + 1)]      # the part of x_k that does not depend on U
        S, J, _ = self.safe_set(float(base[N][4]))
        M = len(S)
        nz = m * N + M
        # cost: input rates, and the learned terminal value lambda' J
        D = np.eye(m * N)
        for k in range(1, N):
            D[m * k:m * k + m, m * (k - 1):m * k] = -np.eye(m)
        Rbar = np.kron(np.eye(N), RATE)
        p = np.zeros(m * N); p[:m] = u_prev
        H = np.zeros((nz, nz)); H[:m * N, :m * N] = 2.0 * D.T @ Rbar @ D
        f = np.zeros(nz); f[:m * N] = -2.0 * D.T @ Rbar @ p; f[m * N:] = J
        # lane and speed constraints on every predicted state
        A_ub, b_ub = [], []
        for k in range(1, N + 1):
            for row, sign, lim in ((5, 1.0, self.W), (5, -1.0, self.W), (0, 1.0, VX_MAX), (0, -1.0, -VX_MIN)):
                r = np.zeros(nz); r[:m * N] = sign * Gm[k][row]
                A_ub.append(r); b_ub.append(lim - sign * base[k][row])
        # terminal state in the convex hull of the local safe set
        A_eq = np.zeros((n + 1, nz)); b_eq = np.zeros(n + 1)
        A_eq[:n, :m * N] = Gm[N]; A_eq[:n, m * N:] = -S.T; b_eq[:n] = -base[N]
        A_eq[n, m * N:] = 1.0; b_eq[n] = 1.0
        lb = np.r_[np.tile(UMIN, N), np.zeros(M)]; ub = np.r_[np.tile(UMAX, N), np.ones(M)]
        res = solve_qp(H, f, A_ub=np.vstack(A_ub), b_ub=np.array(b_ub), A_eq=A_eq, b_eq=b_eq, lb=lb, ub=ub)
        U = res.x[:m * N].reshape(N, m); lam = res.x[m * N:]
        X = np.array([base[k] + Gm[k] @ res.x[:m * N] for k in range(N + 1)])
        return {"success": res.success, "U": U, "lam": lam, "X": X, "S": S, "J": J, "terminal": S.T @ lam,
                "value": float(lam @ J), "nit": res.nit, "fallbacks": fallbacks}
```

Four blocks. The first fits the time-varying model along the guess and accumulates `P`, `Gm` and `d`, the $\Phi_k$, $\Gamma_k$ and $d_k$ of Part 2; `base[k]` is what $x_k$ would be with $U = 0$. The second builds the rate penalty: `D` is the difference matrix of chapter [[a05]]'s rate constraints, and the previous input enters through `p`, so that the first rate is $u_0 - u_{-1}$. The third writes the lane and speed rows for $k = 1, \dots, N$ with the sign trick that turns a two-sided bound into two one-sided rows. The fourth is chapter [[a13]]'s terminal equality, $\Gamma_N U - S^\top \lambda = -\text{base}_N$, with the simplex row under it. The solver's `success` flag drives the fallback in the lap loop.

::: code advanced_mpc_lmpc/lmpc.py:LMPCController.solve
The linear controller of lab [[b02]] is the same problem with three differences. Its prediction matrices are the constant `Sx`, `Su` of chapter [[a02]], computed once in the constructor, where the racing solve rebuilds `Gm` every sample from fourteen local fits. Its safe set is every stored state of the trajectories in the window, `safe_data`, where the racing solve keeps 48 near the plan's end. And its stage cost is the quadratic $x^\top Q x + u^\top R u$ with the $\ell_1$ epigraph block, where the racing cost is a rate penalty alone. Everything else is literally the same rows: the state bounds through the prediction matrices, `A_eq` tying `x_N` to `S.T`, the row of ones, the weights bounded in $[0, 1]$, and one call to `solve_qp`.
:::

## Common pitfalls {#pitfalls}

1. **"The lap time falls every lap, so the method is stable."** Eighteen monotone laps are an observation on a nonlinear plant with no certificate; lap 19 is what the missing certificate looks like.
2. **"The safe set is the hull of all stored states."** Only locally: 48 states near the plan's end. The hull of a whole lap would be meaningless for a nonlinear car and would ask the local model to be valid across the track.
3. **"The controller tracks the fastest lap."** There is no reference anywhere. It minimises the learned samples-to-finish of its terminal state; the fastest lap matters only through the costs its states carry and the inputs the fallback replays.
4. **"Infeasibility means the car is lost."** It means no plan exists under the local model, the lane rows and this safe set. The fallback input is itself stored data, and it brought the car back; a real car needs a certified backup on top.
5. **"The planner's 4.43 s is the optimum this car should reach."** The planner ignores lateral dynamics, tyre saturation and the steering bound and drives the centreline. It bounds a different car.
6. **"More laps always help."** Each lap widens the data envelope by about what the model can be trusted to extrapolate; past the point where the model's error outgrows that step, a lap can leave the track, and a lap that does is not stored.

## Check your understanding {#check}

:::: qa
Try to answer each question before opening it.

::: q 1. Why is the model refitted along the previous plan rather than fixed for the lap?
Because the car's affine model changes with the operating point, as lab [[b04]] measured: along a 14-step horizon the matrices move by norms of order one. The previous plan, shifted by one, is the best estimate of the horizon's operating points, and the fits there are supported by stored data as long as the plan resembles a stored lap.
:::
::: q 2. What does a stored state's cost-to-go count, and why can it be negative?
The samples the lap that visited it still needed to cross the finish line, $T_i - k$. A lap's first 40 states are appended beyond the line with $s + L$ and cost $-k$, standing in for the lap after the line, so that a plan ending past the line is priced correctly instead of being pulled back to it.
:::
::: q 3. Why 12 states from each of the 4 fastest laps, nearest in progress?
The terminal state must land in their hull, and a 1.4 s horizon reaches about a metre or two of track; states nearest in $s$ are the reachable ones. Four laps give the hull some width in the other coordinates; the fastest four carry the smallest costs, which is what the optimiser is after.
:::
::: q 4. Where is the lap time in the cost?
Only in $\lambda^\top J$: the learned samples-to-finish of the terminal state. The rate penalty is for smoothness; there is no state cost and no reference.
:::
::: q 5. Which line of chapter A12's invariance proof fails for the car?
The one that pulls the convex combination through the dynamics, $f(\sum \lambda_r s_r, \sum \lambda_r u_r) = \sum \lambda_r f(s_r, u_r)$: true for a linear model, false for Pacejka tyres. The local safe set makes the error small, not zero.
:::
::: q 6. What exactly happened on lap 19, in the vocabulary of chapter A6?
A loss of recursive feasibility: the plan was feasible, the applied input took the plant somewhere the plan did not predict, and from there no plan satisfied the constraints and the terminal equality. For the linear cart with designed or learned terminal ingredients that cannot happen; here the terminal ingredients are only approximately invariant.
:::
::: q 7. Why is lap 19 not stored, and what would storing it do?
Chapter A12's safe set certifies feasible continuations only from successful runs. A lap that left the lane would offer continuations through states outside the lane as "safe", and the terminal value would price them as cheap because the lap was fast.
:::
::: q 8. Why can the learned car not reach the planner's 7.85 m/s on the straights?
The terminal state must be a mixture of stored states, so the plan can end only at stored speeds, and each lap raises the fastest stored speed by what the local model will extrapolate, about 0.1 m/s. The planner's number also belongs to a car without lateral dynamics; even with unlimited laps the learned car would stop short of it in the corners.
:::

:::: exercise The rate penalty

`RATE` in Part two. A rate penalty is the only term in the cost that depends on the inputs; without it the QP is a linear program in the inputs and the optimiser sits on the bounds.

## The course on one page {#summary}

::: steps
- **A state and a model** (A1, A2): the car's six coordinates, and an affine time-varying model stacked over fourteen steps.
- **A convex problem and its solver** (A3, A4, A5): one QP per sample, 76 variables, solved by the interior-point method to a certificate of optimality.
- **The receding horizon** (A6): apply the first input, measure, shift, refit, solve again, 2376 times in twenty laps.
- **Sets and invariance** (A8 to A11): the lane as a polytope, and terminal ingredients that make the loop feasible and stable when the plant is linear.
- **Learning the terminal ingredients** (A12, A13, B2): a safe set of stored states and a value learned from their costs, here local, with the lap time as the cost.
- **The racing problem** (B3, B4): Frenet coordinates, the bicycle model, and a prediction model learned from laps.
- **Closing the loop** (C4): 30.4 s to 8.3 s in eighteen laps, each inside the lane, then one lap that is not, and a 7.9 s lap after it.
- **What was proved and what was observed** (A11, B6): every certificate in the course was for a model that equals the plant; the racing car is the reminder.
:::

### The vocabulary, in one table

| Word | Meaning here |
|---|---|
| Lap, flying start | One crossing of the line to the next; later laps start where the previous ended. |
| Samples to the finish | The cost-to-go of a stored state: how many samples its lap still needed. |
| Local safe set | 48 stored states near the plan's predicted end, from the four fastest laps. |
| Wrapped states | A lap's first 40 states shifted by one lap length, with negative cost, standing for the next lap. |
| Plan, guess | The 14-step predicted trajectory; the previous plan shifted, along which the model is refitted. |
| Rate penalty | The only stage cost, on $u_k - u_{k-1}$. |
| Fallback | On an infeasible QP, the fastest stored lap's input from the nearest stored state. |
| Model support fallback | A local fit with no stored transition inside the kernel bandwidth. |

**Scope.** A deterministic simulation with a measured state, one controller configuration, and twenty laps; no disturbance, no sensor, no robustness certificate. The planner comparison uses lab B3's reduced model on the same track and is a bound for a different car.
