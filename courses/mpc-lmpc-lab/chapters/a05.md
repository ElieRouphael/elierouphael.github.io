## The constrained finite-time optimal control problem {#problem}

::: define What is a CFTOC?
**In plain words:** choose a finite sequence of inputs so that the predicted trajectory of a model costs as little as possible while every state, input and terminal requirement holds. It is one optimisation, solved once, for a plan; it is not yet a controller.

**More precisely:** for a prediction model $x_{k+1} = f(x_k, u_k)$ and the current state $x_0 = \bar x$,

$$\begin{aligned} J_N^\star(\bar x) = \min_{u_0, \dots, u_{N-1}}\ & V_f(x_N) + \sum_{k=0}^{N-1} q(x_k, u_k) \\ \text{subject to}\ & x_{k+1} = f(x_k, u_k), \quad x_k \in \mathcal X, \quad u_k \in \mathcal U, \quad x_N \in \mathcal X_f, \quad x_0 = \bar x, \end{aligned}$$
%narrow \begin{aligned} J_N^\star(\bar x) = \min_{U}\ & V_f(x_N) + \textstyle\sum_{k=0}^{N-1} q(x_k, u_k) \\ \text{s.t.}\ & x_{k+1} = f(x_k, u_k),\ x_k \in \mathcal X, \\ & u_k \in \mathcal U,\ x_N \in \mathcal X_f,\ x_0 = \bar x \end{aligned}

with $q$ the stage cost, $V_f$ the terminal cost, $\mathcal X$ and $\mathcal U$ the admissible sets and $\mathcal X_f$ a terminal set [[ref:1]]. The solution is the whole open-loop sequence $U^\star(\bar x) = (u_0^\star, \dots, u_{N-1}^\star)$ and the optimal value $J_N^\star(\bar x)$.

- Stage cost $q(x, u)$ :: What one step costs, here $x^\top Q x + R u^2$.
- Terminal cost $V_f(x_N)$ :: The estimated price of everything after the horizon; $P = Q$ until chapter [[a07]].
- Terminal set $\mathcal X_f$ :: Where the plan must end; a point, a set, or everything, chapter [[a11]].
- Decision variable :: $U$ in the condensed form, $(X, U)$ in the sparse form, chapter [[a02]].
:::

For linear dynamics, a quadratic cost and polyhedral sets it is the convex QP of chapter [[a02]]: $H$ fixed, $f$ and the right-hand sides affine in $\bar x$. The chapter's instance has $N = 8$, so 8 decision variables, 64 inequality rows (two per predicted position and velocity, two per input, two per input change) and 2 equality rows for the terminal point. Model predictive control, chapter [[a06]], is the loop that solves such a problem at every sample and applies the first input; everything the loop inherits, feasibility, cost, the meaning of the multipliers, is decided here.

**The plant is not the prediction model.** The problem is posed on $f$, the optimiser's model. The real system evolves on its own. In the concept chapters the two coincide so that the theory can be checked; chapter [[a01]] fixed the vocabulary, chapter [[b06]] counts the consequences of a gap.

## Hard and soft constraints {#hardsoft}

A **hard** constraint $a^\top z \le b$ must hold; if it cannot, the problem has no solution and the solver says so. A **soft** constraint may be violated at a price: add a slack $\epsilon \ge 0$, write $a^\top z \le b + \epsilon$, and add $\rho \epsilon$ to the cost. For a set of rows $H_x x_k \le h_x$ softened together, one slack per row and the penalty $\rho \sum_k \mathbf 1^\top \epsilon_k$ keep the problem a QP, with the slacks as extra variables bounded below by zero.

**The threshold is the multiplier.** Chapter [[a03]] read the multiplier as the price of a constraint: relaxing a row by $\delta$ lowers the cost by $\lambda \delta$. A soft constraint offers exactly that trade at the rate $\rho$ per unit, so the optimiser buys a violation when $\rho < \lambda^\star$ and refuses when $\rho \ge \lambda^\star$. The $\ell_1$ penalty is *exact*: above the threshold the soft problem returns the hard solution unchanged, and it still returns a plan, the least violating one, when the hard problem is infeasible [[ref:4]]. A purely quadratic penalty $\rho \epsilon^2$ never is: its marginal price vanishes at $\epsilon = 0$, so a small violation is always bought.

Softened with $\rho = 0.63$ the optimiser lets the velocity reach $1.047$; with $\rho = 1.26$, $1.021$; from $\rho = 2.5145$ on the slack is zero and the inputs agree with the hard solution to $10^{-14}$.

**Which is which is an engineering decision.** Actuator limits are hard: a motor cannot deliver more than it can. Collision constraints should be hard safety requirements, chapter [[b01]]. Comfort and tracking envelopes may be softened. A slack prevents numerical infeasibility; it does not make a safety violation acceptable, and a controller that relies on slacks to stay feasible is signalling that its hard constraints were wrong.

## Terminal conditions {#terminal}

The last predicted state can be left free, pinned to a point, or confined to a set. Each is a different problem.

**Only a cost.** With $\mathcal X_f = \mathcal X$ the horizon ends wherever the optimiser likes and pays $V_f(x_N)$ for it. The feasible set is largest, nothing is certified about what happens after step $N$, and chapter [[a11]] shows loops built this way losing feasibility a few steps later.

**A point.** $x_N = 0$ is two equality rows of the condensed form, $\mathcal S_{u,N} U = -\mathcal S_{x,N} \bar x$. It is the crudest terminal set: the plan must come to rest at the origin within $N$ steps, which makes the feasible set small for short horizons. The chapter's instance uses it. Its multipliers $\nu$ are unsigned, since an equality pushes from both sides; at the solution they are $(-0.046, 0.013)$, small, because the cost already pulls the cart almost home.

**A set.** $x_N \in \mathcal X_f$ for a polytope $\mathcal X_f = \{x : H_f x \le h_f\}$ is a few more inequality rows, $H_f \mathcal S_{u,N} U \le h_f - H_f \mathcal S_{x,N} \bar x$. When $\mathcal X_f$ is invariant under a local controller the plan need only reach a region from which that controller can finish, which is the whole idea of chapter [[a11]].

## One complete instance {#instance}

**The problem.** The canonical cart from $\bar x = (-3, 0)$ over $N = 8$ steps, with $Q = \mathrm{diag}(1, 0.2)$, $R = 0.2$, $P = Q$, and

$$|p_k| \le 4, \qquad |v_k| \le 3, \qquad |u_k| \le 1, \qquad |u_k - u_{k-1}| \le 0.5 \ (u_{-1} = 0), \qquad x_N = 0 .$$

A convex QP, smallest eigenvalue of $H$ equal to $0.508$. The solver converges in 15 iterations with a largest constraint violation of $6 \times 10^{-15}$. Its answer, which the hero reproduces:

::: table num
| Quantity | Value |
|---|---|
| Physical cost $J$ | 22.2253 (the QP objective $-58.7747$ plus the dropped constant 81) |
| Inputs | 0.5, 0.535, 0.035, −0.465, −0.632, −0.132, 0.134, 0.025 |
| Largest $\lvert u \rvert$, largest $\lvert \Delta u \rvert$ | 0.632, 0.500 |
| Peak velocity | 1.070 |
| Active inequalities | 4 of 64, all rate bounds |
| Terminal state, multipliers $\nu$ | $(0, 0)$ exactly, $(-0.046, 0.013)$ |
:::

**Reading it.** The input ramps up at the rate limit, $0.5$ then $0.535$, coasts, ramps down through zero to $-0.632$ and ramps back to land at rest: a bang-coast-bang shape rounded by the rate bound. Neither the input bound nor the box binds; the velocity peaks at $1.07$ under its bound of 3. The four active rows are rate bounds, at steps 0, 2, 3 and 5, with multipliers $9.85$, $1.86$, $0.88$ and $0.09$. The first is by far the most expensive: the controller would pay most for being allowed to accelerate faster than $0.5$ from a standstill. The numbers script checks the price: relaxing that one bound by $0.001$ lowers $J$ by $0.00985$, which is $9.848$ per unit against the multiplier $9.852$, the difference being the curvature of $J^\star(b)$ that chapter [[a03]] described.

**Without the terminal equality** the cost falls only to $22.2250$ and the horizon ends at $(-0.0135, -0.0004)$: the terminal weight already pulls the state nearly home, and pinning it costs $0.0003$. The rate multipliers barely move. On a short horizon from a far corner the difference is large, Part 5.

**The sparse form agrees.** Solved with the states as variables, 24 unknowns and 18 equalities, the inputs agree with the condensed ones to $7 \times 10^{-15}$: the same problem, as chapter [[a02]] promised.

## When there is no plan {#infeasible}

Shorten the horizon to $N = 4$ and keep $x_N = 0$. The solver fails after its iteration cap, and the feasibility LP of chapter [[a04]] returns a margin of $0.154$: no input sequence brings the cart from $(-3, 0)$ to rest at the origin in four steps when each input may change by at most $0.5$ per step. The inputs can only reach $0.5, 1, 1, 1$ in four steps, and must come back down to stop; the arithmetic does not close. From $N = 5$ on the margin is zero and a plan exists.

Two readings of an infeasible problem, to keep apart. As a statement about the model: *from this state, with these limits and this horizon, no admissible plan meets the requirement.* That is a fact, certified by the LP. As a statement about the world: nothing. The model may be too coarse, the horizon too short, the terminal condition too strict, or the limits too conservative. A controller that meets an infeasible problem needs a fallback, chapter [[b06]], and a design that avoids meeting one is the subject of chapter [[a11]].

## The nonlinear case: the unicycle {#nonlinear}

**Model.** $\dot x = v \cos\theta$, $\dot y = v \sin\theta$, $\dot\theta = \omega$, with state $z = (x, y, \theta)$ and input $u = (v, \omega)$. Forward Euler with $T_s = 0.2$ gives $x_{k+1} = x_k + T_s v_k \cos\theta_k$, $y_{k+1} = y_k + T_s v_k \sin\theta_k$, $\theta_{k+1} = \theta_k + T_s \omega_k$. The prediction map contains sines and cosines, so the states are not an affine function of the inputs: there is no prediction identity, the finite-horizon problem is a nonlinear program, and it is in general nonconvex.

**The terminal-pose problem.** Drive from $(0, 0, 0)$ to $(2, 1, 0)$ in $N = 30$ steps with $|v_k| \le 1$, $|\omega_k| \le 1$, input rates bounded by $0.2$ per step, minimising effort and roughness, $J = 0.05 \sum_k \lVert u_k \rVert^2 + 0.10 \sum_k \lVert u_k - u_{k-1} \rVert^2$, with the terminal pose as a nonlinear equality. The numbers script solves it with SciPy's SLSQP, the sequential quadratic programming method the course's own solver cannot replace here, and reports success with cost $0.3167$ and a terminal residual of $5 \times 10^{-12}$; for the target $(0, 1, \pi)$, cost $0.4941$.

::: callout warm
**Solver convergence is not a certificate of global optimality.** For the linear-quadratic instance the dynamics were affine, the constraints linear, the objective convex: a convex QP, whose KKT point is the global optimum. For the unicycle the solution a local solver returns may depend on the initial guess. The numbers script restarts SLSQP from four different guesses, the course's, straight ahead, turning the other way first, and random inputs, and all four converge to the same cost to four decimals and the same inputs to $1.5 \times 10^{-5}$. That is evidence about this problem, gathered by trying, not a theorem: nonconvexity makes multiple local optima possible, not certain, and a single successful run would not have shown which.
:::

The route back to convexity is to linearise along a trajectory and solve a sequence of QPs, which is how chapter [[b04]] gives a nonlinear car an affine prediction model, and how real nonlinear MPC solvers work.

## Beyond "the solver converged" {#habits}

For every numerical optimal control solution, inspect at least:

1. **the solver status and the KKT residual**, chapter [[a04]]: `success` and `kkt_residual`, not a message;
2. **the constraint violation**: the largest $Gz - g$ and $|Ez - e|$, which should be at round-off;
3. **the terminal residual**, if a terminal condition was imposed;
4. **the active set and its multipliers**: which limits bind and how much they cost, the shape of the solution;
5. **the physical cost**, constant included, when values at different states are compared;
6. **the sensitivity to the initial guess**, for nonconvex problems;
7. **the scaling**: if one state is in millimetres and another in hundreds of metres per second, the Hessian spans many orders of magnitude, the residuals mean different things in different rows and the active set is identified unreliably. Scale the variables so typical values are of order one, and transform weights and constraints consistently;
8. **whether the prediction model matches the plant**, which no residual can tell.

A beautiful trajectory from an infeasible or unconverged solution is not a control result. The hero's readouts are this list applied to one problem.

**Modelling decisions are optimisation decisions.** Before writing code: what is the decision variable? Which model predicts the future? Which constraints are physical, which safety-critical, which can be softened? Is the terminal condition an equality, a set or only a cost? Is the formulation convex? Are there discrete decisions, chapter [[a15]]? Is the model exact or approximate? Is the problem solved once, or repeatedly in feedback? These questions fix the mathematics before they fix the software.

## The code behind it {#code}

The hero's problem is built by the same recipe as the package's MPC class, which the numbers script reproduces row for row; the class is the reference implementation of the condensed CFTOC.

::: code advanced_mpc_lmpc/mpc.py:LinearMPC.solve
After $H$ and $f$, chapter [[a02]], the constraint rows are appended to two lists. The upper state bound is the matrix `Su` against `tile(x_upper, N) - Sx @ x0`: one row per predicted state component, every predicted step at once. The lower bound is `-Su` against `-tile(x_lower, N) + Sx @ x0`. A terminal polytope, when given, contributes `terminal_H @ SuN` against `terminal_h - terminal_H @ SxN @ x0` with the last block rows of the prediction matrices. The `extra_A_ub` hook lets a caller add rows of its own, which is how the rate bounds of this chapter and the collision rows of chapter [[b01]] enter. The input bounds are passed as `lb` and `ub`, which the solver stacks as rows itself. Nothing in the assembly depends on the solver: the lists are the problem, and `solve_qp` could be swapped for any QP solver with the same signature, which is what chapter [[a04]] did.
:::

## Common pitfalls {#pitfalls}

1. **"A CFTOC is a controller."** It is one plan from one state. The controller is the loop that solves it again from the next measured state, chapter [[a06]].
2. **"The objective the solver prints is the cost."** It omits $c(\bar x)$, here 81. The physical cost is $22.2$, not $-58.8$.
3. **"Softening makes the controller safe."** It makes the QP feasible. A violated soft constraint is a violated constraint; the penalty only prices it.
4. **"A small $\nu$ means the terminal equality does not matter."** It means it costs little *here*, because the cost already pulls the state home. From a far corner with a short horizon the same equality makes the problem infeasible.
5. **"Restarts agreeing proves the optimum is global."** They are evidence from a sample of starts. Only convexity, or an exhaustive method, proves it.

## Check your understanding {#check}

:::: qa
Try to answer each question before opening it.

::: q 1. What is a CFTOC, and what is it not?
One finite-horizon optimisation over a prediction model, returning a whole input sequence and its cost. It is not a feedback law: that is the receding-horizon loop around it.
:::
::: q 2. Why is the chapter's instance a convex QP?
Affine dynamics, a quadratic cost with $R > 0$, and polyhedral constraints: the condensed Hessian is positive definite and every constraint is a linear row in $U$.
:::
::: q 3. What does the multiplier 9.85 on the first rate bound mean?
That relaxing the bound $|u_0 - u_{-1}| \le 0.5$ by a small $\delta$ would lower the optimal cost by about $9.85\,\delta$: it is the most expensive limit in the problem.
:::
::: q 4. Why does an $\ell_1$ penalty reproduce the hard solution above a threshold, and a quadratic one never?
The $\ell_1$ penalty charges $\rho$ per unit from the first unit, so for $\rho \ge \lambda^\star$ a violation never pays. A quadratic penalty charges nothing at the margin for the first unit, so a small violation always pays.
:::
::: q 5. What does the feasibility margin $0.154$ for $N = 4$ certify?
That no input sequence satisfies the constraints as posed: the smallest uniform relaxation that would make them compatible is $0.154$, computed by an LP that shares no code with the QP solver.
:::
::: q 6. Why is the unicycle problem nonconvex?
Its predicted states depend on the inputs through $\sin\theta$ and $\cos\theta$, so the dynamics are nonlinear equalities and the feasible set in the inputs is not convex.
:::
::: q 7. What do agreeing restarts establish?
That several starts reached the same local optimum. They raise confidence; they do not prove the optimum is global.
:::
::: q 8. Why reconstruct the full cost rather than trust the solver's objective?
Because the solver drops a state-dependent constant. Comparing values at different states, as a Lyapunov argument does, needs the constant back.
:::
::: q 9. Why does scaling matter to a solver that is exact in theory?
Residuals and tolerances are absolute numbers; rows in different units make the same tolerance mean different accuracies, and badly scaled Hessians make the active set hard to identify.
:::

```python
from advanced_mpc_lmpc.mpc import LinearMPC
N = 8; x0 = np.array([-3.0, 0.0])
mpc = LinearMPC(A, B, Q, R, N, P=Q, x_lower=[-4, -3], x_upper=[4, 3], u_lower=[-1], u_upper=[1])

SuN, SxN = mpc.Su[-2:], mpc.Sx[-2:]
A_extra = np.vstack([D, -D, SuN, -SuN])
b_extra = np.r_[0.5 * np.ones(2 * N), -SxN @ x0, SxN @ x0]
sol = mpc.solve(x0, extra_A_ub=A_extra, extra_b_ub=b_extra)
print(sol.U.ravel().round(4))     # 0.5 0.535 0.035 -0.465 -0.6316 -0.1316 0.1335 0.0249
```
The inputs match the table of Part 4; the two inequality pairs pin $x_N$ exactly as the equality did.

With the rate bound $0.5$ and $x_N = 0$, find by the feasibility LP the smallest $N$ from which $(-3, 0)$ can be brought to rest, and explain the number from the ramp arithmetic.

Count the inputs: they must ramp up by at most 0.5 per step and ramp back down to end at rest, and the velocity must return to zero.

$N = 5$: the margin is $0.154$ at $N = 4$ and zero from $N = 5$. ## The chapter on one page {#summary}

::: steps
- **The problem**: minimise $V_f(x_N) + \sum q(x_k, u_k)$ over $N$ inputs subject to the model, the sets and a terminal condition; one open-loop plan, not a controller.
- **Hard and soft**: a slack with an $\ell_1$ penalty $\rho$ is exact for $\rho \ge \lambda^\star$; the comfort bound's multiplier $2.51$ is the threshold.
- **Terminal conditions**: free, a point ($x_N = 0$, two equality rows), or a set (a few inequality rows); the set is chapter A11's idea.
- **The instance**: $J = 22.225$, inputs ramped by the rate bound, four active rate rows with multipliers $9.85, 1.86, 0.88, 0.09$, $\nu = (-0.046, 0.013)$; without the equality, $22.2250$.
- **Infeasible at $N = 4$**: margin $0.154$ by an independent LP; feasible from $N = 5$.
- **Nonlinear**: the unicycle is a nonconvex NLP; four restarts agree to $10^{-5}$, which is evidence, not proof.
- **Habits**: status and residual, violation, terminal residual, active set, full cost, restarts, scaling, model against plant.
:::

### The vocabulary, in one table

| Word | Meaning |
|---|---|
| CFTOC | Constrained finite-time optimal control problem, one open-loop solve. |
| Stage cost, terminal cost, terminal set | $q$, $V_f$, $\mathcal X_f$: the price per step, the price of the tail, where the plan must end. |
| Hard and soft constraint | Must hold; may be violated at a price through a slack. |
| Exact penalty | An $\ell_1$ penalty at least the multiplier, which reproduces the hard solution. |
| Active set | The rows that bind at the solution, with their multipliers. |
| Terminal equality | $x_N = x_f$; two equality rows for the cart; multipliers $\nu$ unsigned. |
| Feasibility margin | The LP certificate of chapter A4; zero if a plan exists. |
| NLP | A nonlinear program; the unicycle, solved by SQP, locally. |

**Scope.** Deterministic finite-horizon problems with a known state. The linear-quadratic instance is solved exactly by the course's solver; the unicycle by SciPy's SLSQP, as a nonconvex example only. Receding-horizon feedback begins in chapter [[a06]]; the terminal set that makes it safe is chapter [[a11]].
