## Realised costs-to-go and the sampled value {#costtogo}

**Roll-out cost-to-go.** For a successful iteration $i$ with stage cost $q$,

$$\boxed{J_t^i = \sum_{k=t}^{T_i - 1} q\big(x^i[k], u^i[k]\big)}, \qquad J_{T_i}^i = 0 :$$

the remaining cost actually incurred if the stored continuation is replayed from time $t$. In the code it is computed by the backward recursion $J_t = q(x_t, u_t) + J_{t+1}$, which resembles dynamic programming but over realised trajectories, not over the whole state space (chapter [[a14]] does it over the whole space). On the scalar run $4 \to 3 \to 2 \to 1 \to 0$ with inputs $-1$, the costs-to-go are $30.4, 14.3, 5.2, 1.1, 0$: for instance $J(2) = (4 + 0.1) + (1 + 0.1) = 5.2$.

**The sampled value.** If a state appears in several runs, keep the best stored cost-to-go, $V^j(x) = \min\{ J_t^i : x^i[t] = x \}$, with $V^j = 0$ on $\mathcal O$. It is defined only at the sampled states, and that is the difficulty: a terminal state that lands between samples has no value yet.

::: define What is the convex terminal value?
**In plain words:** the cheapest way to write $x$ as a mixture of stored states, charging each stored state its stored cost. It is the lower convex envelope of the stored (state, value) pairs, and it costs one linear program.

**More precisely:**

$$\boxed{V_c^j(x) = \min_{\lambda} \sum_{r=1}^{M} \lambda_r V_r} \quad \text{s.t.} \quad S^\top \lambda = x, \quad \mathbf 1^\top \lambda = 1, \quad \lambda \ge 0,$$

where $V_r$ is the cost-to-go stored with row $r$ of $S$, the stored states of chapter [[a12]]. For fixed data this is a linear program in $\lambda$; it is finite exactly on the convex safe set $CS^j$, and $+\infty$ outside.

- Dominated sample :: A stored pair lying above the envelope. The LP never selects it, and $V_c^j$ need not reproduce its value.
- Carathéodory :: In $\mathbb R^n$ at most $n + 1$ stored points are needed to represent any hull point, so a sparse $\lambda$ always exists.
- Pessimism :: Each $V_r$ is the cost of an admissible run, so $V_r \ge J_\infty^\star(s_r)$: the learned value is an upper bound of the true one, which chapter [[b05]] uses.
:::

## The envelope on a line {#envelope}

**Read the hero.** Two runs of the scalar integrator, $4 \to 3 \to 2 \to 1 \to 0$ and $-3 \to -2 \to -1 \to 0$, give $SS = \{-3, \ldots, 4\}$, $CS = [-3, 4]$, and the stored pairs $(1, 1.1)$, $(2, 5.2)$, $(3, 14.3)$, $(4, 30.4)$ and their mirror images. The dots are values known from previous executions. The curve is not new data: for each intermediate $x$ it answers "what is the cheapest convex combination of stored pairs that represents this state?" In one dimension that is a convex, piecewise-affine lower envelope. At $x = 2.5$ the LP puts $\lambda = 0.5$ on $x = 2$ and $0.5$ on $x = 3$, so $V_c(2.5) = 0.5 \cdot 5.2 + 0.5 \cdot 14.3 = 9.75$; at $x = 3.7$ it is $0.3$ of $14.3$ and $0.7$ of $30.4$, $25.57$.

**Dominated data.** Press the button: a slower third run through $2, 1.6, 1.0, 0.4$ with inputs $-0.4, -0.6, -0.6, -0.4$ costs $7.824$ from $x = 2$ against the stored $5.2$. Its pairs at 2, 1.6 and 1.0 lie above the envelope, dominated and never selected, and the curve there does not move. But its last pair $(0.4, 0.176)$ lies below the old chord from $(0, 0)$ to $(1, 1.1)$, whose value at 0.4 was 0.44, so the envelope drops near the origin: $V_c(0.4)$ falls from 0.44 to 0.176 and $V_c(0.7)$ from 0.77 to 0.638. A worse run overall can still contain a better partial continuation, and the LP keeps exactly the part that helps. Worse data never raise the terminal value.

## Why the learned value decreases {#decrease}

**The data recursion.** For a stored state $s_r$ with input $u_r$ and successor $s_r^+$, the stored costs satisfy $J_r = q(s_r, u_r) + J_r^+$. For $x = \sum_r \lambda_r s_r$ use $u = \sum_r \lambda_r u_r$, so that $x^+ = \sum_r \lambda_r s_r^+$ by the linearity argument of chapter [[a12]].

**The decrease.** Convexity of $q$ gives $q(x, u) \le \sum_r \lambda_r q(s_r, u_r)$. The definition of $V_c^j$ as a minimum gives $V_c^j(x^+) \le \sum_r \lambda_r J_r^+$, since the weights $\lambda$ on the successors are one feasible choice at $x^+$. Adding,

$$q(x, u) + V_c^j(x^+) \le \sum_r \lambda_r \big[ q(s_r, u_r) + J_r^+ \big] = \sum_r \lambda_r J_r .$$
%narrow \begin{aligned} q(x, u) + V_c^j(x^+) &\le \textstyle\sum_r \lambda_r [ q(s_r, u_r) + J_r^+ ] \\ &= \textstyle\sum_r \lambda_r J_r . \end{aligned}

If $\lambda$ is the minimiser defining $V_c^j(x)$, the right side is $V_c^j(x)$, and

$$\boxed{V_c^j(x^+) - V_c^j(x) \le -q(x, u).}$$

This is the terminal-cost condition of chapter [[a11]], $V_f(Ax + B\kappa_f(x)) - V_f(x) \le -q(x, \kappa_f(x))$, with the terminal value built from data instead of a Riccati equation. The convex hull plays the role of $\mathcal X_f$, and the convex combination of stored inputs plays the role of the terminal controller $\kappa_f$.

**Worked instance.** At $x = 2.5$ with $\lambda = (0.5, 0.5)$ on $2, 3$ and stored inputs $-1, -1$: $u = -1$, $x^+ = 1.5$, $V_c(1.5) = 0.5 \cdot 1.1 + 0.5 \cdot 5.2 = 3.15$, $q(2.5, -1) = 6.25 + 0.1 = 6.35$, and $V_c(1.5) - V_c(2.5) = 3.15 - 9.75 = -6.6 \le -6.35$. The slack of 0.25 is the convexity gap of $x^2$ between $2.5^2$ and the average of $2^2$ and $3^2$. The hero's residual readout is this number for whatever probe you choose.

## The LMPC problem {#problem}

At the current state $x_0$, with stored data $(S, V)$ and their continuation inputs, solve

$$\begin{aligned} \min_{\{u_k\}, \lambda}\quad & \sum_{k=0}^{N-1} q(x_k, u_k) + \sum_{r=1}^{M} \lambda_r V_r \\ \text{s.t.}\quad & x_{k+1} = A x_k + B u_k, \qquad x_k \in \mathcal X, \quad u_k \in \mathcal U, \\ & x_N = S^\top \lambda, \qquad \lambda \ge 0, \qquad \mathbf 1^\top \lambda = 1. \end{aligned}$$
%narrow \begin{aligned} \min_{\{u_k\}, \lambda}\ & \textstyle\sum_{k=0}^{N-1} q(x_k, u_k) + \sum_r \lambda_r V_r \\ \text{s.t. } & x_{k+1} = A x_k + B u_k,\ x_k \in \mathcal X,\ u_k \in \mathcal U, \\ & x_N = S^\top \lambda,\ \lambda \ge 0,\ \mathbf 1^\top \lambda = 1. \end{aligned}

**Geometric meaning.** The equality $x_N = S^\top \lambda$ lets the optimiser reconnect to any point in the convex hull of successful experience; the cost $\lambda^\top V$ tells it how expensive the stored continuation from that point is. The two constraints on $\lambda$ and the linear cost are the data-driven terminal ingredients; everything else is the finite-horizon problem of chapter [[a05]]. The decision vector is $(u_0, \ldots, u_{N-1}, \lambda_1, \ldots, \lambda_M)$: $N$ inputs plus one weight per stored state, which is why the online problem grows with experience and why chapter [[b02]] keeps a window of recent runs.

**The first solve on the cart.** Store the slow $N = 2$ seed of chapter [[a12]], 20 inputs at cost 28.087, and solve the LMPC problem from $x_S = (-3.5, 2.5)$ with $N = 3$. The seed had applied $u_0 = 0$; LMPC applies $u_0 = -0.839$. Its objective, three stage costs plus $\lambda^\top V$, is 16.661, below the stored cost 28.087 because the seed's own continuation is a feasible candidate. The terminal state is $(0.061, -0.023)$, which is exactly stored state 11 of the seed with weight 1 and value 0.006: the three-step plan reaches a point eleven steps down the slow run, and the learned cost tells it that finishing from there is almost free. With $N = 2$ the plan cannot get that far: it ends at $(-0.303, 0.631)$, a mixture of 0.166 of $(-1, 2.5)$ and 0.834 of $(-0.164, 0.26)$, at objective 18.906.

## Recursive feasibility by the shifted sequence {#feasibility}

Suppose the solution ends at $x_N^\star = \sum_r \lambda_r^\star s_r$. At the next time, shift the optimised inputs and append

$$\boxed{u_N^{\mathrm{safe}} = \sum_r \lambda_r^\star u_r^{\mathrm{safe}}.}$$

Then $x_{N+1} = A \sum_r \lambda_r^\star s_r + B \sum_r \lambda_r^\star u_r^{\mathrm{safe}} = \sum_r \lambda_r^\star s_r^+ \in CS^j$: the shifted sequence is feasible for the new problem, exactly as in chapter [[a11]]'s terminal-set proof, with the stored continuation inputs in place of the terminal controller. The optimal value at the next state is therefore at most the shifted sequence's cost, and by the decrease of Part 3 it is at most $J(x_0) - q(x_0, u_0^\star)$: the Lyapunov argument of chapter [[a11]] goes through unchanged.

On the cart with $N = 3$: the appended input is $-0.022$, the stored input at state 11, and it lands at $(0.027, -0.045)$, the stored successor. The next problem, from $x_1 = (-1.420, 1.661)$, is feasible with value $3.019106$, against $J(x_0) - q(x_0, u_0) = 3.019919$: a decrease with a slack of $8 \times 10^{-4}$. The code's warm start is this shifted sequence, and chapter [[b02]] runs the loop to the target and back again, nine times.

## Classical against learned terminal ingredients {#compare}

| Role | Classical MPC (chapter [[a11]]) | Learning MPC (this chapter) |
|---|---|---|
| Terminal set | $\mathcal X_f$, an invariant polytope computed from the model | $CS^j$, the hull of states visited by successful runs |
| Terminal cost | $V_f(x) = x^\top P x$ from the Riccati equation | $V_c^j(x) = \lambda^\top V$, barycentric in stored costs-to-go |
| Terminal controller | $\kappa_f(x) = -Kx$ | $\sum_r \lambda_r u_r^{\mathrm{safe}}$, a mixture of stored inputs |
| Decrease condition | $V_f(x^+) - V_f(x) \le -q$, by design | $V_c^j(x^+) - V_c^j(x) \le -q$, by convexity and the data recursion |
| Source of information | The model and the designer | The model and successful closed-loop data |
| What improves with use | Nothing | The set grows and the values fall as runs accumulate |

Both need the model: the LMPC of this course is data-driven, not model-free. What the data replace is the design of the terminal ingredients, which for constrained nonlinear systems is the hard part.

## The code behind it {#code}

::: code advanced_mpc_lmpc/lmpc.py:trajectory_cost_to_go
The backward loop is Part 1's recursion: `J[k]` is the stage cost at step `k` plus `J[k + 1]`, starting from `J[T] = 0` for the terminal state. The length check enforces the course's convention of $T + 1$ states for $T$ inputs. The optional `Q1` adds an $\ell_1$ term $\|Q_1 x\|_1$ to the stage cost, which the package supports through epigraph variables (exercise 6); the canonical task of this course sets it to zero.
:::

::: code advanced_mpc_lmpc/lmpc.py:convex_safe_value
This is Part 2's linear program, written for SciPy's HiGHS: the objective vector is the stored values `V`, the equalities stack $S^\top \lambda = x$ and $\mathbf 1^\top \lambda = 1$, and the bounds keep $\lambda \ge 0$. An infeasible LP means $x$ is outside the hull, and the function returns $+\infty$. The weights it returns are the ones the hero draws; they are one valid representation among possibly many, chosen to minimise the cost.
:::

::: code advanced_mpc_lmpc/lmpc.py:LMPCController.solve
Read it from the decision vector outward: `nu` inputs, then `M` weights, then the epigraph variables when an $\ell_1$ term is present. The Hessian block `H[:nu, :nu]` and the linear term `f[:nu]` are the condensed quadratic cost of chapter [[a02]] with the terminal state unweighted (`Qbar[-n:, -n:] = 0`), because $x_N$ is priced by `f[nu:nu+M] = V`, the stored values. The state bounds are the stacked inequalities of chapter [[a05]]. The two equality rows `A_eq` are Part 4's terminal constraint: `Su[-n:] @ U - S.T @ lam = -Sx[-n:] @ x0`, which is $x_N = S^\top \lambda$ with $x_N$ expanded by the prediction identity, and `1 @ lam = 1`. The bounds `0 <= lam <= 1` complete the simplex. After the solve, the objective is reassembled from the stage costs and `lam @ V`, and the terminal state `S.T @ lam` is returned with the data that the shifted warm start needs.
:::

## Common pitfalls {#pitfalls}

1. **"The terminal value is a neural network."** Not here. It is barycentric interpolation of stored roll-out costs, one linear program.
2. **"The envelope is measured."** The dots are measured; the curve between them is the LP's lower bound built from the dots and the convexity assumptions.
3. **"Stored values are optimal values."** They are upper bounds: realised costs of admissible runs. Chapter [[b05]] shows value iteration approaching the optimum from below and data from above.
4. **"Hull growth is the learning."** The set is half of it. Once the hull stops growing, better stored values still change the short-horizon decision, which chapter [[b02]] measures.
5. **"The decrease needs the exact minimiser."** It needs the weights that define $V_c(x)$ at the current terminal state; any feasible weights give the inequality with $\sum \lambda_r J_r$ in place of $V_c(x)$, which is weaker but still a feasible candidate.

## Check your understanding {#check}

:::: qa
Try to answer each question before opening it.

::: q 1. What is the roll-out cost-to-go?
The sum of the realised stage costs from time $t$ to the end of a successful run, $J_t^i = \sum_{k \ge t} q(x^i[k], u^i[k])$, computed backwards.
:::
::: q 2. What does $\lambda^\top V$ mean?
The learned terminal value: barycentric interpolation of the stored costs-to-go at the terminal state $S^\top \lambda$.
:::
::: q 3. Why is $V_c$ a lower convex envelope?
It is the minimum of $\lambda^\top V$ over all representations of $x$, so it lies below every chord between stored pairs and is convex as the value of a linear program with a right-hand side affine in $x$.
:::
::: q 4. Which stored pairs does the LP ignore?
Dominated ones: pairs that lie above the envelope. A worse run can still lower the envelope where one of its pairs lies below the old chord.
:::
::: q 5. Why does the learned value decrease by at least the stage cost?
Mix the stored inputs with the weights that define $V_c(x)$; linearity sends $x$ to the same mixture of successors, convexity of $q$ bounds the stage cost, and the definition of $V_c$ as a minimum bounds the next value by the mixture of the stored next values.
:::
::: q 6. What does $x_N = S^\top \lambda$ with $\lambda$ in the simplex mean?
That the terminal prediction lies in the convex hull of the stored states, the rows of $S$.
:::
::: q 7. Why is the LMPC problem recursively feasible?
The shifted inputs plus the mixture of the stored continuation inputs reach a mixture of stored successors, which is in the hull, so the next problem has a feasible point.
:::
::: q 8. Why can a horizon-three LMPC outperform a horizon-three plain MPC?
The learned terminal set and value carry information beyond the explicit window: from $x_S$ the seed applies 0 and LMPC applies $-0.839$, because the stored costs say that reaching a state down the seed quickly is cheap.
:::
::: q 9. Is LMPC model-free?
No. $A$ and $B$ appear in every online problem; the data replace the terminal ingredients, not the model.
:::

:::: exercise Build the terminal value yourself
Write the barycentric LP with `scipy.optimize.linprog` and compare it with `convex_safe_value` at ten random points of the cart's hull.
::: hint
Objective $V$, equalities $S^\top \lambda = x$ and $\mathbf 1^\top \lambda = 1$, bounds $\lambda \ge 0$; sample points as random convex combinations of stored states.
:::
::: solution
```python
from scipy.optimize import linprog
def my_value(x, S, V):
    A_eq = np.vstack([S.T, np.ones((1, len(S)))]); b_eq = np.r_[x, 1.0]
    r = linprog(V, A_eq=A_eq, b_eq=b_eq, bounds=[(0, None)] * len(S), method="highs")
    return r.fun if r.success else np.inf
rng = np.random.default_rng(0)
for _ in range(10):
    w = rng.dirichlet(np.ones(len(S))); x = S.T @ w
    assert abs(my_value(x, S, V) - convex_safe_value(x, S, V)[0]) < 1e-9
```
The values agree to round-off. The weights need not: when a point has several cheapest representations, the two solvers may return different ones, but the value is unique.

:::: exercise The epigraph trick
The package allows an $\ell_1$ term $\|Q_1 x\|_1$ in the stage cost. Prove that $\|z\|_1$ can be replaced by $\sum_i e_i$ with the linear constraints $-e_i \le z_i \le e_i$, so the problem stays a QP.
::: hint
Show that the feasible set in $e$ is $e_i \ge |z_i|$ and that minimising makes it tight.
:::
::: solution
For fixed $z$, the constraints $z_i \le e_i$ and $-z_i \le e_i$ are equivalent to $e_i \ge |z_i|$, which also implies $e_i \ge 0$. Hence $\min_e \{ \sum_i e_i : e_i \ge |z_i| \} = \sum_i |z_i| = \|z\|_1$, attained at $e_i = |z_i|$. Inside a larger minimisation over $(z, e)$ the same holds for whatever $z$ is chosen, so replacing $\|z\|_1$ by $\sum_i e_i$ with these linear constraints changes neither the optimal value nor the optimal $z$, and the problem stays a QP. In `solve`, the block after the weights holds these $e$ variables for $x_1, \ldots, x_{N-1}$, with $x_0$ a constant and $x_N$ priced by the terminal value.
:::

$\mathcal X_f$ and $CS^j$ are both control-invariant terminal sets that make the shifted sequence feasible; $V_f$ and $V_c^j$ are both terminal costs satisfying a one-step decrease, $V_f(x^+) - V_f(x) \le -q$ from the Riccati construction and $V_c^j(x^+) - V_c^j(x) \le -q$ from convexity and the stored data recursion; $\kappa_f = -Kx$ and $\sum_r \lambda_r u_r^{\mathrm{safe}}$ are the terminal controllers that realise the decrease. The classical pair is computed from the model offline by the designer; the learned pair is computed from the model and from successful closed-loop data, and it improves as data accumulate. Both need the model.
:::

## The chapter on one page {#summary}

::: steps
- **Cost-to-go**: $J_t = q(x_t, u_t) + J_{t+1}$ backwards along a stored run; $J_0$ is the run's cost.
- **Convex terminal value**: the cheapest barycentric mixture of stored costs, one LP; $V_c(2.5) = 9.75$ on the line.
- **Dominated data** never raise the envelope; a worse run can still lower it where one pair lies below the old chord.
- **Decrease**: $V_c(x^+) - V_c(x) \le -q(x, u)$ under the mixed input, the terminal-cost condition of chapter [[a11]] obtained from data.
- **The problem**: chapter [[a05]]'s QP plus $x_N = S^\top \lambda$, the simplex and $\lambda^\top V$ in the cost; $N + M$ variables.
- **On the cart**: from the slow seed, $N = 3$ applies $-0.839$ instead of 0, ends on stored state 11, objective 16.661 below the stored 28.087.
- **Recursive feasibility**: the shifted sequence plus the mixed stored input lands on a mixture of stored successors; the next value is 3.0191 against 3.0199.
:::

### The vocabulary, in one table

| Term | Meaning here |
|---|---|
| Cost-to-go $J_t$ | Realised remaining cost of a stored run from time $t$. |
| Sampled value $V^j$ | The best stored cost-to-go at a sampled state. |
| Convex terminal value $V_c^j$ | Cheapest barycentric mixture of stored costs; a linear program. |
| Dominated sample | A pair above the envelope, never selected. |
| Decrease residual | $V_c(x^+) - V_c(x) + q(x, u)$, at most zero under the mixed input. |
| LMPC problem | The finite-horizon QP with $x_N = S^\top \lambda$, the simplex and $\lambda^\top V$. |
| Shifted sequence | Old inputs minus the first, plus the mixed stored input: the feasibility witness. |
| Epigraph variable | $e \ge \lvert z \rvert$, turning an $\ell_1$ term into linear constraints. |

**Scope.** Deterministic repeated tasks with known linear dynamics, convex constraints and a convex stage cost. The decrease needs convexity of $q$ and linearity of the model; the sampled value needs neither but is defined only at samples.
