## The dynamic bicycle model and the full raceline problem {#vehicle}

**The six-state spatial vector.** Lab [[b03]] stopped at the shape of the full raceline problem; here is the vehicle inside it. The full spatial problem uses $x(s) = [v_x, v_y, r, e_\psi, t, e_y]^\top$ with the inputs $a_x$ (longitudinal acceleration) and $\delta$ (steering angle). The order of the two inputs is only a convention: raceline formulations often write $[a_x, \delta]$, the course code stores $u = [\delta, a]$. Use the names, not the indices.

**The vehicle.** The simulator is a 1:10-scale RC car with the parameters of the BARC platform: mass $m = 1.98$ kg, $l_f = l_r = 0.125$ m from the centre of gravity to each axle, yaw inertia $I_z = 0.024$ kg m². Its slip angles are

$$\alpha_f = \delta - \operatorname{atan2}(v_y + l_f r,\ v_x), \qquad \alpha_r = -\operatorname{atan2}(v_y - l_r r,\ v_x),$$

and each axle's lateral force follows the simplified Pacejka "magic formula" $F_y = D\sin(C\arctan(B\alpha))$ with stiffness factor $B = 1$, shape factor $C = 1.25$ and peak force $D = 0.8\, mg/2 = 7.77$ N: each axle carries half the weight (because $l_f = l_r$) and can deliver 0.8 times its normal load. With these forces,

$$\dot v_x = a_x - \frac{F_{y,f}}{m}\sin\delta + r v_y, \qquad \dot v_y = \frac{F_{y,f}\cos\delta + F_{y,r}}{m} - r v_x, \qquad \dot r = \frac{l_f F_{y,f}\cos\delta - l_r F_{y,r}}{I_z},$$
%narrow \begin{aligned} \dot v_x &= a_x - \frac{F_{y,f}}{m}\sin\delta + r v_y, \\ \dot v_y &= \frac{F_{y,f}\cos\delta + F_{y,r}}{m} - r v_x, \\ \dot r &= \frac{l_f F_{y,f}\cos\delta - l_r F_{y,r}}{I_z}, \end{aligned}

and the spatial derivatives are $v_x' = \dot v_x / \dot s$, $v_y' = \dot v_y / \dot s$, $r' = \dot r / \dot s$, together with the three kinematic rates of lab [[b03]]. The widget evaluates all six.

**The full raceline problem.** Minimise $t(s_f)$ subject to the spatial vehicle dynamics, tire-force constraints, the track boundaries $-W(s) \le e_y(s) \le W(s)$, initial conditions and terminal or periodic conditions. It is a nonlinear optimal-control problem: trigonometric Frenet geometry, the denominator $1 - K e_y$, nonlinear tire laws, steering-dependent force projections, the minimum-time term $t' = 1/\dot s$, possibly a combined tire-force constraint. It is usually solved by direct transcription: discretise the spatial dynamics on a grid in $s$ and hand the nonlinear program to a solver such as IPOPT, as Perantoni and Limebeer do for a Formula One car. This lab does not solve it; it asks instead how a controller can keep a *quadratic* program while the car is this nonlinear.

## Plant model against prediction model {#plant}

**The nonlinear "real" system.** The vehicle is the model above in curvilinear coordinates, with state $x = [v_x, v_y, r, e_\psi, s, e_y]^\top$: longitudinal and lateral velocity, yaw rate, heading error, progress, lateral deviation. The simulator input is $u = [\delta, a_x]^\top$, steering first. The tire forces are the Pacejka law, so the state transition is nonlinear in both state and steering.

**Why not put the full model in every QP?** One could, and the online problem would then be a nonlinear program. Learning MPC racing (Rosolia and Borrelli [[ref:1]]) instead builds a short-horizon affine approximation

$$x_{k+1} = A_k x_k + B_k u_k + c_k,$$

which keeps the quadratic-program structure of chapter [[a02]] while letting the matrices change with the operating point. That is the role of local identification: a nonlinear plant becomes a sequence of local affine models.

::: define What is a local affine time-varying model?
**In plain words:** near the place where the car currently is, in terms of its speeds and inputs, the next state is well described by a linear map plus a constant. Move somewhere else and the map changes. The controller refits it from stored data at every step of its prediction.

**More precisely:** for a query $(x_q, u_q)$, a first-order expansion of the plant gives $x^+ \approx f(x_q, u_q) + A_q(x - x_q) + B_q(u - u_q) = A_q x + B_q u + c_q$ with $c_q = f(x_q, u_q) - A_q x_q - B_q u_q$. The model here is hybrid: the rows for $v_x, v_y, r$ are estimated from data near the query, the rows for $e_\psi, s, e_y$ are the exact Jacobian of the known Frenet kinematics. Along a prediction horizon the query moves and so do the matrices, hence "time varying", the LTV class of chapter [[a01]].

- Transition tuple :: One stored sample $(x_i, u_i, x_i^+)$ with $x_i^+ = x_{i+1}$.
- Query vector :: $z = [v_x, v_y, r, \delta, a_x]^\top$: the five features used to find similar transitions. Position on the track is not among them.
- Grey box :: Physics fixes the structure, data fix the coefficients.
:::

## The racing data {#data}

**An RC-car-scale track.** Lab [[b03]]'s closed track is scaled geometrically by $\alpha = 0.08$ and given a half-width of 0.4 m. Lengths scale as $s_{\mathrm{new}} = \alpha s$, curvature inversely, $K_{\mathrm{new}} = K / \alpha$, which preserves the shape: 20.187 m long, curvature from −0.157 to 1.626 per metre (a tightest radius of 0.61 m), Frenet margin $\min(1 - |K| W) = 0.349$.

**The exploratory seed controller.** Learning starts from suboptimal but feasible laps driven by a noisy path-following controller,

$$\delta = -0.6 e_y - 0.9 e_\psi + \text{steering dither}, \qquad a_x = 1.5 (v_t - v_x) + \text{acceleration dither},$$

with target speed $v_t = 0.8$ m/s for the training laps and 0.85 m/s for the validation lap, the dither being clipped Gaussian noise drawn independently at every step of 0.1 s (the dynamics are integrated inside each step with explicit Euler at 1 ms). The dither matters for identification: a controller that repeats the same inputs leaves many local parameters unexcited. One safety choice is explicit: the action is clipped to the Learning MPC controller's input bounds $|\delta| \le 0.5$ and $|a_x| \le 10$, after the dither, so every recorded input satisfies the bounds the controller will impose.

**Why a held-out lap.** Four training laps with different random seeds give the regression a richer cloud, 1216 transitions in all, and make a train-against-validation analysis meaningful. The fifth lap uses a different noise realisation and a slightly higher target speed: close to the operating domain but not a copy of any training transition, which is more informative than a residual on the fitting samples. The training features span $v_x \in [0.475, 0.800]$, $v_y \in [-0.107, 0.109]$, $r \in [-1.34, 1.40]$, $\delta \in [-0.5, 0.5]$, $a_x \in [-0.175, 0.579]$. The dense rows at $\delta = \pm 0.5$ in the data cloud of the demo are the 118 transitions where the dithered steering was clipped; 18 validation transitions reach a slightly higher $v_x$ than any training one, because of the higher target speed. The laps themselves are generated in Python and shipped to this page; everything else is recomputed here, and the numbers script recomputes it from the same file.

## The local-neighbourhood metric {#metric}

**Raw distance would mix units.** The query vector holds velocities, a yaw rate, a steering angle and an acceleration; a plain norm would be dominated by whichever has the largest numerical range. The implementation scales with $D = \operatorname{diag}(0.1, 1, 1, 1, 1)$ and uses the scaled $\ell_1$ distance

$$d_i = \big\| D (z_i - z_q) \big\|_1,$$

the smaller coefficient on $v_x$ reducing the dominance of longitudinal-speed differences. What is not in the metric: $e_\psi$, $s$, $e_y$. The regression looks for similar vehicle dynamics wherever they occurred on the track; the geometry is reintroduced analytically in the kinematic rows.

**The Epanechnikov kernel.** With bandwidth $h = 5$, points with $d_i < h$ get the weight

$$w_i = \tfrac34 \Big[ 1 - \big( \tfrac{d_i}{h} \big)^2 \Big],$$

largest at the query, decreasing quadratically, zero outside the bandwidth. At most 7 points are kept from each stored lap, the nearest ones inside the bandwidth. If a lap has no point inside, its seven nearest transitions are used with the bandwidth widened just enough to cover them, and the lap is flagged as a support fallback (Part 11). Why per lap: selecting globally from the pooled samples would let one dense trajectory dominate; a small subset from each successful execution keeps several of them in the regression, at most $4 \times 7 = 28$ samples here.

**An honest observation about this data set.** At the lab's query (sample 120) all 28 selected points lie within 0.38 of the query against a bandwidth of 5, so their weights are all within 1 percent of the maximum. That is not special to sample 120: the ranges of the five features, weighted by $(0.1, 1, 1, 1, 1)$, add up to 4.74, less than $h$, so for any query inside the envelope every stored transition is inside the kernel. The seven-points-per-lap rule does the selecting and the kernel is nearly uniform; a bandwidth below about 0.5 would be needed for its shape to matter (exercise 3). The bandwidth is still a genuine hyperparameter in general, just not an active one on this RC-car data.

## Weighted affine regression {#regression}

**Scalar problem.** For one state component let $y_i = x_{i+1, j}$ and $\phi_i = [\text{selected regressors}, 1]^\top$, the final 1 creating an affine offset. The local model solves

$$\theta^\star = \arg\min_\theta \sum_i w_i \big( y_i - \phi_i^\top\theta \big)^2 + \lambda \|\theta\|_2^2 .$$

**Matrix form and normal equations.** Stacking $\Phi$ (rows $\phi_i^\top$), $y$ and $W = \operatorname{diag}(w)$, the objective is $(y - \Phi\theta)^\top W (y - \Phi\theta) + \lambda\theta^\top\theta$; its gradient $-2\Phi^\top W(y - \Phi\theta) + 2\lambda\theta$ vanishes at

$$\big( \Phi^\top W \Phi + \lambda I \big)\, \theta^\star = \Phi^\top W y,$$

so $\theta^\star = (\Phi^\top W\Phi + \lambda I)^{-1}\Phi^\top W y$ when the matrix is nonsingular. $\lambda = 0$ is ordinary weighted least squares; the implementation uses $\lambda = 10^{-8}$ only as a safeguard against an exactly singular normal matrix.

**Why the affine constant is necessary.** Linearising $x^+ = f(x, u)$ at $(x_q, u_q)$ gives $x^+ \approx A_q x + B_q u + c_q$ with $c_q = f(x_q, u_q) - A_q x_q - B_q u_q$. Unless the operating point is the origin and the map passes through it, forcing $c_q = 0$ creates a systematic bias. Exercise 6 measures it: without the offset the yaw-rate error on the held-out lap nearly doubles.

## The structured dynamic rows {#structure}

The learned model predicts $v_x^+$ from $[v_x, v_y, r, a_x]$ and $v_y^+, r^+$ from $[v_x, v_y, r, \delta]$:

$$\begin{aligned} v_x^+ &\approx a_{11}v_x + a_{12}v_y + a_{13}r + b_{12}a_x + c_1, \\ v_y^+ &\approx a_{21}v_x + a_{22}v_y + a_{23}r + b_{21}\delta + c_2, \qquad r^+ \approx a_{31}v_x + a_{32}v_y + a_{33}r + b_{31}\delta + c_3. \end{aligned}$$
%narrow \begin{aligned} v_x^+ &\approx a_{11}v_x + a_{12}v_y + a_{13}r + b_{12}a_x + c_1, \\ v_y^+ &\approx a_{21}v_x + a_{22}v_y + a_{23}r + b_{21}\delta + c_2, \\ r^+ &\approx a_{31}v_x + a_{32}v_y + a_{33}r + b_{31}\delta + c_3. \end{aligned}

Before the kinematics are added, the learned block has the sparsity pattern

$$A_{\mathrm{dyn}} = \begin{bmatrix} * & * & * & 0 & 0 & 0 \\ * & * & * & 0 & 0 & 0 \\ * & * & * & 0 & 0 & 0 \end{bmatrix}, \qquad B_{\mathrm{dyn}} = \begin{bmatrix} 0 & * \\ * & 0 \\ * & 0 \end{bmatrix},$$

the stars estimated by weighted ridge least squares: the $v_x$ row on its own, the $v_y$ and $r$ rows together since they share regressors. This is a structured choice. The full plant contains more couplings; the restricted regressors reduce the parameter count and encode physical prior knowledge.

**Feature design.** Why does $v_x^+$ use acceleration but not steering, when the simulator contains $-F_{y,f}\sin\delta / m$? Because the restriction is an approximate structured model, not a statement of physical decoupling: fewer parameters, less data, better conditioning, the obvious actuation channel, at the price that the neglected coupling must be absorbed by the state dependence and the offset. The same logic makes the lateral rows use steering but not acceleration. Exercise 7 shows that on this car, which steers up to 0.5 rad, the neglected term is not small: adding $\delta$ to the $v_x$ row cuts its held-out error by a factor 3.4. Adding $a_x$ to the lateral rows helps nothing (exercise 8).

## Analytic Frenet rows {#frenet}

**Why not regress all six equations.** The kinematics of $e_\psi$, $s$, $e_y$ are known exactly from lab [[b03]]. Learn what is hard to model, keep known physics where it is trustworthy: less data needed, more interpretable. Freezing the curvature at the query, $\kappa = K(s_q)$, the one-step Euler models with $q = v_x\cos e_\psi - v_y\sin e_\psi$ and $d = 1 - \kappa e_y$ are

$$e_\psi^+ = e_\psi + T_s \Big( r - \kappa \frac{q}{d} \Big), \qquad s^+ = s + T_s \frac{q}{d}, \qquad e_y^+ = e_y + T_s (v_x\sin e_\psi + v_y\cos e_\psi).$$
%narrow \begin{aligned} e_\psi^+ &= e_\psi + T_s \Big( r - \kappa \frac{q}{d} \Big), \\ s^+ &= s + T_s \frac{q}{d}, \\ e_y^+ &= e_y + T_s (v_x\sin e_\psi + v_y\cos e_\psi). \end{aligned}

**The Jacobian.** For the heading error,

$$\frac{\partial e_\psi^+}{\partial v_x} = -T_s \frac{\kappa\cos e_\psi}{d}, \quad \frac{\partial e_\psi^+}{\partial v_y} = T_s \frac{\kappa\sin e_\psi}{d}, \quad \frac{\partial e_\psi^+}{\partial r} = T_s, \quad \frac{\partial e_\psi^+}{\partial e_\psi} = 1 - T_s \frac{\kappa(-v_x\sin e_\psi - v_y\cos e_\psi)}{d}, \quad \frac{\partial e_\psi^+}{\partial e_y} = -T_s \frac{q\kappa^2}{d^2};$$
%narrow \begin{aligned} \frac{\partial e_\psi^+}{\partial v_x} &= -T_s \frac{\kappa\cos e_\psi}{d}, \quad \frac{\partial e_\psi^+}{\partial v_y} = T_s \frac{\kappa\sin e_\psi}{d}, \quad \frac{\partial e_\psi^+}{\partial r} = T_s, \\ \frac{\partial e_\psi^+}{\partial e_\psi} &= 1 - T_s \frac{\kappa(-v_x\sin e_\psi - v_y\cos e_\psi)}{d}, \quad \frac{\partial e_\psi^+}{\partial e_y} = -T_s \frac{q\kappa^2}{d^2}; \end{aligned}

for the progress,

$$\frac{\partial s^+}{\partial v_x} = T_s \frac{\cos e_\psi}{d}, \quad \frac{\partial s^+}{\partial v_y} = -T_s \frac{\sin e_\psi}{d}, \quad \frac{\partial s^+}{\partial e_\psi} = T_s \frac{-v_x\sin e_\psi - v_y\cos e_\psi}{d}, \quad \frac{\partial s^+}{\partial e_y} = T_s \frac{q\kappa}{d^2};$$
%narrow \begin{aligned} \frac{\partial s^+}{\partial v_x} &= T_s \frac{\cos e_\psi}{d}, \quad \frac{\partial s^+}{\partial v_y} = -T_s \frac{\sin e_\psi}{d}, \\ \frac{\partial s^+}{\partial e_\psi} &= T_s \frac{-v_x\sin e_\psi - v_y\cos e_\psi}{d}, \quad \frac{\partial s^+}{\partial e_y} = T_s \frac{q\kappa}{d^2}; \end{aligned}

and for the lateral deviation,

$$\frac{\partial e_y^+}{\partial v_x} = T_s\sin e_\psi, \quad \frac{\partial e_y^+}{\partial v_y} = T_s\cos e_\psi, \quad \frac{\partial e_y^+}{\partial e_\psi} = T_s(v_x\cos e_\psi - v_y\sin e_\psi), \quad \frac{\partial e_y^+}{\partial e_y} = 1.$$
%narrow \begin{aligned} \frac{\partial e_y^+}{\partial v_x} &= T_s\sin e_\psi, \quad \frac{\partial e_y^+}{\partial v_y} = T_s\cos e_\psi, \\ \frac{\partial e_y^+}{\partial e_\psi} &= T_s(v_x\cos e_\psi - v_y\sin e_\psi), \quad \frac{\partial e_y^+}{\partial e_y} = 1. \end{aligned}

The derivative of the curvature with respect to $s$ is neglected (exercise 12 restores it). Affine remainder: each analytic row takes the offset $c_q = f(x_q) - A_q x_q$, so the affine map is exact at the linearisation point. At the lab's query, $\kappa = 1.430$ and the three rows are the ones shown in the table below, with offsets $(-0.0248, 0.0173, 0.0174)$.

## One-step validation on a different lap {#validation}

**Why the training residual is not enough.** A local regression can fit its selected points very well and still predict poorly on new transitions. The meaningful experiment: fit only on the four training laps, query the model at every point of the held-out lap, predict one step, compare with the simulator's actual next state. Two models are compared, both with the same analytic kinematic rows: the global structured model, one set of learned coefficients from all 1216 transitions with equal weights, and the local structured model, refitted around every query. The comparison isolates the value of locality.

::: table num
| state | local RMSE | global RMSE | ratio |
|---|---|---|---|
| $v_x$ | $1.209 \times 10^{-2}$ | $2.104 \times 10^{-2}$ | 1.74 |
| $v_y$ | $9.00 \times 10^{-4}$ | $1.882 \times 10^{-3}$ | 2.09 |
| $r$ | $1.437 \times 10^{-2}$ | $4.204 \times 10^{-2}$ | 2.93 |
| $e_\psi$, $s$, $e_y$ | identical: $4.61 \times 10^{-2}$, $1.35 \times 10^{-3}$, $4.32 \times 10^{-3}$ for both | | |
:::

The local model wins on all three learned states, by the largest margin on the yaw rate, where the error drops by a factor of nearly three. No validation query needed the support fallback. The kinematic rows' errors are the same in both models by construction; their size (the heading error's $4.6 \times 10^{-2}$ is the largest of all six) comes from the Euler discretisation and the frozen curvature, not from the data, and is shared by any controller built on these rows.

**Why local models help.** For a nonlinear transition the best first-order coefficients are the Jacobians at the operating point, and they change with it. A single global affine regression averages incompatible local behaviours; a local regression estimates the derivative-like behaviour only where the MPC is currently planning to operate. Exercise 9 splits the lap by curvature and speed: locality helps everywhere, most at high speed.

## Data support, conditioning, and the exercise sweeps {#diagnostics}

**Distance to the database.** For every query, $d_{\min}(z_q) = \min_i \|D(z_i - z_q)\|_1$ is a geometric indicator of how close the query is to stored experience, not a probabilistic uncertainty. On the held-out lap larger errors are somewhat more frequent at larger distances (correlation 0.43), but the scatter is large and no monotone relationship should be expected: local nonlinearities differ, the neighbours excite the regressors more or less well, conditioning varies. Note the scale: every validation query has a stored transition within 0.29, a small fraction of $h = 5$, so the held-out lap tests interpolation inside familiar data.

**Conditioning and ridge.** Local regression keeps only nearby points, which can be nearly collinear in regressor space, so $\Phi^\top W\Phi$ can be badly conditioned: median condition number $1.1 \times 10^{5}$ over the lap, 95th percentile $9.3 \times 10^{5}$, and $2 \times 10^{6}$ at the lab's query. Replacing it by $\Phi^\top W\Phi + \lambda I$ improves the conditioning but biases the coefficients, so $\lambda$ is not free accuracy; the lab keeps $10^{-8}$ and makes the conditioning visible rather than hiding it behind a large $\lambda$. It also explains the strange coefficients of Part 6: with condition numbers near $10^{6}$, coefficients far from the true derivatives fit the data almost as well as the true ones.

## The affine LTV horizon {#horizon}

**From one local model to a sequence.** An MPC horizon of length $N$ needs $(A_0, B_0, c_0)$, …, $(A_{N-1}, B_{N-1}, c_{N-1})$; the experiment uses $N = 14$, 1.4 s at $T_s = 0.1$ s. At each prediction step the local data are selected around the current predicted state and input, so the model is linear at each step but time varying across the horizon. The architecture is nonlinear simulator → data → local affine model → QP → input → nonlinear simulator; the affine model is never claimed to be the car, it is a computational surrogate inside the optimiser.

**The experiment.** Take a 14-step segment of the held-out lap starting at sample 145, give both models the inputs that were actually applied, and ask only how well they predict the next 14 states. This is harder than one-step prediction because errors feed back into the next query. In the lab's segment the local LTV prediction follows the simulated $v_x$ closely over the first steps and reproduces the sharp dip around step 8 in shape though not in depth, staying above the true speed afterwards; the global model smooths the dip away. Dynamic-state RMSE over the horizon: 0.0206 local against 0.0408 global, about half. The errors do not grow monotonically: they jump at the transient and can shrink again when the trajectories come back together, and in the last steps the two error norms are comparable (0.060 against 0.055 at step 14).

**Why it is called LTV.** Along the horizon $\|A_k - A_0\|_F$ reaches 1.58 and $\|B_k - B_0\|_F$ 0.56: the controller is not using one fixed linear model. Two mechanisms: the regression neighbourhood changes as $(v_x, v_y, r, \delta, a_x)$ changes, and the analytic rows change with $e_\psi$, $e_y$ and $K(s)$. The variation is not smooth: each fit keeps the seven nearest transitions of every lap with almost equal weights, so a small change of the query can swap neighbours and, with nearly collinear data, move the coefficients abruptly. $B_k$ varies only through the regression, since the kinematic rows of $B$ are zero. **Support along the horizon.** One model-fit diagnostic is not enough: an MPC may start well supported and predict into a poorly supported region several steps ahead, so the nearest-data distance should be evaluated along the whole horizon. Here it never exceeds 0.20, far inside the bandwidth; a horizon point approaching or crossing it would be an explicit warning that the optimiser is planning where the identified dynamics are unsupported. The regression does not turn that distance into a formal uncertainty set; that would be a robust or learning-control extension (exercises 11 and 13).

**Longer horizons (exercise 10).** With $N = 30$ from the same start, the local model's RMSE is 0.070 against 0.042 for the global one, and its final-step error 0.30 against 0.08: once the predicted state has drifted, the local model is queried in places the true trajectory never visited, and its sharper but more variable coefficients amplify the drift. One-step accuracy does not promise long-horizon accuracy, which is one more argument for the short horizons that receding-horizon control (chapter [[a06]]) uses anyway.

## Out of distribution, bias and variance, and the way into LMPC {#limits}

**An out-of-distribution query.** Ask for a point with four times the speed, lateral velocity, yaw rate and acceleration ever recorded: $x = (4, 1, 4, 0.2, 5, 0.2)$, $u = (0.5, 5)$. Its nearest stored transition is 8.546 away in the scaled metric, beyond the bandwidth, so the kernel contains no sample of any lap; the code falls back to the seven nearest transitions per lap with a widened bandwidth and flags all four laps. The object stays inspectable, but the correct engineering conclusion is not "the model still returns a number, so it is valid"; it is that the query is extrapolative and the model's reliability unverified.

**Bias and variance.** A small bandwidth gives a very local fit: less nonlinear-model bias, but few points, large coefficient variance, ill-conditioning, possibly no support. A large bandwidth includes more data: less variance and better conditioning, but points from different dynamics get averaged and the model drifts towards the global affine approximation. The bandwidth is a genuine identification hyperparameter, not a speed setting; on this data it is inactive, and the number of points per lap plays its role (exercise 4 shows five points beating seven and eighty being much worse). **Validation must be trajectory-based.** Consecutive samples satisfy $x_{k+1} \approx x_k$; a random split of individual samples puts near-identical neighbours on both sides and flatters the error. A whole held-out lap is the meaningful first test for an iterative task.

**How this enters LMPC.** Racing LMPC learns two different things: terminal learning from previous successful laps (a local safe set and a cost-to-go, as in chapters [[a12]] and [[a13]]) and model learning from stored transitions (the $(A_k, B_k, c_k)$ of this lab). One says where it is safe to end the horizon and what the continuation costs; the other says how the car will move during the horizon. A racing LMPC combines a horizon of 14, a few stored laps for the model (four here) and a few for the safe set, local safe-set point selection, the local regression, the analytic linearisation, and a QP at every control step whose input goes to the nonlinear simulator. Two details of the racing cost: there is no conventional state-tracking cost, since the objective is lap time ($Q_{\mathrm{LMPC}} = 0$, $R_{\mathrm{LMPC}} = 0$), smoothness coming from an input-rate penalty $\Delta u^\top \operatorname{diag}(5, 50)\,\Delta u$ and the learned terminal cost counting the remaining samples to the finish; and the local safe set is sized by a few laps and points, for instance $4 \times 12 = 48$ points chosen from the fastest laps around the predicted terminal point rather than the hull of everything. One geometric subtlety: $s = 0$ and $s = L$ are neighbouring positions with distant coordinates, so stored states near the finish line must have their progress shifted by $L$ before convex combinations are taken; the lane bound $|e_y| \le W$ itself survives convex combination because an interval is convex.

**Why a learned LTV model can work on a highly nonlinear car, and what that does not prove.** The plant does not become linear. The approach relies on short horizons, receding-horizon feedback, regression around operating points already visited, recomputation as the operating point moves, exact kinematics where physics is reliable, and iterative data that keep the controller near progressively relevant regions. A good nominal local model does not by itself guarantee recursive feasibility under mismatch, probabilistic safety, bounded closed-loop error, protection against a sudden grip change, or safety under localisation errors. Those need robust, stochastic or adaptive constructions; LMPC racing is an effective learning-control architecture, not a formal robust-MPC certificate.

## The code behind it {#code}

The package ships the simplest form of the idea: one unstructured local affine fit from the nearest transitions, every state regressed on every state and input. The lab's structured version (Parts 5 and 6) differs in three ways, and the numbers script implements it in full.

::: code advanced_mpc_lmpc/racing.py:local_affine_regression
Read the four moves. The metric: features are standardised by their standard deviation over the whole database, then a Euclidean distance, where the lab uses a fixed scaling $\operatorname{diag}(0.1, 1, 1, 1, 1)$ and an $\ell_1$ distance, and selects per lap rather than from the pool. The kernel: a Gaussian in the distance normalised by the neighbours' mean distance, where the lab uses a compact Epanechnikov kernel with a fixed bandwidth. The regressors: `Phi` holds every state, every input and a one, so every row of `Y` is regressed on everything, where the lab restricts each row to its physical inputs and keeps the kinematic rows exact. The solve: the same weighted ridge normal equations as Part 5, `Phi.T @ W @ Phi + ridge * I`, with the returned `A`, `B`, `c` read off the rows of `Theta`. On the lab's data, at the lab's query, this unstructured fit from the 28 nearest transitions misses the simulator's next velocities by $5.0 \times 10^{-2}$ against $2.7 \times 10^{-2}$ for the structured local model: structure is worth having, and the exact kinematic rows are free.
:::

::: code advanced_mpc_lmpc/racing.py:nonlinear_vehicle_step
The package's plant is a reduced kinematic model in Frenet coordinates, three states $(e_y, e_\psi, v)$ and the inputs $(\delta, a)$ with a wheelbase $L$, used by its identification demo; the lab's plant is the six-state dynamic bicycle model of Part 1 with tire forces. The two share the Frenet rates of lab [[b03]], and the `max(0.25, 1 - kappa * ey)` guard is the singularity of the position map kept at bay. From $(0, 0, 15)$ under a small steering and acceleration on a gentle curvature the step moves the heading error by 0.0128 rad and the speed to 15.05 m/s.
:::

## Common pitfalls {#pitfalls}

1. **"A local linear model means the system is linear."** No. It is a surrogate valid near one operating point, refitted as that point moves.
2. **"Neighbours should be selected by where the car is on the track."** Position is not in the metric: similar dynamics are looked for wherever they occurred, and the geometry comes back through the exact kinematic rows.
3. **"All six equations should be learned."** Only three are; the Frenet kinematics are known exactly and regressing them would waste data on something physics already gives.
4. **"The offset $c_k$ can be dropped."** Not at a nonzero operating point: without it the yaw-rate error nearly doubles.
5. **"A low training residual proves the model."** Only a held-out trajectory does; a random split of correlated samples flatters the error.
6. **"A large bandwidth is safer."** It averages incompatible dynamics and drifts towards the global fit; here the number of points per lap, not the bandwidth, is the active knob.
7. **"Ridge is free accuracy."** It buys conditioning with bias: $\lambda = 1$ quadruples the error.
8. **"An extrapolated model is a prediction."** It is numerically defined and empirically unvalidated; the support distance is the warning.

:::: qa
Try to answer each question before opening it.

::: q 1. What is the main difference between the simulator and the LMPC prediction model?
The simulator propagates the nonlinear bicycle and Frenet dynamics. The controller uses a locally identified affine time-varying surrogate $x^+ = A_k x + B_k u + c_k$.
:::
::: q 2. Which states are learned from data?
The next-step longitudinal velocity, lateral velocity and yaw rate: $v_x^+$, $v_y^+$, $r^+$.
:::
::: q 3. Which states use analytic kinematics?
Heading error $e_\psi$, progress $s$ and lateral deviation $e_y$.
:::
::: q 4. What query vector selects the local data?
$z = [v_x, v_y, r, \delta, a_x]^\top$.
:::
::: q 5. Why is $v_x$ scaled by 0.1 in the metric?
To stop its numerical range and units from dominating the neighbour distance relative to the other features.
:::
::: q 6. What kernel is used?
The Epanechnikov kernel, compact-support and quadratic, $w = \tfrac34[1 - (d/h)^2]$ for selected points inside the bandwidth $h = 5$.
:::
::: q 7. Why an affine rather than a homogeneous linear model?
The expansion point is generally nonzero, so the intercept $c = f(x_q, u_q) - A_q x_q - B_q u_q$ is required.
:::
::: q 8. Why only acceleration in the $v_x$ input row?
A structured grey-box choice that reduces parameters and encodes the principal longitudinal actuation channel, even though the full model contains more coupling.
:::
::: q 9. What makes the model LTV?
The data neighbourhood and the analytic Frenet Jacobian change along the predicted trajectory, so $(A_k, B_k, c_k)$ vary with the prediction step.
:::
::: q 10. Why validate on a held-out lap rather than random samples?
Time-adjacent racing data are strongly correlated; a random split leaks almost identical neighbours into both sets.
:::
::: q 11. What does the nearest-data distance tell us?
It is a geometric support diagnostic: a large distance indicates extrapolation. It is not a calibrated probabilistic uncertainty.
:::
::: q 12. Why can ridge regularisation help?
Local samples can make $\Phi^\top W\Phi$ nearly singular; adding $\lambda I$ improves conditioning but introduces bias.
:::
::: q 13. How can a local LTV model control a nonlinear vehicle?
The approximation only needs to be useful locally over a short horizon; receding-horizon feedback and repeated model updates prevent reliance on one global approximation.
:::
::: q 14. What are the two separate learning mechanisms in racing LMPC?
Model learning provides the finite-horizon dynamics; safe-set and value learning provide the terminal geometry and cost from successful laps.
:::
::: q 15. Does good local prediction prove closed-loop safety?
No. Prediction validation is necessary but is not a robust or stochastic safety guarantee.
:::

::::: exercises
:::: exercise Weighted normal equations
From $\sum_i w_i(y_i - \phi_i^\top\theta)^2 + \lambda\|\theta\|_2^2$, derive the normal equations.
::: hint
Write the sum as a quadratic form and set the gradient to zero.
:::
::: solution
With $\Phi$, $y$, $W = \operatorname{diag}(w)$ the objective is $J(\theta) = (y - \Phi\theta)^\top W(y - \Phi\theta) + \lambda\theta^\top\theta$. Its gradient is $\nabla J = -2\Phi^\top W(y - \Phi\theta) + 2\lambda\theta$; setting it to zero gives $(\Phi^\top W\Phi + \lambda I)\theta = \Phi^\top W y$. The Hessian $2(\Phi^\top W\Phi + \lambda I)$ is positive definite for $\lambda > 0$ (or $\lambda = 0$ and full column rank), so the stationary point is the unique minimiser.
:::

:::: exercise Data-support monitor
Design a rule that flags a prediction if any horizon point has $d_{\min} > d_{\mathrm{warn}}$. What should the controller do?
::: hint
What does the fallback already do, and what is a safe action for a racing car?
:::
::: solution
After solving the QP, roll the planned inputs through the local model, compute $d_{\min}$ at every predicted $(x_k, u_k)$ and raise a warning if any exceeds $d_{\mathrm{warn}}$, chosen well below the bandwidth, say 1 on this data where supported queries stay below 0.3. On a warning the controller should not trust the plan beyond the first unsupported step: it can tighten the input-rate penalty or the input bounds so that the plan stays near recorded behaviour, shorten the horizon to the supported prefix, add a cost term proportional to the support distance, or fall back to the previous lap's inputs from that point, which are known to be feasible. What it must not do is execute an aggressive plan whose only justification is coefficients fitted to nothing nearby; and the warning should also trigger data collection in that region on the next laps.

:::: exercise Curvature derivative
Derive the terms that appear if $dK/ds$ is included in the kinematic linearisation.
::: hint
$\kappa$ becomes a function of $s$; differentiate $e_\psi^+$ and $s^+$ with respect to $s$.
:::
::: solution
With $\kappa = K(s)$, the column for $s$, which is zero in the rows for $e_\psi$ and $e_y$ and one in the row for $s$, acquires extra terms through $\partial\kappa/\partial s = K'(s)$: $\partial e_\psi^+/\partial s = -T_s K'(s)\,\partial(\kappa q/d)/\partial\kappa = -T_s K'(s)\, q / d^2$, since $\partial(\kappa/d)/\partial\kappa = (d + \kappa e_y)/d^2 = 1/d^2$; and $\partial s^+/\partial s = 1 + T_s K'(s)\, q e_y / d^2$. The $e_y$ row is unchanged. The offsets change accordingly so the map stays exact at the query. On this track $K'$ is large at the corner entries (the curvature rises from near zero to 1.6 within about a metre), so the neglected terms are not negligible there, but they only matter for the one-step prediction of $e_\psi$ and $s$, which is refitted at every step anyway.
:::

:::: exercise Uncertainty model
Estimate a local covariance of the model error from held-out residuals; how could it be used?
::: hint
Pool the residuals of the neighbours used in the fit.
:::
::: solution
For a query, take the residuals $\epsilon_i = x_i^+ - (A_q x_i + B_q u_i + c_q)$ of the selected transitions, or better of held-out transitions near the query, and form the weighted covariance $\Sigma_q = \sum_i w_i \epsilon_i\epsilon_i^\top / \sum_i w_i$ for the three learned rows (the kinematic rows add the discretisation error, which can be estimated the same way). In stochastic MPC it defines the disturbance of $x^+ = A x + B u + c + \epsilon$ and turns the lane constraint into a chance constraint tightened by a multiple of the predicted standard deviation along the horizon; in tube-based robust MPC a bound such as $\|\Sigma_q^{-1/2}\epsilon\| \le \beta$ gives the disturbance set that the tube must absorb. Either way the covariance should grow with the support distance, since residuals measured in supported regions say nothing about unsupported ones; that is the honest link between Part 11's warning and a constraint the optimiser can use.
:::

:::: exercise Error-dynamics learning
With a nominal physics model available, regress the residual $e_i = x_{i+1} - f_{\mathrm{nom}}(x_i, u_i)$ instead of the full dynamics. Why does this reduce the learning burden?
::: hint
What is left to learn if the nominal model is good?
:::
::: solution
Linearise the nominal model at the query, $f_{\mathrm{nom}} \approx A^{\mathrm{nom}}_q x + B^{\mathrm{nom}}_q u + c^{\mathrm{nom}}_q$, and fit the same local weighted regression to the residuals, $e \approx \tilde A_q x + \tilde B_q u + \tilde c_q$; the prediction model is the sum. If the nominal model is good, the residual is small and smooth, its coefficients are near zero, and the regression needs fewer points, tolerates a larger bandwidth or more ridge without harm, and degrades gracefully to the physics model where data are missing, which also answers the extrapolation problem of Part 11: outside the data the correction is simply switched off. The learning burden is the mismatch, not the whole dynamics. The price is that a wrong nominal model biases every prediction, so the residual must be validated like everything else.

import json, numpy as np
from pathlib import Path
text = Path("interactive/b04-data.js").read_text(encoding="utf-8")
D = json.loads(text[text.index("{"):text.rindex("}") + 1])
laps = [(np.array(l["X"])[:-1], np.array(l["U"]), np.array(l["X"])[1:]) for l in D["laps"]]
x, u = np.array(D["val"]["X"][120]), np.array(D["val"]["U"][120])
q, sc = np.r_[x[:3], u], np.array([0.1, 1, 1, 1, 1])
rows = []
for X, U, Xn in laps:
    d = np.abs(np.hstack([X[:, :3], U]) - q) @ sc
    for i in np.argsort(d, kind="stable")[:7]:
        rows.append((X[i], U[i], Xn[i], 0.75 * (1 - (d[i] / 5) ** 2)))
X, U, Xn, w = (np.array([r[j] for r in rows]) for j in range(4))
def ridge(Phi, Y): return np.linalg.solve(Phi.T @ (w[:, None] * Phi) + 1e-8 * np.eye(Phi.shape[1]), Phi.T @ (w[:, None] * Y))
tv = ridge(np.hstack([X[:, :3], U[:, 1:2], np.ones((28, 1))]), Xn[:, :1])[:, 0]
tl = ridge(np.hstack([X[:, :3], U[:, :1], np.ones((28, 1))]), Xn[:, 1:3])
print(tv.round(3), tl[:, 0].round(3), tl[:, 1].round(3))   # a11..a13, b12, c1 | a21..a23, b21, c2 | a31..a33, b31, c3

## The chapter on one page {#summary}

::: steps
- **The car**: a BARC bicycle model with Pacejka axles, $D = 7.77$ N; six spatial states; the full raceline problem is a nonlinear program.
- **Two systems**: the nonlinear simulator, and an affine surrogate $x^+ = A_k x + B_k u + c_k$ inside the QP.
- **Data**: a 20 m RC-car track, four noisy PID laps (1216 transitions) for fitting, one lap held out.
- **Metric**: $\|D(z_i - z_q)\|_1$ on $(v_x, v_y, r, \delta, a_x)$, Epanechnikov weights, seven nearest points per lap.
- **Regression**: $(\Phi^\top W\Phi + \lambda I)\theta = \Phi^\top Wy$ with an affine constant; $\lambda = 10^{-8}$ as a safeguard only.
- **Structure**: $v_x^+$ from $(v_x, v_y, r, a_x)$, $v_y^+, r^+$ from $(v_x, v_y, r, \delta)$; kinematic rows exact.
- **Validation**: held-out one-step RMSE $(0.0121, 0.0009, 0.0144)$ local against $(0.0210, 0.0019, 0.0420)$ global.
- **Diagnostics**: support distance below 0.29 on the lap, condition numbers near $10^{5}$; coefficients are not derivatives.
- **Horizon**: 14 steps, RMSE 0.021 against 0.041; matrices vary along the horizon; at 30 steps the local model loses.
- **Limits**: the out-of-distribution query at distance 8.5 triggers the fallback on every lap; the number is not a prediction.
- **Into LMPC**: model learning for the horizon, safe-set and value learning for the terminal; no robustness certificate comes with it.
:::

### The vocabulary, in one table

| Term | Meaning here |
|---|---|
| Slip angle, magic formula | Tire angle to its velocity; $D\sin(C\arctan(B\alpha))$. |
| Local affine (LTV) model | $A_k x + B_k u + c_k$ refitted at every predicted step. |
| Transition tuple | One stored $(x_i, u_i, x_{i+1})$. |
| Query vector $z$ | The five features used to find neighbours; no track position. |
| Scaled $\ell_1$ distance | $\lVert D(z_i - z_q) \rVert_1$ with $D = \operatorname{diag}(0.1, 1, 1, 1, 1)$. |
| Epanechnikov kernel | $\tfrac34[1 - (d/h)^2]$ inside the bandwidth, zero outside. |
| Support fallback | A lap with no point inside the bandwidth lends its nearest points, and is flagged. |
| Weighted ridge regression | Kernel-weighted least squares with $\lambda I$ added to the normal matrix. |
| Structured rows | Each learned row sees only the physically relevant input. |
| Analytic kinematic rows | Exact Jacobian of the Euler-discretised Frenet kinematics, curvature frozen. |
| Support distance | Nearest stored transition in the metric: a geometric warning, not an uncertainty. |
| Condition number | Sensitivity of the coefficients to the data; large for nearly collinear neighbours. |
| Held-out lap | A complete lap kept out of the fit; the only honest validation for correlated data. |

**Scope.** The vehicle model and the prediction model of a Learning MPC racing controller, built and validated as in the published method: identification laps, local kernel-weighted structured regression, analytic kinematics, trajectory-based validation, support and conditioning diagnostics. The closed-loop controller itself is not implemented; Part 11 says how the model enters it. The laps are generated in Python and shipped to this page because their random dither cannot be reproduced bit for bit in a browser; every fit, validation and sweep is recomputed here and by the numbers script from the same file.
