## The language of dynamical systems {#state}

**State, input, dynamics, output.** A deterministic discrete-time system is written

$$x_{k+1} = f_k(x_k, u_k), \qquad x_k \in \mathbb R^n,\quad u_k \in \mathbb R^m .$$

The index $k$ counts samples, not seconds: $x_k$ is the state at time $k T_s$ for a sample period $T_s$. The input $u_k$ is what the controller chooses. An output equation $y_k = h_k(x_k, u_k)$ may be added when only part of the state is measured; this course assumes the state is measured, and says in chapter [[b06]] what changes when it is not.

::: define What is a state?
**In plain words:** the smallest list of numbers that, together with the inputs from now on, determines everything the system will do. For a cart, its position and velocity; its position alone is not enough, since two carts at the same place moving at different speeds have different futures.

**More precisely:** a vector $x_k$ such that the next state is a function of the current state and input only, $x_{k+1} = f_k(x_k, u_k)$, with no dependence on earlier states or inputs. The dimension $n$ is the order of the system. Any quantity the controller needs to predict must be part of the state or computable from it.

- State $x_k \in \mathbb R^n$ :: Position and velocity of the cart: $n = 2$.
- Input $u_k \in \mathbb R^m$ :: The acceleration the motor applies: $m = 1$.
- Dynamics $f_k$ :: The rule that advances the state by one sample.
- Trajectory :: The sequence $x_0, x_1, x_2, \dots$ produced by an input sequence $u_0, u_1, \dots$ from a start $x_0$.
:::

**Why the state, and not the history.** Model predictive control predicts: it asks what the next $N$ states would be under a candidate input sequence. That question has an answer only if the current state summarises the past. The hero demo shows the summary at work: the trajectory in the plane is a sequence of points, and from any of them the rest of the path depends only on the inputs still to come.

## Four model classes {#classes}

The course moves between four kinds of $f$, deliberately.

| Class | Dynamics | Where the course uses it |
|---|---|---|
| LTI, linear time-invariant | $x_{k+1} = A x_k + B u_k$ | Every concept chapter: the double integrator below |
| Affine | $x_{k+1} = A x_k + B u_k + c$ | The locally identified models of chapter [[b04]], where the constant is the linearisation offset |
| LTV, linear time-varying | $x_{k+1} = A_k x_k + B_k u_k + c_k$ | The prediction model along a racing horizon, chapter [[b04]] |
| Nonlinear | $x_{k+1} = f(x_k, u_k)$ | The unicycle of chapter [[a05]], the bicycle model of chapter [[b03]] |

For an LTI model, prediction is matrix algebra (chapter [[a02]]) and the optimal-control problem is a quadratic program (chapter [[a05]]). For an affine model the same holds with one extra constant. For a nonlinear model the problem is a nonlinear program, and chapter [[a05]] shows what that costs. The racing chapters keep a nonlinear plant and give the optimiser a sequence of affine models instead: that is the whole point of local model learning.

## The cart: a double integrator from Newton {#cart}

**The physics.** A cart of unit mass on a rail, pushed by a force equal to its acceleration $a$: $\dot p = v$, $\dot v = a$. Two integrations take the input to the position, hence the name.

**One sample.** Hold the acceleration constant at $a_k$ for one sample period $T_s$. Integrating twice,

$$p_{k+1} = p_k + T_s v_k + \tfrac{1}{2} T_s^2 a_k, \qquad v_{k+1} = v_k + T_s a_k ,$$

exactly, with no approximation: a piecewise-constant input makes the continuous cart's state at the sample instants an LTI system. With the state $x_k = (p_k, v_k)$ and the input $u_k = a_k$,

$$A = \begin{pmatrix} 1 & T_s \\ 0 & 1 \end{pmatrix}, \qquad B = \begin{pmatrix} T_s^2 / 2 \\ T_s \end{pmatrix}, \qquad \text{and with } T_s = 1:\quad \boxed{A = \begin{pmatrix} 1 & 1 \\ 0 & 1 \end{pmatrix},\ B = \begin{pmatrix} 0.5 \\ 1 \end{pmatrix}}.$$
%narrow A = \begin{pmatrix} 1 & T_s \\ 0 & 1 \end{pmatrix}, \quad B = \begin{pmatrix} T_s^2 / 2 \\ T_s \end{pmatrix}; \qquad T_s = 1: \quad \boxed{A = \begin{pmatrix} 1 & 1 \\ 0 & 1 \end{pmatrix},\ B = \begin{pmatrix} 0.5 \\ 1 \end{pmatrix}}

These are the course's matrices. The eigenvalues of $A$ are both 1: left alone, the cart neither returns to rest nor runs away, it coasts. That is why every stabilising result later is about what the input does, not what the plant does on its own (chapter [[a07]]).

**Read the hero.** From $x_0 = (-3, 0)$, the inputs $1, 1, 0, -1, -1$ move the velocity to 1, 2, 2, 1, 0 and the position to $-2.5, -1, 1, 2.5, 3$: the cart crosses the origin at full speed and stops at $p = 3$. Each position increment is the old velocity plus half the input, $v_k + u_k / 2$, the second term being the distance gained during the sample by the acceleration itself. Braking one step earlier stops it at $p = 1$. Halving the inputs and holding them twice as long gives the same peak velocity of 2 but twice the distance, 8 in all, and the cart leaves the box at step 7: the same kind of sequence, scaled, is no longer admissible. Scale the first sequence in the demo to find the factor at which it first leaves the box.

**This tiny system already contains the difficulties of MPC.** The input acts on the velocity at once but on the position only through the velocity, so correcting a position error takes planning; the physical limits bound both states and the input; and a cart moving fast near the edge of its box cannot be saved by any admissible input, which chapter [[a10]] turns into geometry.

## Two discretisations: zero-order hold against Euler {#discretisation}

The zero-order-hold model above is exact. A cruder model, explicit Euler, replaces the derivative by a difference:

$$p_{k+1} = p_k + T_s v_k, \qquad v_{k+1} = v_k + T_s a_k, \qquad B_{\mathrm{Euler}} = \begin{pmatrix} 0 \\ T_s \end{pmatrix}.$$

The velocity update is the same; the position update ignores the acceleration during the sample, so the position lags the true one by $\tfrac12 T_s^2 a_k$ per step, or, summed, by $T_s v_k / 2$ for a cart that started at rest. With $T_s = 1$ and the first hero sequence the Euler positions are $-3, -2, 0, 2, 3$ against the exact $-2.5, -1, 1, 2.5, 3$: a whole unit apart at the peak velocity, agreeing again only once the cart is at rest.

**Why keep Euler at all.** Lab [[b01]] uses it with a one-second sample, as the published collision-avoidance exercise does, and the lag is visible in its feasibility maps: with Euler a car cannot clear a crossing that the exact model says it can. Chapter [[b04]] uses Euler for the Frenet kinematics at a 0.1 s sample, where the lag is small. The rule: a discretisation is part of the model, its error is a modelling error, and a one-second Euler step on a cart is coarse.

## The plant and the prediction model {#plant}

::: callout
**Two models, one system.** The *plant* is the system being controlled, or its simulation: it evolves according to physics. The *prediction model* is what the optimiser uses to imagine the future. In the concept chapters the two coincide, so that every theorem can be checked exactly. On a real system they never do: the plant is nonlinear, its parameters drift, its sample is not quite periodic, and disturbances act on it. MPC optimises with the model; the plant decides what happens.
:::

The gap between the two is the recurring theme of the labs: chapter [[b04]] fits a prediction model to a nonlinear car from its own recorded laps, and chapter [[b06]] asks which guarantees survive a mismatch (none, strictly, and what to do about it). Keep the distinction in mind every time a chapter says "the model": it means the prediction model, and a statement about the model becomes a statement about the plant only when the two agree.

## Constraints as sets {#constraints}

The cart's limits are written as sets. The state must stay in a box and the input in an interval,

$$\mathcal X = \{x : |p| \le 4,\ |v| \le 3\} = \{x : H_x x \le h_x\}, \qquad \mathcal U = \{u : |u| \le 1\},$$

with four rows for the box, $H_x = \begin{pmatrix} 1 & 0 \\ 0 & 1 \\ -1 & 0 \\ 0 & -1 \end{pmatrix}$ and $h_x = (4, 3, 4, 3)$. Writing $|p| \le 4$ as two inequalities $p \le 4$ and $-p \le 4$ is the format every optimisation solver takes, and chapter [[a08]] builds a whole geometry on it. The input interval is a one-dimensional box of the same kind.

**A constraint is checked on every state, not only the last.** From $(-3, 0)$ with the input held at its bound $u = 1$, the velocity reaches its bound 3 after three steps, at position 1.5; one more push would violate $|v| \le 3$ at a position that is still comfortably inside. Whether a sequence of inputs is *admissible* depends on the whole trajectory it produces, and that is what the prediction matrices of chapter [[a02]] make checkable in one matrix inequality.

::: define The canonical system
**In plain words:** one cart, one set of limits, one cost, used in every concept chapter so that the numbers carry over: the LQR gain computed in chapter [[a07]] is the one that defines the terminal set in chapter [[a10]] and the terminal cost in chapter [[a11]].

**More precisely:** $x^+ = Ax + Bu$ with the matrices above, $\mathcal X$ the box $|p| \le 4$, $|v| \le 3$, $\mathcal U$ the interval $|u| \le 1$, and the stage cost $q(x, u) = x^\top Q x + R u^2$ with $Q = \mathrm{diag}(1, 0.2)$ and $R = 0.2$. Where a chapter needs a weaker motor to make an effect visible it says so and uses $|u| \le 0.5$. The [notation page](notation.html) lists every number computed from it.
:::

## The code behind it {#code}

The course package keeps the model in two small functions. The first rolls any LTI system out under an input sequence; it is what the hero demo and the numbers script call.

::: code advanced_mpc_lmpc/linear.py:rollout
Three things to read. The inputs arrive as a two-dimensional array with one row per step, `np.atleast_2d(U)`, so that a scalar input and a vector input are handled by the same loop. The state is copied before the loop, `x = ...copy()`, because the function must not modify the caller's `x0`; this is the first of many places where a numerical course has to be careful about aliasing. And the returned array has one more row than there are inputs: `xs` starts with $x_0$ and gains one state per input, which is why every trajectory in the course has $T + 1$ states for $T$ inputs.
:::

The second builds the matrices for either discretisation; lab [[b01]] uses it with its Euler default.

::: code advanced_mpc_lmpc/collision.py:vehicle_matrices
The matrix $A$ is the same for both models, since both update the velocity exactly and both carry the position forward with the old velocity. Only $B$ differs: Euler puts a zero where the zero-order hold has $T_s^2 / 2$. That single entry is the whole difference the widget of Part 4 draws.
:::

## Common pitfalls {#pitfalls}

1. **"The position is the state."** Not for anything with inertia. Two carts at the same position with different velocities have different futures; the state must contain both.
2. **"$k$ is time in seconds."** It counts samples. With $T_s = 0.5$ the state $x_6$ is the state at 3 s, and a horizon of $N = 6$ steps looks 3 s ahead.
3. **"Euler is fine because it is first order."** At $T_s = 1$ its position lags the truth by $v / 2$, a whole unit at the cart's cruising speed. Whether that matters depends on what is being checked; for a constraint on the position it matters.
4. **"The model is the system."** The prediction model is the optimiser's picture of the plant. Every guarantee in Part A is proved for the model; it transfers to the plant only when they agree.

## Check your understanding {#check}

:::: qa
Try to answer each question before opening it.

::: q 1. Why is the double integrator called that?
Two integrations separate the input from the position: the acceleration integrates to the velocity and the velocity to the position. In discrete time the input reaches the velocity in one step and the position only through the velocity.
:::
::: q 2. Where does the $\tfrac12 T_s^2$ in $B$ come from?
From integrating a constant acceleration twice over one sample: the velocity grows linearly, so the extra distance covered during the sample is $\tfrac12 a T_s^2$. The zero-order-hold model is exact for piecewise-constant inputs because of it.
:::
::: q 3. What does Euler change, and by how much?
Only the position update, which drops the $\tfrac12 T_s^2 a_k$ term. For a cart starting at rest the position then lags the exact one by $T_s v_k / 2$: one unit at $T_s = 1$ and $v = 2$, an eighth of a unit at $T_s = 0.1$.
:::
::: q 4. Is the double integrator stable on its own?
No, and not unstable either: both eigenvalues of $A$ equal 1, so a coasting cart keeps its velocity for ever. Stability has to come from the input, which is why chapter [[a07]] designs a feedback law.
:::
::: q 5. What makes an input sequence admissible?
That every state it produces lies in $\mathcal X$ and every input in $\mathcal U$. It is a property of the whole trajectory, checked with the prediction matrices of chapter [[a02]].
:::
::: q 6. Why does the course keep the plant and the prediction model apart in its vocabulary?
Because every theorem is about the model, and a controller is judged on the plant. Naming the gap keeps track of which statements are proofs and which are hopes; chapter [[b06]] makes the list.
:::

## Exercises {#exercises}

Each exercise has a hint and a solution; the code runs with the course package installed. Try first, then peek.

::::: exercises
:::: exercise Derive the zero-order hold
Starting from $\dot p = v$, $\dot v = a$ with $a$ held constant on $[kT_s, (k+1)T_s)$, derive $p_{k+1}$ and $v_{k+1}$ and read off $A$ and $B$ for a general $T_s$.
::: hint
Integrate the velocity equation first, then substitute the result into the position equation and integrate again.
:::
::: solution
$v(t) = v_k + a_k (t - kT_s)$ on the sample, so $v_{k+1} = v_k + T_s a_k$. Then $p(t) = p_k + v_k (t - kT_s) + \tfrac12 a_k (t - kT_s)^2$, so $p_{k+1} = p_k + T_s v_k + \tfrac12 T_s^2 a_k$. Hence $A = \begin{pmatrix} 1 & T_s \\ 0 & 1 \end{pmatrix}$, $B = (T_s^2 / 2, T_s)$. Nothing was approximated: the model is exact at the sample instants for any piecewise-constant input.
:::
::::
:::: exercise A faster sample
Write the matrices for $T_s = 0.5$ and roll the cart out from $x_0 = (-2, 0.25)$ under the inputs $0.4, 0.2, 0, -0.2, -0.3, 0.1$. Check the states against `rollout`.
::: hint
$B = (0.125, 0.5)$; the first position is $-2 + 0.5 \cdot 0.25 + 0.125 \cdot 0.4$.
:::
::: solution
$A = \begin{pmatrix} 1 & 0.5 \\ 0 & 1 \end{pmatrix}$, $B = (0.125, 0.5)$. The states are $(-1.825, 0.45)$, $(-1.575, 0.55)$, $(-1.3, 0.55)$, $(-1.05, 0.45)$, $(-0.8625, 0.3)$ and $(-0.7, 0.35)$: the cart drifts right, speeds up to 0.55, and is braked back to 0.35.

```python
from advanced_mpc_lmpc.collision import vehicle_matrices
from advanced_mpc_lmpc.linear import rollout
A, B = vehicle_matrices(0.5, "zoh")
X = rollout(A, B, [-2.0, 0.25], np.array([0.4, 0.2, 0, -0.2, -0.3, 0.1])[:, None])
print(X.round(4))        # six rows after the start, ending at (-0.7, 0.35)
```

:::: exercise Euler's lag
Show that for a cart starting at rest the Euler position lags the exact position by exactly $T_s v_k / 2$ at every step $k$, whatever the inputs.
::: hint
Subtract the two position recursions; the velocities are identical in both models.
:::
::: solution
Both models have the same velocities, $v_k = T_s \sum_{j<k} a_j$. The exact position adds $\tfrac12 T_s^2 a_j$ at each step and Euler does not, so the gap after $k$ steps is $\tfrac12 T_s^2 \sum_{j<k} a_j = \tfrac12 T_s v_k$. The gap is zero whenever the cart is at rest, which is why the two models agree on the final position of a manoeuvre that ends at rest and disagree everywhere in between. The numbers script prints the gap for $T_s = 1, 0.5, 0.25, 0.1$: 1, 0.625, 0.3125 and 0.125, each equal to $T_s / 2$ times the peak velocity.
:::
::::
:::: exercise Classify the models
For each of these, say which of the four classes it belongs to and why: (a) $x^+ = 1.2x + u$; (b) $x^+ = Ax + Bu + c$ with a fixed $c$; (c) the unicycle $x^+ = x + T_s v \cos\theta$; (d) $x_{k+1} = A_k x_k + B_k u_k$ with $A_k$ from a lookup table indexed by $k$. Then simulate (a) with $u = 0$ from $x = 1$ for ten steps.
::: hint
Look for constants added to a linear map, for time indices on the matrices, and for anything that is not linear in $(x, u)$.
:::
::: solution
(a) LTI, scalar, and unstable: the eigenvalue is 1.2, so from $x = 1$ with no input the state reaches $1.2^{10} = 6.19$ after ten steps. (b) Affine: linear plus a constant; it becomes LTI in the shifted variable $x - x_{\mathrm{eq}}$ if an equilibrium $x_{\mathrm{eq}} = A x_{\mathrm{eq}} + c$ exists. (c) Nonlinear: $\cos\theta$ multiplies an input by a function of the state. (d) LTV: linear at each step, with matrices that depend on the step.
:::
::::
:::: exercise The box as inequalities
Write $-2 \le p \le 3$, $-1 \le v \le 4$ as $H x \le h$, and check that $(3, 4)$ is in the set and $(3.5, 0)$ is not.
::: hint
Each lower bound becomes a row with a minus sign.
:::
::: solution
$H = \begin{pmatrix} 1 & 0 \\ -1 & 0 \\ 0 & 1 \\ 0 & -1 \end{pmatrix}$, $h = (3, 2, 4, 1)$. For $(3, 4)$ the four products are $3, -3, 4, -4$, each at most its bound; for $(3.5, 0)$ the first is $3.5 > 3$. `HPolytope.box([-2, -1], [3, 4]).contains(x)` does the same test, in chapter [[a08]].
:::

## The chapter on one page {#summary}

::: steps
- **The state** is what the future depends on: position and velocity for the cart, $x_{k+1} = f_k(x_k, u_k)$.
- **Four classes**: LTI for the concepts, affine and LTV for the racing prediction models, nonlinear for the plants.
- **The cart**: $A = \begin{pmatrix} 1 & 1 \\ 0 & 1 \end{pmatrix}$, $B = (0.5, 1)$ at $T_s = 1$, exact for held inputs; eigenvalues 1, so it coasts.
- **Euler** drops the $\tfrac12 T_s^2 a_k$ term and lags the exact position by $T_s v_k / 2$: one unit at $T_s = 1$, $v = 2$.
- **Plant against prediction model**: the theorems are about the model; the plant decides.
- **Constraints are sets**: the box $|p| \le 4$, $|v| \le 3$ as four rows $H_x x \le h_x$, the input interval $|u| \le 1$, checked on every state of a trajectory.
- **The canonical system**: these matrices and sets with $Q = \mathrm{diag}(1, 0.2)$, $R = 0.2$, in every concept chapter.
:::

### The vocabulary, in one table

| Word | Meaning |
|---|---|
| State, input, output | What the future depends on; what the controller chooses; what is measured. |
| Sample period $T_s$ | The time between two states $x_k$ and $x_{k+1}$. |
| LTI, affine, LTV, nonlinear | $Ax + Bu$; plus a constant; with time-varying matrices; anything else. |
| Zero-order hold | A piecewise-constant input; the discretisation that is exact for it. |
| Explicit Euler | Derivative replaced by a difference; the position lags by $T_s v / 2$. |
| Plant, prediction model | The system that evolves; the model the optimiser predicts with. |
| Admissible | A trajectory whose every state is in $\mathcal X$ and every input in $\mathcal U$. |
| Canonical system | The course's cart, box, interval and weights, shared by every concept chapter. |

**Scope.** Deterministic discrete-time models with a measured state. Noise, estimation and sampling jitter are out of scope; the labs say where they enter.
