## Four rules, 24 orders {#paint}

Chapter [[a01]] measured one schedule of the paint machine. Here we ask the shop manager's question: **in which order should the machine paint?** It is set up for blue, a colour change (a *changeover*) takes 10 minutes, and four orders wait: A (blue, 20 min, due at minute 30), B (red, 10 min, due 25), C (blue, 15 min, due 70), D (red, 25 min, due 60). The measure is the **total tardiness**: the sum over orders of how late each finishes, an early order counting zero.

The simplest answer is a **rule**: each time the machine is free, take the waiting order that is best by one criterion.

- **First come, first served (FIFO)**: A, B, C, D. Three colour changes; B 15 and D 40 min late: **55**.
- **Shortest job first (SPT)**: B, C, A, D. A 35 and D 40 min late: **75**.
- **Most urgent first (EDD**, earliest due date): B, A, D, C. Four colour changes; A 20, D 25, C 40 min late: **85**.
- **Shortest setup first (SST)**: A, C, then B, D. One colour change; B 30 and D 20 min late: **50**.

Four orders can be arranged in $4! = 24$ ways, few enough to try them all. The best, A, B, D, C, is **40** min late in total. The hero's histogram shows all 24 totals, from 40 to 135 with a median of 77.5: SST is beaten by 1 order, FIFO by 2, SPT by 11 and EDD by 13. **Move the slider**: with no changeover EDD is optimal; at 20 min, avoiding colour changes is; at 10 min no rule is. This chapter explains why.

## One machine, precisely {#problems}

Chapter [[a01]] defined the completion time $C_j$, the lateness $L_j = C_j - d_j$, the tardiness $T_j = \max(0, L_j)$, and the three-field notation $\alpha \mid \beta \mid \gamma$ (machines, constraints, objective). Here $\alpha = 1$ (one machine) and, unless $\beta$ says otherwise, every job is available at time 0 with processing time $p_j > 0$. An empty middle field, as in $1 \Vert \sum C_j$, means no extra constraint: no release dates, no changeovers.

::: define What is a single-machine sequencing problem?
**In plain words:** one machine, a list of jobs all waiting now, and one question: in which order? Once the order is fixed, nothing is left to decide.

**More precisely:** a *sequence* is a permutation $\sigma = (\sigma_1, \dots, \sigma_n)$ of the jobs. Without changeovers or idle time, $C_{\sigma_k} = \sum_{i \le k} p_{\sigma_i}$. With sequence-dependent changeovers, $s_{ij} = s(f(i), f(j))$ is the changeover between the families of $i$ and $j$; the initial state $\sigma_0 = \circ$ is the family the machine is set up for (not a job: jobs are numbered from 0), with first changeover $s_{\circ j}$, and $C_{\sigma_k} = \sum_{i \le k} ( s_{\sigma_{i-1} \sigma_i} + p_{\sigma_i} )$. On the paint machine at 10 min, SST's A, C, B, D gives $C_A = 20$, $C_C = 35$, $C_B = 55$, $C_D = 80$. An objective $\gamma$ maps the completion times to a number to minimise.

- Regular objective :: Cannot decrease when a $C_j$ increases: $\sum C_j$, $\sum w_j C_j$, $L_{\max} = \max_j L_j$, $\sum T_j$, $C_{\max}$.
- Index rule :: Gives each job a number computed from that job alone ($p_j$, $d_j$, $p_j/w_j$) and sorts by it.
- Dynamic rule :: Its priority also reads the machine's state, as SST reads the current colour.
- Optimal rule :: Attains the minimum of $\gamma$ on *every* instance of the problem, not on one.
:::

**Why a sequence is enough.** For a regular objective with all jobs available at 0, sliding operations left to close idle gaps never increases a completion time, so some optimal schedule has no idle time and is fixed by its order: the search space is the $n!$ permutations.

::: table
| Problem | Answer |
|---|---|
| $1 \Vert \sum C_j$ | shortest job first (Part 3) |
| $1 \Vert \sum w_j C_j$ | Smith's ratio rule (Part 3) |
| $1 \Vert L_{\max}$ | most urgent first (Part 4) |
| $1 \Vert \sum T_j$ | NP-hard: no polynomial rule is optimal unless P = NP (Parts 5, 6) |
| $1 \mid s_{ij} \mid C_{\max}$ | an asymmetric travelling salesman (Part 7) |
:::

## The exchange argument {#interchange}

**On the paint machine first**, without changeovers. FIFO starts with A then B, completing at 20 and 30 (sum 50); B then A completes at 10 and 30 (sum 40). C and D come after and start at 30 either way, so the swap saves exactly $p_A - p_B = 10$, wherever the pair sits.

The idea in one sentence: **if swapping two neighbours that are in the "wrong" order never makes things worse, the "right" order is optimal.** Let $\sigma$ contain job $i$ immediately followed by job $j$, starting at time $t$, and let $\sigma'$ exchange them. Without changeovers the jobs before the pair are untouched, the jobs after it start at $t + p_i + p_j$ in both sequences, and only the pair moves: $C_i = t + p_i$, $C_j = t + p_i + p_j$ in $\sigma$; $C_j' = t + p_j$, $C_i' = t + p_i + p_j$ in $\sigma'$.

::: callout
**The adjacent pairwise interchange.** The difference between $\sigma$ and $\sigma'$ involves only the two jobs and their start time $t$. If its sign is fixed by a number of $i$ alone against a number of $j$ alone, sorting by that number is optimal. If it depends on $t$, the argument gives no index, and another tool (or a hardness theorem) is needed.
:::

**Theorem (Smith 1956).** For $1 \Vert \sum C_j$, every sequence in non-decreasing order of $p_j$ (SPT) is optimal.

*Proof.* With the pair as above,

$$\begin{aligned} \sum_k C_k(\sigma) - \sum_k C_k(\sigma') &= (t + p_i) + (t + p_i + p_j) \\ &\quad - (t + p_j) - (t + p_i + p_j) \\ &= p_i - p_j . \end{aligned}$$

The start time cancels: in the Part 5 widget, choose *sum of completions* and the two lines are parallel, $p_i - p_j$ apart, whatever $t$. If $p_i > p_j$ the swap strictly decreases $\sum C_j$, so a sequence with a longer job just before a shorter one is not optimal. An optimal sequence exists (there are finitely many), so it has no such pair: it is sorted by $p$. Sorted sequences differ only in the order of equal-length jobs, and swapping equal neighbours changes the sum by $p_i - p_j = 0$, so all of them are optimal. $\square$

**The same result as a formula.** With $p_{[k]}$ the time of the job in position $k$, $p_{[k]}$ is counted in its own completion and in every later one:

$$\sum_{j} C_j = \sum_{k=1}^{n} (n - k + 1)\, p_{[k]} .$$

The weights $n, n-1, \dots, 1$ decrease, so the sum is smallest when the shortest job takes the largest weight. On the paint machine without changeovers SPT gives B, C, A, D, completing at 10, 25, 45, 70, and $4 \cdot 10 + 3 \cdot 15 + 2 \cdot 20 + 1 \cdot 25 = 150$, against 165 for FIFO; trying all 24 orders confirms B, C, A, D as the unique minimiser.

**Theorem (Smith 1956, weighted).** For $1 \Vert \sum w_j C_j$ with $w_j > 0$, every sequence in non-decreasing order of $p_j / w_j$ (WSPT) is optimal.

*Proof.* The same swap gives

$$\begin{aligned} \sum_k w_k C_k(\sigma) - \sum_k w_k C_k(\sigma') &= w_i (t + p_i) + w_j (t + p_i + p_j) \\ &\quad - w_j (t + p_j) - w_i (t + p_i + p_j) \\ &= w_j p_i - w_i p_j , \end{aligned}$$

positive exactly when $p_i / w_i > p_j / w_j$; the rest is unchanged. $\square$

The weight is the cost of a minute of waiting; Exercise 1 applies the rule.

**The proof requires that there be no changeovers.** With them, swapping $i$ and $j$ also changes the changeovers into, between and out of the pair, so the later jobs move too. On the paint machine with 10-min colour changes, SPT's B, C, A, D totals $\sum C_j = 230$ while C, A, B, D reaches 185.

## Most urgent first and the worst lateness {#jackson}

**In plain words:** to make the worst delay as small as possible, serve the order that is due soonest. Take B (10 min, due 25) and A (20 min, due 30), no changeover. A then B gives latenesses $-10$ and $5$; B then A gives $-15$ and $0$. Putting the more urgent order first lowers the worst lateness from 5 to 0, and the theorem says this always works.

**Theorem (Jackson 1955).** For $1 \Vert L_{\max}$, every sequence in non-decreasing order of due dates (EDD) is optimal; since $T_{\max} = \max(0, L_{\max})$, it also minimises the maximum tardiness.

*Proof.* Let $i$ immediately precede $j$ with $d_i > d_j$, starting at $t$, and swap them. Only their latenesses change. Before, $L_j = t + p_i + p_j - d_j$; after,

$$L_j' = t + p_j - d_j \le L_j, \qquad L_i' = t + p_i + p_j - d_i < t + p_i + p_j - d_j = L_j ,$$
%narrow L_j' = t + p_j - d_j \le L_j, \quad L_i' = t + p_i + p_j - d_i < L_j

so $\max(L_i', L_j') \le L_j \le \max(L_i, L_j)$ and $L_{\max}$ cannot increase (in the Part 5 widget, choose *worst lateness*: the line of the more urgent job first never lies above the other). The swap need not improve *strictly*, so run the argument from an optimal sequence: remove its due-date inversions one adjacent swap at a time, as bubble sort does. No swap raises $L_{\max}$, and after at most $n(n-1)/2$ swaps the sequence is in EDD order, with $L_{\max}$ no larger than the optimum. Swapping equal due dates changes nothing, so ties are harmless. $\square$

EDD **ignores the processing times**, yet is optimal for the worst lateness whatever they are; and if it finishes every job on time it is optimal for total tardiness too. On the paint machine without changeovers EDD's B, A, D, C has latenesses $-15, 0, -5, 0$, the only order of the 24 with nothing late. With 10-min changeovers it reaches $L_{\max} = 40$, while A, B, D, C achieves 20.

## Total tardiness: where the exchange breaks {#tardiness}

**A counterexample by hand.** Three jobs, no changeovers: X takes 10 min, due at 30; Y takes 20, due at 10; Z takes 30, due at 20.

::: table num
| Order | Completions | Tardiness of each | Total |
|---|---|---|---|
| X Y Z (SPT) | 10, 30, 60 | 0, 20, 40 | 60 |
| X Z Y | 10, 40, 60 | 0, 20, 50 | 70 |
| Y X Z (best) | 20, 30, 60 | 10, 0, 40 | 50 |
| Y Z X (EDD) | 20, 50, 60 | 10, 30, 30 | 70 |
| Z X Y | 30, 40, 60 | 10, 10, 50 | 70 |
| Z Y X | 30, 50, 60 | 10, 40, 30 | 80 |
:::

SPT scores 60, EDD 70; the optimum, 50, is neither.

**Why: the swap depends on the clock.** For neighbours $i$, $j$ starting at $t$, with $x^+ = \max(0, x)$, the pair's tardiness is

$$\begin{aligned} \Phi_{ij}(t) &= (t + p_i - d_i)^+ + (t + p_i + p_j - d_j)^+ && (i \text{ first}), \\ \Phi_{ji}(t) &= (t + p_j - d_j)^+ + (t + p_i + p_j - d_i)^+ && (j \text{ first}). \end{aligned}$$
%narrow \begin{aligned} \Phi_{ij}(t) &= (t + p_i - d_i)^+ + (t + p_i + p_j - d_j)^+, \\ \Phi_{ji}(t) &= (t + p_j - d_j)^+ + (t + p_i + p_j - d_i)^+ . \end{aligned}

Take C (15 min, due 70) and D (25 min, due 60), ignoring the colour change: $\Phi_{CD}(t) = (t - 55)^+ + (t - 20)^+$ and $\Phi_{DC}(t) = (t - 35)^+ + (t - 30)^+$. Up to $t = 20$ both are 0. From 21 to 44 D first is strictly better (at $t = 30$: 10 against 0); at 45 they tie at 25; from 46 on C first is better (at $t = 60$: 45 against 55).

Read the extremes. When both jobs are late in either order, every bracket is positive and $\Phi_{ij} - \Phi_{ji} = p_i - p_j$: **late jobs want shortest first**. When the first job of the pair is on time in both orders, only the second brackets count: $\Phi_{ij} - \Phi_{ji} = (t + p_i + p_j - d_j)^+ - (t + p_i + p_j - d_i)^+$, which equals $d_i - d_j$ when both are positive and never has the other sign: **early jobs want most urgent first**. In between the preference flips at a time set by all four numbers, and since $t$ is the length of the jobs placed before the pair, no number of $i$ alone and $j$ alone can settle it.

**Three cases where a rule is optimal anyway.** (1) If EDD has no tardy job, it is optimal. (2) If $d_j \le p_j$ for every $j$, no job is early in any sequence ($C_j \ge p_j$), so $\sum T_j = \sum C_j - \sum d_j$ and SPT is optimal. (3) If the data are *agreeable*, $p_i \le p_j \Rightarrow d_i \le d_j$, the common SPT and EDD order is optimal (Exercise 2). Outside these edges a rule is a heuristic: fast, reasonable, unguaranteed.

## NP-hard, for an engineer {#nphard}

That the exchange fails does not prove that no clever rule exists; a theorem does.

**Theorem (Du and Leung 1990).** $1 \Vert \sum T_j$ is NP-hard: deciding, for a number $K$, whether some sequence has total tardiness at most $K$ is NP-complete. The proof reduces a number-partitioning problem to it: each partition instance becomes a set of jobs and a bound $K$ such that a sequence within $K$ exists exactly when the partition has a solution. It is long and technical; we only cite it.

::: define What does NP-hard mean?
**In plain words:** a method that always solved it quickly would also solve quickly a huge family of problems nobody has managed to solve quickly in fifty years: a precise reason to stop looking for a formula.

**More precisely:** measure an instance by the bits needed to write it. *P* is the class of yes-or-no problems solvable in time polynomial in that size. *NP* holds the yes-or-no problems whose "yes" can be *checked* in polynomial time from a certificate: here a sequence, whose total tardiness takes $\mathcal O(n)$ to compute. A problem is *NP-hard* if every problem in NP reduces to it, and *NP-complete* if it is also in NP. Whether P = NP is open and widely believed false (Garey and Johnson [[ref:7]]).

- Reduction :: A polynomial-time translation of each instance of problem A into an instance of B with the same answer; a fast method for B then solves A.
- Ordinary sense :: NP-hard, yet solvable in time polynomial in $n$ and in the numbers' values (pseudo-polynomial), as $1 \Vert \sum T_j$ is.
- Strong sense :: NP-hard even when the numbers are bounded by a polynomial in $n$.
:::

What it means at the machine:

1. **No dispatching rule is optimal for total tardiness**, unless P = NP: a rule sorts or scans the queue in polynomial time, so if it were always optimal it would solve an NP-hard problem in polynomial time.
2. **Exact methods have exponential worst cases** (Part 8), but many instances, like the paint machine, are solved instantly.
3. **The size of the numbers matters.** Lawler [[ref:5]] solves $1 \Vert \sum T_j$ in time polynomial in $n$ and $\sum_j p_j$, practical with small integer minutes and consistent with the theorem, since $\sum_j p_j$ can be exponential in the number of bits that write it. The weighted $1 \Vert \sum w_j T_j$ is NP-hard in the strong sense [[ref:1]], and so is the version with changeovers (Exercise 3).
4. **It forbids only a fast method that is always exactly optimal.** Solvers that prove the optimum of the instances you have are chapters [[c01]] and [[c02]].

## Changeovers: a travelling salesman inside the machine {#setups}

**The plain picture.** A salesman visits every city once and wants the shortest trip; read "city" as "job" and "distance" as "changeover". On the paint machine the painting always takes $20 + 10 + 15 + 25 = 70$ min, so the last order is done at 70 plus 10 per colour change: 100 for A, B, C, D, 110 for B, A, D, C, and 80 for A, C, B, D, the smallest of the 24.

**The equivalence.** For $1 \mid s_{ij} \mid C_{\max}$, with $\sigma_0 = \circ$ the initial state of Part 2,

$$C_{\max}(\sigma) = \sum_{j} p_j + \sum_{k=1}^{n} s_{\sigma_{k-1} \sigma_k} .$$

The first sum is constant; the second is the length of a path from $\circ$ through every job once in the directed graph with arc lengths $s_{ij}$, and zero-length arcs back to $\circ$ turn such paths into tours of the same length. So $1 \mid s_{ij} \mid C_{\max}$ **is** a travelling-salesman problem on $n + 1$ cities, *asymmetric* since $s_{ij} \ne s_{ji}$ in general. Conversely, take a salesman instance with a home city $h$, $n$ other cities and distances $c_{ab}$. Make one job of length 1 per city $a \ne h$, let the initial state $\circ$ stand for $h$ ($s_{\circ a} = c_{ha}$, $s_{ab} = c_{ab}$), and add a job $z$ of length 1, "back home", with $s_{az} = c_{ah}$ and $s_{za}$ larger than all distances together, so that it always comes last; then $C_{\max}$ is $n + 1$ plus the tour length. The salesman is NP-hard in the strong sense, so $1 \mid s_{ij} \mid C_{\max}$ is too.

**The workshop's changeovers.** A *batch* is a run of consecutive jobs of one family. On machine $m$ the changeover between two jobs depends only on their families, $s_{ij} = s_m(f(i), f(j))$: between 3 and 10 minutes, and asymmetric, $s_0(0, 2) = 10$ but $s_0(2, 0) = 6$. The numbers script prints all five machines (`JS.WORKSHOP.setup` holds them); here are two, read from row $f$ to column $g$:

::: table num
| From $f$ | $s_0(f, 0)$ | $s_0(f, 1)$ | $s_0(f, 2)$ | $s_0(f, 3)$ | $s_3(f, 0)$ | $s_3(f, 1)$ | $s_3(f, 2)$ | $s_3(f, 3)$ |
|---|---|---|---|---|---|---|---|---|
| 0 | 0 | 7 | 10 | 3 | 0 | 5 | 4 | 7 |
| 1 | 6 | 0 | 9 | 9 | 10 | 0 | 5 | 10 |
| 2 | 6 | 6 | 0 | 6 | 6 | 9 | 0 | 4 |
| 3 | 7 | 4 | 9 | 0 | 6 | 5 | 4 | 0 |
:::

**One batch per family is optimal for $C_{\max}$** when the triangle inequality $s(f, g) \le s(f, h) + s(h, g)$ holds. Take a second batch of $h$ out from between families $f$ and $g$: that saves $s(f, h) + s(h, g) - s(f, g) \ge 0$. Insert it right after the first batch of $h$: that costs $s(h, h) = 0$, and the arc out of the merged batch is unchanged. Repeat until each family forms one batch; $C_{\max}$ never grows. The workshop breaks the inequality in 4 places, e.g. $s_3(1, 3) = 10 > s_3(1, 2) + s_3(2, 3) = 9$. With one batch per family a machine is a salesman on 4 cities: on machine 0, from a machine that has run nothing yet (no first changeover), the best of the 24 family orders costs 13 min of changeovers (families 2, 0, 3, 1), the worst 26.

**Shortest setup first is the nearest-neighbour heuristic**: always go to the closest unvisited city. Greed can trap it. On machine 3, set up for family 2, SST goes to family 3 (4 min), then to family 1 (5 min, cheaper than the 6 to family 0), and must pay 10 for $1 \to 0$: 19 min, where $2 \to 3 \to 0 \to 1$ costs $4 + 6 + 5 = 15$.

**Total tardiness with changeovers** has both difficulties. How often is a rule optimal anyway? The widget draws random instances exactly as the numbers script does: processing times from 5 to 30 min, random families, and due dates $d_j$ uniform on $[(0.7 - \tau) \sum_j p_j,\ (1.3 - \tau) \sum_j p_j]$, rounded to the minute and never below 0. The *tightness* $\tau$ sets how early they fall: larger $\tau$, earlier due dates, more late orders. Each optimum is found exactly, by a search over orders that drops a prefix once it is already as late as the best order found (Part 8).

## Counting orders, and what exact methods do instead {#counting}

**How fast $n!$ grows.** Comparing $\ln n! = \sum_{k=1}^n \ln k$ with the integral of the increasing function $\ln x$,

$$n \ln n - n + 1 \;\le\; \ln n! \;\le\; (n + 1) \ln(n + 1) - n ,$$
%narrow n \ln n - n + 1 \le \ln n! \le (n + 1) \ln(n + 1) - n

so $\ln n! = n \ln n - n + \mathcal O(\ln n)$, and $n!$ outgrows every $c^n$: in $n!/c^n = \prod_k (k / c)$ each factor with $k > 2c$ exceeds 2.

::: table num
| Jobs $n$ | $n!$ | At $10^9$ orders per second | $n\,2^n$ | $n^2\,2^n$ |
|---|---|---|---|---|
| 4 | 24 | instant | 64 | 256 |
| 10 | 3,628,800 | 3.63 ms | 10,240 | 102,400 |
| 15 | 1.3 × 10¹² | 21.8 min | 491,520 | 7.4 × 10⁶ |
| 20 | 2.4 × 10¹⁸ | 77.1 years | 2.1 × 10⁷ | 4.2 × 10⁸ |
| 60 | 8.3 × 10⁸¹ | 2.6 × 10⁶⁵ years | 6.9 × 10¹⁹ | 4.2 × 10²¹ |
:::

A simulated day of this course has 60 jobs; brute force stops being practical between 13 and 15 (6.23 s and 21.8 min at that speed).

**Dynamic programming over subsets.** Without changeovers, the jobs of a set $S$ scheduled first occupy $[0, p(S)]$ whatever their order, $p(S) = \sum_{i \in S} p_i$, so the last of them completes at $p(S)$; and the best schedule of $S$ with $j$ last is the best schedule of $S \setminus \{j\}$ followed by $j$. With $F(S)$ the least total tardiness of $S$ scheduled first,

$$F(\emptyset) = 0, \qquad F(S) = \min_{j \in S} \Big[ F(S \setminus \{j\}) + \big(p(S) - d_j\big)^+ \Big], \qquad \text{optimum} = F(\mathcal J) .$$
%narrow F(S) = \min_{j \in S} \big[ F(S \setminus \{j\}) + (p(S) - d_j)^+ \big], \quad F(\emptyset) = 0

**By hand on X, Y, Z of Part 5** ($p = 10, 20, 30$; $d = 30, 10, 20$), smallest sets first; each entry tries every job of $S$ as the last one:

::: table
| Set $S$ | $p(S)$ | Last job $j$: $F(S \setminus \{j\}) + (p(S) - d_j)^+$ | $F(S)$ |
|---|---|---|---|
| X | 10 | X: 0 + 0 | 0 |
| Y | 20 | Y: 0 + 10 | 10 |
| Z | 30 | Z: 0 + 10 | 10 |
| X, Y | 30 | X: 10 + 0; Y: 0 + 20 | 10 (Y X) |
| X, Z | 40 | X: 10 + 10; Z: 0 + 20 | 20 (a tie) |
| Y, Z | 50 | Y: 10 + 40; Z: 10 + 30 | 40 (Y Z) |
| X, Y, Z | 60 | X: 40 + 30; Y: 20 + 50; Z: 10 + 40 | 50 (Y X Z) |
:::

The optimum 50 ends with Z after the best order of X and Y, which is Y X: the table recovers Y X Z from 12 terms, where listing the 6 orders costs 18.

That is $2^n$ sets with at most $n$ choices each, $\mathcal O(n\, 2^n)$: 21 million steps for 20 jobs instead of $2.4 \times 10^{18}$. It agrees with brute force on all 300 instances without changeovers.

**With changeovers the state must say more.** The finish time of $S$ now depends on its order and its last job, so Held and Karp [[ref:6]] use the state $(S, j)$: with $G(S, j)$ the least time to process $S$ ending with $j$,

$$G(\{j\}, j) = s_{\circ j} + p_j, \qquad G(S, j) = \min_{i \in S \setminus \{j\}} \big[ G(S \setminus \{j\}, i) + s_{ij} \big] + p_j ,$$
%narrow G(S, j) = \min_{i \in S \setminus \{j\}} [ G(S \setminus \{j\}, i) + s_{ij} ] + p_j

and $C_{\max}^* = \min_j G(\mathcal J, j)$, in $\mathcal O(n^2 2^n)$: $4.2 \times 10^8$ steps for 20 jobs, $4.2 \times 10^{21}$ for 60. This is exact for the makespan. For total tardiness with changeovers even $(S, j)$ is not enough: two partial orders of the same set ending with the same job can trade tardiness so far against finish time, and the less tardy one may finish later and cost more afterwards. In Exercise 5, the state (jobs 0, 1, 3; last 1) is reached by 3, 0, 1 (1 min late, done at 26) and by 0, 3, 1 (on time, done at 35); keeping only the second makes job 2, due at 35, finish at 40. Keeping only the least tardiness per $(S, j)$ returns a wrong optimum on 37 of the 300 six-order instances with changeovers; the exact version keeps every (finish time, tardiness) pair that no other pair beats on both. The lesson returns in chapter [[d01#bellman]]: **a recursion is exact only if its state holds everything the future cost depends on.**

**Branch and bound** grows sequences as a tree of prefixes and drops a prefix when a *lower bound* on its completions is no better than the best sequence found; the Part 7 widget uses the crudest bound, the prefix's own tardiness. How a solver searches and proves optimality is chapter [[c02#bnb]].

## How the repository's rules order a queue {#code}

The four rules of the course are four key functions and one `min`.

::: code jobshop/rules.py:16-39
Each rule maps job `j` waiting at machine `m` to a tuple, and `pick` returns the job of `m.queue` with the smallest. Tuples compare entry by entry, so later entries are tie-breaks, ending with `j.idx`: no two jobs tie and runs are reproducible. `_fifo` uses `j.queued_at`, when the job joined *this machine's* queue; `_spt` uses `ws.proc(j.family, j.op, m.idx)`, the time of the current operation *on this machine* (it differs between machines in the shop of [[a03]]); `_edd` uses the due date. `_sst` uses `ws.setup_time(m.idx, m.last_family, j.family)` and then the due date. It reads `m.last_family`, which changes after every job: the dynamic rule, the nearest neighbour of Part 7. A decision scans the queue once; a simulated day of 60 jobs under SST makes 240 of them, one per operation, on queues of at most 3 jobs.
:::

On the paint queue `pick` returns exactly the hero's sequences (Exercise 4 builds the stub `shop`); the hero uses the repository's tie-break, the due date, so at a 0-minute changeover SST is B, A, D, C. Chapter [[b02]] shows the controller around `pick`.

## Common pitfalls {#pitfalls}

1. **"SPT is optimal, so use SPT."** Only for $\sum C_j$ on one machine with every job present and no changeovers. With release dates $r_j$ (a job cannot start before it arrives), $1 \mid r_j \mid \sum C_j$ is already NP-hard in the strong sense [[ref:1]].
2. **"EDD minimises total tardiness."** It minimises the *worst* lateness. On X, Y, Z it scores 70, worse than SPT's 60, against an optimum of 50.
3. **"NP-hard means it cannot be solved."** It means no method is known that is fast on *every* instance. The paint machine is solved by listing 24 orders, and chapters [[c01]] to [[c03]] model, solve with a proven gap, and re-plan snapshots of the workshop.
4. **"Shortest setup first minimises changeovers."** It is greedy: 19 min on machine 3 where 15 suffice. And changeovers are not the objective: on the paint machine A, B, D, C has one more than A, C, B, D and is less late.
5. **"Computers are fast; try every order."** 20 jobs take 77 years at a billion orders per second; dynamic programming still grows like $2^n$.

## Check your understanding {#check}

:::: qa
Try to answer each question before opening it.

::: q 1. Why is the order of the jobs all there is to decide?
Closing idle gaps never increases a completion time, so for a regular objective some optimal schedule has no idle time and is fixed by its order.
:::
::: q 2. Which completion times change when two adjacent jobs are swapped?
Only theirs. Jobs before are untouched; without changeovers, jobs after start at $t + p_i + p_j$ either way.
:::
::: q 3. Why does $t$ cancel for $\sum C_j$ but not for $\sum T_j$?
For $\sum C_j$ both orders contain $2t$ and differ by $p_i - p_j$. For $\sum T_j$ each term is clipped at zero at a point that depends on $t$, so the difference can change sign with $t$.
:::
::: q 4. How can EDD be optimal for the worst lateness while ignoring processing times?
Swapping a pair out of due-date order never raises the larger of their latenesses: afterwards both are at most $t + p_i + p_j - d_j$, the old lateness of the more urgent job. The times appear on both sides.
:::
::: q 5. What does the NP-hardness of $1 \Vert \sum T_j$ say about dispatching rules?
That no rule computable in polynomial time, as every dispatching rule is, is optimal on every instance unless P = NP.
:::
::: q 6. Why is $1 \mid s_{ij} \mid C_{\max}$ a travelling-salesman problem?
$C_{\max} = \sum p_j$ plus the changeovers along the sequence: a constant plus the length of a path from the initial state through every job, asymmetric because $s_{ij} \ne s_{ji}$.
:::
::: q 7. Why does the subset recursion work for $1 \Vert \sum T_j$ but not with changeovers?
Without changeovers the jobs of $S$ finish at $p(S)$ in any order, so the cost of putting $j$ last depends on $S$ only. With changeovers the finish time depends on the order, so the state must also carry it.
:::

Without changeovers, give order D weight 2 and the others weight 1. Find the optimal order for $\sum w_j C_j$ and its value, and compare with SPT.

Compute $p_j / w_j$; the swap difference is $w_j p_i - w_i p_j$.

SPT's B, C, A, D gives $10 + 25 + 45 + 2 \cdot 70 = 220$. Swapping C before D would change the sum by $w_D p_C - w_C p_D = 2 \cdot 15 - 25 = 5 > 0$, so D goes first. All 24 orders confirm 200 as the minimum.
:::

:::: exercise Agreeable due dates
Prove: if $p_i \le p_j$ implies $d_i \le d_j$ for all jobs, the order that is both SPT and EDD minimises $\sum T_j$.
::: hint
Use $a^+ + b^+ = \max(0, a, b, a + b)$ on an adjacent pair.
:::
::: solution
For a pair with $p_i \le p_j$, $d_i \le d_j$, starting at $t$: let $a = t + p_i - d_i$, $b = t + p_i + p_j - d_j$ ($i$ first) and $c = t + p_j - d_j$, $e = t + p_i + p_j - d_i$ ($j$ first). Then $e \ge a$, $e \ge b$ (as $d_j \ge d_i$), and $(c + e) - (a + b) = p_j - p_i \ge 0$, so
$$a^+ + b^+ = \max(0, a, b, a + b) \le \max(0, e, c + e) \le c^+ + e^+ .$$
Putting $i$ first is never worse. From an optimal sequence, swap out-of-order neighbours one at a time; the total never increases and the sequence ends sorted, so the sorted order is optimal.
:::
::::
:::: exercise Zero tardiness is a travelling salesman
With changeovers and a common due date $D$ for every job, show that deciding whether some sequence has $\sum T_j = 0$ is deciding whether the salesman of Part 7 has a path of length at most $D - \sum_j p_j$. Conclude that $1 \mid s_{ij} \mid \sum T_j$ is NP-hard in the strong sense.
::: hint
With a common due date, $\sum T_j = 0$ holds exactly when the last job is on time.
:::
::: solution
Since $C_j \le C_{\max}$, $\sum T_j = 0$ if and only if $C_{\max} \le D$, that is (Part 7) if and only if the changeover path is at most $D - \sum_j p_j$ long. That question is NP-complete even with distances 0 and 1: given a directed graph on $n$ vertices, take one job per vertex with $p_j = 1$, $s_{\circ j} = 0$, $s_{ij} = 0$ for an arc and 1 otherwise, and $D = n$. Then $\sum T_j = 0$ exactly when the graph has a path through every vertex once (a Hamiltonian path), a classic NP-complete question [[ref:7]]. All numbers are at most $n$, hence NP-hardness in the strong sense.
:::

Call `jobshop.rules.pick` on the four paint orders with stub objects, reproduce A B C D, B C A D, B A D C and A C B D, then set the changeover to 0 and explain SST's sequence.
::: hint
`pick` reads the machine's `queue`, `idx`, `last_family`, the jobs' `idx`, `family`, `op`, `due`, `queued_at`, and `shop.ws.proc`, `shop.ws.setup_time`; give each order its own `op`.

```python
from types import SimpleNamespace as NS
from jobshop import rules

orders = [("A", 0, 20, 30), ("B", 1, 10, 25), ("C", 0, 15, 70), ("D", 1, 25, 60)]   # name, family, p, due
def sequence(rule, setup=10):
    # op is reused as the order's index so that proc can find its painting time;
    # in the shop, op is the operation number (chapter A3)
    ws = NS(proc=lambda f, op, m: orders[op][2],
            setup_time=lambda m, prev, f: 0 if prev is None or prev == f else setup)
    m = NS(idx=0, last_family=0, queue=[NS(idx=k, op=k, family=f, due=d, queued_at=k, name=n)
                                         for k, (n, f, p, d) in enumerate(orders)])
    out = []
    while m.queue:
        j = rules.pick(rule, NS(ws=ws), m)
        out.append(j.name); m.queue.remove(j); m.last_family = j.family
    return "".join(out)
```

:::: exercise Dynamic programming over subsets
Implement $F(S)$ of Part 8 with bitmasks and check it against brute force. Then try the state $(S, j)$ with changeovers, keeping the least tardiness, and find an instance where it is wrong.
::: hint
Compute $p(S)$ from $p(S$ minus its lowest bit$)$. For the second part use six jobs, `make_workshop().setup[0]` and `itertools.permutations`.

::: solution
```python
from itertools import permutations
def subset_dp(p, d):
    n = len(p); F = [0] + [float("inf")] * ((1 << n) - 1); P = [0] * (1 << n)
    for S in range(1, 1 << n):
        low = (S & -S).bit_length() - 1
        P[S] = P[S ^ (1 << low)] + p[low]
        F[S] = min(F[S ^ (1 << j)] + max(0, P[S] - d[j]) for j in range(n) if S >> j & 1)
    return F[-1]
def brute(p, d):
    best = float("inf")
    for seq in permutations(range(len(p))):
        t = s = 0
        for j in seq: t += p[j]; s += max(0, t - d[j])
        best = min(best, s)
    return best
print(subset_dp([10, 20, 30], [30, 10, 20]), brute([10, 20, 30], [30, 10, 20]))   # 50 50: X, Y, Z

def naive_state_dp(p, fam, d, s):        # state (set, last job), keeps only the least tardiness
    n = len(p); G = {(1 << j, j): (max(0, p[j] - d[j]), p[j]) for j in range(n)}
    for S in sorted(range(1, 1 << n), key=lambda x: bin(x).count("1")):
        for j in range(n):
            if (S, j) not in G: continue
            T, t = G[(S, j)]
            for k in range(n):
                if S >> k & 1: continue
                tk = t + s[fam[j]][fam[k]] + p[k]; cand = (T + max(0, tk - d[k]), tk)
                if (S | 1 << k, k) not in G or cand < G[(S | 1 << k, k)]: G[(S | 1 << k, k)] = cand
    return min(G[((1 << n) - 1, j)][0] for j in range(n))
```

## The chapter on one page {#summary}

::: steps
- **The paint machine**: FIFO 55, SPT 75, EDD 85, SST 50 min of total tardiness; the best of the 24 orders, A B D C, 40.
- **Exchange**: if the sign of a neighbour swap depends on the two jobs alone, sorting is optimal. **Smith**: SPT minimises $\sum C_j = \sum_k (n - k + 1) p_{[k]}$; the ratio $p_j / w_j$ minimises $\sum w_j C_j$. **Jackson**: EDD minimises $L_{\max}$ and $T_{\max}$.
- **Total tardiness**: the swap depends on the start time; X, Y, Z gives SPT 60, EDD 70, optimum 50. Rules are guaranteed optimal only at the edges.
- **NP-hard** (Du and Leung): no polynomial rule is always optimal unless P = NP; pseudo-polynomial by Lawler.
- **Changeovers**: $1 \mid s_{ij} \mid C_{\max}$ is an asymmetric travelling salesman and SST its nearest neighbour; on random six-order instances the best of the four rules is optimal 20.0 % of the time.
- **Counting**: $20! = 2.4 \times 10^{18}$; subsets in $\mathcal O(n\, 2^n)$, Held–Karp in $\mathcal O(n^2 2^n)$; with changeovers and tardiness the state must carry the time.
:::
