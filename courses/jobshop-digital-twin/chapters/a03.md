## A workshop in plain words {#idea}

The paint machine of chapters [[a01]] and [[a02]] had one decision: the order of the orders. In a real workshop every order goes through several machines, one step after another. In the course's workshop an order of family 0 has four steps, and each can be done on more than one machine: step 0 on machine 1 in 6 minutes or on machine 2 in 10. So the workshop decides two things for every step of every order:

- **where**: which of the machines able to do this step will do it. Machine 1 is faster, but if it already has a long queue, machine 2 may finish sooner;
- **when**: in which order each machine works through the steps sent to it. That is the paint-machine question on five machines at once, except that a step cannot start before the previous step of the same order has finished elsewhere and the order has been carried over.

The machines are coupled through the orders, which makes a workshop harder than five paint machines side by side: putting an order first on machine 1 makes it arrive early at machine 2, which changes what machine 2 should do.

A small instance shows everything. Three jobs, three machines, each job visiting each machine once in its own order:

::: table num
| Job | Step 0 | Step 1 | Step 2 | Total |
|---|---|---|---|---|
| J0 | M0, 2 min | M1, 7 min | M2, 7 min | 16 |
| J1 | M1, 7 min | M2, 4 min | M0, 5 min | 16 |
| J2 | M2, 2 min | M0, 6 min | M1, 2 min | 10 |
:::

Machine M1 has $7 + 7 + 2 = 16$ minutes of work, the others 13 each, and no job takes longer than 16 minutes, so no schedule can finish before minute 16. The best finishes at 21, and exactly one way of ordering the machines achieves it: find it in the hero; the chapter explains why every other choice is longer or impossible.

::: define What is a flexible job shop?
**In plain words:** a workshop where each order follows its own route of steps through the machines, and a step may be done on any of a few machines, at a speed that depends on the machine. Deciding means choosing a machine for every step and an order for every machine.

**More precisely:** a set of jobs $\mathcal J$; job $j$ consists of operations $(j, 0), \dots, (j, K_j - 1)$ that must be done in this order; operation $(j,k)$ can be processed by any machine of a set $\mathcal M_{jk} \subseteq \mathcal M$, taking $p_{jkm}$ minutes on machine $m$, without interruption; a machine does one operation at a time.

- Operation :: One step of one job, $(j, k)$: what the code calls `(job, op)`.
- Routing :: The sequence of operations of a job, with their eligible machines; in the workshop it depends only on the job's family, so `ws.alternatives(f, k)` returns $\mathcal M_{jk}$ with its times.
- Eligible machines $\mathcal M_{jk}$ :: The machines able to process $(j,k)$: 1 to 3 of them in the course's workshop.
- Assignment $\mu$ :: The choice of one machine $\mu_{jk} \in \mathcal M_{jk}$ for each operation; also called routing decision.
- Sequence :: The order in which a machine processes the operations assigned to it.
- Classical job shop :: The special case $|\mathcal M_{jk}| = 1$: only the sequences are to be chosen. The 3 × 3 instance is one.
- Flow shop :: The special case where every job visits the machines in the same order.
:::

## The constraints, written as mathematics {#constraints}

A schedule assigns to each operation a machine $\mu_{jk}$, a start $S_{jk}$ and an end $E_{jk}$. Its measures are those of chapter [[a01]]: the completion $C_j = E_{j,K_j-1}$, the tardiness $T_j = \max(0, C_j - d_j)$, the makespan $C_{\max} = \max_j C_j$. Five kinds of constraints make a schedule valid. Each is first a sentence, then a formula.

**1. Assignment and duration.** Every operation goes to exactly one eligible machine and runs there without interruption. With binary variables $x_{jkm} = 1$ when $(j,k)$ runs on $m$,

$$\sum_{m \in \mathcal M_{jk}} x_{jkm} = 1, \qquad E_{jk} = S_{jk} + \sum_{m \in \mathcal M_{jk}} p_{jkm}\, x_{jkm}, \qquad x_{jkm} \in \{0, 1\}.$$
%narrow \textstyle\sum_{m} x_{jkm} = 1, \quad E_{jk} = S_{jk} + \sum_{m} p_{jkm} x_{jkm}

Equivalently $\mu_{jk}$ is the machine with $x_{jkm} = 1$ and $E_{jk} = S_{jk} + p_{jk\mu_{jk}}$. Breakdowns, which do interrupt operations, are left to the simulator of chapter [[b01]]; the static problem of this chapter has none.

**2. Release and the first move.** Job $j$ arrives at the load station at its release time $r_j$, and a cart carries it to the machine of its first operation. Write $\operatorname{st}(m) = m + 1$ for the station of machine $m$ (station 0 is the load station) and $\tau(a, b)$ for the travel time between stations, as in [notation](notation.html#objects). The job reaches its first machine at

$$A_{j0} = r_j + \tau\big(0, \operatorname{st}(\mu_{j0})\big),$$

and $S_{j0} \ge A_{j0}$, plus a changeover if one is needed (constraint 5).

**3. Precedence with transport.** Step $k + 1$ cannot start before step $k$ has ended and the job has been carried from one machine to the next:

$$A_{j,k+1} = E_{jk} + \tau\big(\operatorname{st}(\mu_{jk}), \operatorname{st}(\mu_{j,k+1})\big), \qquad S_{j,k+1} \ge A_{j,k+1}.$$
%narrow A_{j,k+1} = E_{jk} + \tau(\operatorname{st}(\mu_{jk}), \operatorname{st}(\mu_{j,k+1})), \quad S_{j,k+1} \ge A_{j,k+1}

$A_{jk}$ is the *arrival* of the job at the machine of operation $(j,k)$. Since $\tau(a, a) = 0$, a job that stays on the same machine has no transport. Note that the travel time depends on *both* machines chosen: transport couples the assignment of two consecutive operations.

**4. Capacity.** A machine processes one operation at a time. For any two operations $u$ and $v$ of different jobs assigned to the same machine, one of them ends before the other starts:

$$\mu_u = \mu_v \quad \Longrightarrow \quad E_u \le S_v \ \ \text{or} \ \ E_v \le S_u .$$

The word "or" is the whole difficulty of scheduling. Constraints 1 to 3 are linear once the assignment is fixed; constraint 4 is a *disjunction*, one for every pair of operations of different jobs on $m$ (at most $\binom{n_m}{2}$ with $n_m$ operations on $m$). Two operations of the same job need none: precedence keeps them apart.

**5. Sequence-dependent changeovers.** When the machine passes from a job of family $f$ to a job of family $g$ it must be re-equipped for $s_m(f, g)$ minutes, zero if $g = f$, and the changeover can only start once the machine is free *and* the job has arrived (the convention of the repository's simulator and of its CP-SAT model). If $v$ directly follows $u$ on machine $m$,

$$S_v \ge \max(E_u, A_v) + s_m\big(f(u), f(v)\big),$$

where $f(u)$ is the family of the job of $u$. A machine that has run nothing yet needs no changeover: for the first operation on a machine $S_v \ge A_v$. The maximum splits into two linear inequalities, $S_v \ge E_u + s_m(f(u), f(v))$ and $S_v \ge A_v + s_m(f(u), f(v))$. The changeover belongs to a pair of consecutive operations, not to one operation, which is why it cannot be folded into $p_{jkm}$.

**A worked case, with the workshop's numbers.** A job of family 0 is released at $r_j = 100$; its step 0 goes to machine 1, 6 minutes. The cart ride from the load station is $\tau(0, \operatorname{st}(1)) = 2$, so constraint 2 gives $A = 102$. Machine 1 last ran a job of family 2 and is free from minute 98; $s_1(2, 0) = 10$. Constraint 5 gives $S = \max(98, 102) + 10 = 112$ and $E = 118$: the machine sits idle from 98 to 102 waiting for the job, then is re-equipped. Had machine 1 been busy until 105, the job would wait instead: $S = \max(105, 102) + 10 = 115$, $E = 121$.

**The objective.** The makespan, the total tardiness and the planner's objective $10 \sum_j T_j + \sum_j C_j$ are all *regular* measures (chapter [[a01#regular]]): they never improve when a completion time increases (they are non-decreasing in every $C_j$). Part 4 turns this into a theorem: the decisions are the assignment and the sequences, and the times follow.

::: define What is a disjunctive constraint?
**In plain words:** "this or that": one of two operations must go first, and we have not said which.

**More precisely:** a constraint that is the logical "or" of linear inequalities, as constraint 4; chapter [[c01#nooverlap]] writes it for a solver.

- Static problem :: All jobs, their releases and the shop known in advance, as in this chapter. The course's shop is dynamic; chapters [[b01]] to [[c03]] deal with that.
:::

## The disjunctive graph {#graph}

Strip the problem to its core: the classical job shop with makespan, written $Jm \mid\mid C_{\max}$ in the three-field notation of chapter [[a01#notation]]. Every operation has one machine, there are no changeovers, no transport, and all jobs are available at time 0. Bernard Roy and Bernard Sussmann [[ref:1]] drew it as a graph, and that drawing is still how the job shop is usually taught.

::: define What is a disjunctive graph?
**In plain words:** a box per step; a solid arrow means "must finish first"; a dashed line between two boxes on the same machine means "one of them first, you choose".

**More precisely:** $G = (V, C, D)$, with

* **nodes** $V$: one node per operation, plus two dummy nodes, $\alpha$ ("the start of the day") and $\omega$ ("everything is done");
* **conjunctive arcs** $C$: the routes, $(j, k) \to (j, k + 1)$ for every job and step, plus $\alpha \to (j, 0)$ and $(j, K_j - 1) \to \omega$. They are fixed by the data;
* **disjunctive pairs** $D$: for every machine, a pair $\{u, v\}$ for every two operations of different jobs on that machine. A pair is an arc whose direction is not decided yet.

- Arc weight $w(u, v)$ :: The weight of the arc $u \to v$: here $p_u$, the processing time of its tail, and 0 for the arcs leaving $\alpha$. The arc is read "$v$ cannot start before $u$ has ended": $S_v \ge S_u + w(u, v)$.
:::

The smallest example has two jobs on two machines with opposite routes: J0 does M0 for 3 minutes then M1 for 2, J1 does M1 for 4 then M0 for 1. Four boxes, two solid arrows $J0.0 \to J0.1$ and $J1.0 \to J1.1$, and two dashed lines, $\{J0.0, J1.1\}$ on M0 and $\{J0.1, J1.0\}$ on M1. Two pairs, so $2^2 = 4$ ways to orient them; putting J1.1 first on M0 *and* J0.1 first on M1 closes a circle of arrows $J0.0 \to J0.1 \to J1.0 \to J1.1 \to J0.0$, and exercise 1 asks for the makespans of the three others.

In the hero, each job's three operations follow its route along solid arrows; each machine has three operations, one per job, hence $\binom{3}{2} = 3$ pairs per machine and 9 dashed lines in all: $|D| = 9$.

::: define What is a selection?
**In plain words:** for each pair of operations that compete for a machine, a decision of which goes first. Making all these decisions is the scheduling.

**More precisely:** a selection $\sigma$ picks one direction, $u \to v$ or $v \to u$, for some of the pairs of $D$; it is *complete* when every pair is oriented. The selection turns $G$ into the directed graph $G(\sigma) = (V, C \cup \sigma)$.

- Orientation :: The direction given to one pair; $2^{|D|}$ complete selections in all.
- Acyclic :: A directed graph with no directed cycle, that is, no way to follow arrows and come back to where you started.
- Path length :: The sum of the weights of its arcs. $\ell(u, v)$ denotes the length of a longest path from $u$ to $v$ in $G(\sigma)$.
- Critical path :: A longest path from $\alpha$ to $\omega$; its operations run back to back, with no slack.
:::

**Counting selections.** The 9 pairs of the instance can be oriented in $2^9 = 512$ ways. Many of them are absurd before any timing is computed: if on machine M0 you choose $J0.0 \to J1.2$, $J1.2 \to J2.1$ and $J2.1 \to J0.0$, you have asked each of three operations to come before the next, round in a circle. A selection makes sense on one machine only if it is a *total order* of that machine's operations, and $n_m$ operations have $n_m!$ orders, so at most $\prod_m n_m! = 3!^3 = 216$ of the 512 selections survive the machines one at a time. The routes remove more: of those 216, only **64** are acyclic, as the numbers script finds by trying all of them.

**A cycle across machines.** Two orientations are enough to make a selection impossible. Put J1.2 before J0.0 on M0, and J0.1 before J1.0 on M1. Then

$$J0.0 \to J0.1 \to J1.0 \to J1.1 \to J1.2 \to J0.0,$$

two route arcs of J0, the M1 arc, two route arcs of J1, and the M0 arc, closing a circle. In words: J1 must finish its last step on M0 before J0 starts its first step there, but J0's second step must be done on M1 before J1's first step there. Each job waits for the other. The numbers script counts 6 such cycle-closing pairs of orientations; the hero shows one in red as soon as you create it.

## Cycle means impossible, longest path means makespan {#longest}

Two facts make the graph useful: every impossible selection is visible as a cycle, and every possible one *is* a schedule whose length is a longest path. Both are due to Roy and Sussmann [[ref:1]]; Pinedo's book [[ref:4]] gives them in its chapter on deterministic job shops.

::: callout
**Theorem.** Let $\sigma$ be a complete selection of a job shop whose processing times are all positive.

1. If $G(\sigma)$ has a directed cycle, no schedule processes the operations in the orders $\sigma$ prescribes.
2. If $G(\sigma)$ is acyclic, setting $S_v = \ell(\alpha, v)$ for every operation $v$ gives a valid schedule; every schedule that follows $\sigma$ has $S_v \ge \ell(\alpha, v)$; and its makespan is $\ell(\alpha, \omega)$.
:::

**Proof of 1.** A schedule follows $\sigma$ when every arc $u \to v$ of $G(\sigma)$ holds as $S_v \ge S_u + w(u, v)$: route arcs by precedence, oriented pairs by the order chosen on the machine. Suppose a cycle $u_1 \to u_2 \to \dots \to u_q \to u_1$. Write the inequality of each of its arcs,

$$S_{u_2} \ge S_{u_1} + p_{u_1}, \quad S_{u_3} \ge S_{u_2} + p_{u_2}, \quad \dots, \quad S_{u_1} \ge S_{u_q} + p_{u_q},$$

and add them. Every $S_{u_i}$ appears once on each side and cancels, leaving $0 \ge p_{u_1} + \dots + p_{u_q}$. The right side is positive, so no start times satisfy all the inequalities. $\square$

**Proof of 2.** First, $\ell(\alpha, v)$ is well defined: an acyclic graph has finitely many paths from $\alpha$ to $v$, and at least one, since every operation is reached from $\alpha$ along its job's route.

*It is a lower bound.* Take any schedule that follows $\sigma$ and any path $\alpha = v_0 \to v_1 \to \dots \to v_q = v$. By the arc inequalities $S_{v_1} \ge 0$ and $S_{v_{i}} \ge S_{v_{i-1}} + w(v_{i-1}, v_i)$; adding them gives $S_v \ge$ the length of the path. This holds for every path, hence for the longest: $S_v \ge \ell(\alpha, v)$.

*It is feasible.* For an arc $u \to v$, a longest path to $u$ followed by the arc is a path to $v$, so $\ell(\alpha, v) \ge \ell(\alpha, u) + w(u, v)$: setting $S_v = \ell(\alpha, v)$ satisfies every arc inequality. The route arcs give precedence. Now take two operations $u$ and $v$ on the same machine. If they belong to different jobs, their pair is oriented, say $u \to v$, and the arc gives $S_v \ge S_u + p_u$. If they belong to the same job, say $u$ earlier in its route, the route arcs form a path from $u$ to $v$ whose first arc weighs $p_u$, so again $S_v \ge S_u + p_u$. Either way one ends before the other starts. All constraints of $Jm \mid\mid C_{\max}$ hold.

*The makespan.* The arcs into $\omega$ come from the last operation of each job with weight $p$, so $\ell(\alpha, \omega) = \max_j \big(\ell(\alpha, (j, K_j - 1)) + p_{j, K_j - 1}\big) = \max_j C_j = C_{\max}$. $\square$

**What the theorem buys.** Three consequences, each used in the rest of the course.

*Every valid schedule comes from an acyclic selection.* Take any schedule and orient each pair by the order of the start times on the machine. Every arc then goes from an operation to one that starts strictly later ($S_v \ge S_u + p_u > S_u$), and a walk along arcs on which the start time strictly increases cannot come back to where it began. So the selection is acyclic.

*The longest-path schedule is the best for its selection.* By part 2 it starts every operation as early as the selection allows, so for a regular measure nothing following the same selection does better. It is the **semi-active** schedule of chapter [[a01#regular]]: no operation can start earlier without changing an order on a machine. Hence

$$\min_{\text{schedules}} C_{\max} \;=\; \min_{\sigma \text{ complete and acyclic}} \; \ell_{G(\sigma)}(\alpha, \omega),$$

and the same holds with any regular measure in place of $C_{\max}$: the search is over orders, a finite set; the times are computed.

*Only the critical path matters for the makespan.* A critical path stays in the graph when a pair off that path is reversed, so to shorten a schedule you must change an arc on a longest path. This is the idea behind *local search* for the job shop (improve a schedule by small changes, its *neighbourhood*, here the reversal of a critical arc), described in Pinedo's book [[ref:4]].

**Computing it.** Visit the nodes in an order where every arc goes forward (a *topological order*) and set each start to the largest "start of a predecessor plus the arc's weight". If some nodes are never visited, the subgraph they form contains a cycle (each has an unvisited predecessor; walk backwards until a node repeats). This one pass, Kahn's procedure, runs in time proportional to the number of nodes plus arcs; the hero and the numbers script both use it.

**The instance, solved by hand.** The machine loads give a lower bound of 16, yet the optimum is 21. Why? Look at the one pair on M1 between J0.1 and J1.0, both 7 minutes. Either way round, the graph contains a long path:

- if J1.0 goes first, $\alpha \to J1.0 \to J0.1 \to J0.2 \to \omega$ has length $7 + 7 + 7 = 21$;
- if J0.1 goes first, $\alpha \to J0.0 \to J0.1 \to J1.0 \to J1.1 \to J1.2 \to \omega$ has length $2 + 7 + 7 + 4 + 5 = 25$.

So every acyclic selection has $C_{\max} \ge 21$, whatever the other eight pairs. And 21 is reached: with the orders M0: J0.0, J2.1, J1.2; M1: J1.0, J0.1, J2.2; M2: J2.0, J1.1, J0.2, the longest-path schedule is

::: table num
| Machine | First | Second | Third |
|---|---|---|---|
| M0 | J0.0 [0, 2) | J2.1 [2, 8) | J1.2 [11, 16) |
| M1 | J1.0 [0, 7) | J0.1 [7, 14) | J2.2 [14, 16) |
| M2 | J2.0 [0, 2) | J1.1 [7, 11) | J0.2 [14, 21) |
:::

with critical path J1.0 → J0.1 → J0.2. The two arguments together prove it optimal, without enumeration. The enumeration agrees and adds that this optimal selection is unique: the 64 acyclic selections have makespans from 21 to 42, with 21 reached once and 24 six times. "Job 0 first everywhere, then job 1, then job 2" gives 33 minutes, the reverse priority 42. Press *J0, J1, J2 first* in the hero, then flip pairs on its critical path and watch the length drop.

**How hard is the general problem?** The classical job shop with makespan is NP-hard already with three machines even when every job visits the machines in the same order (the flow shop $F3 \mid\mid C_{\max}$), and with two machines once a job may visit a machine twice; this chapter only cites these results, which the survey of Graham, Lawler, Lenstra and Rinnooy Kan [[ref:3]] collects. No known algorithm avoids, in the worst case, a search that grows exponentially, which is why chapter [[c02]] is about how a solver searches cleverly.

## Assignment first: the flexible job shop {#flexible}

In the course's workshop an operation has 1 to 3 eligible machines. Brandimarte [[ref:2]] was among the first to treat this *flexible* job shop, splitting it into a routing problem, which machine for each operation, and the job shop that results, and attacking both with tabu search (a local search that forbids undoing recent moves); his instances are still used to compare methods.

**Formally**, a schedule is now a pair $(\mu, \sigma)$: an assignment $\mu$, one machine $\mu_{jk} \in \mathcal M_{jk}$ per operation, and a selection $\sigma$ of the job shop that $\mu$ creates. Fixing $\mu$ fixes the processing times $p_{jk\mu_{jk}}$ and decides *which* pairs exist: two operations of different jobs compete only if they were sent to the same machine. So the graph keeps its nodes and routes, but its weights and its disjunctive pairs change with the assignment. With $\mu$ ranging over all assignments, one eligible machine per operation,

$$\min_{(\mu, \sigma)} C_{\max} \;=\; \min_{\mu} \ \ \min_{\sigma \text{ acyclic for } \mu} \ell_{G_\mu(\sigma)}(\alpha, \omega).$$
%narrow \min_{\mu} \ \min_{\sigma \text{ acyclic for } \mu} \ell_{G_\mu(\sigma)}(\alpha, \omega)

The number of assignments is the product of the sizes of the eligible sets, $\prod_{j,k} |\mathcal M_{jk}|$, and each brings its own family of selections. The flexible job shop contains the classical one (take every $|\mathcal M_{jk}| = 1$), so it is at least as hard.

**The instance, made flexible.** Give three operations a second machine: J0.1 can also run on M2 in 6 minutes instead of 7 on M1, J1.0 too, and J2.2 can run on M0 in 3 minutes instead of 2 on M1. That is $2^3 = 8$ assignments. The widget below tries all of them, and for each one every order on every machine, 5,832 combinations in all.

## Where changeovers and transport enter the graph {#extras}

The theorem of Part 4 was proved for the plain job shop. The course's workshop adds release times, transport and changeovers. All three fit into the same graph as arc weights, and the theorem survives, because its proofs used only one thing: each arc is an inequality "start of the head $\ge$ start of the tail + a positive weight".

**Release and transport** go on the route arcs. With an assignment fixed,

- the arc $\alpha \to (j, 0)$ weighs $r_j + \tau(0, \operatorname{st}(\mu_{j0}))$, the release plus the ride from the load station;
- the arc $(j, k) \to (j, k+1)$ weighs $p_{jk\mu_{jk}} + \tau(\operatorname{st}(\mu_{jk}), \operatorname{st}(\mu_{j,k+1}))$: processing, then the ride.

In the flexible problem the second weight depends on two assignment decisions, which is how the CP-SAT planner of chapter [[c01]] writes it (adding an allowance $\delta = 2$ min for an empty cart to come). The carts themselves are not in the graph: two carts serving all moves is a second capacity constraint that this model, like the repository's planner, leaves out; the simulator of chapter [[b01]] moves real carts.

**Changeovers** go on the disjunctive arcs, and on the route arc into the operation. Let $u'$ be the operation directly before $v = (j, k)$ on its machine $m = \mu_{jk}$.

- The arc $u \to v$ on machine $m$ weighs $p_u + s_m(f(u), f(v))$: the machine must finish $u$ and be re-equipped before $v$ starts.
- The changeover also waits for the job (constraint 5), so for $k \ge 1$ the route arc $(j, k-1) \to (j, k)$ weighs $p_{j,k-1,\mu_{j,k-1}} + \tau\big(\operatorname{st}(\mu_{j,k-1}), \operatorname{st}(\mu_{jk})\big) + s_m(f(u'), f(v))$, and for $k = 0$ the arc $\alpha \to (j, 0)$ weighs $r_j + \tau(0, \operatorname{st}(\mu_{j0})) + s_m(f(u'), f(v))$. The $s$ term is 0 when $v$ is first on its machine. Unlike every other weight so far, this one depends on the selection.

The weights are positive and the inequalities are still of the form $S_v \ge S_u + w$, so a cycle is still impossible and an acyclic selection still gives its earliest schedule by a longest path. In the hero's toy each job counts as its own family, so the changeover box means 1 minute whenever a machine switches job. Toggle the two boxes: with carts taking 1 minute between any two stations the optimum becomes 23, with 1-minute changeovers it becomes 23 too, and with both 25; in this instance the same selection stays optimal each time, which need not happen in general.

**A subtlety about non-consecutive pairs.** The graph has an arc for *every* ordered pair on a machine, but changeovers happen only between *directly consecutive* operations. If $u$, $v$, $w$ run in this order on $m$, the arc $u \to w$ demands $S_w \ge E_u + s_m(f(u), f(w))$, while the chain through $v$ already gives $S_w \ge E_u + s_m(f(u), f(v)) + p_v + s_m(f(v), f(w))$. The arc is implied, hence harmless, whenever the *weak triangle inequality*

$$s_m(f, h) \le s_m(f, g) + p_v + s_m(g, h) \qquad \text{for all families } f, g, h \text{ and operations } v \text{ of family } g \text{ on } m$$
%narrow s_m(f, h) \le s_m(f, g) + p_v + s_m(g, h)

holds; applying it repeatedly handles any number of operations between $u$ and $w$. The ordinary triangle inequality, without $p_v$, fails in the workshop in 4 of the 120 triples of distinct families (on machine 1, family 2 to family 0 takes 10 minutes directly, but $4 + 3 = 7$ via family 3), while the weak one always holds there: it is trivial when $g$ equals $f$ or $h$, and otherwise its right side is at least $3 + 6 + 3 = 12$, more than the largest changeover, 10. In general it can fail, which is one reason the repository's model uses a *circuit* that knows who directly follows whom, chapter [[c01#circuit]].

## The code behind it {#code}

The workshop is a frozen data class (an immutable record): the fixed part of the shop, identical in every run.

::: code jobshop/scenario.py:Workshop
`routings[f][k]` is a dictionary `{machine: minutes}`: its keys are $\mathcal M_{fk}$ and its values $p_{fkm}$. The routing depends only on the family, so the code indexes by `f` where the mathematics indexes by job $j$, with $f = f(j)$. `alternatives(f, op)` returns that dictionary, `proc(f, op, m)` one time, and `n_ops` gives $K_j$. `setup_time` implements $s_m(f, g)$ with the convention of constraint 5: `previous_family=None` means the machine has run nothing yet and needs no changeover. `station(m)` is $\operatorname{st}(m) = m + 1$, and `travel` is $\tau$, indexed by stations, with zeros on the diagonal so that staying on a machine costs nothing. `min_remaining_work(f, op)` sums the fastest times from step `op` to the end: from step 0 it is the fastest-route work $W_f$.
:::

The workshop itself is drawn once from a seeded generator.

::: code jobshop/scenario.py:make_workshop
The generator is seeded with `[seed, 0]`, a stream used for nothing else, so the workshop never changes when the scenarios do. Per family it draws 3 or 4 operations (all four got 4); per operation the number of eligible machines from `[1, 2, 2, 3]`, so 2 is twice as likely as 1 or 3 (the workshop has 2, 10 and 4); a base time from 8 to 24 minutes; and per machine the base time scaled by a factor in $[0.8, 1.3]$, which makes $p_{jkm}$ machine-dependent. Changeovers are integers from 3 to 10, drawn independently for every machine and ordered pair of families, hence asymmetric. The machines sit on distinct cells of a 4 × 3 grid, the load station at $(0, 1)$; a move costs 1 minute of handling plus half the Manhattan distance rounded up, `(d + 1) // 2`: 2 or 3 minutes here.
:::

## Common pitfalls {#pitfalls}

1. **"A job shop is several single machines."** The machines are coupled through the routes: an order on one machine moves arrivals on the others. The cycle of Part 3 involves two machines and could not be seen on either alone.
2. **"There are $2^{|D|}$ schedules."** Most selections are cyclic. On one machine only the $n_m!$ total orders can be acyclic, and the routes remove more: 512, then 216, then 64 on the small instance.
3. **"The start times are decisions."** For a regular measure they are not: once the assignment and the orders are fixed, the earliest schedule is a longest-path computation, and it is the best for those orders. The decisions are discrete.
4. **"The fastest machine is the best machine."** On the flexible instance the fastest assignment gives 25 minutes against 19 for the best; on the workshop it sends 77 operations to one machine and 15 to another. Load and queues matter more than speed.
5. **"A changeover is part of the processing time."** It depends on which job came directly before, so it lives on the arcs between operations, not in the nodes. Putting it on every pairwise arc is exact only under the weak triangle inequality of Part 6.
6. **"The longest path of a partial selection is the makespan."** It is a lower bound: orienting more pairs adds arcs and can only lengthen paths. The hero writes "≥" until all nine pairs are ordered. That lower bound is the first ingredient of the solvers of chapter [[c02#bnb]].

## Check your understanding {#check}

:::: qa
Try to answer each question before opening it.

::: q 1. What are the two decisions of a flexible job shop, and which one does a classical job shop lack?
The assignment, a machine $\mu_{jk} \in \mathcal M_{jk}$ for each operation, and the sequence of operations on each machine. A classical job shop has $|\mathcal M_{jk}| = 1$, so the assignment is given and only the sequences remain.
:::
::: q 2. Why is the capacity constraint not a linear inequality?
It says "$u$ ends before $v$ starts, or $v$ ends before $u$ starts". The set of $(S_u, S_v)$ satisfying it is the union of two half-planes, which is not convex (convex: the segment between two feasible points stays feasible; here $(0, p_u)$ and $(p_v, 0)$ are feasible, their midpoint is not), while a system of linear inequalities always describes a convex set. Choosing the direction (orienting the pair) makes it linear.
:::
::: q 3. In the disjunctive graph, what is a node, a conjunctive arc and a disjunctive pair?
A node is an operation (plus a source and a sink); a conjunctive arc is a fixed precedence between consecutive operations of a job; a disjunctive pair joins two operations of different jobs that need the same machine, with a direction still to choose.
:::
::: q 4. Where does the proof that a cycle is infeasible use positive processing times?
At the last step: summing the arc inequalities around the cycle gives $0 \ge \sum p$, a contradiction only if the sum is positive. With operations of zero duration a cycle of zero length would be satisfiable, all of them starting at the same instant.
:::
::: q 5. Why does an acyclic complete selection never make two operations overlap on a machine?
Two operations of different jobs on the machine form a pair, which the complete selection orients, and the arc keeps them apart: $S_v \ge S_u + p_u$. Two operations of the same job on one machine are joined by a path of route arcs, which keeps them apart in the same way.
:::
::: q 6. Why a longest path, not a shortest one?
Each arc into $v$ is a lower bound $S_v \ge S_u + w$; all of them must hold, so the start is the largest of them, and by induction the largest over all paths from the source.
:::
::: q 7. How does flexibility change the graph?
The nodes and routes stay; the weights become the processing times on the chosen machines (and the travel times between them); and the disjunctive pairs are those of operations sent to the same machine, so a different assignment draws different pairs.
:::
::: q 8. Why can the optimum of the 3 × 3 instance (21) exceed the load bound (16)?
The load bound ignores the routes. The pair J0.1–J1.0 on M1 forces a path of 21 one way and of 25 the other, through the routes of J0 and J1: a machine can be idle because the next job is still elsewhere.
:::

:::: exercise Two jobs, two machines, opposite routes
J0 goes M0 (3 min) then M1 (2 min); J1 goes M1 (4 min) then M0 (1 min). Part 3 described its graph and its one cyclic selection. Draw the graph, then compute the makespan of each of the three acyclic selections by longest paths, and say which is optimal and why.

Write the selections as (M0 arc, M1 arc).

- $J0.0 \to J1.1$, $J1.0 \to J0.1$: J0.0 and J1.0 start at 0; J0.1 at $\max(3, 4) = 4$, ending at 6; J1.1 at $\max(4, 3) = 4$, ending at 5. Makespan **6**, the optimum: both machines start at once.

- $J1.1 \to J0.0$, $J1.0 \to J0.1$: symmetric, J1 first: J1.0 [0, 4), J1.1 [4, 5), J0.0 [5, 8), J0.1 [8, 10). Makespan **10**.

The numbers script prints the same four lines: three of four selections are acyclic, against 64 of 512 on the 3 × 3 instance.

:::: exercise A single priority never makes a cycle
Rank the jobs once and for all, and on every machine let the higher-ranked job go first. Prove that this selection is acyclic, for any job shop. What does it give on the 3 × 3 instance with the ranking J0, J1, J2?
::: hint
Label each node by its job's rank and its step number. Follow an arc: what can happen to the pair (rank, step)?
:::
::: solution
Give operation $(j, k)$ the pair $(\text{rank}(j), k)$, compared lexicographically. A route arc $(j, k) \to (j, k + 1)$ keeps the rank and increases the step; a disjunctive arc goes from a job to a job of strictly larger rank (lower priority). Either way the pair strictly increases. Along a cycle it would have to come back to its starting value, which a strictly increasing sequence cannot do. So the selection is acyclic, and its longest-path schedule is valid. This is why simple dispatching by a fixed priority always produces a schedule.

On the instance, the ranking J0, J1, J2 gives a makespan of **33** minutes, and the reverse ranking 42, tied for the worst of the 64 acyclic selections (3 selections reach 42). The *J0, J1, J2 first* button of the hero sets this selection; the critical path it shows suggests which pair to flip.

print(makespan_of([sorted(x) for x in on]))                  # 33
print(makespan_of([sorted(x, reverse=True) for x in on]))    # 42
```

:::: exercise Prove that 19 is optimal for the flexible instance
In the flexible instance of Part 5, J0.1 and J1.0 may each run on M1 (7 min) or M2 (6 min), and J2.2 on M1 (2 min) or M0 (3 min). Prove, without enumeration, that no assignment and order gives a makespan below 19, and that 19 is reached.

Split the 8 assignments by where J0.1 and J1.0 go. If both stay on M1, reuse the argument of Part 4. If both go to M2, look at M2's load. Otherwise compute the load of M2.

*Both on M1.* The pair J0.1–J1.0 on M1 has the same times as in the classical instance, so either $\alpha \to J1.0 \to J0.1 \to J0.2 \to \omega$ of length 21 or $\alpha \to J0.0 \to J0.1 \to J1.0 \to J1.1 \to J1.2 \to \omega$ of length 25 is in the graph: $C_{\max} \ge 21$.

So 19 is a lower bound for every assignment. It is reached, for instance, with J0.1 on M1, J1.0 on M2 and J2.2 on M1, as the widget of Part 5 shows. The numbers script confirms that 4 of the 8 assignments reach 19 and none goes lower.

:::: exercise Count the workshop's choices

n_m = [sum(fastest(f, k) == m for f in fams for k in range(ws.n_ops(f))) for m in range(ws.n_machines)]
from collections import Counter

print(n_m, sum(n * (n - 1) // 2 for n in n_m) - same, same)  # [45, 75, 28, 15, 77] 7142 32
log_perm = sum(math.lgamma(n + 1) for n in n_m) / math.log(10)
print(round(log_perm, 1), round(log_perm - same * math.log10(2), 1))   # 320.2 310.6
```

:::: exercise Solve the 3 × 3 instance by brute force
Write a function that, for each machine order (one permutation per machine), builds the arcs, computes the longest-path schedule or detects a cycle, and returns the makespan. Enumerate all $3!^3$ machine orders of the instance, count the acyclic ones and find the optimum. Then add 1 minute of transport to every route arc and to the source arcs and solve again.
::: hint
Kahn's procedure: keep the number of unvisited predecessors of each node; start from the nodes with none; when a node is visited, update its successors' starts with "start + weight" and decrease their counts. Nodes never visited mean a cycle.
:::
::: solution
```python
from collections import Counter
TOY = [[(0, 2), (1, 7), (2, 7)], [(1, 7), (2, 4), (0, 5)], [(2, 2), (0, 6), (1, 2)]]

def makespan_of(orders, tau=0):
    ops = [(j, k) for j in range(3) for k in range(3)]
    succ = {o: [] for o in ops}
    for j in range(3):
        for k in range(2):
            succ[(j, k)].append(((j, k + 1), TOY[j][k][1] + tau))
    for seq in orders:                      # consecutive arcs suffice for longest paths
        for u, v in zip(seq, seq[1:]):
            succ[u].append((v, TOY[u[0]][u[1]][1]))
    indeg = Counter(v for o in ops for v, _ in succ[o])
    start = {o: tau if o[1] == 0 else 0 for o in ops}
    queue = [o for o in ops if indeg[o] == 0]
    for u in queue:
        for v, w in succ[u]:
            start[v] = max(start[v], start[u] + w)
            indeg[v] -= 1
            if indeg[v] == 0:
                queue.append(v)
    if len(queue) < len(ops):
        return None                          # a cycle
    return max(start[(j, 2)] + TOY[j][2][1] for j in range(3))

on = [[(j, k) for j in range(3) for k in range(3) if TOY[j][k][0] == m] for m in range(3)]
for tau in (0, 1):
    vals = [makespan_of(p, tau) for p in itertools.product(*[itertools.permutations(x) for x in on])]
    ok = [v for v in vals if v is not None]
    print(tau, len(vals), len(ok), min(ok))      # 0 216 64 21   then   1 216 64 23
```
Arcs between consecutive operations of each machine suffice: the others are implied and never lengthen a path. The counts and optima match the hero and the numbers script.

## The chapter on one page {#summary}

::: steps
- **The problem**: choose a machine $\mu_{jk} \in \mathcal M_{jk}$ for every operation and an order on every machine.
- **The constraints**: assignment, release, precedence with transport, capacity as a disjunction, changeovers once the machine is free and the job is there.
- **The graph** (Roy and Sussmann): routes as fixed arcs, machine conflicts as pairs to orient; on the 3 × 3 instance 512 selections, 216 that order each machine, 64 acyclic.
- **The theorem**: a cycle means no schedule; an acyclic complete selection gives the semi-active schedule $S_v = \ell(\alpha, v)$, $C_{\max} = \ell(\alpha, \omega)$. Search over orders, compute the times.
- **The instance**: optimum 21, unique, proved by the two paths through one M1 pair.
- **Flexibility** (Brandimarte): the assignment changes weights and pairs; best 19, fastest machines 25.
- **Extras**: release and transport on route arcs, changeovers on machine arcs, exact under the weak triangle inequality.
- **The workshop**: about $10^{74}$ assignments for a day; on the fastest machines, $10^{310.6}$ machine orders that respect the routes.
:::

### The vocabulary, in one table

| Word | Meaning |
|---|---|
| Flexible / classical job shop | Each step may run on one of several eligible machines $\mathcal M_{jk}$ / on exactly one. |
| Operation, routing | Step $(j,k)$ of a job; a job's steps with their eligible machines $\mathcal M_{jk}$ and times $p_{jkm}$. |
| Assignment $\mu$ | One machine per operation; classical job shop when there is no choice. |
| Arrival $A_{jk}$ | When the job reaches the machine of step $k$: release or previous end, plus the ride. |
| Changeover $s_m(f,g)$, travel $\tau(a,b)$ | Re-equipping machine $m$ from family $f$ to $g$, once the machine is free and the job there; the cart ride between stations. |
| Disjunctive graph | Operations, conjunctive arcs (routes), disjunctive pairs (machine conflicts). |
| Conjunctive arc / disjunctive pair | A fixed "must finish first" arrow of a route / two operations of different jobs on one machine, direction to choose. |
| Selection | An orientation of the pairs; complete when all are oriented. |
| Acyclic | No directed cycle; for a complete selection, the same as "a schedule exists". |
| Topological order | An order of the nodes in which every arc goes forward; Kahn's procedure finds one or a cycle. |
| Semi-active schedule | Every operation as early as its orders allow; the longest-path schedule. |
| Critical path | A longest path from source to sink. |
| Weak triangle inequality | $s_m(f,h) \le s_m(f,g) + p + s_m(g,h)$: pairwise changeover arcs are then exact. |

**Scope.** A static, deterministic problem: all jobs known, no breakdowns, carts not modelled as resources.
