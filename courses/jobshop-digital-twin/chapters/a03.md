## A workshop in plain words {#idea}

The paint machine of chapters [[a01]] and [[a02]] had one decision: the order of the orders. In a workshop every order goes through several machines, one step after another, and a step can often be done on more than one machine: step 0 of a family-0 order runs on machine 1 in 6 minutes or on machine 2 in 10. So the workshop decides two things for every step:

- **where**: which of the eligible machines (those able to do the step) will do it, the *assignment (routing)*. Machine 1 is faster, but if it has a long queue, machine 2 may finish sooner;
- **when**: in which order each machine works through what it receives: the paint-machine question on five machines at once, except that a step waits for the previous step of its order to end elsewhere, and for the ride.

The machines are coupled through the orders: putting an order first on machine 1 makes it arrive early at machine 2, which changes what machine 2 should do.

A small instance shows everything. Three jobs, three machines, each job visiting each machine once in its own order:

::: table num
| Job | Step 0 | Step 1 | Step 2 | Total |
|---|---|---|---|---|
| J0 | M0, 2 min | M1, 7 min | M2, 7 min | 16 |
| J1 | M1, 7 min | M2, 4 min | M0, 5 min | 16 |
| J2 | M2, 2 min | M0, 6 min | M1, 2 min | 10 |
:::

Machine M1 has $7 + 7 + 2 = 16$ minutes of work, the others 13 each, and no job takes longer than 16 minutes, so no schedule finishes before minute 16. The best finishes at 21, and exactly one way of ordering the machines achieves it: find it in the hero.

::: define What is a flexible job shop?
**In plain words:** each order follows its own route of steps, and a step may be done on any of a few machines, at a machine-dependent speed. Deciding means choosing a machine for every step and an order for every machine.

**More precisely:** a set of jobs $\mathcal J$; job $j$ consists of operations $(j, 0), \dots, (j, K_j - 1)$ to be done in this order; operation $(j,k)$ can be processed by any machine of a set $\mathcal M_{jk} \subseteq \mathcal M$, taking $p_{jkm}$ minutes on machine $m$, without interruption; a machine does one operation at a time.

- Operation :: One step of one job, $(j, k)$: what the code calls `(job, op)`.
- Route, eligible machines :: The route of a job is its sequence of operations; $\mathcal M_{jk}$, the eligible machines of $(j, k)$ (1 to 3 in the workshop), depend only on the family, and `ws.alternatives(f, k)` returns them with their times.
- Assignment (routing) $\mu$ :: One machine $\mu(j, k) \in \mathcal M_{jk}$ for each operation.
- Sequence $\sigma_m$ :: The order in which machine $m$ processes the operations assigned to it, as $\sigma$ was the order of the paint machine.
- Classical job shop :: The special case $|\mathcal M_{jk}| = 1$: only the sequences are to be chosen. The 3 × 3 instance is one.
- Flow shop :: The special case where every job visits the machines in the same order.
:::

## The constraints, written as mathematics {#constraints}

A schedule gives each operation a machine $\mu(j, k)$, a start $S_{jk}$ and an end $E_{jk}$. Its measures are those of chapter [[a01]]: $C_j = E_{j,K_j-1}$, $T_j = \max(0, C_j - d_j)$, $C_{\max} = \max_j C_j$. Five kinds of constraints make it valid.

**1. Assignment and duration.** Every operation goes to exactly one eligible machine and runs there without interruption. With binary variables $x_{jkm} = 1$ when $(j,k)$ runs on $m$,

$$\sum_{m \in \mathcal M_{jk}} x_{jkm} = 1, \qquad E_{jk} = S_{jk} + \sum_{m \in \mathcal M_{jk}} p_{jkm}\, x_{jkm}, \qquad x_{jkm} \in \{0, 1\}.$$
%narrow \textstyle\sum_{m} x_{jkm} = 1, \quad E_{jk} = S_{jk} + \sum_{m} p_{jkm} x_{jkm}

So $\mu(j, k)$ is the machine with $x_{jkm} = 1$, and $E_{jk} = S_{jk} + p_{jk\mu(j,k)}$. Breakdowns are left to the simulator of chapter [[b01]].

**2. Release and the first move.** Job $j$ arrives at the load station at its release time $r_j$, and a cart carries it to its first machine. With $\operatorname{st}(m) = m + 1$ the station of machine $m$ (station 0 is the load station) and $\tau(a, b)$ the travel time between stations ([notation](notation.html#objects)), the job reaches its first machine at

$$\alpha_{j0} = r_j + \tau\big(0, \operatorname{st}(\mu(j, 0))\big), \qquad S_{j0} \ge \alpha_{j0},$$

plus a changeover if one is needed (constraint 5).

**3. Precedence with transport.** Step $k + 1$ cannot start before step $k$ has ended and the job has been carried to the next machine:

$$\alpha_{j,k+1} = E_{jk} + \tau\big(\operatorname{st}(\mu(j,k)), \operatorname{st}(\mu(j,k+1))\big), \qquad S_{j,k+1} \ge \alpha_{j,k+1}.$$
%narrow \alpha_{j,k+1} = E_{jk} + \tau(\operatorname{st}(\mu(j,k)), \operatorname{st}(\mu(j,k+1))), \quad S_{j,k+1} \ge \alpha_{j,k+1}

$\alpha_{jk}$ is the *arrival* of job $j$ at the machine of $(j,k)$; $\tau(a, a) = 0$. The ride depends on *both* machines chosen, so transport couples consecutive assignments; chapter [[c01]] writes it as the transport lag $\ell(m', m)$.

**4. Capacity.** A machine processes one operation at a time. For any two operations $u$ and $v$ of different jobs assigned to the same machine, one ends before the other starts:

$$\mu(u) = \mu(v) \quad \Longrightarrow \quad E_u \le S_v \ \ \text{or} \ \ E_v \le S_u .$$

The word "or" is the whole difficulty of scheduling. Constraints 1 to 3 are linear once the assignment is fixed; constraint 4 is a **disjunctive constraint**, a logical "or" of linear inequalities, one per pair on a machine (chapter [[c01#nooverlap]] writes it for a solver). Two operations of one job need none: precedence keeps them apart.

**5. Sequence-dependent changeovers.** When a machine passes from a job of family $f$ to one of family $g$ it is re-equipped for $s_m(f, g)$ minutes, zero if $g = f$, and the changeover starts only once the machine is free *and* the job has arrived (the convention of the repository's simulator and CP-SAT model). If $v$ directly follows $u$ on machine $m$,

$$S_v \ge \max(E_u, \alpha_v) + s_m\big(f(u), f(v)\big),$$

with $f(u)$ the family of the job of $u$; for the first operation on a machine, $S_v \ge \alpha_v$. The changeover belongs to a pair of consecutive operations, so it cannot be folded into $p_{jkm}$.

**A worked case, with the workshop's numbers.** A family-0 job is released at $r_j = 100$; its step 0 goes to machine 1, 6 minutes. The ride from the load station is $\tau(0, \operatorname{st}(1)) = 2$, so $\alpha = 102$. Machine 1 last ran family 2 and is free from minute 98; $s_1(2, 0) = 10$. Then $S = \max(98, 102) + 10 = 112$ and $E = 118$: the machine idles from 98 to 102. Had it been busy until 105, the job would wait instead: $S = 115$, $E = 121$.

**The objective.** The makespan, the total tardiness and the planner's $10 \sum_j T_j + \sum_j C_j$ are *regular* measures (chapter [[a01#regular]]): non-decreasing in every $C_j$. Part 4 turns this into a theorem: the decisions are the assignment and the sequences; the times follow.

## The disjunctive graph {#graph}

Strip the problem to its core: the classical job shop with makespan, $Jm \mid\mid C_{\max}$ (chapter [[a01#notation]]): one machine per operation, no changeovers, no transport, all jobs present at time 0. Roy and Sussmann [[ref:1]] drew it as a graph, still how the job shop is taught.

::: define What is a disjunctive graph?
**In plain words:** a box per step; a solid arrow means "must finish first"; a dashed line between two boxes on the same machine means "one of them first, you choose".

**More precisely:** $G = (V, C, D)$, with

* **nodes** $V$: one per operation, plus two dummy nodes, $0$ ("the start of the day") and $\ast$ ("everything is done");
* **conjunctive arcs** $C$: the routes, $(j, k) \to (j, k + 1)$, plus $0 \to (j, 0)$ and $(j, K_j - 1) \to \ast$, fixed by the data;
* **disjunctive pairs** $D$: for every machine, a pair $\{u, v\}$ for every two operations of different jobs on it, an arc whose direction is not decided yet.

- Arc weight $w(u, v)$ :: Here $p_u$, the processing time of the tail, and 0 for the arcs leaving $0$. The arc reads "$v$ cannot start before $u$ has ended": $S_v \ge S_u + w(u, v)$.
:::

Two jobs on two machines with opposite routes give four boxes, two solid arrows and one dashed pair per machine (exercise 1). In the hero each machine has three operations, one per job, hence $\binom{3}{2} = 3$ pairs per machine and $|D| = 9$.

::: define What is a selection?
**In plain words:** for each pair of operations that compete for a machine, a decision of which goes first. Making all these decisions is the scheduling.

**More precisely:** a selection $\mathcal S$ picks one direction, $u \to v$ or $v \to u$, for some of the pairs of $D$; it is *complete* when every pair is oriented. It turns $G$ into the directed graph $G(\mathcal S) = (V, C \cup \mathcal S)$.

- Acyclic :: With no directed cycle: no way to follow arrows and come back to the start.
- Path length :: The sum of the weights of its arcs; $\operatorname{len}(u, v)$ is the length of a longest path from $u$ to $v$ in $G(\mathcal S)$.
- Critical path :: A longest path from $0$ to $\ast$; its operations run back to back.
:::

**Counting selections.** The 9 pairs can be oriented in $2^9 = 512$ ways. Many are absurd before any timing: on M0, $J0.0 \to J1.2$, $J1.2 \to J2.1$ and $J2.1 \to J0.0$ go round in a circle. A selection makes sense on one machine only if it is a *total order*, a sequence $\sigma_m$, and $n_m$ operations have $n_m!$ of them, so at most $\prod_m n_m! = 3!^3 = 216$ selections survive the machines one at a time. The routes remove more: only **64** of those are acyclic, as the numbers script finds by trying them all.

**A cycle across machines.** Two orientations can be enough. Put J1.2 before J0.0 on M0, and J0.1 before J1.0 on M1:

$$J0.0 \to J0.1 \to J1.0 \to J1.1 \to J1.2 \to J0.0.$$

Each job waits for the other. The numbers script counts 6 such cycle-closing pairs of orientations; the hero shows a cycle in red as soon as you create one.

## Cycle means impossible, longest path means makespan {#longest}

Two facts make the graph useful, both due to Roy and Sussmann [[ref:1]] and given in Pinedo's book [[ref:4]].

::: callout
**Theorem.** Let $\mathcal S$ be a complete selection of a job shop whose processing times are all positive.

1. If $G(\mathcal S)$ has a directed cycle, no schedule processes the operations in the orders $\mathcal S$ prescribes.
2. If $G(\mathcal S)$ is acyclic, $S_v = \operatorname{len}(0, v)$ for every operation $v$ is a valid schedule; every schedule that follows $\mathcal S$ has $S_v \ge \operatorname{len}(0, v)$; and its makespan is $\operatorname{len}(0, \ast)$.
:::

**Proof of 1.** A schedule follows $\mathcal S$ when every arc $u \to v$ of $G(\mathcal S)$ holds as $S_v \ge S_u + w(u, v)$. Suppose a cycle $u_1 \to u_2 \to \dots \to u_q \to u_1$ and write the inequality of each of its arcs,

$$S_{u_2} \ge S_{u_1} + p_{u_1}, \quad S_{u_3} \ge S_{u_2} + p_{u_2}, \quad \dots, \quad S_{u_1} \ge S_{u_q} + p_{u_q}.$$

Adding them, every $S_{u_i}$ appears once on each side and cancels, leaving $0 \ge p_{u_1} + \dots + p_{u_q}$. The right side is positive, so no start times satisfy all the inequalities. $\square$

**Proof of 2.** $\operatorname{len}(0, v)$ is well defined: an acyclic graph has finitely many paths from $0$ to $v$, and at least one, along $v$'s route.

*Lower bound.* For a schedule that follows $\mathcal S$, the arc inequalities along any path $0 = v_0 \to \dots \to v_q = v$ add up to $S_v \ge$ its length, hence $S_v \ge \operatorname{len}(0, v)$.

*Feasible.* For an arc $u \to v$, a longest path to $u$ followed by the arc is a path to $v$, so $\operatorname{len}(0, v) \ge \operatorname{len}(0, u) + w(u, v)$: $S_v = \operatorname{len}(0, v)$ satisfies every arc inequality, so precedence holds. Take two operations $u$, $v$ on one machine. If they belong to different jobs, their pair is oriented, say $u \to v$, and $S_v \ge S_u + p_u$. If they belong to the same job, $u$ earlier, the route arcs form a path from $u$ to $v$ whose first arc weighs $p_u$, so again $S_v \ge S_u + p_u$. Either way one ends before the other starts.

*Makespan.* The arcs into $\ast$ come from the last operation of each job with weight $p$, so $\operatorname{len}(0, \ast) = \max_j \big(\operatorname{len}(0, (j, K_j - 1)) + p_{j, K_j - 1}\big) = C_{\max}$. $\square$

**What the theorem buys.**

*Every valid schedule comes from an acyclic selection.* Orient each pair by the order of the start times on its machine. Every arc then goes to an operation that starts strictly later ($S_v \ge S_u + p_u > S_u$), and a walk on which the start strictly increases cannot return to where it began.

*The longest-path schedule is the best for its selection.* The left-shifted schedule (LS) of [[a01#left-shift]] is exactly this longest path, the **semi-active** schedule, so for a regular measure nothing following the same selection does better. Hence

$$\min_{\text{schedules}} C_{\max} \;=\; \min_{\mathcal S \text{ complete and acyclic}} \; \operatorname{len}_{G(\mathcal S)}(0, \ast),$$

and likewise for any regular measure: the search is over orders, a finite set; the times are computed.

*Only the critical path matters.* Reversing a pair off a critical path leaves that path in the graph, so to shorten a schedule you must reverse an arc on it: the moves of *local search* for the job shop [[ref:4]].

**Computing it.** Visit the nodes in a *topological order* (every arc goes forward) and set each start to the largest "start of a predecessor plus the arc's weight". Nodes never visited contain a cycle (each has an unvisited predecessor; walk backwards until one repeats). This pass, Kahn's procedure, is linear in nodes plus arcs; the hero and the numbers script use it.

**The instance, solved by hand.** The loads give a lower bound of 16, yet the optimum is 21. Look at the one pair on M1 between J0.1 and J1.0, both 7 minutes. Either way round, the graph contains a long path:

- if J1.0 goes first, $0 \to J1.0 \to J0.1 \to J0.2 \to \ast$ has length 21 ($7 + 7 + 7$);
- if J0.1 goes first, $0 \to J0.0 \to J0.1 \to J1.0 \to J1.1 \to J1.2 \to \ast$ has length 25 ($2 + 7 + 7 + 4 + 5$).

So every acyclic selection has $C_{\max} \ge 21$, and 21 is reached: with the sequences M0: J0.0, J2.1, J1.2; M1: J1.0, J0.1, J2.2; M2: J2.0, J1.1, J0.2, the longest-path schedule is

::: table num
| Machine | First | Second | Third |
|---|---|---|---|
| M0 | J0.0 [0, 2) | J2.1 [2, 8) | J1.2 [11, 16) |
| M1 | J1.0 [0, 7) | J0.1 [7, 14) | J2.2 [14, 16) |
| M2 | J2.0 [0, 2) | J1.1 [7, 11) | J0.2 [14, 21) |
:::

with critical path J1.0 → J0.1 → J0.2. The two arguments prove it optimal without enumeration; enumeration adds that it is unique: the 64 acyclic selections range from 21 to 42, with 21 once and 24 six times. Press *J0, J1, J2 first* in the hero (33 minutes), then flip pairs on its critical path and watch the length drop.

**How hard is it?** NP-hard already for three machines visited in the same order ($F3 \mid\mid C_{\max}$); this chapter only cites the result, from the survey of Graham, Lawler, Lenstra and Rinnooy Kan [[ref:3]]. No known algorithm avoids an exponential search in the worst case, hence chapter [[c02]] on searching cleverly.

## Assignment first: the flexible job shop {#flexible}

In the course's workshop an operation has 1 to 3 eligible machines. Brandimarte [[ref:2]] was among the first to treat this *flexible* job shop, splitting it into routing and the job shop that results, both attacked by tabu search (a local search that forbids undoing recent moves).

**Formally**, a schedule is a pair $(\mu, \mathcal S)$: an assignment (routing), one machine $\mu(j, k) \in \mathcal M_{jk}$ per operation, and a selection of the job shop it creates. Fixing $\mu$ fixes the processing times $p_{jk\mu(j,k)}$ and decides *which* pairs exist: two operations compete only if they were sent to the same machine. The graph $G_\mu$ keeps its nodes and routes, but its weights and pairs change with the assignment, and

$$\min_{(\mu, \mathcal S)} C_{\max} \;=\; \min_{\mu} \ \ \min_{\mathcal S \text{ acyclic for } \mu} \operatorname{len}_{G_\mu(\mathcal S)}(0, \ast).$$
%narrow \min_{\mu} \ \min_{\mathcal S \text{ acyclic for } \mu} \operatorname{len}_{G_\mu(\mathcal S)}(0, \ast)

There are $\prod_{j,k} |\mathcal M_{jk}|$ assignments, each with its own selections. The flexible job shop contains the classical one (every $|\mathcal M_{jk}| = 1$), so it is at least as hard.

**The instance, made flexible.** Three operations get a second machine: J0.1 and J1.0 can also run on M2 in 6 minutes instead of 7 on M1, and J2.2 on M0 in 3 minutes instead of 2 on M1. The complete data, for reuse in chapter [[c01]]; each cell lists the eligible machines with their minutes:

::: table
| Job | Step 0 | Step 1 | Step 2 |
|---|---|---|---|
| J0 | M0: 2 | **M1: 7** or M2: 6 | M2: 7 |
| J1 | **M1: 7** or M2: 6 | M2: 4 | M0: 5 |
| J2 | M2: 2 | M0: 6 | **M1: 2** or M0: 3 |
:::

The machines in bold give back the classical instance of the hero, optimum 21; with all eight assignments allowed the optimum is 19. The widget below tries every assignment and, for each, every order on every machine: 5,832 combinations in all.

Four of the 8 assignments reach 19; none does better (exercise 3 proves it by hand). Two lessons carry over: assignment and sequencing interact, so neither can be decided well alone; and how busy a machine is matters more than how fast it is. This is why the repository's rules route a job to the machine with the *earliest expected finish*, which counts the queue, rather than to the fastest one, chapter [[b02#routing]].

## Where changeovers and transport enter the graph {#extras}

The course's workshop adds release times, transport and changeovers. All three become arc weights, and the theorem survives, because its proofs used only one thing: each arc is an inequality "start of the head $\ge$ start of the tail + a positive weight". With an assignment fixed:

- the arc $0 \to (j, 0)$ weighs $r_j + \tau(0, \operatorname{st}(\mu(j, 0)))$, the release plus the first ride;
- the route arc $(j, k) \to (j, k+1)$ weighs $p_{jk\mu(j,k)} + \tau\big(\operatorname{st}(\mu(j,k)), \operatorname{st}(\mu(j,k+1))\big)$: processing, then the ride;
- the machine arc $u \to v$ on $m$ weighs $p_u + s_m(f(u), f(v))$: finish $u$, then re-equip;
- since the changeover also waits for the job (constraint 5), the arc *into* $v$ along its route gains $s_m(f(u'), f(v))$, where $u'$ is the operation directly before $v$ on its machine (nothing if $v$ is first). Unlike the others, this weight depends on the selection.

The CP-SAT planner of chapter [[c01]] writes the ride this way, plus an allowance $\delta = 2$ min for an empty cart to come. The two carts themselves are a capacity that this model, like the planner, leaves out; the simulator of chapter [[b01]] moves them.

In the hero's toy each job is its own family, so the changeover box means 1 minute whenever a machine switches job. Toggle the boxes: with 1-minute rides the optimum becomes 23, with 1-minute changeovers 23 too, with both 25; here the same selection stays optimal each time, which need not happen in general.

**One caution.** The graph has an arc for *every* ordered pair on a machine, but a changeover happens only between *directly consecutive* operations. If $u$, $v$, $w$ run in this order, the arc $u \to w$ charges a changeover $s_m(f(u), f(w))$ that never happens. It is harmless when the chain through $v$ already implies it, that is when $s_m(f(u), f(w)) \le s_m(f(u), f(v)) + p_v + s_m(f(v), f(w))$: the triangle inequality of chapter [[a02#setups]] with $p_v$ added on the right. The workshop breaks the plain inequality in 4 places, as A2 counts, but always satisfies this weaker one, since every changeover is at most 10 min $\le 3 + 6 + 3$: the smallest changeover twice plus the shortest operation. Rather than rely on it, the repository's model uses a *circuit* that knows who directly follows whom, chapter [[c01#circuit]].

## The code behind it {#code}

The workshop is a frozen data class (an immutable record): the fixed part of the shop, identical in every run.

::: code jobshop/scenario.py:Workshop
`routings[f][k]`, the eligible machines, is a dictionary `{machine: minutes}`: keys $\mathcal M_{fk}$, values $p_{fkm}$, indexed by family $f = f(j)$. `setup_time` is $s_m(f, g)$, zero for a machine that has run nothing (`previous_family=None`). `station(m)` is $\operatorname{st}(m)$; `travel` is $\tau$. `min_remaining_work(f, 0)` is $W_f$.
:::

The workshop itself is drawn once from a seeded generator.

::: code jobshop/scenario.py:make_workshop
The stream `[seed, 0]` serves nothing else, so the workshop never changes when the scenarios do. Per family: 3 or 4 operations (all got 4); per operation, the number of eligible machines from `[1, 2, 2, 3]` and a base time from 8 to 24 minutes, scaled per machine by a factor in $[0.8, 1.3]$. Changeovers are drawn independently per machine and ordered pair of families, hence asymmetric. A move costs 1 minute plus half the Manhattan distance on a 4 × 3 grid, rounded up.
:::

## Common pitfalls {#pitfalls}

1. **"A job shop is several single machines."** The routes couple the machines: an order on one moves arrivals on the others. The cycle of Part 3 involves two machines and is invisible on either alone.
2. **"There are $2^{|D|}$ schedules."** Most selections are cyclic: 512, then 216 total orders per machine, then 64 acyclic on the small instance.
3. **"The start times are decisions."** For a regular measure they are not: once the assignment and the sequences are fixed, the earliest schedule is a longest-path computation, and it is the best for those sequences.
4. **"The fastest machine is the best machine."** On the flexible instance it gives 25 minutes against 19; on the workshop it sends 77 operations to one machine and 15 to another.
5. **"A changeover is part of the processing time."** It depends on which job came directly before, so it lives on the arcs between operations, not in the nodes.
6. **"The longest path of a partial selection is the makespan."** It is a lower bound: orienting more pairs adds arcs and can only lengthen paths. The hero writes "≥" until all nine pairs are ordered; the solvers of chapter [[c02#bnb]] start from such bounds.

## Check your understanding {#check}

:::: qa
Try to answer each question before opening it.

::: q 1. What are the two decisions of a flexible job shop, and which one does a classical job shop lack?
The assignment (routing), a machine $\mu(j, k) \in \mathcal M_{jk}$ for each operation, and the sequence on each machine. A classical job shop has $|\mathcal M_{jk}| = 1$: the assignment is given.
:::
::: q 2. Why is the capacity constraint not a linear inequality?
It says "$u$ ends before $v$ starts, or $v$ ends before $u$ starts". The feasible $(S_u, S_v)$ form two half-planes whose union is not convex ($(0, p_u)$ and $(p_v, 0)$ are feasible, their midpoint is not), while linear inequalities describe convex sets. Orienting the pair makes it linear.
:::
::: q 3. In the disjunctive graph, what is a node, a conjunctive arc and a disjunctive pair?
An operation (plus $0$ and $\ast$); a fixed precedence inside a job; two operations of different jobs on one machine, direction to choose.
:::
::: q 4. Where does the proof that a cycle is infeasible use positive processing times?
At the last step: summing around the cycle gives $0 \ge \sum p$, a contradiction only if the sum is positive. With zero durations a cycle would be satisfiable, all its operations starting at the same instant.
:::
::: q 5. Why does an acyclic complete selection never make two operations overlap on a machine?
Two operations of different jobs on it form a pair, oriented by the selection, and the arc gives $S_v \ge S_u + p_u$. Two of the same job are joined by a path of route arcs, which does the same.
:::
::: q 6. Why a longest path, not a shortest one?
Each arc into $v$ is a lower bound $S_v \ge S_u + w$; all must hold, so the start is the largest of them, and by induction the largest over all paths from $0$.
:::
::: q 7. How does flexibility change the graph?
Nodes and routes stay; weights become the times on the chosen machines; the pairs are those of operations sent to the same machine, so another assignment draws other pairs.
:::
::: q 8. Why can the optimum of the 3 × 3 instance (21) exceed the load bound (16)?
The load bound ignores the routes. The pair J0.1–J1.0 on M1 forces a path of 21 one way and 25 the other, through the routes of J0 and J1: a machine can be idle because its next job is still elsewhere.
:::

:::: exercise Solve the 3 × 3 instance by brute force
Write a function that, for each machine order (one permutation per machine), builds the arcs, computes the longest-path schedule or detects a cycle, and returns the makespan. Enumerate all $3!^3$ machine orders of the instance, count the acyclic ones and find the optimum. Then add 1 minute of transport to every route arc and to the source arcs and solve again.
::: hint
Kahn's procedure: keep the number of unvisited predecessors of each node; start from the nodes with none; when a node is visited, update its successors' starts with "start + weight" and decrease their counts. Nodes never visited mean a cycle.
:::
::: solution
```python
from collections import Counter
TOY = [[(0, 2), (1, 7), (2, 7)], [(1, 7), (2, 4), (0, 5)], [(2, 2), (0, 6), (1, 2)]]

def makespan_of(orders, tau=0):
    ops = [(j, k) for j in range(3) for k in range(3)]
    succ = {o: [] for o in ops}
    for j in range(3):
        for k in range(2):
            succ[(j, k)].append(((j, k + 1), TOY[j][k][1] + tau))
    for seq in orders:                      # consecutive arcs suffice for longest paths
        for u, v in zip(seq, seq[1:]):
            succ[u].append((v, TOY[u[0]][u[1]][1]))
    indeg = Counter(v for o in ops for v, _ in succ[o])
    start = {o: tau if o[1] == 0 else 0 for o in ops}
    queue = [o for o in ops if indeg[o] == 0]
    for u in queue:
        for v, w in succ[u]:
            start[v] = max(start[v], start[u] + w)
            indeg[v] -= 1
            if indeg[v] == 0:
                queue.append(v)
    if len(queue) < len(ops):
        return None                          # a cycle
    return max(start[(j, 2)] + TOY[j][2][1] for j in range(3))

on = [[(j, k) for j in range(3) for k in range(3) if TOY[j][k][0] == m] for m in range(3)]
for tau in (0, 1):
    vals = [makespan_of(p, tau) for p in itertools.product(*[itertools.permutations(x) for x in on])]
    ok = [v for v in vals if v is not None]
    print(tau, len(vals), len(ok), min(ok))      # 0 216 64 21   then   1 216 64 23
```
The results match the hero.

## The chapter on one page {#summary}

::: steps
- **The problem**: choose an assignment (routing) $\mu(j, k) \in \mathcal M_{jk}$, an eligible machine for every operation, and a sequence on every machine.
- **The constraints**: assignment, release, precedence with transport, capacity as a disjunction, changeovers once the machine is free and the job there.
- **The graph** (Roy and Sussmann): routes as fixed arcs, machine conflicts as pairs to orient; on the 3 × 3 instance 512 selections, 216 that order each machine, 64 acyclic.
- **The theorem**: a cycle means no schedule; an acyclic complete selection gives the semi-active schedule $S_v = \operatorname{len}(0, v)$, with $C_{\max} = \operatorname{len}(0, \ast)$; on the instance, 21, unique.
- **Flexibility** (Brandimarte): the assignment changes weights and pairs; best 19, fastest machines 25.
- **Extras**: release and transport on route arcs, changeovers on machine arcs.
- **The workshop**: about $10^{74}$ assignments for a day; on the fastest machines alone, about $10^{320}$ machine orders.
:::

### The vocabulary, in one table

| Word | Meaning |
|---|---|
| Route, eligible machines $\mathcal M_{jk}$ | A job's sequence of operations; the machines able to do operation $(j, k)$. |
| Flexible / classical job shop | Several eligible machines per operation / exactly one. |
| Assignment (routing) $\mu(j, k)$ | One eligible machine per operation. |
| Sequence $\sigma_m$ | The order of the operations on machine $m$. |
| Arrival $\alpha_{jk}$ | When the job reaches the machine of step $k$: release or previous end, plus the ride. |
| Disjunctive graph | Operations, conjunctive arcs (routes), disjunctive pairs (machine conflicts). |
| Selection $\mathcal S$ | An orientation of the pairs; complete when all are oriented. |
| Acyclic | No directed cycle; for a complete selection, the same as "a schedule exists". |
| Semi-active schedule | Every operation as early as its orders allow; the longest-path schedule. |
| Critical path | A longest path from $0$ to $\ast$, of length $\operatorname{len}(0, \ast) = C_{\max}$. |

**Scope.** A static, deterministic problem: all jobs known, no breakdowns, carts not modelled. Chapter [[b01]] simulates the dynamic shop, [[b02]] builds selections on the fly with rules, [[c01]] writes this model for a solver, [[c03]] re-solves it at every event.
