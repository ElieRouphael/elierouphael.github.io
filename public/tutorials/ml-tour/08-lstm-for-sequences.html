Part 1

From one series to many training examples

A plain feedforward network (chapter 06) has no notion of order: shuffle a sequence's time steps and its prediction for a fixed input does not change. A recurrent network processes a sequence step by step, carrying a hidden state forward; an LSTM (Long Short-Term Memory) [1] adds gates that let it choose what to remember, forget and output at each step, which makes it much easier to train on longer sequences than a plain RNN. This chapter builds a small LSTM that predicts the next value of a synthetic series from a window of recent history, and checks it against the simplest possible baseline, "tomorrow looks like today", to make sure the network earned its keep.

A time series is a list of numbers measured at regular steps, y_1, y_2, \dots, y_T. Here each y_t is a single unitless number, roughly between -2 and 2, and T = 2000; the code calls the series y. The task is one-step-ahead forecasting: predict y_t from the values before it.

Most learning methods need a table of examples, each with a fixed-size input and a target. A sliding window of length L builds one: the input is the L most recent values and the target is the next value,

\mathbf{x}^{(t)} = (y_{t-L},\ \dots,\ y_{t-1}) \in \mathbb{R}^L, \qquad \text{target } y_t .

Sliding the window one step at a time gives T - L pairs. With L = 3 on the short series 3, 5, 4, 6, 7, 5: the pairs are (3, 5, 4) \to 6, (5, 4, 6) \to 7 and (4, 6, 7) \to 5. In the code L is window = 30, which gives 2000 - 30 = 1970 pairs: X_all has shape 1970 \times 30 and y_all holds the 1970 targets. Every input uses only values from before its target. The first 80% of the pairs, in time order, are used for training and the last 20% for testing, so the model is scored on a stretch of time it has never seen. Slide the window over the real series:

The loss. For N targets with predictions \hat y_t, the mean squared error is

\text{MSE} = \frac{1}{N}\sum_{t} (\hat y_t - y_t)^2 .

Squaring makes every error count as positive and punishes large misses more than small ones. Among all forecasts that use the same information, the one with the smallest expected squared error is the conditional mean of y_t given that information. MSE is both the training loss and the test score in this chapter.

The baseline every forecast must beat. The persistence forecast [4] says the next value equals the last one, \hat y_t = y_{t-1}. It needs no training, and for a series that changes little from one step to the next it is hard to beat. A model that does not beat it has learned nothing useful about how the series moves, however complex the model is.

For this series one can work out in advance what persistence will score. The series is a smooth signal s_t plus independent noise \varepsilon_t with standard deviation 0.15, so y_t = s_t + \varepsilon_t, and the persistence error is

y_{t-1} - y_t = (s_{t-1} - s_t) + (\varepsilon_{t-1} - \varepsilon_t) .

The two independent noise terms each have variance 0.15^2 = 0.0225, so noise alone gives persistence an MSE of about 2 \times 0.0225 = 0.045. The change of the signal over one step adds about 0.025: a sine of amplitude A and period P changes by about 2\pi A / P times another sine per step, and a sine of amplitude B has mean square \frac{B^2}{2}, so the two main components give \frac{1}{2}\left(\frac{2\pi}{50}\right)^2 + \frac{1}{2}\left(\frac{\pi}{17}\right)^2 \approx 0.008 + 0.017. Persistence should therefore land near 0.07. A forecaster that knew s_t exactly would still face the fresh noise \varepsilon_t, which nothing can predict, so its MSE would be 0.0225. Any useful model must fall between these two numbers. On the actual test stretch the pieces come out at 0.0244 for the signal change and 0.0448 for the noise, 0.0693 in all, and the floor at 0.0213: the 394 noise draws happen to be a little quieter than their nominal 0.15.

Part 2

Recurrent networks and vanishing gradients

A window could be given to a dense network as 30 unrelated numbers. A recurrent neural network (RNN) instead reads the window in order, one value per step, and carries a summary of what it has read so far [5]. Inside one window, write the inputs as x_1, \dots, x_L, so x_1 = y_{t-L} and x_L = y_{t-1}. The summary is the hidden state h_s \in \mathbb{R}^H, a vector of H numbers (H = 24 in the code). It starts at h_0 = 0 and is updated at every step s by

h_s = \tanh\big(W_h\,h_{s-1} + W_x\,x_s + b\big),

with W_h \in \mathbb{R}^{H \times H}, W_x \in \mathbb{R}^{H \times 1} and b \in \mathbb{R}^H; \tanh, the hyperbolic tangent, squashes any number into (-1, 1), entry by entry. Read it as: the new memory is a squashed mix of the old memory and the new input. The same weights are used at every step, which is weight sharing over time. After the last step, a dense layer reads the forecast off the final state: \hat y_t = v^\top h_L + c, with v \in \mathbb{R}^H and a number c.

Why a plain RNN struggles to remember. Training needs the gradient of the loss with respect to the weights, and that requires knowing how the final state depends on earlier states [2]. Take the smallest case, a scalar state h_s = \tanh(w\,h_{s-1} + u\,x_s). Using \tanh'(z) = 1 - \tanh^2(z), one step back multiplies the gradient by

\frac{\partial h_s}{\partial h_{s-1}} = w\,\big(1 - h_s^2\big) .

Going back k steps, the chain rule multiplies k such factors:

\frac{\partial h_L}{\partial h_{L-k}} = \prod_{s=L-k+1}^{L} w\,\big(1 - h_s^2\big) .

A product of many factors behaves exponentially. If every factor is 0.9, then across the 29 steps of a 30-step window the product is 0.9^{29} \approx 0.047; across 50 steps it is 0.9^{50} \approx 0.005; across 100 steps, about 0.00003. If every factor is 1.1, then 1.1^{50} \approx 117. In the first case the gradient vanishes: what happened 50 steps back has almost no influence on the weight update, so long-range patterns cannot be learned. In the second it explodes and training becomes unstable. Because 1 - h_s^2 \le 1, and is close to 0 whenever the tanh saturates, vanishing is the more common failure. With vector states, w becomes the matrix W_h and the same effect acts along each of its directions.

Part 3

The LSTM cell

The LSTM [1] adds a second state, the cell state c_s \in \mathbb{R}^H: a memory line that is updated by addition instead of being squashed again at every step. Three gates control it (the forget gate came a little later [3]). A gate is a vector of numbers between 0 and 1, produced by the sigmoid \sigma(z) = \frac{1}{1 + e^{-z}}, that multiplies another vector entry by entry (written \odot): a 1 lets a value through, a 0 blocks it. (This \sigma is the sigmoid function, not the sigma used for scaling in the code.) At each step:

\begin{aligned} f_s &= \sigma\big(W_f\,x_s + U_f\,h_{s-1} + b_f\big) && \text{forget gate} \\ i_s &= \sigma\big(W_i\,x_s + U_i\,h_{s-1} + b_i\big) && \text{input gate} \\ o_s &= \sigma\big(W_o\,x_s + U_o\,h_{s-1} + b_o\big) && \text{output gate} \\ \tilde c_s &= \tanh\big(W_c\,x_s + U_c\,h_{s-1} + b_c\big) && \text{candidate} \\ c_s &= f_s \odot c_{s-1} + i_s \odot \tilde c_s && \text{cell update} \\ h_s &= o_s \odot \tanh(c_s) && \text{output} \end{aligned}

Each W is H \times 1 (it multiplies the scalar input), each U is H \times H, and each b has H entries. In plain words:

  • Forget gate f_s: how much of each entry of the old memory c_{s-1} to keep.
  • Candidate \tilde c_s: new content proposed from the current input and the previous output, with values in (-1, 1).
  • Input gate i_s: how much of the candidate to write into memory.
  • Output gate o_s: how much of the squashed memory to reveal as the output h_s, which is what the next step and the final dense layer see.

The diagrams most people learn this cell from are in [6]; the equations above are what they draw.

With H = 24 and a scalar input, the four blocks hold 4 \cdot (24 + 24 \cdot 24 + 24) = 2{,}496 parameters, and the dense output layer adds 24 + 1 = 25.

Why the gradient survives. Follow the memory line alone. From the cell update, the direct derivative is

\frac{\partial c_s}{\partial c_{s-1}} = f_s \quad \text{(entry by entry)},

so going back k steps along the cell state multiplies k forget gates (this ignores the smaller indirect paths through h_{s-1} inside the gates). The product contains no weight matrix and no tanh derivative, and the forget gate is learned. When the network needs to remember, it can hold f_s close to 1: with f_s = 0.99 at every step, 0.99^{50} \approx 0.61 of the gradient survives 50 steps, against 0.005 for the RNN factor 0.9 above. The key is the addition in c_s = f_s \odot c_{s-1} + i_s \odot \tilde c_s: new information is added to the memory rather than folded into it through a squashing function at every step.

What is an LSTM?

In plain words: a recurrent network with a memory that is updated by adding, not by overwriting, and with learned gates that decide at every step what to keep, what to write and what to show.

More precisely: a recurrent cell with hidden state h_s and cell state c_s whose update is c_s = f_s \odot c_{s-1} + i_s \odot \tilde c_s, h_s = o_s \odot \tanh(c_s), with sigmoid gates f_s, i_s, o_s and a tanh candidate \tilde c_s, each an affine function of x_s and h_{s-1} [1], [3]. Along the cell state the gradient is multiplied by the forget gate alone, so long-range dependencies survive training.

Part 4

One step of the cell, by hand

Take an LSTM with a single unit (H = 1), so every quantity is a number. Suppose the old memory is c_{s-1} = 2.0 and the four pre-activations (the expressions inside \sigma and \tanh) at this step are:

quantitypre-activationfunctionvalue
forget gate f_s2.197\sigma0.9
input gate i_s0\sigma0.5
output gate o_s1.386\sigma0.8
candidate \tilde c_s0.693\tanh0.6

The pre-activations are \ln 9, 0, \ln 4 and \ln 2, chosen so that the outputs are round: \sigma(\ln 9) = \frac{1}{1 + \frac{1}{9}} = 0.9, \sigma(\ln 4) = \frac{1}{1 + \frac{1}{4}} = 0.8 and \tanh(\ln 2) = \frac{e^{2 \ln 2} - 1}{e^{2 \ln 2} + 1} = \frac{4 - 1}{4 + 1} = 0.6. Then

c_s = f_s\,c_{s-1} + i_s\,\tilde c_s = 0.9 \times 2.0 + 0.5 \times 0.6 = 1.8 + 0.3 = 2.1,
h_s = o_s\,\tanh(c_s) = 0.8 \times \tanh(2.1) \approx 0.8 \times 0.970 = 0.776 .

The memory kept 90% of its old content and added half of the new proposal; the output reveals 80% of the squashed memory. Along the memory line, \frac{\partial c_s}{\partial c_{s-1}} = f_s = 0.9. That is the same factor as in the RNN example, with one difference: here the network chooses it. Raising the forget pre-activation from 2.197 to 4.6 gives f_s = \sigma(4.6) \approx 0.99, and the memory, together with its gradient, is carried almost unchanged from step to step. In the code. X_all and y_all are the windowed pairs of Part 1 with L = 30. Inputs and targets are standardised as (value - mu) / sigma, using training statistics only, and each window is reshaped to 30 \times 1 so that the LSTM reads one number x_s per step. The model is LSTM(24), which runs the six equations of Part 3 with H = 24 and returns only the last output h_L, followed by Dense(1), which computes \hat y_t = v^\top h_L + c. It is trained with loss="mse". The model works in standardised units, where every error is divided by sigma, so its mean squared error is multiplied by sigma**2 to return to the original units. Finally, naive_pred = X_test[:, -1] is the persistence forecast \hat y_t = y_{t-1}: the last value of each test window.

Part 5

A synthetic sequence

Two sine waves at different periods, a slow drift, and noise: enough structure for a model to find, and enough noise that it cannot predict perfectly. Real data (weather, sensor readings) usually looks like a messier version of exactly this.

tf.keras.utils.set_random_seed(0)          # seeds Python, NumPy and TensorFlow together
tf.config.experimental.enable_op_determinism()  # identical results on every run

t = np.arange(0, 2000)
y = (np.sin(2*np.pi*t/50) + 0.5*np.sin(2*np.pi*t/17) + 0.02*np.sin(2*np.pi*t/400)
     + np.random.normal(0, 0.15, size=t.shape)).astype("float32")

The widget of Part 1 shows the series itself. The periods, 50 and 17 steps, and the amplitudes, 1 and 0.5, are what Part 1's back-of-the-envelope used; the drift, with period 400 and amplitude 0.02, is too slow and too small to matter for a one-step forecast.

Part 6

Windowing: turning a sequence into (input, target) pairs

As in Part 1, we slide a window of 30 past values across the series; the target is the very next value. This is exactly the same "honest windows, no peeking" idea as the Understanding Time Series course's chapter 04: the window at time t may only see values up to t - 1.

window = 30
X_all = np.stack([y[i:i+window] for i in range(len(y) - window)])
y_all = y[window:]

n_train = int(0.8 * len(X_all))
X_train, X_test = X_all[:n_train], X_all[n_train:]
y_train, y_test = y_all[:n_train], y_all[n_train:]
print(f"train windows: {X_train.shape}, test windows: {X_test.shape}")
train windows: (1576, 30), test windows: (394, 30)
# scale using TRAINING statistics only, to avoid leaking test information
mu, sigma = X_train.mean(), X_train.std()
X_train_s = ((X_train - mu) / sigma)[..., np.newaxis]
X_test_s = ((X_test - mu) / sigma)[..., np.newaxis]
y_train_s = (y_train - mu) / sigma
y_test_s = (y_test - mu) / sigma

The training mean is -0.005 and the training standard deviation 0.804; the test windows are scaled with these same two numbers, never with their own.

Part 7

The model and the baselines

The naive baseline just predicts "the next value equals the last observed value", persistence. Any real model has to beat this to be worth its complexity.

model = tf.keras.Sequential([
    tf.keras.layers.Input(shape=(window, 1)),
    tf.keras.layers.LSTM(24),
    tf.keras.layers.Dense(1),
])
model.compile(optimizer="adam", loss="mse")
history = model.fit(X_train_s, y_train_s, epochs=15, batch_size=32, validation_split=0.1, verbose=0)
print(f"final training loss: {history.history['loss'][-1]:.4f}, "
      f"validation loss: {history.history['val_loss'][-1]:.4f}")
final training loss: 0.0471, validation loss: 0.0423

These losses are in standardised units. The training loss falls from 0.59 in the first epoch to 0.047 in the fifteenth and is still edging down, so the model is not fully trained; exercise 5 trains it longer.

pred_s = model.predict(X_test_s, verbose=0).flatten()
mse_lstm = float(np.mean((pred_s - y_test_s) ** 2)) * sigma**2       # back to original units

naive_pred = X_test[:, -1]                                            # "next = last observed"
mse_naive = float(np.mean((naive_pred - y_test) ** 2))

print(f"LSTM test MSE:              {mse_lstm:.4f}")
print(f"naive persistence test MSE: {mse_naive:.4f}")
print(f"LSTM is {mse_naive / mse_lstm:.2f}x better than the naive baseline")
LSTM test MSE:              0.0300
naive persistence test MSE: 0.0693
LSTM is 2.31x better than the naive baseline

The LSTM tracks the fast wiggle the naive baseline always lags by one step: it has learned the short-period sine component well enough to anticipate the turn, not just repeat the last value. Persistence lands at 0.0693, exactly where Part 1 predicted, and the LSTM at 0.0300 sits between that and the noise floor of 0.0213.

The baseline the notebook did not try. Beating persistence is a low bar. The demo at the top has a second one: an ordinary least-squares regression of y_t on the same 30 past values, 31 numbers fitted in a fraction of a second. It scores 0.0246 on the test set, better than the LSTM's 0.0300 and within 0.003 of the floor. There is nothing surprising in this: the signal is a sum of sines, and a sum of sines obeys a linear recurrence, so a linear rule on enough lags predicts it almost perfectly and only the noise remains. The LSTM earned its keep against persistence, not against the simplest model that respects order. On a series with real nonlinear structure the ranking could flip; the point is to check (exercise 3).

A forecaster is judged by what it beats. Persistence is the floor, a linear model on the same window the next rung, and the noise the ceiling nothing can pass; the LSTM's 0.030 reads very differently against 0.069, 0.025 and 0.021.

Part 8

The chapter on one page

  1. Windowing: a sliding window of L past values and the next value as target turns one series into T - L supervised pairs; the window may only look backward.
  2. Baselines first: persistence scores 0.0693, predictable from the noise and the signal's slope; the noise floor is 0.0213 (0.0225 by design).
  3. Plain RNNs forget: k steps back the gradient carries k factors w(1-h_s^2); at 0.9 each, half a percent survives 50 steps.
  4. The LSTM cell: an additive memory line gated by f_s, i_s, o_s; along it the gradient is multiplied by the learned forget gate alone.
  5. The result: LSTM(24) on 30-value windows reaches a test MSE of 0.0300, 2.31 times better than persistence.
  6. The fine print: a linear autoregression on the same windows scores 0.0246, a SimpleRNN 0.0280; on a linear signal the gates buy nothing, which is worth knowing before reaching for them.

Part 9

Exercises

Each exercise has a hint and a solution. Try first, then peek. The first two share a helper that rebuilds the windows and retrains from the same seed:

def run(window, layer, epochs=15):
    X_all = np.stack([y[i:i+window] for i in range(len(y) - window)]); y_all = y[window:]
    n_train = int(0.8 * len(X_all))
    X_train, X_test, y_train, y_test = X_all[:n_train], X_all[n_train:], y_all[:n_train], y_all[n_train:]
    mu, sigma = X_train.mean(), X_train.std()
    tf.keras.utils.set_random_seed(0)
    model = tf.keras.Sequential([tf.keras.layers.Input(shape=(window, 1)), layer(), tf.keras.layers.Dense(1)])
    model.compile(optimizer="adam", loss="mse")
    model.fit(((X_train - mu) / sigma)[..., np.newaxis], (y_train - mu) / sigma, epochs=epochs, batch_size=32, validation_split=0.1, verbose=0)
    pred_s = model.predict(((X_test - mu) / sigma)[..., np.newaxis], verbose=0).flatten()
    return float(np.mean((pred_s - (y_test - mu) / sigma) ** 2)) * sigma**2, float(np.mean((X_test[:, -1] - y_test) ** 2))
  1. Window size. Retrain with window = 5 and window = 100. Which does better on test MSE? What does too short a window fail to capture here, given the periods used to build y?
    Hint

    The fastest component repeats every 17 steps. How much of one cycle does a window of 5 see?

    Solution
    for w in (5, 30, 100):
    print(w, "LSTM: %.4f  naive: %.4f" % run(w, lambda: tf.keras.layers.LSTM(24)))

    Window 5 gives a test MSE of 0.0509, window 30 gives 0.0300 and window 100 gives 0.0306 (persistence is 0.069 in all three cases; the test sets differ by a few windows). A window of 5 is shorter than even the fastest period, 17 steps, so it sees less than a third of a cycle and cannot tell where in the cycle it is; it still beats persistence, but by much less. A window of 100 covers both periods several times over and does no better than 30: once the window spans the relevant periods, more history adds parameters and training time, not accuracy.

  2. SimpleRNN vs. LSTM. Swap tf.keras.layers.LSTM(24) for tf.keras.layers.SimpleRNN(24) and retrain. Does test MSE change much on a sequence this short? At what point (longer sequences, more history required) would you expect the LSTM's gating to start mattering more?
    Hint

    Part 2's product has only 29 factors here, and the gradient only has to reach back 17 to 50 steps to see a full cycle.

    Solution
    for w in (5, 30, 100):
    print(w, "SimpleRNN: %.4f  naive: %.4f" % run(w, lambda: tf.keras.layers.SimpleRNN(24)))

    The plain RNN scores 0.0513, 0.0280 and 0.0289 at windows 5, 30 and 100, against 0.0509, 0.0300 and 0.0306 for the LSTM: no worse, and at 30 and 100 slightly better. On a window of 30 the gradient has to survive at most 29 steps, and a factor of 0.9 still leaves 5% of it after 29 steps; the information the forecast needs, the phase of two sines, is in the last 17 to 50 values anyway. The gates start to matter when the useful information sits hundreds of steps back, where 0.9^{k} is effectively zero: a rare event that changes the level of a series long afterwards, a bracket that has to be closed at the end of a sentence, a dependency on a value many cycles ago. On a series like this one, the LSTM's extra machinery is unused.

  3. A linear baseline. Fit an ordinary least-squares regression of y_train on the 30 columns of X_train (plus an intercept) and score it on the test windows. How does it compare with the LSTM, and why?
    Hint

    One call to np.linalg.lstsq. Then recall that a sine satisfies y_t = 2\cos(\omega)\,y_{t-1} - y_{t-2}.

    Solution
    A_train = np.c_[X_train, np.ones(len(X_train))]
coef = np.linalg.lstsq(A_train, y_train, rcond=None)[0]
lin_pred = np.c_[X_test, np.ones(len(X_test))] @ coef
mse_linear = float(np.mean((lin_pred - y_test) ** 2))
print(f"linear autoregression test MSE: {mse_linear:.4f}")

    The linear model scores 0.0246, better than the LSTM's 0.0300 and the SimpleRNN's 0.0280. The signal is a sum of sines, and a noise-free sine obeys the exact linear recurrence in the hint, so a sum of three sines is reproduced exactly by a linear rule on six lags; with noise on every lag, averaging over 30 lags is what keeps the fit close to the floor of 0.0213. Nothing in this series is nonlinear, so the LSTM's nonlinearity has nothing to model and only its optimisation error shows. With 100 lags the linear model reaches 0.0233. Before training a recurrent network on a series, fit the linear autoregression: if the network cannot beat it, the series does not need the network.

  4. The noise floor. The notebook built y from a known signal plus noise. Use the noise-free signal as a forecast of the test targets and compute its MSE. Where do persistence, the LSTM and the linear model sit relative to it?
    Hint

    Rebuild the three sines without the np.random.normal term and index them with window + n_train onwards.

    Solution
    signal = (np.sin(2*np.pi*t/50) + 0.5*np.sin(2*np.pi*t/17) + 0.02*np.sin(2*np.pi*t/400)).astype("float32")
mse_oracle = float(np.mean((signal[window + n_train:] - y_test) ** 2))
print(f"noise floor (true signal as the forecast): {mse_oracle:.4f}")

    The perfect forecast scores 0.0213: the variance of the 394 test noise draws, a little under the nominal 0.15^2 = 0.0225. Persistence is 0.0480 above the floor, the LSTM 0.0087 above it, the linear model 0.0033. Measured as "excess error over what is possible", the LSTM removed 82% of persistence's excess and the linear model 93%. The floor is only known because the series is synthetic; on real data it is the quantity one would most like to know and cannot, which is why baselines matter so much.

  5. Train longer. The training loss is still falling at epoch 15. Train for 60 epochs, and try two other random seeds at 15 epochs. How much of the LSTM's gap to the linear model is under-training, and how much is run-to-run variation?
    Hint

    The helper takes an epochs argument; for the seeds, change the number in set_random_seed.

    Solution
    print(run(30, lambda: tf.keras.layers.LSTM(24), epochs=60))

    Sixty epochs bring the test MSE from 0.0300 to 0.0288, still above the linear model's 0.0246. Seeds 1, 2 and 3 give 0.0323, 0.0304 and 0.0315 at 15 epochs, so the notebook's 0.0300 is at the lucky end of a spread of about 0.002. Neither longer training nor a kinder seed closes the gap: the remaining 0.004 is the price of fitting 2,521 parameters by stochastic gradient descent to a problem that 31 parameters solve in closed form.
