Part 1

Reinforcement learning from scratch

1.1 Learning from consequences

Most machine learning you have met is supervised: a dataset of inputs paired with correct answers, and a model trained to reproduce those answers. Reinforcement learning (RL) drops the answers. An agent acts in an environment, the environment responds, and every so often a number called the reward says how well things are going. The agent's job is to discover, by trial and error, behaviour that collects as much reward as possible over time.

That small change makes the problem different in kind, not just in degree:

Supervised learningReinforcement learning
DataA fixed dataset, collected beforehandGenerated by the agent's own actions, so what it sees depends on how it behaves
FeedbackThe correct answer for every inputA scalar reward that says how good an outcome was, never what the right action would have been
TimingImmediate: each prediction is scored on its ownOften delayed: a move early in a chess game decides the result 40 moves later
SamplesAssumed independent and identically distributedStrongly correlated sequences, and the distribution shifts as the agent improves
GoalMinimise prediction error on new inputsMaximise cumulative reward

Two difficulties follow from this table and run through the whole field. The credit assignment problem: when a reward finally arrives, which of the many earlier actions deserve the credit? And the exploration–exploitation dilemma: to find better behaviour the agent must try things it currently thinks are worse (section 1.3).

Read more: the opening chapter of [Sutton & Barto, ch. 1] is the classic, very readable introduction. [Morales, ch. 1–2] covers the same ground with more pictures and code.

1.2 The vocabulary

Every RL problem is described with the same handful of words. You will see all of them again in the math and in the code.

  • Agent: the learner and decision-maker. Here, a neural network plus the rule for choosing actions.
  • Environment: everything outside the agent. It receives actions and returns observations and rewards. Here, the simulated cart and pole.
  • State s (or observation): what the agent sees at a time step. A state fully describes the situation, an observation may be partial. In CartPole they coincide.
  • Action a: what the agent can do. CartPole has two: push left or push right.
  • Reward r: a scalar signal after each step. It defines the goal, but only through its sum over time.
  • Episode: one run from a start state to an end, such as one game or one attempt at balancing.
  • Policy \pi: the agent's behaviour, a mapping from states to actions (or to probabilities of actions). Learning a good policy is the whole point.
  • Return G: the (discounted) sum of rewards from some time onwards. The quantity the agent actually maximises.
  • Value function: the expected return from a state, or from a state and an action. It predicts long-term consequences, which is how RL tackles credit assignment.
  • Model: the agent's knowledge of how the environment works, meaning which state follows which action and what reward arrives. DQN does not use one.

The field rests on one assumption, which Sutton and Barto call the reward hypothesis: any goal we care about can be expressed as maximising the expected cumulative sum of a scalar reward. Designing that reward is part of the problem:

TaskStateActionsReward
CartPoleCart position and velocity, pole angle and angular velocityPush left, push right+1 per step the pole stays up
ChessThe board and whose turn it isLegal moves+1 win, −1 loss, 0 otherwise (only at the end)
ThermostatTemperatures, time of day, occupancyHeating power− energy cost − discomfort
Robot arm graspingJoint angles, camera imageJoint torques (continuous)+1 when the object is lifted

Read more: the agent–environment interface and the reward hypothesis are in [Sutton & Barto, §3.1–3.2].

1.3 Exploration versus exploitation

Imagine you have a favourite restaurant. Going back is exploiting what you know. Trying a new place is exploring: usually worse, occasionally a new favourite. With only exploitation you never find out whether something better exists. With only exploration you never benefit from what you've learned.

The simplest RL problem that captures this is the multi-armed bandit: k slot machines, each paying out a random reward with an unknown mean q_*(a). There are no states and no delayed consequences, just repeated choices. A natural strategy is to estimate each machine's value by the average reward it has paid so far, Q(a), and usually pick the best estimate. The standard rule is ε-greedy: with probability 1-\varepsilon pick \arg\max_a Q(a), and with probability \varepsilon pick uniformly at random. DQN uses exactly this rule (section 3.14). The averaging trick behind Q(a) turns out to underpin every update in this tutorial (section 3.1).

Read more: [Sutton & Barto, ch. 2] is devoted to bandits, including the 10-armed testbed and cleverer strategies such as optimistic initial values and upper confidence bounds.

1.4 A map of RL methods

RL algorithms differ along a few independent axes. Knowing them tells you what DQN is, and what it is not.

  • Model-based or model-free. A model-based method knows or learns the environment's dynamics and plans with them. AlphaZero searches ahead with the rules of chess. A model-free method learns what to do directly from experienced transitions. DQN is model-free: it never learns the physics of the cart.
  • Value-based, policy-based or actor-critic. Value-based methods learn how good each action is and act greedily on those estimates. Policy-based methods adjust a parameterised policy \pi_\theta(a \mid s) directly by gradient ascent on expected return. Actor-critic methods do both. DQN is value-based.
  • On-policy or off-policy. On-policy methods learn about the policy they are currently running, so old data goes stale. Off-policy methods can learn about one policy (the greedy one) from data generated by another (an exploring one, or an older version). DQN is off-policy, which is what lets it replay old experience.
  • Discrete or continuous actions. DQN needs a \max over actions, so it is built for small discrete action sets. Continuous control (the robot arm) usually calls for actor-critic methods such as SAC.

Read more: [Sutton & Barto, §1.3–1.6] for the elements of RL, [Graesser & Keng, ch. 1] for a taxonomy of deep RL algorithms, and [OpenAI Spinning Up, part 2] for a one-page map.

Part 2

The Gymnasium API

Gymnasium [Towers et al., 2024], the maintained successor of OpenAI Gym, is the standard Python interface between RL agents and environments. Because every environment speaks the same small API, the same agent code runs on CartPole, Atari games, MuJoCo robots, or an environment you write yourself. This part covers the API in depth. Everything shown was run with Gymnasium 1.3.

2.1 The interaction loop

import gymnasium as gym

env = gym.make("CartPole-v1")

obs, info = env.reset(seed=42)          # first observation of a new episode
episode_return = 0.0
while True:
    action = env.action_space.sample()  # a random policy, for now
    obs, reward, terminated, truncated, info = env.step(action)
    episode_return += reward
    if terminated or truncated:          # the episode is over
        break

print(episode_return)                   # about 22 on average for random actions
env.close()                             # free resources (windows, simulators)

Every environment is a subclass of gym.Env and exposes:

MemberWhat it does
reset(seed=None, options=None)Starts a new episode. Returns (observation, info).
step(action)Advances one time step. Returns (observation, reward, terminated, truncated, info).
render()Draws the current state, in the mode chosen at creation: render_mode="human" opens a window, "rgb_array" returns a NumPy image.
close()Releases resources.
observation_space, action_spaceDescribe valid observations and actions (section 2.2).
spec, metadataRegistration details (id, time limit, reward threshold) and supported render modes.
np_randomThe environment's own NumPy random generator, seeded by reset(seed=...).
unwrappedThe raw environment underneath all wrappers (section 2.5).

The five values from step deserve care. reward is a float. terminated is True when the environment reached a terminal state of the task itself, for CartPole when the pole fell or the cart left the track. truncated is True when something outside the task stopped the episode, usually a time limit. info is a dict of diagnostics that should never be used for learning. Older Gym versions returned a single done flag. Splitting it in two matters for learning, as section 3.11 explains.

2.2 Spaces: describing inputs and outputs

A space describes a set of valid values, can check membership, and can sample from itself. The network's input and output sizes come straight from the environment's spaces.

Each space has its own random generator for sample(), seeded with space.seed(n). That is separate from the environment's generator, which is seeded through reset.

2.3 Creating environments: make, the registry and specs

Environments are created by id from a global registry. gym.make looks up the id, builds the environment, and wraps it in a few standard wrappers:

env = gym.make("CartPole-v1")
print(env)          # <TimeLimit<OrderEnforcing<PassiveEnvChecker<CartPoleEnv<CartPole-v1>>>>>
print(env.spec.id, env.spec.max_episode_steps, env.spec.reward_threshold)  # CartPole-v1 500 475.0
print(env.metadata) # {'render_modes': ['human', 'rgb_array'], 'render_fps': 50}
print(env.unwrapped)                                   # <CartPoleEnv<CartPole-v1>>

short = gym.make("CartPole-v1", max_episode_steps=200)   # override the time limit
video = gym.make("CartPole-v1", render_mode="rgb_array") # frames as NumPy arrays
gym.pprint_registry()                                   # list every registered id
  • PassiveEnvChecker checks, once, that the environment follows the API (correct return types, observations inside the observation space).
  • OrderEnforcing raises an error if you call step before reset.
  • TimeLimit counts steps and sets truncated=True after max_episode_steps. The time limit is not part of CartPole's physics; this wrapper adds it.

The -v1 suffix is a version number. When an environment's behaviour changes, its version is bumped, so published results remain comparable.

2.4 Seeding and reproducibility

Randomness enters an RL experiment in several places, and each has its own seed:

obs_a, _ = env.reset(seed=0)
obs_b, _ = env.reset(seed=0)
assert (obs_a == obs_b).all()     # same seed, same start state
obs_c, _ = env.reset()            # no seed: continue the RNG seeded above -> new start state

env.action_space.seed(0)          # the RNG behind env.action_space.sample()

import random, numpy as np, torch
random.seed(0); np.random.seed(0); torch.manual_seed(0)   # the agent's own randomness

Passing seed to reset re-seeds env.np_random. The usual pattern is to seed the first reset only and let later resets continue the same random stream. The code in Part 4 instead passes a different seed on every episode, which makes each episode's start state reproducible on its own. Even with every seed fixed, results can differ slightly across hardware and library versions, which is one reason to average over several runs (section 5.2).

2.5 Wrappers

A wrapper is an environment that contains another environment and changes some part of its behaviour: observations, rewards, actions, or bookkeeping. Wrappers compose, and the outermost one is applied last.

from gymnasium.wrappers import RecordEpisodeStatistics, TransformReward

env = gym.make("CartPole-v1")
env = RecordEpisodeStatistics(env)            # adds the episode's return and length to info
env = TransformReward(env, lambda r: 0.1 * r) # scales every reward

obs, info = env.reset(seed=1)
while True:
    obs, reward, terminated, truncated, info = env.step(env.action_space.sample())
    if terminated or truncated:
        break
print(reward)            # 0.1: the agent sees scaled rewards
print(info["episode"])   # {'r': 29.0, 'l': 29, 't': 0.001}: statistics of the raw rewards

Order matters: RecordEpisodeStatistics sits inside TransformReward, so it records the original rewards while the agent trains on the scaled ones. Commonly used built-in wrappers include:

WrapperEffect
TimeLimitTruncates episodes after a number of steps (added by make)
RecordEpisodeStatisticsPuts return r, length l and time t in info["episode"] when an episode ends
RecordVideoSaves videos of selected episodes (needs render_mode="rgb_array")
NormalizeObservationStandardises observations with a running mean and variance
TransformObservation, TransformRewardApply any function to observations or rewards
FrameStackObservationStacks the last k observations, which makes single image frames Markov (section 3.2)

Writing your own wrapper means subclassing gym.Wrapper (or the narrower ObservationWrapper, RewardWrapper and ActionWrapper) and overriding the method you want to change. This one adds a penalty for drifting away from the centre, a technique called reward shaping that exercise 4 asks you to try:

class CenteringPenalty(gym.Wrapper):
    """Penalise the cart for drifting away from the centre of the track."""

    def __init__(self, env, weight=0.5):
        super().__init__(env)
        self.weight = weight

    def step(self, action):
        obs, reward, terminated, truncated, info = self.env.step(action)
        reward -= self.weight * abs(obs[0]) / 2.4     # obs[0] is the cart position
        return obs, reward, terminated, truncated, info

env = CenteringPenalty(gym.make("CartPole-v1"))

2.6 Writing your own environment

The best way to understand the interface is to implement it. Here is a tiny environment used again in section 3.9: a corridor of 7 cells. The agent starts in the middle and can step left or right. Reaching the right end gives +1 and ends the episode. Reaching the left end ends it with nothing.

import gymnasium as gym
from gymnasium import spaces

class Corridor(gym.Env):
    """Walk right to the goal. Actions: 0 = left, 1 = right."""
    metadata = {"render_modes": []}

    def __init__(self, length=7):
        self.length = length
        self.observation_space = spaces.Discrete(length)  # the cell index
        self.action_space = spaces.Discrete(2)

    def reset(self, *, seed=None, options=None):
        super().reset(seed=seed)          # seeds self.np_random; always call it
        self.pos = self.length // 2
        return self.pos, {}               # (observation, info)

    def step(self, action):
        self.pos += 1 if action == 1 else -1
        terminated = self.pos in (0, self.length - 1)
        reward = 1.0 if self.pos == self.length - 1 else 0.0
        return self.pos, reward, terminated, False, {}   # truncation is TimeLimit's job

from gymnasium.utils.env_checker import check_env
check_env(Corridor())                     # raises if the API contract is broken

gym.register(id="Corridor-v0", entry_point=Corridor, max_episode_steps=50)
env = gym.make("Corridor-v0")             # <TimeLimit<OrderEnforcing<PassiveEnvChecker<Corridor>>>>

Note the division of labour: the environment reports terminated for real endings, and the TimeLimit wrapper added by registration reports truncated. Any randomness in reset or step should come from self.np_random, so that seeding works.

2.7 Vectorised environments

Deep RL is often limited by how fast it can collect experience. A vectorised environment steps several copies at once and returns batched arrays:

envs = gym.make_vec("CartPole-v1", num_envs=8, vectorization_mode="sync")  # or "async"
obs, info = envs.reset(seed=42)       # obs.shape == (8, 4)
envs.single_action_space              # Discrete(2)
envs.action_space                     # MultiDiscrete([2 2 2 2 2 2 2 2])
obs, rewards, terminated, truncated, info = envs.step(envs.action_space.sample())
rewards.shape, terminated.shape       # (8,), (8,)

Sub-environments reset themselves automatically. In Gymnasium 1.x the default next-step autoreset means that the step after a sub-environment's episode ends returns the first observation of its new episode, and the action you sent for it on that step is ignored. Handle this when storing transitions. The DQN in this tutorial uses a single environment, which keeps the code simple.

2.8 CartPole-v1 in detail

A pole is attached by an unactuated hinge to a cart that moves along a frictionless track. The agent pushes the cart left or right with a fixed force of 10 N, 50 times per second, and must keep the pole upright. This is the same problem that Barto, Sutton and Anderson used in 1983 [Barto et al., 1983].

IndexObservationMinMaxEpisode ends when
0Cart position x (m)−4.84.8|x| > 2.4
1Cart velocity \dot x (m/s)−∞∞
2Pole angle \theta (rad, 0 = upright)−0.4190.419|\theta| > 12^\circ \approx 0.2095

The episode return is therefore the number of steps survived, and 500 is a perfect score. A random policy survives about 22 steps on average. The observation bounds for x and \theta are twice the termination thresholds, so the episode always ends before an observation reaches them.

2.9 The physics inside step

With cart mass m_c = 1 kg, pole mass m_p = 0.1 kg, half pole length l = 0.5 m, g = 9.8 m/s² and force F = \pm 10 N, CartPole integrates the equations of motion of a cart carrying an inverted pendulum [Barto et al., 1983], as corrected by [Florian, 2007]:

Equations of motion
\ddot\theta = \frac{g\sin\theta - \cos\theta\,\dfrac{F + m_p l \dot\theta^2 \sin\theta}{m_c + m_p}}{l\left(\dfrac{4}{3} - \dfrac{m_p \cos^2\theta}{m_c + m_p}\right)}
\ddot x = \frac{F + m_p l \dot\theta^2 \sin\theta}{m_c + m_p} - \frac{m_p l\, \ddot\theta \cos\theta}{m_c + m_p}
Explicit Euler step, τ = 0.02 s
x_{t+1} = x_t + \tau \dot x_t, \qquad \dot x_{t+1} = \dot x_t + \tau \ddot x_t
\theta_{t+1} = \theta_t + \tau \dot\theta_t, \qquad \dot\theta_{t+1} = \dot\theta_t + \tau \ddot\theta_t

Two things to take from this. First, the dynamics are deterministic: the only randomness in CartPole is the start state. Second, the agent never sees these equations. DQN is model-free (section 1.4) and learns only from sampled transitions. The simulation at the top of this page runs exactly these equations in JavaScript.

Why is this hard at all? Pushing the cart right tips the pole left at first (try it in the demo as "You"). To move the pole right you must first move the cart the "wrong" way. The agent has to discover this from rewards alone.

Part 3

The math, from averages to the DQN loss

This part builds everything DQN needs, one idea at a time. The only prerequisites are expectations and a little calculus. The notation follows [Sutton & Barto] where possible.

3.1 Expectations and running averages

The expectation of a function f of a random variable x with distribution p is its probability-weighted average. When we can only draw samples, we estimate it by a sample mean:

\mathbb{E}_{x \sim p}\big[f(x)\big] = \sum_x p(x)\, f(x) \;\approx\; \frac{1}{n} \sum_{i=1}^{n} f(x_i), \qquad x_i \sim p

Keeping every sample to recompute the mean is wasteful. With a little algebra the mean of n samples can be written in terms of the mean of the first n-1:

\mu_n = \frac{1}{n}\sum_{i=1}^{n} x_i = \frac{1}{n}\Big( x_n + (n-1)\,\mu_{n-1} \Big) = \mu_{n-1} + \frac{1}{n}\big( x_n - \mu_{n-1} \big)

Replace the step 1/n by a constant \alpha \in (0, 1] and you get the update at the heart of almost every RL algorithm:

The universal update
\text{estimate} \leftarrow \text{estimate} + \alpha \,\big(\, \text{target} - \text{estimate} \,\big)

A constant \alpha weights recent samples more than old ones: after n updates, \mu_n = (1-\alpha)^n \mu_0 + \sum_{i=1}^{n} \alpha (1-\alpha)^{n-i} x_i. That is what you want when the thing being estimated keeps changing, and in RL it always does, because the targets depend on a policy that keeps improving. With a decreasing step size \alpha_n, stochastic approximation theory [Robbins & Monro, 1951] guarantees convergence to the true mean under the conditions

\sum_{n=1}^{\infty} \alpha_n = \infty, \qquad \sum_{n=1}^{\infty} \alpha_n^2 \lt \infty

The first condition makes the steps large enough to overcome any initial error, and the second makes them small enough to average out the noise eventually. \alpha_n = 1/n satisfies both; a constant \alpha does not, and keeps tracking instead. Every learning rule below is this update with a different target.

Read more: [Sutton & Barto, §2.4–2.5] derive the incremental update and the step-size conditions. For probability background see [Goodfellow et al., ch. 3].

3.2 Markov decision processes

RL problems are formalised as a Markov decision process (MDP) [Bellman, 1957], a tuple

\mathcal{M} = (\mathcal{S}, \mathcal{A}, P, R, \gamma)
  • \mathcal S, the set of states. For CartPole, s = (x, \dot x, \theta, \dot\theta) \in \mathbb{R}^4.
  • \mathcal A, the set of actions: \{0, 1\}.
  • P(s' \mid s, a), the probability of moving to s' after taking a in s. For CartPole all of it sits on the single state given by the Euler step in section 2.9.
  • R(s, a), the expected immediate reward. For CartPole, always 1.
  • \gamma \in [0, 1), the discount factor (section 3.3).

At each step t the agent sees s_t, picks a_t, receives r_{t+1} and lands in s_{t+1}. The word Markov means the current state contains everything needed to predict what happens next:

P(s_{t+1} \mid s_t, a_t) = P(s_{t+1} \mid s_0, a_0, s_1, a_1, \dots, s_t, a_t)

CartPole's observation is Markov because it includes the velocities. A single camera frame would not be: from one image you cannot tell which way the pole is swinging. That is why DQN on Atari stacks the last four frames (the FrameStackObservation wrapper from section 2.5).

A policy \pi(a \mid s) and the dynamics together define the probability of a whole trajectory \tau = (s_0, a_0, s_1, a_1, \dots):

p_\pi(\tau) = p(s_0) \prod_{t \ge 0} \pi(a_t \mid s_t)\, P(s_{t+1} \mid s_t, a_t)

Tasks that end, like CartPole or a game of chess, are episodic. Tasks that go on forever, like the thermostat, are continuing. Discounting handles both with the same formulas.

Read more: [Sutton & Barto, ch. 3] for finite MDPs. [Puterman, ch. 2–4] is the rigorous reference, and [Bertsekas, ch. 1] gives the control-theory perspective.

3.3 Returns and discounting

The agent maximises the return, the discounted sum of future rewards:

Discounted return
G_t = r_{t+1} + \gamma r_{t+2} + \gamma^2 r_{t+3} + \dots = \sum_{k=0}^{\infty} \gamma^k\, r_{t+k+1}
Its recursive form, which everything below builds on
G_t = r_{t+1} + \gamma\, G_{t+1}

If rewards are bounded by |r| \le r_{\max}, then |G_t| \le r_{\max}/(1-\gamma), so the discount keeps infinite sums finite. It also makes reward that arrives sooner worth more than reward that arrives later. A useful rule of thumb is that the agent effectively looks about 1/(1-\gamma) steps ahead. After an episode ends, all later rewards are taken to be 0. In CartPole every reward is 1, so a state from which the pole survives exactly N more steps has return

G = \sum_{k=0}^{N-1} \gamma^k = \frac{1 - \gamma^N}{1 - \gamma}, \qquad \lim_{N \to \infty} G = \frac{1}{1-\gamma}

With \gamma = 0.99, balancing forever is worth 100, while a state 10 steps before a certain fall is worth only about 9.6. That gap is how the agent "sees" danger. Drag the slider to see how \gamma shapes it:

Read more: [Sutton & Barto, §3.3–3.4] on returns, episodic and continuing tasks.

3.4 Policies and value functions

A policy can be deterministic, a function a = \mu(s), or stochastic, a distribution \pi(a \mid s). ε-greedy is stochastic. Returns are random: they depend on the start state, on the policy's random choices and, in general, on random transitions. Value functions are their expectations, and they come in two flavours:

State-value function: how good is it to be in s?
V^\pi(s) = \mathbb{E}_\pi\!\left[\, G_t \mid s_t = s \,\right]
Action-value function: how good is it to take a in s, then follow π?
Q^\pi(s, a) = \mathbb{E}_\pi\!\left[\, G_t \mid s_t = s,\ a_t = a \,\right]

The subscript \pi means the expectation is over trajectories generated by following \pi. The two functions are tied together. The value of a state is the policy-weighted average of its action values, and the value of an action is its immediate reward plus the discounted value of where it leads:

V^\pi(s) = \sum_{a} \pi(a \mid s)\, Q^\pi(s, a)
Q^\pi(s, a) = R(s, a) + \gamma \sum_{s'} P(s' \mid s, a)\, V^\pi(s')

For control, Q is the more useful of the two. To choose between actions with V you need to know where each action leads, which requires P. With Q you compare numbers directly, without a model.

3.5 The Bellman expectation equation

Here is the derivation that makes RL tractable. Start from the definition of V^\pi and substitute the recursive return from section 3.3:

Derivation
\displaystyle V^\pi(s) = \mathbb{E}_\pi\big[\, G_t \mid s_t = s \,\big]definition
\displaystyle = \mathbb{E}_\pi\big[\, r_{t+1} + \gamma\, G_{t+1} \mid s_t = s \,\big]recursive return
\displaystyle = \sum_a \pi(a \mid s) \Big( R(s, a) + \gamma \sum_{s'} P(s' \mid s, a)\; \mathbb{E}_\pi\big[\, G_{t+1} \mid s_{t+1} = s' \,\big] \Big)condition on a and s′; Markov property
\displaystyle = \sum_a \pi(a \mid s) \Big( R(s, a) + \gamma \sum_{s'} P(s' \mid s, a)\; V^\pi(s') \Big)definition of Vπ(s′)

The second line uses linearity of expectation. The third conditions on the first action and next state, and uses the Markov property: once we know s_{t+1} = s', the future return does not depend on how we got there. The last line recognises that expectation as V^\pi(s'). The result is the Bellman expectation equation, and the same steps give its action-value form:

Bellman expectation equations
V^\pi(s) = \sum_a \pi(a \mid s) \Big( R(s, a) + \gamma \sum_{s'} P(s' \mid s, a)\, V^\pi(s') \Big)
Q^\pi(s, a) = R(s, a) + \gamma \sum_{s'} P(s' \mid s, a) \sum_{a'} \pi(a' \mid s')\, Q^\pi(s', a')

A statement about infinitely long futures has become a relation between neighbouring states. For a finite MDP with n states this is a linear system: stacking values into a vector, V^\pi = R^\pi + \gamma P^\pi V^\pi, so V^\pi = (I - \gamma P^\pi)^{-1} R^\pi. The matrix is invertible because \gamma \lt 1.

3.6 Optimality

The optimal value functions are the best achievable over all policies:

V^*(s) = \max_\pi V^\pi(s), \qquad Q^*(s, a) = \max_\pi Q^\pi(s, a)
V^*(s) = \max_a Q^*(s, a)

Acting optimally from s means taking the best action, collecting its reward, and acting optimally again from wherever you land. Replacing the policy average in section 3.5 by a maximum gives the Bellman optimality equations:

Bellman optimality equations
V^*(s) = \max_a \Big( R(s, a) + \gamma \sum_{s'} P(s' \mid s, a)\, V^*(s') \Big)
Q^*(s, a) = R(s, a) + \gamma \sum_{s'} P(s' \mid s, a)\, \max_{a'} Q^*(s', a')

Once you have Q^*, acting optimally needs no model and no planning. The greedy policy is optimal:

\pi^*(s) = \arg\max_{a} Q^*(s, a)

Why greedy is enough is the policy improvement theorem: if \pi' is greedy with respect to Q^\pi, then V^{\pi'}(s) \ge V^\pi(s) in every state. A policy greedy with respect to Q^* therefore cannot be improved on. In finite MDPs an optimal policy that is deterministic always exists. This is the quantity DQN learns, and it is what the demo does: the network outputs Q(s,\text{left}) and Q(s,\text{right}), and the cart is pushed toward the larger one.

Read more: [Sutton & Barto, §3.5–3.6 and §4.2] for the Bellman equations and policy improvement. [Puterman, ch. 6] proves existence of deterministic optimal policies.

3.7 Dynamic programming: solving Bellman when the model is known

If we know P and R, we can compute Q^* by treating the right-hand side of the optimality equation as an operator \mathcal T that maps one Q-function to another:

(\mathcal{T} Q)(s, a) = R(s, a) + \gamma \sum_{s'} P(s' \mid s, a)\, \max_{a'} Q(s', a')

Q^* is a fixed point: \mathcal T Q^* = Q^*. The key fact is that \mathcal T is a \gamma-contraction in the max-norm \|Q\|_\infty = \max_{s,a} |Q(s,a)|. For any two Q-functions,

Contraction
\displaystyle \big|(\mathcal{T} Q)(s,a) - (\mathcal{T} Q')(s,a)\big| = \gamma \,\Big| \sum_{s'} P(s' \mid s,a) \big( \max_{a'} Q(s',a') - \max_{a'} Q'(s',a') \big) \Big|R(s, a) cancels
\displaystyle \le \gamma \sum_{s'} P(s' \mid s,a)\, \max_{a'} \big| Q(s',a') - Q'(s',a') \big|triangle inequality; |max f − max g| ≤ max |f − g|
\displaystyle \le \gamma\, \| Q - Q' \|_\inftyprobabilities sum to 1

The middle step uses |\max_a f(a) - \max_a g(a)| \le \max_a |f(a) - g(a)|, and the last uses that the probabilities sum to 1. Taking the maximum over (s,a) gives \|\mathcal T Q - \mathcal T Q'\|_\infty \le \gamma \|Q - Q'\|_\infty. By the Banach fixed-point theorem, Q^* is the unique fixed point, and repeatedly applying \mathcal T from any starting point converges to it geometrically:

Q_{k+1} = \mathcal{T} Q_k \quad\Longrightarrow\quad \| Q_k - Q^* \|_\infty \le \gamma^k\, \| Q_0 - Q^* \|_\infty

This algorithm is value iteration. Its sibling, policy iteration, alternates between computing V^\pi exactly (section 3.5) and making the policy greedy (section 3.6), and converges in finitely many iterations for finite MDPs. Both are planning methods: they need P and R. Reinforcement learning is what you do when you don't have them and can only sample. You can run value iteration by hand in the corridor widget in section 3.9.

Read more: [Sutton & Barto, ch. 4] for dynamic programming, [Szepesvári, §1.3 and ch. 2] and [Agarwal et al., ch. 1] for the contraction argument, [Bertsekas] for the broader theory.

3.8 Learning from samples: Monte Carlo and temporal differences

Without a model, we estimate values from experience using the universal update of section 3.1. The question is what to use as the target. Consider estimating V^\pi while following \pi:

Monte Carlo: wait for the actual return
V(s_t) \leftarrow V(s_t) + \alpha \big[\, G_t - V(s_t) \,\big]
Temporal difference, TD(0): use one reward plus the current estimate
V(s_t) \leftarrow V(s_t) + \alpha \big[\, r_{t+1} + \gamma V(s_{t+1}) - V(s_t) \,\big]
Monte CarloTemporal difference
TargetG_t, the real returnr_{t+1} + \gamma V(s_{t+1})
Can updateOnly after the episode endsAfter every step, online
BiasUnbiased: \mathbb{E}[G_t] = V^\pi(s_t)Biased while V is wrong
VarianceHigh: sums many random rewardsLow: one random step
Uses the Markov propertyNoYes: bootstraps from its own estimate

The TD target is a one-sample estimate of the right-hand side of the Bellman equation, so TD learning is a sampled, incremental version of dynamic programming. The bracketed quantity \delta_t = r_{t+1} + \gamma V(s_{t+1}) - V(s_t) is the TD error. Methods in between, which sum n real rewards and then bootstrap, are called n-step methods.

Read more: [Sutton & Barto, ch. 5] for Monte Carlo methods, [ch. 6] for TD learning (the random-walk example in §6.2 is a close cousin of the corridor below), and [ch. 7] for n-step methods.

3.9 From prediction to control: SARSA and Q-learning

To improve behaviour we estimate action values instead of state values and act (mostly) greedily on them. There are two classic ways to build the TD target:

SARSA (on-policy): bootstrap from the action actually taken next
Q(s, a) \leftarrow Q(s, a) + \alpha \big[\, r + \gamma\, Q(s', a') - Q(s, a) \,\big], \qquad a' \sim \pi(\cdot \mid s')
Q-learning (off-policy): bootstrap from the best next action
Q(s, a) \leftarrow Q(s, a) + \alpha\, \underbrace{\Big[\, \overbrace{r + \gamma \max_{a'} Q(s', a')}^{\text{TD target } y} - Q(s, a) \,\Big]}_{\text{TD error } \delta}

SARSA (named after the quintuple s, a, r, s', a') learns the value of the policy it is running, exploration included. Q-learning [Watkins & Dayan, 1992] uses \max_{a'}, so its target is a sample of the Bellman optimality equation: it learns about the greedy policy whatever the agent actually does next. That makes it off-policy, which is what later lets DQN learn from random exploration and from old, replayed experience. For a table of Q-values, Watkins and Dayan proved that Q-learning converges to Q^* with probability 1, provided every state–action pair is visited infinitely often and the step sizes satisfy the conditions of section 3.1. For terminal s' the future term is dropped, and the target is just r.

Try it. Each cell below is a state of the corridor environment from section 2.6, showing its two Q-values. The small grey numbers are Q^*, computed by value iteration. The update line shows exactly the formula above with the numbers filled in.

The same algorithm in Python, using the corridor environment from section 2.6:

import numpy as np

Q = np.zeros((7, 2))                     # one row per cell, one column per action
alpha, gamma, epsilon = 0.5, 0.9, 0.1
rng = np.random.default_rng(0)

def greedy(q_row):                       # argmax with random tie-breaking
    return int(rng.choice(np.flatnonzero(q_row == q_row.max())))

env = gym.make("Corridor-v0")
for episode in range(300):
    s, _ = env.reset(seed=episode)
    done = False
    while not done:
        a = int(rng.integers(2)) if rng.random() < epsilon else greedy(Q[s])
        s_next, r, terminated, truncated, _ = env.step(a)
        target = r + gamma * (0.0 if terminated else Q[s_next].max())
        Q[s, a] += alpha * (target - Q[s, a])            # the universal update
        s, done = s_next, terminated or truncated

print(Q.round(3))   # Q[3:6, 1] -> 0.81, 0.9, 1.0: matches Q* along the path to the goal

A classic pitfall: with np.argmax(Q[s]) in place of greedy, ties always go to action 0. All Q-values start at 0, so the agent walks left every time, rarely reaches the goal with ε = 0.1, and learns nothing. Random tie-breaking fixes it.

Read more: [Sutton & Barto, §6.4–6.5] for SARSA and Q-learning, including the cliff-walking example that shows how their behaviour differs. The convergence proof is in [Watkins & Dayan, 1992].

3.10 From a table to a neural network

CartPole's state is continuous, so no table can hold it, and even a fine grid would never visit the same cell twice. Instead we approximate Q with a neural network Q(s, a; \theta) with weights \theta. Similar states get similar values, so what is learned in one state generalises to states never seen before. The network takes the 4 state numbers and outputs one value per action, so a single forward pass scores both actions. The Q-learning update becomes a regression problem: make Q(s,a;\theta) match the TD target, on average over transitions (s,a,r,s',d) drawn from a replay buffer \mathcal D:

DQN loss [Mnih et al., 2015]
\mathcal{L}(\theta) = \mathbb{E}_{(s,a,r,s',d) \sim \mathcal{D}}\Big[ \big(\, y - Q(s, a; \theta) \,\big)^2 \Big]
y = r + \gamma\,(1 - d)\, \max_{a'} Q(s', a'; \theta^-)
  • d \in \{0, 1\} is the terminal flag. When d = 1 the future term vanishes and y = r, exactly as the Bellman equation requires.
  • \theta^- are the weights of a separate target network, a lagged copy of \theta (section 3.12).

Differentiating while treating the target y as a constant label gives the semi-gradient:

\nabla_\theta \mathcal{L} = -2\, \mathbb{E}\Big[ \big(y - Q(s,a;\theta)\big)\, \nabla_\theta Q(s,a;\theta) \Big]

A gradient step with learning rate \eta is then \theta \leftarrow \theta + 2\eta\, \delta\, \nabla_\theta Q(s,a;\theta) with \delta = y - Q(s,a;\theta): the universal update of section 3.1, applied to the parameters instead of a table entry. For a table, where \nabla_\theta Q picks out one entry, it reduces to tabular Q-learning. We deliberately don't differentiate through y, even though it depends on the network too. The target plays the role of a label, and letting gradients flow through it would also move the label toward the prediction, which in practice learns worse. In PyTorch this means computing y inside torch.no_grad().

Many implementations replace the square with the Huber loss [Huber, 1964], which is quadratic for small errors and linear for large ones, so one surprising transition cannot produce a huge gradient:

\ell(\delta) = \begin{cases} \tfrac12 \delta^2 & |\delta| \le 1 \\ |\delta| - \tfrac12 & \text{otherwise} \end{cases}

Its derivative is \ell'(\delta) = \operatorname{clip}(\delta, -1, 1): each transition's pull on the weights is capped.

Read more: [Sutton & Barto, ch. 9–10] for semi-gradient methods with function approximation, [Goodfellow et al., ch. 6 and 8] for neural networks and their optimisation.

3.11 Terminated is not truncated

The terminal flag d needs care, because an episode can stop for two reasons and only one of them is terminal in the MDP. This is why Gymnasium's step returns two flags (section 2.1).

Terminated (pole fell)Truncated (500 steps reached)
What happenedThe MDP reached a terminal stateWe stopped watching; the pole is still up
True future value0Up to 1/(1-\gamma) = 100
Correct targety = ry = r + \gamma \max_{a'} Q(s', a'; \theta^-)
Flag to stored = 1d = 0

The time step t is not part of CartPole's state. A balanced state at step 500 is indistinguishable from the same balanced state at step 200. If we stored d = 1 on truncation, the network would get the target y = 1 for inputs whose target is close to 100 everywhere else: contradictory labels for the same input, attached to the agent's most successful moments. Formally, the time limit makes the process non-Markov with respect to the observed state, unless you either bootstrap through it or add t to the observation [Pardo et al., 2018].

Rule: end the episode loop on terminated or truncated, but store only terminated as the terminal flag.

3.12 Making it stable: replay and target networks

Function approximation, bootstrapping and off-policy learning are each useful, but together they can make value estimates diverge. Sutton and Barto call this combination the deadly triad [Sutton & Barto, §11.3]. DQN's two stabilisers each tackle a different cause.

Experience replay [Lin, 1992]. Consecutive transitions are almost identical, while stochastic gradient descent assumes roughly independent samples. So every transition is stored in a buffer \mathcal D holding the most recent N (50,000 here), and each update samples a random mini-batch from it. This breaks the correlations, reuses each experience many times, and averages over many past behaviours. It works only because Q-learning is off-policy: the stored transitions were generated by older policies.

Target network. If y used \theta itself, every gradient step would also move the target it is chasing. Using a lagged copy \theta^- turns each stretch of training into an almost ordinary regression problem, which is roughly one step of value iteration (section 3.7) carried out by gradient descent. There are two common ways to update it:

Hard update, every C steps (or episodes)
\theta^- \leftarrow \theta
Soft (Polyak) update, every step, τ ≪ 1
\theta^- \leftarrow \tau\, \theta + (1 - \tau)\, \theta^-

With \tau = 0.005, the target network is an exponential moving average of the online weights over roughly the last 1/\tau = 200 steps. This is the running average of section 3.1 again.

Read more: [Sutton & Barto, ch. 11] on off-policy divergence, [Mnih et al., 2015] (Methods section) for the original design, and [Sutton & Barto, §16.5] for a textbook account of DQN on Atari.

3.13 Double DQN: the max is biased

The network's estimates are noisy, and the maximum of noisy numbers picks up the lucky ones. For any random estimates \hat Q, because the max is a convex function (Jensen's inequality),

\mathbb{E}\big[\max_{a} \hat Q(s, a)\big] \;\ge\; \max_{a} \mathbb{E}\big[\hat Q(s, a)\big]

so the DQN target is biased upward, and bootstrapping copies the bias from state to state. Double DQN [van Hasselt et al., 2016] decouples choosing the action from evaluating it. The online network picks the action and the target network scores it:

Double DQN target
y = r + \gamma\,(1-d)\; Q\big(s',\ \underbrace{\arg\max_{a'} Q(s', a'; \theta)}_{\text{chosen by the online net}};\ \theta^-\big)

Read more: [Sutton & Barto, §6.7] on maximisation bias and double learning in the tabular case.

3.14 Exploration with ε-greedy

The ε-greedy rule from section 1.3 takes a uniformly random action with probability \varepsilon and the greedy action otherwise. With |\mathcal A| = 2, the greedy action is chosen with probability 1 - \varepsilon/2. Exploration matters most early on, when the estimates are poor, so \varepsilon decays with the number of environment steps t:

\varepsilon(t) = \varepsilon_{\text{end}} + (\varepsilon_{\text{start}} - \varepsilon_{\text{end}})\, e^{-t / T}

with \varepsilon_{\text{start}} = 1, \varepsilon_{\text{end}} = 0.05 and T = 8000 steps in the code of Part 4.

Because Q-learning is off-policy, this random behaviour does not corrupt what is learned: the targets still describe the greedy policy.

3.15 The whole algorithm

Deep Q-learning with experience replay

  1. Initialise the online network \theta randomly, copy it into the target network \theta^- \leftarrow \theta, and create an empty replay buffer \mathcal D.
  2. For each episode, reset the environment to get s. Then repeat until the episode ends:
    1. With probability \varepsilon(t) pick a random action, otherwise a = \arg\max_a Q(s,a;\theta).
    2. Step the environment to get r, s', terminated and truncated. Store (s, a, r, s', d) in \mathcal D with d = terminated.
    3. Sample a mini-batch from \mathcal D, compute the targets y with \theta^-, and take one gradient step on (y - Q(s,a;\theta))^2.
    4. Update \theta^- (hard or soft). Set s \leftarrow s', and stop if terminated or truncated.

3.16 Beyond DQN

DQN opened the field of deep RL, and many improvements build directly on it:

  • Dueling networks [Wang et al., 2016] split the output into a state value and per-action advantages, Q(s,a) = V(s) + A(s,a) - \tfrac{1}{|\mathcal A|}\sum_{a'} A(s,a').
  • Prioritised replay [Schaul et al., 2016] samples transitions with large TD error more often.
  • Rainbow [Hessel et al., 2018] combines six extensions, including n-step returns and distributional value estimates.
  • Policy-gradient and actor-critic methods such as PPO [Schulman et al., 2017] optimise the policy directly and handle continuous actions. See [Sutton & Barto, ch. 13].

Read more: [Graesser & Keng] and [Lapan] implement most of these step by step. [Morales, ch. 9–10] covers DQN, Double DQN, dueling networks and prioritised replay.

The code, line by line

4.1 The Q-network

import torch
import torch.nn as nn

class DQN(nn.Module):
    def __init__(self, state_dim=4, action_dim=2, hidden_sizes=(128, 128)):
        super().__init__()
        layers, d = [], state_dim
        for h in hidden_sizes:
            layers += [nn.Linear(d, h), nn.ReLU()]
            d = h
        layers.append(nn.Linear(d, action_dim))  # one output per action, no activation
        self.net = nn.Sequential(*layers)

    def forward(self, s):   # s: (batch, 4)
        return self.net(s)  # -> (batch, 2): Q(s, left), Q(s, right)

A plain multilayer perceptron, 4 → 128 → 128 → 2, with 17,410 parameters. The output layer has no activation because Q-values are unbounded real numbers. One forward pass evaluates Q(s,\cdot\,;\theta) for both actions at once, which is why DQN is built for discrete action spaces.

4.2 The replay buffer

import random
from collections import deque, namedtuple

Transition = namedtuple("Transition", "state action reward next_state terminal")

class ReplayBuffer:
    def __init__(self, capacity=50_000):
        self.buffer = deque(maxlen=capacity)  # the oldest transitions fall off the end

    def push(self, state, action, reward, next_state, terminal):
        self.buffer.append(Transition(state, action, reward, next_state, terminal))

    def sample(self, batch_size=64):
        batch = random.sample(self.buffer, batch_size)  # uniform, without replacement
        return Transition(*zip(*batch))                  # rows -> columns

    def __len__(self):
        return len(self.buffer)

Transition(*zip(*batch)) transposes a list of 64 transitions into one Transition whose fields are 64-tuples, ready to become tensors. A deque with maxlen gives first-in, first-out memory for free.

4.3 Acting: ε-greedy

import math

def epsilon_by_step(t, eps_start=1.0, eps_end=0.05, decay_steps=8_000):
    return eps_end + (eps_start - eps_end) * math.exp(-t / decay_steps)

def select_action(q_net, state, epsilon):
    if random.random() < epsilon:
        return random.randrange(2)                     # explore
    with torch.no_grad():                              # acting needs no gradients
        s = torch.as_tensor(state, dtype=torch.float32).unsqueeze(0)  # (1, 4)
        return int(q_net(s).argmax(dim=1))             # exploit: argmax_a Q(s, a)

unsqueeze(0) adds the batch dimension the network expects, and argmax(dim=1) picks the action with the larger Q-value: the greedy policy of section 3.6. With continuous-valued network outputs, exact ties practically never happen, unlike in the tabular example.

4.4 The TD target

@torch.no_grad()  # y is a fixed label: the semi-gradient of section 3.10
def td_targets(r, s_next, terminal, q_net, target_net, gamma=0.99, double_dqn=True):
    q_next_target = target_net(s_next)                      # Q(s', . ; theta-)    (B, 2)
    if double_dqn:
        a_star = q_net(s_next).argmax(dim=1, keepdim=True)  # choose with theta    (B, 1)
    else:
        a_star = q_next_target.argmax(dim=1, keepdim=True)  # choose with theta-
    q_next = q_next_target.gather(1, a_star)                # evaluate with theta- (B, 1)
    return r + gamma * (1.0 - terminal) * q_next

This is the target from sections 3.10 and 3.13, one line per symbol. terminal is a float tensor of 0s and 1s, so (1.0 - terminal) switches off the future term exactly for true terminal transitions. gather(1, a_star) picks one column per row: row i returns q_next_target[i, a_star[i]].

4.5 One gradient step

import numpy as np
import torch.nn.functional as F

def optimize(q_net, target_net, optimizer, buffer, batch_size=64, gamma=0.99):
    s, a, r, s_next, terminal = buffer.sample(batch_size)
    s        = torch.as_tensor(np.array(s), dtype=torch.float32)             # (64, 4)
    a        = torch.as_tensor(a, dtype=torch.int64).unsqueeze(1)            # (64, 1)
    r        = torch.as_tensor(r, dtype=torch.float32).unsqueeze(1)          # (64, 1)
    s_next   = torch.as_tensor(np.array(s_next), dtype=torch.float32)        # (64, 4)
    terminal = torch.as_tensor(terminal, dtype=torch.float32).unsqueeze(1)   # (64, 1)

    q_sa = q_net(s).gather(1, a)             # Q(s, a; theta) for the actions actually taken
    y = td_targets(r, s_next, terminal, q_net, target_net, gamma)
    loss = F.smooth_l1_loss(q_sa, y)         # Huber loss (F.mse_loss for the squared error)

    optimizer.zero_grad()
    loss.backward()                          # gradients flow through q_sa only
    torch.nn.utils.clip_grad_norm_(q_net.parameters(), max_norm=10.0)
    optimizer.step()
    return loss.item()

The network outputs Q-values for both actions, but the loss only involves the action actually taken in each transition, selected with another gather. The other action's output gets no gradient from that sample. Gradient-norm clipping is an extra safety net on top of the Huber loss.

4.6 The training loop

import gymnasium as gym

env = gym.make("CartPole-v1")
q_net, target_net = DQN(), DQN()
target_net.load_state_dict(q_net.state_dict())   # theta- = theta
optimizer = torch.optim.Adam(q_net.parameters(), lr=1e-3)
buffer = ReplayBuffer(50_000)
t = 0                                            # environment steps so far

for episode in range(300):
    state, _ = env.reset(seed=episode)
    while True:
        action = select_action(q_net, state, epsilon_by_step(t))
        next_state, reward, terminated, truncated, _ = env.step(action)

        # Only a real failure has no future. Hitting the time limit does (section 3.11).
        buffer.push(state, action, reward, next_state, terminated)

        if len(buffer) >= 1_000:                 # warm up the buffer before learning
            optimize(q_net, target_net, optimizer, buffer)
        t += 1
        state = next_state
        if terminated or truncated:              # either way, this episode is over
            break

    if (episode + 1) % 10 == 0:                  # hard target update
        target_net.load_state_dict(q_net.state_dict())

Note the two different uses of the flags: terminated goes into the buffer, while terminated or truncated ends the loop. The soft update from section 3.12 would replace the last two lines with a call after every optimize:

@torch.no_grad()
def soft_update(target_net, q_net, tau=0.005):
    for p_target, p in zip(target_net.parameters(), q_net.parameters()):
        p_target.lerp_(p, tau)                   # theta- += tau * (theta - theta-)

4.7 Evaluating a policy

Training returns are measured while the agent is still exploring, so they understate the greedy policy, and they come from the starting states the agent trains on. Evaluate separately instead: greedy actions, fresh starting states, several episodes.

def evaluate(q_net, episodes=20, seed_offset=20_000_000):
    env = gym.make("CartPole-v1")
    returns = []
    for i in range(episodes):
        state, _ = env.reset(seed=seed_offset + i)   # starting states never used in training
        total, done = 0.0, False
        while not done:
            action = select_action(q_net, state, epsilon=0.0)   # purely greedy
            state, reward, terminated, truncated, _ = env.step(action)
            total += reward
            done = terminated or truncated
        returns.append(total)
    env.close()
    return float(np.mean(returns))

5.1 Exploration is slower than it looks

5.2 One training run tells you very little

The random seed sets the initial weights, the random actions and the replay samples. Changing nothing but the seed gives a very different learning curve:

This is why RL papers should report means over many seeds with confidence intervals, and why two configurations should never be compared from one run each [Henderson et al., 2018], [Agarwal et al., 2021]. The rest of this section follows that rule.

Exercises

The best way to understand DQN is to break it. Each exercise changes one or two lines of the code in Parts 2 to 4. Run at least 5 seeds before drawing a conclusion.

  1. Predict the Q-values. Set \gamma = 0.9. Using section 3.3, what should Q be for a well-balanced state? Train, then print q_net(torch.zeros(1, 4)). Is it closer to the prediction than at \gamma = 0.99, and why? (Section 5.6 has a hint.)
  2. Solve the corridor exactly. Write value iteration for the corridor of section 2.6 in NumPy, check that it matches the grey Q^* numbers in the widget, and verify the contraction bound \|Q_k - Q^*\|_\infty \le \gamma^k \|Q_0 - Q^*\|_\infty numerically.
  3. SARSA versus Q-learning. Change one line of the tabular code in section 3.9 to get SARSA. With \varepsilon = 0.3, do the learned values differ? Which one estimates the values of the policy you are actually running?
  4. Fix the drift with reward shaping. Section 5.5 shows the cart drifting off the track. Train with the CenteringPenalty wrapper from section 2.5. Does the failure mode change? Evaluate with the original reward.
  5. Remove the target network. Use q_net in place of target_net inside td_targets. Plot the loss and the greedy return. What changes?
  6. Get the terminal flag wrong. Store terminated or truncated in the buffer and shorten the time limit with gym.make("CartPole-v1", max_episode_steps=200), so it is hit often. Compare with the correct version over several seeds.
  7. Measure the overestimation. Log the mean of q_sa during training with double_dqn=True and False. Do you see the bias from section 3.13?
  8. Stop forgetting. Decay the learning rate over training, or enlarge the replay buffer. Does the gap between the final network and the best checkpoint shrink?

Part 7

References and further reading

If you read one book, make it Sutton and Barto: it is the standard text, and the authors provide it free online. For deep RL in code, pick one of Graesser & Keng, Lapan or Morales. For rigour, go to Puterman, Bertsekas, Szepesvári, or Agarwal et al.
