Automatic differentiation from scratch

Chapters 03 and 04 train a model by computing the gradient of a loss through a thousand steps of a Kalman filter, with one call to jax.grad. This chapter opens that call. A derivative of a program is not computed from a formula, and not by nudging the inputs: the program is broken into elementary operations, and the chain rule is applied to each, in one of two orders. Forward mode carries derivatives along with the values; reverse mode records the computation and sweeps back through it. Both fit in thirty lines of Python, and you will write them. At the end, the page computes the gradient of a Kalman filter's likelihood itself, with forward mode, and uses it to find the filter's noise levels from data.

Part 1

Three ways to get a derivative

Symbolic differentiation applies the rules of calculus to a formula and returns a formula, as a computer algebra system does. It is exact, but it needs the program as one expression, which a loop of a thousand filter steps is not, and the derivative's expression can grow much faster than the original: differentiating a product of n factors gives n terms of n factors each.

Numerical differentiation treats the program as a black box and nudges its input:

f'(x) \approx \frac{f(x + h) - f(x)}{h} \quad \text{(forward)}, \qquad f'(x) \approx \frac{f(x + h) - f(x - h)}{2h} \quad \text{(central)}.

It needs no access to the code, but it costs one or two evaluations per input, and its accuracy is caught between two errors. The formulas are Taylor approximations, wrong by about h (forward) or h^2 (central), so h should be small. But the difference f(x+h) - f(x) is a cancellation (J1, Part 5): each value carries a rounding error of about u\,|f|, and dividing by h magnifies it, so h should be large. The best compromise for forward differences is h \approx \sqrt{u}, which leaves about half the digits; in float32 that is three or four.

Automatic differentiation is the third way. It applies the chain rule to the operations the program actually performs, as it performs them, with numbers rather than formulas. The result is exact up to the rounding of those operations: JAX's float32 derivative above agrees with float64 to about 2 \times 10^{-6}, while the best float32 finite difference is off by 9 \times 10^{-4} and most are useless. It costs a small constant multiple of one evaluation, whatever the number of inputs. The rest of the chapter is how.

Part 2

A program is a graph

However a program is written, running it performs a sequence of elementary operations, each with a known derivative. Write each intermediate result as a variable v_i. For the running example, f(x_1, x_2) = \log x_1 + x_1 x_2 - \sin x_2, the sequence is

v_{-1} = x_1, \quad v_0 = x_2, \quad v_1 = \log v_{-1}, \quad v_2 = v_{-1} v_0, \quad v_3 = \sin v_0, \quad v_4 = v_1 + v_2, \quad v_5 = v_4 - v_3, \quad y = v_5.

This list is called the evaluation trace, or a Wengert list after the 1964 paper that first differentiated programs this way [3]. Drawn with an arrow from each variable to the operations that use it, it is the graph in the demo. You have seen it before: it is J2's jaxpr.

jax.make_jaxpr(f)(2.0, 5.0)
{ lambda ; a:f32[] b:f32[]. let
    c:f32[] = log a
    d:f32[] = mul a b
    e:f32[] = add c d
    f:f32[] = sin b
    g:f32[] = sub e f
  in (g,) }

The jaxpr's c, d, e, f, g are v_1, v_2, v_4, v_3, v_5; the jaxpr follows Python's evaluation order, which reaches v_4 before v_3; the order of independent operations does not matter. Each line has a local derivative that a table can supply: \partial v_1 / \partial v_{-1} = 1/v_{-1}, \partial v_2 / \partial v_{-1} = v_0, \partial v_3 / \partial v_0 = \cos v_0, and so on. The chain rule says the derivative of the output with respect to an input is the sum, over all paths from that input to the output, of the products of the local derivatives along the path. From x_1 there are two paths, through v_1 and through v_2:

\frac{\partial y}{\partial x_1} = \underbrace{\tfrac{1}{v_{-1}}}_{v_1} \cdot 1 \cdot 1 \;+\; \underbrace{v_0}_{v_2} \cdot 1 \cdot 1 = \frac{1}{2} + 5 = 5.5 .

Summing over paths one by one would be exponential in a deep graph. The two modes of automatic differentiation are two ways of organising the sum so that every edge is visited once: from the inputs forward, or from the output backward.

Part 3

Forward mode

The idea. Choose one input direction, say x_1. Carry, next to every value v_i, its tangent \dot v_i = \partial v_i / \partial x_1. Seed the inputs with \dot v_{-1} = 1 and \dot v_0 = 0, then compute each tangent from its operation's local rule as the value is computed: \dot v_1 = \dot v_{-1} / v_{-1}, \dot v_2 = \dot v_{-1} v_0 + v_{-1} \dot v_0, and so on. When the output is reached, \dot y = \partial y / \partial x_1. Step through it in the demo with Forward, seed x₁.

One sweep gives the derivative with respect to one input, or more generally along one direction \dot x: the product of the Jacobian with a vector, J \dot x, called a Jacobian-vector product or JVP. For the full gradient of a function of n inputs, forward mode needs n sweeps, one per seed.

Dual numbers. Pairing each value with its tangent can be done by the number type itself. A dual number a + b\varepsilon with \varepsilon^2 = 0 obeys f(a + b\varepsilon) = f(a) + f'(a)\, b\, \varepsilon, so arithmetic on dual numbers is forward mode. In Python, with operator overloading:

import math

class Dual:
    """A number with a tangent: forward mode."""
    def __init__(self, value, tangent=0.0):
        self.value, self.tangent = value, tangent
    def __add__(self, other):
        return Dual(self.value + other.value, self.tangent + other.tangent)
    def __sub__(self, other):
        return Dual(self.value - other.value, self.tangent - other.tangent)
    def __mul__(self, other):          # the product rule
        return Dual(self.value * other.value,
                    self.tangent * other.value + self.value * other.tangent)

def d_log(x): return Dual(math.log(x.value), x.tangent / x.value)
def d_sin(x): return Dual(math.sin(x.value), math.cos(x.value) * x.tangent)

def f(x1, x2):
    return d_log(x1) + x1 * x2 - d_sin(x2)

f(Dual(2.0, 1.0), Dual(5.0, 0.0)).tangent    # 5.5                 seed x1
f(Dual(2.0, 0.0), Dual(5.0, 1.0)).tangent    # 1.7163378145367738  seed x2

The function f was written for numbers, and runs unchanged on dual numbers. That is forward-mode AD in full; a library adds more operations and makes it fast.

In JAX the same is jax.jvp, which takes the inputs and a tangent for each:

jax.jvp(f, (2.0, 5.0), (1.0, 0.0))     # (11.652072, 5.5): the value and the tangent

And since a JVP is itself a program, J2's tools show it. The traced JVP of f interleaves the original operations with their tangent rules, just like the dual-number class; c and d are the input tangents:

{ lambda ; a:f32[] b:f32[] c:f32[] d:f32[]. let
    e:f32[] = log a
    f:f32[] = div c a          # tangent of log: c / a
    g:f32[] = mul a b
    h:f32[] = mul c b          # product rule, first half
    i:f32[] = mul a d          # product rule, second half
    j:f32[] = add_any h i
    k:f32[] = add e g
    l:f32[] = add f j
    m:f32[] = sin b
    n:f32[] = cos b
    o:f32[] = mul d n          # tangent of sin: d cos b
    p:f32[] = sub k m          # the value
    q:f32[] = sub l o          # the tangent
  in (p, q) }

(The comments are added; the rest is JAX's output.) Forward mode costs about two to three times one evaluation, and it needs no extra memory: each tangent is computed when its value is and can be discarded with it.

Part 4

Reverse mode

The idea. Turn the question around. Instead of asking how every variable depends on one input, ask how the one output depends on every variable: the adjoint \bar v_i = \partial y / \partial v_i. The output's adjoint is \bar y = 1. A variable's adjoint is the sum, over the operations that use it, of that operation's adjoint times the local derivative:

\bar v_i = \sum_{j \,:\, v_j \text{ uses } v_i} \bar v_j \, \frac{\partial v_j}{\partial v_i} .

So adjoints are computed from the output backwards, in the reverse of the order the values were computed. That needs two sweeps: a forward sweep that computes and stores every value, because the local derivatives need them, and a backward sweep that propagates adjoints. When the backward sweep reaches the inputs, it has every partial derivative at once: \bar x_1 = 5.5 and \bar x_2 = 1.716. Step through it in the demo with Reverse, and notice v_0, used twice, collecting two contributions.

One backward sweep gives the derivative of one output with respect to all inputs: more generally, a row vector times the Jacobian, \bar y^\top J, a vector-Jacobian product or VJP. For a scalar loss of a million parameters, that is the whole gradient, for the price of about one extra evaluation, instead of the million sweeps forward mode would need. This is backpropagation [5], and it is the reason neural networks can be trained at all. The algorithm itself is older: Linnainmaa described reverse accumulation in 1970 [4].

A tape. Reverse mode needs the graph, so each value must remember how it was made. In Python, each operation records its inputs and its local derivatives; backward visits the nodes in reverse topological order and accumulates:

class Var:
    """A number that remembers how it was made: reverse mode."""
    def __init__(self, value, parents=()):
        self.value, self.parents, self.adjoint = value, parents, 0.0
    def __add__(self, other):
        return Var(self.value + other.value, ((self, 1.0), (other, 1.0)))
    def __sub__(self, other):
        return Var(self.value - other.value, ((self, 1.0), (other, -1.0)))
    def __mul__(self, other):
        return Var(self.value * other.value, ((self, other.value), (other, self.value)))

def v_log(x): return Var(math.log(x.value), ((x, 1.0 / x.value),))
def v_sin(x): return Var(math.sin(x.value), ((x, math.cos(x.value)),))

def backward(y):
    order, seen = [], set()
    def visit(v):                      # every node after the nodes it was made from
        if id(v) not in seen:
            seen.add(id(v))
            for parent, _ in v.parents:
                visit(parent)
            order.append(v)
    visit(y)
    y.adjoint = 1.0
    for v in reversed(order):          # the backward sweep
        for parent, local in v.parents:
            parent.adjoint += local * v.adjoint

a, b = Var(2.0), Var(5.0)
y = v_log(a) + a * b - v_sin(b)        # the forward sweep builds the graph
backward(y)
a.adjoint, b.adjoint                   # (5.5, 1.7163378145367738)

The += is where a variable used twice collects its two contributions. This is a complete reverse-mode AD in the style of PyTorch's autograd and of small teaching libraries, and, like the dual numbers, it agrees with JAX to the last digit.

In JAX, jax.vjp(f, 2.0, 5.0) returns the value and a function that maps an output adjoint to input adjoints, and jax.grad(f) is the special case for a scalar output with \bar y = 1. JAX does not record a tape at run time. It traces, as in J2, and builds the backward sweep as a new program:

jax.make_jaxpr(jax.grad(f, argnums=(0, 1)))(2.0, 5.0)
{ lambda ; a:f32[] b:f32[]. let
    c:f32[] = log a
    d:f32[] = mul a b
    e:f32[] = add c d
    f:f32[] = sin b
    g:f32[] = cos b
    _:f32[] = sub e f
    h:f32[] = neg 1.0:f32[]
    i:f32[] = mul h g
    j:f32[] = mul a 1.0:f32[]
    k:f32[] = mul 1.0:f32[] b
    l:f32[] = add_any i j
    m:f32[] = div 1.0:f32[] a
    n:f32[] = add_any k m
  in (n, l) }

The first six lines are the forward sweep; _ marks y itself, computed but not needed, since grad returns only the derivative. From h on it is the backward sweep with \bar y = 1 as a constant: l is \bar x_2 = -\cos x_2 + x_1 and n is \bar x_1 = x_2 + 1/x_1. The values the backward sweep needs, a, b and cos b, are what a tape would have stored. JAX derives this program from the forward-mode rules, by linearising the function and transposing the linear part, so each primitive needs only its JVP rule [6].

The price. Reverse mode must keep every intermediate value until the backward sweep uses it. For the Kalman filter's likelihood over 1000 steps, that is every step's state, covariance and gain. Memory grows with the length of the computation; forward mode's does not. When memory runs out, jax.checkpoint trades it back for time by recomputing parts of the forward sweep during the backward one. In time, the cost of a gradient is a small multiple of one evaluation, whatever the number of inputs. Theory bounds the multiple by a small constant that does not depend on the number of inputs [2]; for the Kalman likelihood below, JAX's value_and_grad took 2.35 ms against 1.08 ms for the value alone, a factor of 2.2.

Forward and reverse mode

In plain words: forward mode pushes "how much does this change if the input moves?" from the inputs to the output; reverse mode pulls "how much does the output care about this?" from the output back to the inputs.

More precisely: for f: \mathbb R^n \to \mathbb R^m with Jacobian J, one forward sweep computes a JVP J\dot x and one reverse sweep a VJP \bar y^\top J, each at a small constant multiple of the cost of f. Reverse mode also stores the forward sweep's intermediate values.

Tangent, adjoint
\dot v = \partial v / \partial x for a chosen input direction; \bar v = \partial y / \partial v for a chosen output weighting. Also called primal–tangent and cotangent.
Backpropagation
Reverse mode applied to a neural network's loss.
Part 5

Forward or reverse?

A full Jacobian of f: \mathbb R^n \to \mathbb R^m is m \times n numbers. Forward mode builds it a column at a time, one JVP per input, n sweeps; reverse mode a row at a time, one VJP per output, m sweeps. JAX offers both, as jax.jacfwd and jax.jacrev, and runs the sweeps as one batched computation with vmap (J4). They return the same matrix; the cost differs. For f(x) = \tanh(Wx), compiled, on a laptop CPU:

Shape of the Jacobianjacfwd (n sweeps)jacrev (m sweeps)
4 outputs, 1000 inputs: wide656 µs16 µs
1000 outputs, 4 inputs: tall21 µs658 µs
300 × 300: square328 µs283 µs

The rule: reverse for few outputs, forward for few inputs. A loss is one output with many parameters, so training always uses reverse mode. The EKF's Jacobians are small and square, where the two cost about the same, and forward mode, which stores nothing, is the natural default. The Hessian, the matrix of second derivatives of a scalar function, is the Jacobian of the gradient: JAX defines jax.hessian(f) as jacfwd(jacrev(f)), reverse mode for the gradient's many inputs and forward mode on top for its square Jacobian.

Part 6

Where autodiff surprises

Automatic differentiation differentiates the program as written, operation by operation. Most surprises come from the gap between the program and the mathematical function it stands for.

Kinks get a convention. |x| and \max(x, 0) have no derivative at 0, but each primitive has a rule, and the rule gives a number: in JAX, jax.grad(jnp.abs)(0.0) is 1.0 and jax.grad(jax.nn.relu)(0.0) is 0.0. jax.grad(jnp.sqrt)(0.0) is inf, and the gradient of jnp.linalg.norm at the zero vector is [nan nan], because the norm is a square root of a sum of squares.

The where trap. J2 used jnp.where to keep a computation's value safe. Its gradient is another matter:

def safe_sqrt(x):
    return jnp.where(x > 0, jnp.sqrt(x), 0.0)

safe_sqrt(-1.0)              # 0.0: the value is fine
jax.grad(safe_sqrt)(-1.0)    # nan

where computes both branches, so jnp.sqrt(-1.0) is computed, NaN, and its local derivative is NaN too. The backward sweep sends an adjoint of 0 into the unused branch, and 0 \times \text{NaN} is NaN. The fix is to make the unused branch harmless before it is computed, not after: jnp.sqrt(jnp.where(x > 0, x, 1.0)) inside the outer where gives a gradient of 0.0. Part 7 meets this trap in the Kalman filter.

Gradients need a scalar output and float inputs. jax.grad(lambda x: x * 2)(3) fails: "grad requires real- or complex-valued inputs (input dtype that is a sub-dtype of np.inexact), but got int32". On a vector output, "Gradient only defined for scalar-output functions. Output had shape: (3,)", with the advice to sum it or use jax.jacobian.

Reverse mode needs to know the loop's length. A lax.while_loop runs until a condition fails, a number of steps unknown when the program is compiled, so there is nowhere to store its intermediate values in advance. Forward mode needs no storage and works; reverse mode refuses: "Reverse-mode differentiation does not work for lax.while_loop or lax.fori_loop with dynamic start/stop values. Try using lax.scan, ...". The Kalman code's lax.scan has a fixed length, which is one reason it is used (J5).

Stopping a gradient on purpose. lax.stop_gradient(x) is x in value and a constant to the differentiator: jax.grad(lambda x: x * lax.stop_gradient(x))(3.0) is 3.0, not 6.0. It is how a quantity is used in a loss without being trained, such as a target network's output or a filter gain treated as fixed.

Part 7

Back to Kalman

The EKF's Jacobians, for free. The repository's extended filter takes its Jacobians as arguments, run_ekf(measurements, f, h, F_jacobian, H_jacobian, ...), and its script passes hand-written ones for a linear model. For a nonlinear sensor the derivation is where mistakes happen. Suppose the sensor measures the distance to the vehicle from a point 10 m to the side of the road, h(x) = \sqrt{p^2 + 10^2}. By hand, H = (p / \sqrt{p^2 + 100},\ 0); at p = 24 that is 24/26. Forward mode gives the same without the derivation:

def h_range(x):
    return jnp.array([jnp.sqrt(x[0] ** 2 + 10.0 ** 2)])

jax.jacfwd(h_range)(jnp.array([24.0, 1.0]))     # [[0.923077 0.      ]] = 24/26, 0
run_ekf(ranges, f, h_range, jax.jacfwd(f), jax.jacfwd(h_range), Q, R, x0, P0)   # ranges: the sensor's readings

The Jacobian is exact to rounding, stays correct when h_range changes, and is evaluated inside the compiled filter like any other operation.

The gradient of the filter's likelihood. A Kalman filter does more than estimate the state: at each step it predicts the next measurement, as a Gaussian with mean H\hat x_{k|k-1} and variance S_k. How surprising each measurement was, summed over the run, is the negative log-likelihood of the data under the model:

\ell(\theta) = \frac{1}{T} \sum_{k=1}^{T} \tfrac12 \Big( \log 2\pi + \log S_k + \frac{v_k^2}{S_k} \Big), \qquad v_k = z_k - H\hat x_{k|k-1} .

This is the prediction-error decomposition of the likelihood [7]. It depends on the noise levels the filter assumes, the process noise \sigma_a in Q and the measurement noise \sigma_z in R, which chapter 02 simply set to the values that generated the data, 0.1 and 0.5. With real data nobody knows them. Minimising \ell over \theta = (\log \sigma_a, \log \sigma_z) estimates them, and the gradient through 1000 filter steps is one call: jax.grad(nll)(theta). (The logarithms keep both levels positive and put them on a common scale.)

What the descent finds. From \sigma_a = \sigma_z = 1, 400 steps reach \sigma_a = 0.063, \sigma_z = 0.513, and the minimum, found by Newton's method in JAX, is at \sigma_a = 0.061, \sigma_z = 0.513. The measurement noise is recovered within 3%. The process noise is not, and the surface shows why: it is a long, shallow valley. The Hessian at the minimum has eigenvalues 0.022 and 1.94, a ratio of 88, so the likelihood is 88 times more sensitive to \log \sigma_z than to \log \sigma_a. A thousand measurements pin \sigma_z to about 2% and \sigma_a only to about 20% (one standard error, from the same Hessian), and the true 0.1 is 2.3 standard errors above the estimate: this particular record happens to look calmer than the process that made it, and the likelihood has little power to tell. The valley is also why plain gradient descent crawls along it: a step size small enough for the steep direction is far too small for the shallow one. J6's optimiser, Adam, rescales each direction for that reason.

Chapter 03's gradient. Chapter 03 trains a neural network inside the filter with value_and_grad(loss_fn): reverse mode, because the loss is one number and the network has many parameters, through a lax.scan over the sequence. Everything above applies. The backward sweep runs the scan in reverse, from the last step to the first, and the forward sweep's states and covariances are kept for it, so memory grows with the sequence length. And reverse mode differentiates only what the program actually computes: chapter 03 found that the gain sequence does not depend on the trained parameters, so JAX's gradient through it is exactly zero.

J2's missing measurement, differentiated. J2's exercise 4 replaced a NaN measurement with jnp.nan_to_num(z) before the update, then selected the prediction with where. Without the replacement, the step's value is the same, 2.1 in the test in j3_numbers.py. But its gradient with respect to \log \sigma_z is 0.0 with the replacement and NaN without it: the update's gain depends on \sigma_z, its innovation is NaN, and the unused branch's 0 \times \text{NaN} reaches the gradient. Code that will be differentiated must keep NaN out of both branches.

Part 8

Check your understanding

1. Why can a float32 finite difference not be made accurate by choosing a smaller step?

Its error has two parts that move in opposite directions. The truncation error of the formula shrinks with h, but the rounding error of f(x+h) - f(x), about u|f|, is divided by h and grows. In float32 the best compromise leaves three or four digits, and for h \le 10^{-8} even the input \theta + h rounds back to \theta, so the estimate is 0.

2. What is automatic differentiation exact up to?

The rounding of the operations it performs. It applies exact derivative rules to each elementary operation, with no truncation error, so its error is of the same order as the error in the function's own value.

3. What does one forward-mode sweep compute, and one reverse-mode sweep?

Forward: a Jacobian-vector product J\dot x, the derivative of every output along one input direction. Reverse: a vector-Jacobian product \bar y^\top J, the derivative of one weighted output with respect to every input.

4. Why does a dual number a + b\varepsilon with \varepsilon^2 = 0 compute derivatives?

Expanding f(a + b\varepsilon) in a Taylor series, every term with \varepsilon^2 or higher vanishes, leaving f(a) + f'(a)\,b\,\varepsilon. Arithmetic on dual numbers therefore carries the derivative exactly in the \varepsilon part, which is forward mode.

5. Why must reverse mode store the forward sweep's values, and what does that cost?

The local derivatives in the backward sweep, such as 1/v_{-1} or \cos v_0, need the values, and the backward sweep visits them in the reverse of the order they were computed. Memory therefore grows with the length of the computation, for example with the number of filter steps; jax.checkpoint recomputes instead of storing when that is too much.

6. Which mode would you use for the Jacobian of a map from 3 inputs to 500 outputs, and for the gradient of a loss of 10 000 parameters?

Forward for the first: 3 sweeps instead of 500. Reverse for the second: 1 sweep instead of 10 000.

7. jnp.where(x > 0, jnp.sqrt(x), 0.0) is 0 at x = -1. Why is its gradient NaN there?

where evaluates both branches, so \sqrt{-1} and its derivative are NaN. The backward sweep multiplies the unused branch's derivative by an adjoint of 0, and 0 \times \text{NaN} = \text{NaN}. Replace the input of the dangerous branch with a safe value first.

8. Gradient descent on the filter's likelihood finds \sigma_z quickly and \sigma_a slowly. Why?

The likelihood is about 88 times more curved along \log \sigma_z than along \log \sigma_a, the ratio of its Hessian's eigenvalues. A step size stable for the steep direction makes slow progress along the shallow one. The shallowness also means the data determine \sigma_a poorly.

  1. Extend the dual numbers. Add division and d_exp to the Dual class, and use them to differentiate s(x) = x / (1 + e^{-x}) at x = 1.5. Compare with jax.grad.
    Hint

    Solution

    u^{1/3} is about 4 \times 10^{-3} in float32 and 5 \times 10^{-6} in float64.     def check_grad(f, theta, h):
    g = jax.grad(f)(theta)
    for i in range(theta.size):
        e = jnp.zeros_like(theta).at[i].set(h)
        fd = (f(theta + e) - f(theta - e)) / (2 * h)
        print(i, float(g[i]), float(fd), float(abs(fd - g[i]) / abs(g[i])))
  4. The NaN in the gradient. Take J2's kf_step_missing, make R depend on a parameter log_sigma_z, and differentiate the sum of the returned state with respect to it, for z = jnp.array([jnp.nan]). Do it with and without jnp.nan_to_num. Explain the difference.
    Hint

    Which branch of the final where is used, and what is the derivative of the other branch with respect to \sigma_z?

    Solution

    Both versions return the same value, the prediction (2.1 for the state [1, 1]). The gradient is 0.0 with nan_to_num and NaN without it. The updated state depends on \sigma_z through the gain, multiplied by the innovation, which is NaN; the backward sweep multiplies that NaN derivative by the unused branch's adjoint of 0.     Hint

    Enable float64 at startup (J1). jnp.linalg.solve(H, g) is better than forming the inverse.

    Solution

    Newton converges to \sigma_a = 0.0611, \sigma_z = 0.5128, where the gradient is below 10^{-14}, in 7 iterations. Gradient descent with step 0.5 needs 713 steps just to bring \sigma_a within 0.1% of it. The Hessian's eigenvalues at the minimum are 0.0219 and 1.936. Newton's step divides by the curvature in each direction, which is exactly what the shallow valley needs.

theta = jnp.zeros(2)
for _ in range(20):

Part 10

The chapter on one page

  1. Finite differences trade truncation error against rounding error; in float32 they give three or four digits at best and 0 for small steps. Use them only to check gradients, in float64.
  2. A program is a graph of elementary operations with known local derivatives: the evaluation trace, which in JAX is the jaxpr. The chain rule sums products of local derivatives over paths.
  3. Forward mode carries a tangent with every value: one sweep is a JVP, the derivative along one input direction. Dual numbers implement it; jax.jvp and jax.jacfwd are JAX's.
  4. Reverse mode stores the forward sweep and propagates adjoints back from the output: one sweep is a VJP, the gradient of one output with respect to every input, at about twice the cost of the function. A tape implements it; jax.grad, jax.vjp and jax.jacrev are JAX's.
  5. Choose by shape: reverse for few outputs, forward for few inputs. jax.hessian is jacfwd(jacrev(f)).
  6. Surprises: kinks get conventions, where passes NaN from an unused branch into the gradient, reverse mode needs fixed-length loops, and stop_gradient makes a value a constant.
  7. In the Kalman code: jacfwd supplies the EKF's Jacobians; the gradient of the filter's likelihood estimates its noise levels, \sigma_z = 0.513 well and \sigma_a = 0.061 poorly, from 1000 measurements; chapter 03's training is reverse mode through a scan.

Part 11

Scope and further reading

Scope. This chapter covers numerical and automatic differentiation, forward and reverse mode with their costs, JAX's jvp, vjp, grad, jacfwd, jacrev and hessian, the common pitfalls, and gradient-based estimation of a Kalman filter's noise levels. Not covered: custom derivative rules (jax.custom_jvp, custom_vjp), higher-order Taylor methods, differentiating through linear solvers and fixed points implicitly, and the details of checkpointing policies.
