A first-order filter in C

Four chapters of Python and JAX, and then the filter has to run on a microcontroller with 32 kilobytes of memory and no NumPy. This chapter is about that step. It takes the simplest useful filter, the first-order low-pass, derives its exact discrete form, and implements it in C the way the author's coursework program TD3.c does: arrays, pointers, functions with return codes, and files read and written by hand. The program is read line by line as a C lesson; compiling and running it finds three bugs that turned its output into a column of zeros; and the fixed filter runs below on the program's own recording, where it also teaches what a first-order filter cannot do.

Part 1

The first-order filter

Continuous time. The first-order low-pass filter is the simplest system with memory: an output that chases its input with a time constant \tau and a static gain K,

\tau\,\dot y(t) + y(t) = K\,u(t), \qquad H(s) = \frac{Y(s)}{U(s)} = \frac{K}{1 + \tau s}.

An RC circuit, a thermometer in a bath, a motor's speed under a voltage step: all are first-order. Its step response is K(1 - e^{-t/\tau}), 63% of the way after one time constant; its frequency response has magnitude K/\sqrt{1 + (\omega\tau)^2} and phase -\arctan(\omega\tau), so it passes frequencies well below the cutoff f_c = 1/(2\pi\tau) and attenuates those above it by a factor of ten per decade (20 dB per decade), with a lag that reaches 45° at the cutoff and 90° far above it [1].

Discrete time, exactly. A program sees the input only at the sampling instants kT_e and must produce y_k from y_{k-1} and past inputs. If the input is held constant over each sampling interval (what a digital-to-analogue converter does, the zero-order hold), the differential equation can be solved exactly over one interval: the homogeneous part decays by z_0 = e^{-T_e/\tau} and the held input contributes K(1 - z_0)u_{k-1}, so

y_k = z_0\, y_{k-1} + K(1 - z_0)\, u_{k-1}, \qquad z_0 = e^{-T_e/\tau}.

This is the recursion in the program's filtrage(). It is an infinite-impulse-response filter with one pole at z_0, and it costs one multiplication, one multiply-add and one memory cell per sample, which is why it runs on anything. Two things to notice: the coefficients sum to K, so a constant input gives output K times it; and the input enters with one sample of delay, u_{k-1}, because the sample held over the interval ending at k is the one taken at k-1. (Many implementations use u_k instead, which is the bilinear or backward-Euler variant; the difference is one sample of lag, visible in the phase plot of Part 5.)

Numbers for the program's setting. With T_e = 0.01 s and \tau = 2 s, z_0 = e^{-0.005} = 0.99501 and K(1 - z_0) = 0.00499: each new sample moves the output half a percent of the way toward it, an average over about 200 samples. The cutoff is 1/(4\pi) = 0.080 Hz. The recording the program filters is a sine at 1.00 Hz, thirteen times the cutoff, which the filter passes at 8% of its amplitude. Part 4 shows what the program made of that.

Exact (zero-order-hold) discretisation

In plain words: instead of approximating the derivative by a difference, solve the differential equation exactly between two samples, assuming the input stays constant in between.

More precisely: for \dot y = -y/\tau + (K/\tau)u with u constant on [kT_e - T_e, kT_e), y_k = e^{-T_e/\tau} y_{k-1} + \int_0^{T_e} e^{-s/\tau} (K/\tau)\,u_{k-1}\,ds = z_0 y_{k-1} + K(1 - z_0) u_{k-1}. The discrete system has the continuous one's pole mapped by z_0 = e^{sT_e} with s = -1/\tau, is stable for every T_e (since 0 < z_0 < 1), and matches the continuous response exactly at the sampling instants for held inputs [2].

Forward Euler
y_k = (1 - T_e/\tau)y_{k-1} + (KT_e/\tau)u_{k-1}: the first-order Taylor approximation of the same thing, unstable for T_e > 2\tau.
Pole
z_0: the factor by which the output decays per sample when the input is zero; the closer to one, the longer the memory.
Cutoff
f_c = 1/(2\pi\tau), where the gain is K/\sqrt 2 and the lag 45°.
Part 2

The C you need

C is a small language that maps almost directly onto the machine: numbers live in typed memory cells, arrays are consecutive cells, a pointer is the address of a cell, and nothing is checked at run time. That is what makes it fast and portable to microcontrollers, and what makes the bugs of Part 4 possible. This section covers exactly the subset the program uses [3].

Compile and run. A C program is text that a compiler turns into an executable. With gcc, which the repository's editor configuration also uses:

gcc -Wall -Wextra -o td3 TD3.c
./td3

-Wall -Wextra turns on the warnings; read them, they are free bug reports. On Windows the executable is td3.exe.

Part 3

The program, line by line

The filter. The heart of the program is six lines. The length check and the return code are the C idiom for "this can fail":

int filtrage(double *u, int taille_u, double *y, int taille_y, double K, double tau, double Te) {
    if (taille_u != taille_y) return -1;        /* the caller passed arrays of different lengths */
    double z0 = exp(-Te / tau);                 /* the pole: how much of y survives one sample   */
    y[0] = 0;                                   /* start at rest                                  */
    for (int k = 1; k < taille_u; k++)
        y[k] = z0 * y[k - 1] + K * (1 - z0) * u[k - 1];
    return 0;
}

Note what is not here: no allocation (the caller owns both arrays), no state between calls (a real-time version would keep y[k-1] in a variable and process one sample per call, Exercise 1), and exp computed once, outside the loop.

Reading a file of numbers. LireEntree opens the file, reads doubles one at a time with fscanf until it fails, and distinguishes "end of file" from "something else went wrong":

int LireEntree(const char *nom_fichier, double *valeurs) {
    FILE *fichier = fopen(nom_fichier, "r");
    if (fichier == NULL) return -1;
    int compteur = 0;
    while (compteur < 10000) {
        if (fscanf(fichier, "%lf", &valeurs[compteur]) != 1) {
            if (feof(fichier)) break;           /* clean end of file */
            fclose(fichier); return -1;         /* a line that is not a number */
        }
        compteur++;
    }
    fclose(fichier);
    return compteur;                            /* how many values were read */
}

The return value does double duty, count on success and −1 on failure, a common C convention. The cap of 10000 protects the caller's array, which the function cannot otherwise know the size of. EcrireSortie is the mirror image: fopen(…, "w"), a loop of fprintf(fichier, "%.2f\n", valeurs[i]), fclose. The two decimals of %.2f will matter in Part 4.

Minimum, maximum, histogram. ChercheMinMax walks the array once and writes its two results through pointers. CalculeHistogramme divides [\min, \max] into nb_bins equal bins and counts; the one subtle line is

int index = (tableau[i] - min) / largeur_bin;   /* double -> int truncates */
if (index >= nb_bins) index = nb_bins - 1;       /* the maximum lands exactly on the edge */

where the implicit conversion from double to int is the floor for non-negative values, and the clamp catches the maximum, whose index would otherwise be nb_bins.

main. Three stages. First a self-test: build a 51-sample input (0.5 s at T_e = 0.01) with a 1 at t = 0, filter it with K = 1, \tau = 2, and print the table. Second, read enregistrement-bruit.txt into valeurs and print it. Third, read it again into bruit, filter it into sortie, write sortie.txt, and print a 16-bin histogram of bruit − sortie. Each stage checks its return codes.

C gives you the machine and nothing else: no bounds checks, no exceptions, no length on an array. Every function therefore carries its lengths and returns its errors, and every program is tested with an input whose correct output is known and not zero.

Part 5

What the filter does to the signal

The recording is 250 samples of a sine at 1.00 Hz with amplitude 1.00 and additive noise of standard deviation 0.096 (a least-squares sine fit; the fitted sine is the dashed line in the hero demo). The question a filter is supposed to answer is: can we get the sine back with less noise? The response plots say how a first-order filter trades the two.

Three settings tell the story. At the program's \tau = 2 s the sine is thirteen times above the cutoff: gain 0.08, lag 87°, the signal is gone. At \tau = 0.2 s the gain is 0.62 and the lag 52°: a smaller, later sine, further from the clean one (RMSE 0.54) than the raw recording (0.10). At \tau = 0.02 s the gain is 0.99 and the lag 9°, two samples; the output is now within 0.12 of the clean sine, close to the raw recording's 0.10 but still not better. Sweeping \tau finely, the output is never closer to the clean sine than the recording itself: the best time constant is 0.008 s, less than a sample, where the filter does almost nothing.

This is not a failure of the implementation. A causal first-order low-pass removes noise by averaging the recent past, and averaging the recent past of a sine delays it; at 100 samples per period and 10% noise, the delay costs more than the averaging saves. Removing noise from a signal at a known frequency calls for a filter that knows the frequency, a narrow band-pass, a notch on the noise, or an oscillator model inside a Kalman filter, or for an offline zero-phase filter run forwards and backwards. The first-order filter earns its keep where the signal is much slower than the noise, which the program's own recording is not.

Part 6

Back to Kalman

The first-order filter and the Kalman filter of chapters 01 and 02 are closer than they look. Take the scalar Kalman filter for a slowly drifting level, x_{k+1} = x_k + w_k, z_k = x_k + \nu_k, with noise variances q and r. Chapter 02's exercise 4 shows that its gain converges to a constant K_\infty, after which the update reads

\hat x_k = (1 - K_\infty)\,\hat x_{k-1} + K_\infty\, z_k, \qquad K_\infty = \frac{p_\infty}{p_\infty + r}, \quad p_\infty = \frac{q + \sqrt{q^2 + 4qr}}{2}.

That is the C program's recursion with z_0 = 1 - K_\infty, static gain 1, and the current sample instead of the delayed one: a first-order low-pass with time constant \tau = -T_e / \ln(1 - K_\infty). The Kalman filter's contribution is not the recursion, which is forty years older, but the choice of its coefficient: the time constant is derived from how fast the level drifts (q) relative to how noisy the sensor is (r), rather than guessed. For q \ll r, K_\infty \approx \sqrt{q/r}, and the filter averages over about \sqrt{r/q} samples. Chapter 04's forecaster had K_\infty = 0.31, a three-sample time constant, and lagged the series for exactly the reason the sine lags here.

Conversely, a first-order filter whose time constant was chosen by ear is a Kalman filter for some unstated q/r, and stating it is often the quickest way to see whether the choice is reasonable. On a microcontroller the two cost the same: one multiply-add per sample. The full Kalman filter with a time-varying gain costs a few more and a 2×2 matrix in memory, chapter 01's twenty lines translated to C, which Exercise 4 asks for.

Part 7

Check your understanding

1. Why is z_0 = e^{-T_e/\tau} rather than 1 - T_e/\tau?

Because the differential equation is solved exactly over one sampling interval for a held input; 1 - T_e/\tau is the first-order Taylor approximation (forward Euler), which is less accurate and unstable for T_e > 2\tau. For the program's values the two differ in the fifth decimal, but the exact form costs nothing more.

2. Why does the recursion use u_{k-1} and not u_k?

With a zero-order hold the sample taken at k-1 is the input applied during the interval that ends at k. Using u_k gives a different, also common, discretisation with one sample less delay; the phase plot shows the extra 360° f T_e of lag that u_{k-1} adds.

3. Why does every C function in the program take a length argument?

A C array carries no length; a pointer parameter is just an address. The function must be told how many cells it may touch, and the mismatch check in filtrage is the only protection the program has.

4. How does LireEntree return both a count and an error?

By convention: a non-negative return is the count, −1 is an error, and the caller tests < 0. C has no exceptions and one return value, so this and output pointers are the two mechanisms available.

5. Why did the original program produce all zeros without crashing?

It filtered the wrong array, a 51-sample impulse, and read 199 cells past its end. Reading past an array is undefined behaviour: here the memory happened to hold small values, the output was near zero, and %.2f printed it as 0.00. Nothing in C checks the index.

6. The corrected program still prints mostly 0.00. Is it still wrong?

It is correct and badly configured: with \tau = 2 s the 1 Hz signal is attenuated to 8%, and two decimals cannot show it. The test (an impulse of amplitude 0.005) could not reveal either problem. A unit step and %.4f would.

7. Why can no time constant make the output closer to the clean sine than the recording?

Because a causal low-pass delays what it smooths, and at 100 samples per period the delay of even a two-sample time constant costs as much as the noise it removes. Denoising a known-frequency signal needs a filter that knows the frequency, or an offline zero-phase filter.

8. In what sense is the steady-state Kalman filter a first-order filter?

Its update \hat x_k = (1-K_\infty)\hat x_{k-1} + K_\infty z_k is the same recursion with z_0 = 1 - K_\infty. The Kalman filter supplies the coefficient from q and r instead of a guess, and, before convergence, a time-varying one.

Part 8

Exercises

  1. Make it real-time. Rewrite the filter as a function that takes one input sample and returns one output sample, keeping its state between calls, as a sensor loop on a microcontroller would call it.
    Hint

    The state is the previous output and the previous input. Keep them in a struct that the caller owns, or in static variables if there is only ever one filter.

    Solution 
    typedef struct { double z0, b, y_prev, u_prev; } Filtre;

void filtre_init(Filtre *f, double K, double tau, double Te) {
    f->z0 = exp(-Te / tau); f->b = K * (1 - f->z0); f->y_prev = 0; f->u_prev = 0;
}
double filtre_step(Filtre *f, double u) {
    double y = f->z0 * f->y_prev + f->b * f->u_prev;   /* one multiply-add, one multiply */
    f->y_prev = y; f->u_prev = u;
    return y;
}

    Calling filtre_step on each sample of the recording reproduces filtrage() exactly; the whole state is four doubles, and nothing is allocated.

  2. Test it properly. Replace the impulse self-test by a unit step and check, in code, that the output reaches 63.2% of K after \tau/T_e samples (plus one for the delay) and 99.3% after five time constants.
    Hint

    Use \tau = 0.05 s so that the test fits in half a second; compare with a tolerance, since 63.2% falls between samples.

    Solution

    With \tau = 0.05 s the step response first exceeds 0.632 at the fifth sample after the step and 0.993 at the 25th (the recursion's one-sample delay shifts the whole curve by one sample, so the count from the step itself is exact); the page's "unit step" input shows the curve. A test that prints PASS or FAIL and returns a non-zero exit code on failure is worth more than the printed table, because a build script can run it.

  3. Choose \tau for the recording. Fit the clean sine, as the page does, then sweep \tau and report the RMSE between the filter output and the clean sine. Where is the minimum, and what does that say about using a first-order filter here?
    Hint

    In Python: a least-squares fit of a\sin\omega t + b\cos\omega t + c over a grid of frequencies, then np.exp(-Te/tau) and the recursion in a loop.

    Solution

    The fit gives 1.002 Hz, amplitude 0.997, noise sd 0.096. The RMSE to the clean sine is 0.697 at \tau = 2, 0.539 at 0.2, 0.228 at 0.05, 0.120 at 0.02, and its minimum, 0.095, is at \tau \approx 0.008 s, below one sample, where the filter barely acts. The recording is not a job for a causal first-order filter.

  4. Chapter 01 in C. Translate the two-state Kalman filter of chapter 01 to C: a struct with x and the four entries of P, a predict and an update function with the scalar innovation, and no matrix library. Run it on the vehicle CSV and compare with the Python estimates.
    Hint

    With H = (1, 0) the innovation covariance is the scalar P_{00} + R, so no inverse is needed; write the 2×2 products out by hand, as the page's JavaScript does.

    Solution

    About forty lines. The estimates agree with the NumPy class to rounding (the page's JavaScript version, written the same way, matches the Python output to 7 \times 10^{-5}, the precision of the CSV). The cost per sample is a dozen multiply-adds and eight doubles of state: a Kalman filter fits on any microcontroller that has a floating-point unit, and on most that do not.

Part 10

Scope and further reading

Scope. This chapter covers the first-order filter, its exact discretisation, the subset of C needed to implement it with file I/O, and the reading of a small program for bugs. It does not cover higher-order or FIR filter design, fixed-point arithmetic, which a microcontroller without a floating-point unit would need, or the toolchains of specific devices.
