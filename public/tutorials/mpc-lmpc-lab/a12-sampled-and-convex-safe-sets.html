Sampled and convex safe sets

Chapters A10 and A11 computed a terminal set from the model: an invariant polytope under a designed local law. Learning MPC gets one from experience instead. If the same task has been completed before, every state an earlier successful run passed through comes with a known admissible way to the goal, the rest of that run. This chapter defines the sampled safe set those states form, convexifies it into a polytope with barycentric coordinates, and proves that the hull is control invariant for a linear system, using linearity exactly once. Below, three successful runs of the course's cart are stored; click any state to learn what, if anything, certifies it.

Part 1

Repeated tasks

Two indices. Learning MPC keeps an iteration index j for the repetition of the task and a time index t inside one repetition. A trajectory of iteration j is x^j[0], u^j[0], x^j[1], \ldots, x^j[T_j], generated by the plant x^j[t+1] = f(x^j[t], u^j[t]), and every iteration starts from the same state x^j[0] = x_S. The repetition is what makes experience from one run relevant to the next: a racing lap, a batch in a reactor, a pick-and-place cycle, or, here, the cart brought from x_S = (-3.5, 2.5) to rest at the origin, again and again.

Target and success. Let \mathcal O be the target set. An iteration is successful if it respects every state and input constraint and ends in the target, x^j[T_j] \in \mathcal O. In this course \mathcal O = \{0\}, and a run is completed exactly by two deadbeat inputs once it is within 10^{-3} of the origin (Part 6). Only successful iterations feed the construction; a run that left the box or never arrived teaches nothing here.

The three runs above. Plain receding-horizon MPC with N = 2 and no terminal ingredients (chapter A6) applies u = 0 first, coasts to (-1, 2.5) and (1, 1.5), overshoots to p = 2 and spirals back: 20 inputs, cost 28.09. With N = 3 it brakes at once, u_0 = -0.58, and needs 11 inputs at cost 17.03; the LQR law of chapter A7 clipped to |u| \le 1 takes 11 inputs at cost 17.12. All three are successful, and the slow one is by far the worst. It is also the one that matters most below.

Part 2

The sampled safe set

What is the sampled safe set?

In plain words: every state that some earlier successful run passed through, plus the target. Each such state is "safe" because a known admissible way to the target exists from it: replay the rest of that run.

More precisely: after successful iterations 0, \ldots, j,

\boxed{SS^j = \Big( \bigcup_{i=0}^{j} \bigcup_{t=0}^{T_i} \{x^i[t]\} \Big) \cup \mathcal O.}

It is finite for finitely many finite runs, and it grows as runs are added. Every non-terminal element carries three facts with it: the input that was applied there, the state that followed, and the cost that was paid from there to the end.

Continuation
The stored input u^i[t] and successor x^i[t+1] kept with each stored state.
Control invariance
From every point of the set, some admissible input keeps the next state in the set.
"Safe"
A model- and task-specific notion: a certificate that the task can be completed from here under the conditions of the run. Not a certificate against disturbances, perception errors or model mismatch.

Why the sampled safe set is control invariant. Take a stored non-terminal state x = x^i[t] \in SS^j. Its stored input u^i[t] was admissible and produced f(x^i[t], u^i[t]) = x^i[t+1] \in SS^j. Hence

\boxed{x \in SS^j \;\Longrightarrow\; \exists\, u \in \mathcal U : f(x, u) \in SS^j,}

with the convention that an admissible controller keeps the state inside \mathcal O once it arrives, which for the origin of the cart is u = 0. The stored trajectory itself is the continuation. Note the quantifiers, the same ones as in chapter A10: for every state there exists an input, and each sample may use a different one. Nothing about the model was used: the certificate is the run itself. Click a stored state in the demo: the answer names the run, the step, the stored input and the successor it leads to, with its realised cost-to-go.

Part 3

Convex safe sets and barycentric coordinates

Why convexify. A terminal constraint x_N \in SS^j would force the prediction to end exactly on one of finitely many stored points, a combinatorial constraint that no quadratic program can hold. For a linear system with convex constraints one uses instead the convex safe set

\boxed{CS^j = \operatorname{conv}(SS^j),}

which fills the space between stored states and keeps the online problem convex. In the demo it is the shaded polygon: 7 vertices, area 10.25, against 48 for the box and 39.25 for the control-invariant set \mathcal C_\infty of chapter A10.

Barycentric coordinates. Let the stored safe states be s_1, \ldots, s_M. A point x \in CS^j can be written x = \sum_{r=1}^{M} \lambda_r s_r with \lambda_r \ge 0 and \sum_r \lambda_r = 1. Stacking the stored states as the rows of S \in \mathbb R^{M \times n},

\boxed{x = S^\top \lambda, \qquad \lambda \ge 0, \qquad \mathbf 1^\top \lambda = 1.}

The row convention is shared by the formulas and the code, which is why the transpose appears, both here and in the LMPC terminal constraint of chapter A13. The weights are not unique in general: Carathéodory's theorem says that in \mathbb R^n at most n + 1 stored points are needed, three in the plane, and a linear program picks one such representation. The default probe (-1, 1.8) lies on no run; the demo writes it as 0.05 of (1, 1.5), 0.83 of (-1.281, 1.938) and 0.12 of (0.156, 0.938), one state from the slow run and two from the N = 3 run.

Who shapes the hull. Switch the runs off one at a time: the hull does not change until the slow N = 2 run goes. Its overshoot to p = 2 and its return at v = -1.5 explore states the two good runs never visit, so it sets the whole hull on its own, and the good runs only add stored costs inside it. A worse run can be the more informative one about safety, which chapter A13 separates from its information about cost.

Part 4

Why the convex safe set is control invariant

Assume x^+ = Ax + Bu, convex \mathcal X and \mathcal U, and that every stored state s_r comes with an admissible continuation input u_r^{\mathrm{safe}} and safe successor s_r^+ \in SS^j. For x = \sum_r \lambda_r s_r choose u = \sum_r \lambda_r u_r^{\mathrm{safe}}. By linearity,

x^+ = A \sum_r \lambda_r s_r + B \sum_r \lambda_r u_r^{\mathrm{safe}} = \sum_r \lambda_r \big( A s_r + B u_r^{\mathrm{safe}} \big) = \sum_r \lambda_r s_r^+ .

The input is admissible because \mathcal U is convex; the successor lies in CS^j because every s_r^+ does and the hull is convex; and x itself is admissible because SS^j \subseteq \mathcal X and \mathcal X is convex. Hence CS^j is control invariant. Linearity is used exactly once, to pull the convex combination through f; convexity is used twice, for the input and for the hull (three times, counting \mathcal X).

The identity, in arithmetic. At the probe (-1, 1.8) the mixed input is u = -1, every one of the three contributing states having braked at full force, and Ax + Bu = (0.3, 0.8); the same weights on the three stored successors give (0.3, 0.8) to 6 \times 10^{-16}. The widget below does the same with four states of the slow run and weights you can shift.

What the two certificates say. A stored state is safe because of what happened: the run is the proof, and the model is not needed. A hull point that is on no run is safe because of the model: linearity and convexity turn the stored facts into a prediction about a state nobody has visited. The first claim survives any model error that did not show up in the run; the second does not. Chapter B6 asks which line of the proof fails under mismatch.

Part 5

What breaks outside the assumptions

Nonlinear dynamics. For nonlinear f, f(\sum_r \lambda_r s_r, \sum_r \lambda_r u_r) is in general not \sum_r \lambda_r f(s_r, u_r), and the one line of the proof that used linearity fails. The smallest example is f(x, u) = x^2 + u on the line, with stored states 0 and 2, inputs 0, successors 0 and 4: the midpoint 1 with the mixed input 0 goes to 1, while the mixture of successors is 2.

Convexifying stored trajectories for a nonlinear task therefore needs a separate justification: a local convex safe set around the current operating point with a local affine model, which is what the racing controller of chapter B4 does, or a sampled safe set kept as it is, at the price of a mixed-integer terminal constraint (chapter A15).

Nonconvex constraints. Convex combinations of admissible states can be inadmissible when \mathcal X is not convex: in the collision-avoidance lab of chapter B1 two safe positions on either side of the crossing have a midpoint in the middle of it. The hull of stored states is then not even a subset of \mathcal X, let alone invariant.

What stays true. The sampled safe set is control invariant for any f and any \mathcal X: its certificate is the run. Everything between the samples is the model's claim.

Part 6

The code behind it

The course package stores runs in the LMPCController of chapter A13; the two methods below are its database. The first admits a trajectory only if it ends on the target.

advanced_mpc_lmpc/lmpc.py · LMPCController.add_trajectory

    def add_trajectory(self, X, U):
        X = np.asarray(X, float)
        U = np.asarray(U, float)

        if len(X) != len(U) + 1:
            raise ValueError("X must contain one more state sample than U")

        if X.shape[1] != self.n or U.shape[1] != self.m:
            raise ValueError("trajectory dimensions do not match the controller")

        if np.linalg.norm(X[-1] - self.target) > self.target_tolerance:
            raise ValueError(
                "trajectory does not terminate sufficiently close to the target"
            )

        J = trajectory_cost_to_go(X, U, self.Q, self.R, self.Q1)

        self.trajectories.append(X.copy())
        self.inputs.append(U.copy())
        self.qfun.append(J.copy())
        self.iteration_costs.append(float(J[0]))

A trajectory arrives as T + 1 states and T inputs, the convention of chapter A1's rollout, and the method refuses anything else. It then checks what "successful" means for the construction: the last state must be the target to within target_tolerance, 10^{-7} by default, which is why every run in this chapter is completed by the exact deadbeat bridge before it is stored. (Constraint satisfaction along the run is the caller's responsibility: the runs above were generated by controllers that enforce the box and the interval at every step.) The realised cost-to-go J is computed backwards from the end and kept with the states; J[0] is the iteration cost that chapter B2's learning curve plots.

advanced_mpc_lmpc/lmpc.py · LMPCController.safe_data

    def safe_data(self, last_n_trajectories=None):
        """
        Return safe states, sampled cost-to-go, continuation inputs, and
        successor indices.

        The target is stored once explicitly at index 0. Terminal copies of
        the target from each trajectory are omitted to reduce degeneracy.
        """
        if last_n_trajectories is None:
            indices = range(len(self.trajectories))
        else:
            q = max(int(last_n_trajectories), 1)
            start = max(0, len(self.trajectories) - q)
            indices = range(start, len(self.trajectories))

        S = [self.target.copy()]
        V = [0.0]
        Usafe = [np.zeros(self.m)]
        next_index = [0]

        for it in indices:
            X = self.trajectories[it]
            U = self.inputs[it]
            J = self.qfun[it]

            T = len(U)
            start_idx = len(S)

            for k in range(T):
                S.append(X[k].copy())
                V.append(float(J[k]))
                Usafe.append(U[k].copy())

                if k < T - 1:
                    next_index.append(start_idx + k + 1)
                else:
                    next_index.append(0)

        return (
            np.asarray(S, float),
            np.asarray(V, float),
            np.asarray(Usafe, float),
            np.asarray(next_index, int),
        )

This builds the matrix S, one stored state per row, and three parallel arrays: V, the cost-to-go of each row; Usafe, the continuation input; and next_index, the row of the stored successor. The target is row 0, stored once with value 0, input 0 and successor 0, so that the convention "once at the target, stay there" is a row like any other. Each trajectory contributes its states x[0], \ldots, x[T-1] but not x[T], which is the target already stored at row 0, so the last state of every run points to row 0 as its successor. The optional last_n_trajectories keeps only the most recent runs, the window of chapter B2, which bounds the number of barycentric variables in the online problem.

Part 7

Common pitfalls

  1. "Every stored state is optimal." No. Stored states are safe because they belong to successful runs, and a successful run may be very suboptimal: the slow run above costs 65 percent more than the others.
  2. "The convex hull is always safe." No. The proof relies on linear dynamics and convex constraints; Part 5 shows one line failing for x^2 + u.
  3. "Safety here means robust safety." No. The certificate is nominal: the stored run happened under the conditions of the run, and the hull argument uses the model exactly.
  4. "Control invariance means one input works for the whole set." No. \forall x\ \exists u, and the input differs from state to state: it is the stored one at a stored state and a mixture elsewhere.
  5. "The hull grows with every run." Not necessarily. A better run that stays inside the explored region adds costs, not geometry; the slow run above sets the hull on its own.
Part 8

Check your understanding

Try to answer each question before opening it.

1. What is the sampled safe set?

The union of the states visited by successful previous iterations, together with the target set.

2. Why is a sampled state safe?

Because replaying its stored continuation input takes the system to the next state of a successful trajectory and, step by step, to the target.

3. What is the convex safe set, and why is it used?

The convex hull of the sampled safe set, CS^j = \operatorname{conv}(SS^j). A terminal constraint on finitely many points is combinatorial; the hull is a polytope that a quadratic program can hold.

4. Why is it control invariant in the linear case?

Linearity maps convex combinations of safe state and input pairs to the same convex combinations of safe successors, and the state and input constraints are convex.

5. What is stored besides the state?

A continuation input with its successor, and a realised cost-to-go.

6. Where does the proof use linearity, and where convexity?

Linearity once, to write A \sum \lambda_r s_r + B \sum \lambda_r u_r as \sum \lambda_r (A s_r + B u_r); convexity for the input set, for the hull and for the state set.

7. What does the target set have to satisfy?

It must be control invariant under an admissible input: for the origin of the cart, u = 0 keeps it there. Without that, the terminal states of the stored runs would have no continuation.

8. Can a worse run enlarge the safe set?

Yes. The slow N = 2 run explores states that the good runs never visit, and its hull contains theirs. Geometry and cost are different pieces of information.

Part 9

Exercises

Each exercise has a hint and a solution; the code runs with the course package installed. Try first, then peek.

  1. Sampled safe-set invariance. Prove x \in SS^j \Rightarrow \exists u \in \mathcal U : f(x, u) \in SS^j, and state the required target-set assumption.

    Hint

    Two cases: a stored non-terminal state, and a point of the target.

    Solution

    If x = x^i[t] with t < T_i, the stored input u^i[t] \in \mathcal U was applied in a successful, hence admissible, run and produced x^i[t+1], which is in SS^j by definition. If x \in \mathcal O, which includes every terminal state x^i[T_i], one must assume that \mathcal O is itself control invariant under an admissible controller: there is u \in \mathcal U with f(x, u) \in \mathcal O \subseteq SS^j. For \mathcal O = \{0\} and the double integrator, u = 0 does it, which is why safe_data stores the target with input 0 and itself as successor.

  2. Convex invariance. For x^+ = Ax + Bu, prove control invariance of CS^j under convex constraints and identify where linearity and convexity enter.

    Hint

    Use the mixture of stored inputs with the same weights.

    Solution

    Let x = \sum_r \lambda_r s_r with \lambda in the simplex, and u = \sum_r \lambda_r u_r^{\mathrm{safe}}. Convexity of \mathcal U: u is a convex combination of admissible inputs, so u \in \mathcal U. Linearity: Ax + Bu = \sum_r \lambda_r (A s_r + B u_r^{\mathrm{safe}}) = \sum_r \lambda_r s_r^+. Convexity of the hull: each s_r^+ \in SS^j \subseteq CS^j, so their convex combination is in CS^j. Convexity of \mathcal X is needed too: the hull of admissible states must consist of admissible states, which holds since SS^j \subseteq \mathcal X and \mathcal X is convex.

  3. The identity at a probe. Take the probe (-1, 1.8) of the hero with the weights the LP chose, compute the mixed input and the successor two ways, and check that they agree.

    Hint

    convex_safe_value returns the weights; safe_data returns the stored inputs and the successor indices.

    Solution

    The LP gives \lambda = 0.0505 on (1, 1.5), 0.834 on (-1.281, 1.938) and 0.1155 on (0.156, 0.938), which reconstruct (-1, 1.8) exactly. All three stored inputs are -1, so the mixed input is -1, and Ax + Bu = (-1 + 1.8 - 0.5,\ 1.8 - 1) = (0.3, 0.8). The same weights on the stored successors (2, 0.5), (0.129, 0.919) and (0.594, -0.062) give (0.3, 0.8) to 6 \times 10^{-16}.

    S, V, Usafe, nxt = ctrl.safe_data()               # ctrl holds the three runs
val, lam, ok = convex_safe_value([-1.0, 1.8], S, V)
u = lam @ Usafe[:, 0]
print(A @ [-1.0, 1.8] + B[:, 0] * u, S[nxt].T @ lam)   # (0.3, 0.8) twice

  4. Build the database yourself. Write a function that takes a list of successful runs and returns S, the costs-to-go, the continuation inputs and the successor indices, with the target stored once. Compare it with safe_data on the three runs.

    Hint

    Loop over runs, append x[0], \ldots, x[T-1], point the last one at row 0; compute the costs backwards.

    Solution 
    def my_safe_data(runs, Q, R):
    S, V, Us, nxt = [np.zeros(2)], [0.0], [np.zeros(1)], [0]
    for X, U in runs:
        J = np.zeros(len(X))
        for k in range(len(U) - 1, -1, -1):
            J[k] = X[k] @ Q @ X[k] + U[k] @ R @ U[k] + J[k + 1]
        base = len(S)
        for k in range(len(U)):
            S.append(X[k]); V.append(J[k]); Us.append(U[k])
            nxt.append(base + k + 1 if k < len(U) - 1 else 0)
    return np.array(S), np.array(V), np.array(Us), np.array(nxt)

    On the three runs it returns 43 rows, and every array agrees with safe_data to round-off. The one design decision is where the target lives: once, at row 0, so that every run's last state points to the same row.

  5. Who shapes the hull. Compute the hull area with the slow run alone, with the two plain-MPC runs, and with all three.

    Hint

    scipy.spatial.ConvexHull(points).volume is the area in two dimensions; include the origin.

    Solution

    10.25 in all three cases: the slow run's 21 states already contain the other two runs' states in their hull, because the overshoot to p = 2 and the return at v = -1.5 bound the region the good runs stay inside. Adding good runs adds 22 stored states with lower costs, and no geometry.

  6. A nonlinear counter-example of your own. Give a nonlinear f(x, u) and two stored transitions for which the mixed successor leaves the hull of the stored states.

    Hint

    Make the successors of the two stored states the stored states themselves, so the hull is just the segment between them, then make f bend away from it.

    Solution

    Take f(x, u) = x + u + x^2 on the line, stored states s_1 = 0 with u_1 = 0 and s_2 = 1 with u_2 = -1: both are fixed points, so SS = \{0, 1\} and CS = [0, 1]. The midpoint 0.5 with the mixed input -0.5 goes to 0.5 - 0.5 + 0.25 = 0.25, still inside; but s_2 = 2 with u_2 = -4 is also a fixed point, and then the midpoint 1 with u = -2 goes to 1 - 2 + 1 = 0, which is the boundary, while x = 1.5 with u = -3 goes to 1.5 - 3 + 2.25 = 0.75. Pick instead f(x, u) = x + u - x^2 with the fixed points 0 (u = 0) and 2 (u = 4): the midpoint 1 with u = 2 goes to 1 + 2 - 1 = 2, on the boundary, and x = 1.5 with u = 3 goes to 1.5 + 3 - 2.25 = 2.25 > 2, outside the hull. The mixed input of two admissible fixed-point inputs leaves the segment.

Part 10

The chapter on one page

  1. Repetition: the same task from x_S every time; successful runs end in \mathcal O = \{0\} and respect the constraints.
  2. Sampled safe set: all visited states of successful runs plus the target; control invariant by replaying the stored input, for any model.
  3. Convex safe set: its hull, x = S^\top \lambda on the simplex; 7 vertices and area 10.25 for the three runs, set by the slowest of them.
  4. The proof: mix the stored inputs with the same weights; linearity once, convexity for \mathcal U, the hull and \mathcal X.
  5. In numbers: the probe (-1, 1.8) is 0.05, 0.83, 0.12 of three stored states, u = -1, successor (0.3, 0.8) both ways.
  6. What breaks: x^2 + u sends the midpoint of 0 and 2 to 1, the mixed successor is 2; nonconvex \mathcal X puts midpoints in the forbidden region.
  7. Next: a value function on the same data, and the problem that uses both (chapter A13).

The vocabulary, in one table

Term Meaning here
Iteration j, time t Which repetition of the task; where inside it.
Successful iteration Constraints respected and the final state in \mathcal O.
Sampled safe set SS^j Visited states of successful runs plus the target.
Convex safe set CS^j Its convex hull.
Barycentric coordinates \lambda Non-negative weights summing to one; x = S^\top \lambda.
Continuation input The stored u_r^{\mathrm{safe}} that moved s_r to s_r^+.
Deadbeat bridge Two inputs that bring the cart exactly to the origin, so a run ends on the target.
Carathéodory At most n + 1 stored points represent any hull point.

Scope. Deterministic repeated tasks with known linear dynamics and convex constraints, the setting in which the convex construction is justified; the sampled set needs neither. The runs are nominal closed loops of the model.
