Advanced MPC and Learning MPC · Chapter 05 of 09

Learning Model Predictive Control on a repeated double-integrator task

Chapter 03 designed the terminal set and terminal cost by hand, from a Riccati equation and an invariant polytope. Learning MPC asks a different question: if the same constrained task is run again and again from the same start, can the earlier successful runs supply those terminal ingredients? They can. The states visited by successful runs form a safe set, the costs they accumulated form a value function, and for linear dynamics with convex constraints both can be convexified into one quadratic program. Below, a three-step MPC with no terminal ingredients produces a feasible but poor first run, and nine learning iterations, computed live, close almost all of its gap to a long-horizon reference.

Part 1

Repeated tasks and sampled safe sets

Two indices. LMPC keeps an iteration index j for the repetition of the task and a time index t inside one repetition. A trajectory of iteration j is x^j[0], u^j[0], x^j[1], \ldots, x^j[T_j], generated by the plant x^j[t+1] = f(x^j[t], u^j[t]), here f(x, u) = Ax + Bu, and every iteration starts from the same state x^j[0] = x_S. The repetition is what makes experience from one run relevant to the next.

Target and success. Let \mathcal O be the target set. An iteration is successful if it respects every state and input constraint and ends in the target, x^j[T_j] \in \mathcal O. In both examples of this chapter, \mathcal O = \{0\}. Only successful iterations feed the construction.

What is the sampled safe set?

In plain words: every state that some earlier successful run passed through, plus the target. Each such state is "safe" because a known admissible way to the target exists from it: replay the rest of that run.

More precisely: after successful iterations 0, \ldots, j,

\boxed{SS^j = \Big( \bigcup_{i=0}^{j} \bigcup_{t=0}^{T_i} \{x^i[t]\} \Big) \cup \mathcal O.}

It is finite for finitely many finite runs and grows as runs are added.

Control invariance
From every point of the set, some admissible input keeps the next state in the set.
Continuation
The stored input u^i[t] and successor x^i[t+1] kept with each stored state.
"Safe"
A model- and task-specific notion. It is not a certificate against disturbances, perception errors or model mismatch.

Why the sampled safe set is control invariant. Take a stored nonterminal state x = x^i[t] \in SS^j. Its stored input u^i[t] was admissible and produced f(x^i[t], u^i[t]) = x^i[t+1] \in SS^j. Hence

\boxed{x \in SS^j \;\Longrightarrow\; \exists\, u \in \mathcal U : f(x, u) \in SS^j,}

with the convention that an admissible controller keeps the state inside \mathcal O once it arrives. The stored trajectory itself is the continuation. Note the quantifiers: for every state there exists an input. It does not say that one input works for all states; each sample may use a different continuation.

Part 2

Convex safe sets and barycentric coordinates

Why convexify. A terminal constraint x_N \in SS^j would force the prediction to end exactly on one of finitely many stored points, a combinatorial constraint. In the linear, convex setting one uses instead the convex safe set

\boxed{CS^j = \operatorname{conv}(SS^j),}

which fills the space between stored states and keeps the online problem convex.

Barycentric coordinates. Let the stored safe states be s_1, \ldots, s_M. A point x \in CS^j can be written x = \sum_{r=1}^{M} \lambda_r s_r with \lambda_r \ge 0 and \sum_r \lambda_r = 1. Stacking the stored states as the rows of S \in \mathbb R^{M \times n},

\boxed{x = S^\top \lambda, \qquad \lambda \ge 0, \qquad \mathbf 1^\top \lambda = 1.}

The row convention is shared by the formulas and the code, which is why the transpose appears, both here and in the LMPC terminal constraint of Part 5.

Why the convex safe set is control invariant

Assume x^+ = Ax + Bu, convex \mathcal X and \mathcal U, and that every stored state s_r comes with an admissible continuation input u_r^{\mathrm{safe}} and safe successor s_r^+. For x = \sum_r \lambda_r s_r choose u = \sum_r \lambda_r u_r^{\mathrm{safe}}. By linearity,

x^+ = \sum_r \lambda_r \big( A s_r + B u_r^{\mathrm{safe}} \big) = \sum_r \lambda_r s_r^+ .

The input is admissible because \mathcal U is convex; the successor lies in CS^j because every s_r^+ does and the hull is convex. Hence CS^j is control invariant. Linearity is used exactly once, to pull the convex combination through f; convexity is used twice, for the input and for the hull. Part 7 checks this identity numerically on the stored seed to round-off.

What breaks outside these assumptions. For nonlinear f, f(\sum_r \lambda_r s_r, \sum_r \lambda_r u_r) is in general not \sum_r \lambda_r f(s_r, u_r), and convex combinations can violate nonconvex constraints (chapter 04's disjunction is the standing example). Convexifying stored trajectories for a nonlinear task needs a separate justification.

Part 3

Learning a terminal value function

Roll-out cost-to-go. For a successful iteration i with stage cost h,

\boxed{J_t^i = \sum_{k=t}^{T_i - 1} h\big(x^i[k], u^i[k]\big)}, \qquad J_{T_i}^i = 0 :

the remaining cost actually incurred if the stored continuation is replayed from time t. In the code it is computed by the backward recursion J_t = h(x_t, u_t) + J_{t+1}, which resembles dynamic programming but over realised trajectories, not over the whole state space.

Sampled value function. If a state appears in several runs, keep the best stored cost-to-go, V^j(x) = \min\{ J_t^i : x^i[t] = x \}, with V^j = 0 on \mathcal O. The difficulty is that this function is defined only at sampled states.

What is the convex terminal value?

In plain words: the cheapest way to write x as a mixture of stored states, charging each stored state its stored cost. It is the lower convex envelope of the stored (state, value) pairs, and it costs one linear program.

More precisely:

\boxed{V_c^j(x) = \min_{\lambda} \sum_{r=1}^{M} \lambda_r V_r} \quad \text{s.t.} \quad S^\top \lambda = x, \quad \mathbf 1^\top \lambda = 1, \quad \lambda \ge 0,

where V_r is the cost-to-go stored with row r of S. For fixed data this is a linear program in \lambda.

Dominated sample
A stored pair lying above the envelope. The LP never selects it and V_c^j need not reproduce its value.
Carathéodory
In \mathbb R^n at most n + 1 stored points are needed to represent any hull point, so a sparse \lambda always exists.

A one-dimensional example. The scalar integrator x^+ = x + u with x \in [-5, 5], u \in [-1, 1], target \{0\} and h(x, u) = x^2 + 0.1u^2. Two successful runs, 4 \to 3 \to 2 \to 1 \to 0 and -3 \to -2 \to -1 \to 0, give SS^1 = \{-3, \ldots, 4\}, CS^1 = [-3, 4], and stored costs-to-go such as J(4) = 16.1 + 9.1 + 4.1 + 1.1 = 30.4 and J(2) = 4.1 + 1.1 = 5.2.

How to read the figure. The dots are values known from previous executions. The curve is not new measured data: for each intermediate x it answers "what is the cheapest convex combination of stored pairs that represents this state?" In one dimension that is a convex, piecewise-affine lower envelope. The notebook's query is x = 2.5: \lambda = 0.5 on x = 2 and 0.5 on x = 3, so V_c^1(2.5) = 0.5 \cdot 5.2 + 0.5 \cdot 14.3 = 9.75, and the reconstructed state is exactly 2.5.

Part 4

Why the learned value can act like a terminal Lyapunov function

Data recursion. For a stored state s_r with input u_r and successor s_r^+, the stored costs satisfy J_r = h(s_r, u_r) + J_r^+. For x = \sum_r \lambda_r s_r use u = \sum_r \lambda_r u_r, so that x^+ = \sum_r \lambda_r s_r^+ by Part 2.

Learned-value decrease. Convexity of h gives h(x, u) \le \sum_r \lambda_r h(s_r, u_r). The definition of V_c^j as a minimum gives V_c^j(x^+) \le \sum_r \lambda_r J_r^+, since the weights \lambda on the successors are one feasible choice. Adding,

h(x, u) + V_c^j(x^+) \le \sum_r \lambda_r \big[ h(s_r, u_r) + J_r^+ \big] = \sum_r \lambda_r J_r .

If \lambda is the minimiser defining V_c^j(x), the right side is V_c^j(x), and

\boxed{V_c^j(x^+) - V_c^j(x) \le -h(x, u).}

This is the same structural condition as the terminal-cost decrease p(Ax + B\kappa_f(x)) - p(x) \le -\ell(x, \kappa_f(x)) of chapter 03, with the terminal value built from data instead of a Riccati equation. The convex hull plays the role of \mathcal X_f, the convex combination of stored inputs plays the role of the terminal controller \kappa_f.

Worked instance. In the scalar example take x = 2.5, \lambda = (0.5, 0.5) on s = 2, 3, stored inputs -1, -1, so u = -1 and x^+ = 1.5. Then V_c(1.5) = 0.5 \cdot 1.1 + 0.5 \cdot 5.2 = 3.15, h(2.5, -1) = 6.25 + 0.1 = 6.35, and V_c(1.5) - V_c(2.5) = 3.15 - 9.75 = -6.6 \le -6.35. The slack of 0.25 is the convexity gap of x^2 between 2.5^2 and the average of 2^2 and 3^2.

Part 5

The LMPC online optimisation

At the current state, with stored data (S, V), solve

\begin{aligned} \min_{\{u_k\}, \lambda}\quad & \sum_{k=0}^{N-1} h(x_k, u_k) + \sum_{r=1}^{M} \lambda_r V_r \\ \text{s.t.}\quad & x_{k+1} = A x_k + B u_k, \qquad x_k \in \mathcal X, \quad u_k \in \mathcal U, \\ & x_N = S^\top \lambda, \qquad \lambda \ge 0, \qquad \mathbf 1^\top \lambda = 1. \end{aligned}

Geometric meaning. The equality x_N = S^\top \lambda lets the optimiser reconnect to any point in the convex hull of successful experience; the cost \lambda^\top V tells it how expensive the stored continuation from that point is. LMPC therefore learns terminal geometry and terminal value at once. The last two constraints and the learned cost are the data-driven terminal ingredients; everything else is chapter 01's CFTOC.

Recursive feasibility by the shifted sequence. Suppose the solution ends at x_N^\star = \sum_r \lambda_r^\star s_r. At the next time, shift the optimised inputs and append

\boxed{u_N^{\mathrm{safe}} = \sum_r \lambda_r^\star u_r^{\mathrm{safe}}.}

Then x_{N+1} = A \sum_r \lambda_r^\star s_r + B \sum_r \lambda_r^\star u_r^{\mathrm{safe}} = \sum_r \lambda_r^\star s_r^+ \in CS^j: the shifted sequence is feasible for the new problem, exactly as in chapter 03's terminal-set proof, with the stored continuation inputs in place of the terminal controller. The code's warm start is this shifted sequence.

Stage cost.

\boxed{h(x, u) = x^\top Q x + u^\top R u + \|Q_1 x\|_1,}

convex but not purely quadratic. At the start, h(x_S, 0) = 225 + 0 + 0.01 \cdot 15 = 225.15. The small \ell_1 term is there to show that the value-decrease argument of Part 4 needs only convexity of h, and that the online problem can still be a QP.

Epigraph formulation of the \ell_1 term. Let z_k = Q_1 x_k. Introduce e_{i,k} \ge 0 with z_{i,k} \le e_{i,k} and -z_{i,k} \le e_{i,k}, and add \sum_i e_{i,k} to the objective. At the optimum e_{i,k} = |z_{i,k}|, because any larger value could be lowered at no cost, so the \ell_1 term becomes linear inequalities plus a linear objective term. The code places epigraph variables on x_1, \ldots, x_{N-1}; x_0 is a constant and x_N is priced by the terminal value.

Why such a short horizon. The seed controller and LMPC both use N = 3, the same stage cost and the same constraints; they differ only in their terminal ingredients, none for the seed, learned for LMPC. The short horizon is what leaves room for learning: with a substantially longer horizon, plain MPC already comes very close to the reference on this task (exercise 7: N = 5 alone gets within 7 \times 10^{-4}).

Long-horizon reference. A common benchmark is one open-loop solve with a very long horizon, say N = 1000, as a proxy for the infinite-horizon optimum. Here the computation is kept light and solver-independent by checking horizon convergence instead:

About the step counts. The notebook reports a 26-step seed and iterations of 22 to 19 steps. Those counts measure the solver's tolerance, not the controllers: near the origin the states are of order 10^{-5}, the remaining cost is below 10^{-6}, and SciPy's SLSQP (tolerance 10^{-8} on a cost near 674) wanders for several steps before the stop test \|x\| \le 10^{-6} fires. With the tighter interior-point solver used on this page, every LMPC iteration reaches the origin in 12 steps plus the 2-step bridge, and the seed MPC approaches it geometrically (about a factor 2 per step) so its count depends on the stopping tolerance alone. The complete task costs agree with the notebook to 7 \times 10^{-5}, which is exactly the size of the solver's tolerance. Compare costs, not step counts.

Part 8

The first LMPC solve and the learning iterations

The first solve from the start. The explicit horizon is still 3, but the terminal set and value now carry information beyond those three steps. From x_S the first LMPC input is u_0 = 5, saturated, where the seed chose 4.285. The predicted terminal state x_3 = (-4.994, 2.486) equals its barycentric reconstruction S^\top \lambda, \sum \lambda = 1, and only two of the 27 weights are active: \lambda_4 = 0.5308 on s_4 = (-6.430, 3.061) with value 72.106 and \lambda_5 = 0.4692 on s_5 = (-3.369, 1.836) with value 19.799. The terminal state is two-dimensional, so Carathéodory's theorem promises a representation with at most three points; the optimum here uses two, a point on an edge of the hull.

Why saturating is suddenly worth it. The seed judged u_0 = 5 too expensive because its three-step objective charged the input but credited nothing for arriving earlier. LMPC charges the same three stages and adds \lambda^\top V, the stored cost of finishing the task from x_3: landing further along the seed path, between its samples 4 and 5, buys a much cheaper continuation. The information came entirely from one slow run.

The iteration algorithm. Each iteration resets to x_S, solves the LMPC problem at every step with the shifted warm start, reaches the target, closes with the exact bridge, appends the new successful trajectory and updates the costs-to-go. The online QP uses the target plus the most recent four trajectories; the full history is kept for analysis. The notebook runs nine iterations:

What is guaranteed and what is observed

Under the deterministic repetitive-task assumptions, the previous successful trajectory remains a feasible candidate for the next iteration: its terminal state is in the hull, its continuation is stored, and the LMPC objective at x_S is at most the stored cost. That supports the non-increasing iteration-cost result J^{j+1}(x_S) \le J^j(x_S), visible in the table. It is a different statement from "every LMPC converges to the unique global infinite-horizon optimum", which this chapter does not claim. What is observed in addition is that the learned trajectories approach the long-horizon reference to within 5 \times 10^{-5}. Exercise 8 shows that other seeds give curves that are flat at the same level with wiggles of 10^{-5}, the solver's tolerance, not violations of the theory.

Part 9

Anatomy of the learning: trajectories, hull growth, stored values

Phase plane and controls. The seed curls slowly towards the origin at low speed; the first LMPC iteration already lies close to the reference, accelerating hard at the start, coasting, then braking hard. The later iterations are visually indistinguishable from the reference and from each other, which is consistent with costs differing in the fourth decimal. The input sequences tell the same story: the seed never saturates, LMPC saturates at +5 for the first steps and at -5 when braking, like the reference.

Safe-set growth. Every successful run adds its states to the database and can enlarge or reshape the convex hull. After the seed the hull is the region between one slow curve and its chord back to the origin; the first LMPC runs push it out to the fast, saturated trajectories, and then it stops changing (in the browser's run the areas are 45.1 after the seed, 55.1 after three iterations and 55.1 after nine). Yet the costs keep improving. The hull is only half of the learning: LMPC also learns better cost-to-go values, and even when the geometry near convergence is fixed, improved terminal values still alter the short-horizon decision.

Stored costs-to-go. The cost-to-go along each stored trajectory is computed backward, J_T = 0, J_t = h(x_t, u_t) + J_{t+1}. The notebook checks the recursion on the last iteration: the maximum residual is 2.8 \times 10^{-14}, round-off. The curve t \mapsto J_t is the learned value function sampled along one run; J_0 is the iteration cost that the learning curve plots.

Part 10

What is learned, data growth, and common pitfalls

The plant model is not learned. A and B are known and used explicitly in every online QP. What is learned: safe terminal geometry, successful continuation inputs, and terminal cost-to-go information. Data-driven, not model-free.

LMPC is not DQN. A deep Q-network learns an action-value approximation, usually with a neural network and temporal-difference updates. This LMPC keeps an explicit model and explicit constraints, solves an optimisation online, and uses data only to build terminal ingredients. The two are related through value information, not through the algorithm.

LMPC against iterative learning control. Both exploit repetition. Classical ILC updates a trial-indexed input signal from one execution to the next; LMPC inserts learned trajectory information into a constrained receding-horizon problem. Its distinctive object is the learned terminal set and value pair.

Do different initialisations converge to the same solution? LMPC only needs an initial feasible successful trajectory, from MPC, LQR, a demonstration or anything else. Feasibility alone gives no universal global-optimum guarantee; the answer depends on the task, convexity, stored data and the formulation. This convex example does produce the same limiting cost from different reasonable seeds (exercise 8), but that observation is not a theorem.

Time-varying safe sets and data growth. If every state of every run is kept, the number of barycentric variables grows with the total sample count. One remedy is a time-varying subset,

TS_t^{l,j} = \Big( \bigcup_{i=l}^{j} \bigcup_{s=t}^{T_i} \{x^i[s]\} \Big) \cup \mathcal O,

which keeps only iterations l, \ldots, j and, from each, only the states visited at time t or later. The notebook's controller uses the iteration window alone, the most recent four trajectories, and keeps all time indices. The previous iteration is always retained, which the cost-improvement argument needs. Any such subset trades richer data against a smaller online QP.

What the experiment establishes. The short-horizon seed is feasible but more expensive; successful data provide terminal geometry and cost-to-go; the LMPC terminal state satisfies a barycentric safe-set constraint; repeated executions reduce the complete task cost; the learned trajectories approach the long-horizon reference; the modelled constraints are satisfied throughout. What it does not establish: robustness to disturbances or model mismatch, safety of arbitrary nonlinear convexification, global-optimality convergence for every LMPC problem, model-free learning, or transfer to other initial conditions without further analysis.

Common pitfalls. Every stored state is optimal: no, stored states are safe because they belong to successful runs, and a successful run may be very suboptimal (the seed is). The convex hull is always safe: no, the proof relies on linear dynamics and convex constraints. The terminal value is a neural network: not here; it is barycentric interpolation of stored roll-out costs. Hull growth alone explains the learning: no, the learned value is equally important, and after a few iterations the hull hardly changes while the cost still falls. The long-horizon reference proves the exact infinite-horizon optimum: no, it is a finite-horizon proxy whose convergence was checked. A three-step horizon only sees three steps ahead: only the explicit prediction is three steps long; the terminal constraint links it to stored continuations that reach the target and the terminal cost prices the remainder, which is why LMPC beats the seed with the same horizon. LMPC is reinforcement learning because it learns from data: here it is model-based predictive control with terminal ingredients learned from successful closed-loop data.

Part 11

Check your understanding

Try to answer each question before opening it.

1. What is the sampled safe set?

The union of the states visited by successful previous iterations, together with the target set.

2. Why is a sampled state safe?

Because replaying its stored continuation input takes the system to the next state of a successful trajectory and, step by step, to the target.

3. What is the convex safe set?

The convex hull of the sampled safe set, CS^j = \operatorname{conv}(SS^j).

4. Why is it control invariant in this example?

Linearity maps convex combinations of safe state and input pairs to the same convex combinations of safe successors, and the state and input constraints are convex.

5. What is stored besides the state?

A continuation input with its successor, and a realised cost-to-go.

6. What does x_N = S^\top \lambda mean?

Together with \lambda \ge 0 and \mathbf 1^\top \lambda = 1, it places the terminal prediction inside the convex hull of the stored successful states, which are the rows of S.

7. What does \lambda^\top V mean?

The learned terminal value: barycentric interpolation of the stored costs-to-go.

8. What is actually learned?

Terminal safe geometry, continuation information and terminal cost-to-go. Not the system matrices, which are known here.

9. Why is one feasible trajectory enough to start?

It provides a complete admissible continuation from the repeated initial condition to the target, together with safe states and their costs-to-go.

10. Why can a horizon-three LMPC outperform the horizon-three seed MPC?

The learned terminal set and value communicate information about safe and costly behaviour beyond the explicit three-step window. From x_S, the seed applies 4.285 and LMPC applies 5 for exactly that reason.

11. Why is the \ell_1 term represented with epigraph variables?

Absolute values become linear inequalities -e_i \le z_i \le e_i, e_i \ge 0, with \sum e_i minimised, so the online problem stays a QP.

12. Does monotone iteration cost imply global optimality?

No. Performance improvement and convergence to a global optimum are different statements.

13. Why does the QP grow with experience?

Each active safe-state sample contributes one barycentric variable \lambda_r.

14. Why use a limited trajectory window?

It bounds the size of the online QP while retaining recent successful continuations, including the previous iteration, which the cost-improvement argument needs.

Exercises

  1. Sampled safe-set invariance. Prove x \in SS^j \Rightarrow \exists u \in \mathcal U : f(x, u) \in SS^j, and state the required target-set assumption.
    Hint

    Two cases: a stored nonterminal state, and a point of the target.

    Solution

    If x = x^i[t] with t < T_i, the stored input u^i[t] \in \mathcal U was applied in a successful, hence admissible, run and produced x^i[t+1], which is in SS^j by definition. If x \in \mathcal O (this includes every terminal state x^i[T_i]), one must assume that \mathcal O is itself control invariant under an admissible controller: there is u \in \mathcal U with f(x, u) \in \mathcal O \subseteq SS^j. For \mathcal O = \{0\} and the double integrator, u = 0 does it.

  2. Convex invariance. For x^+ = Ax + Bu, prove control invariance of CS^j under convex constraints and identify where linearity and convexity enter.
    Hint

    Use the mixture of stored inputs with the same weights.

    Solution

    Let x = \sum_r \lambda_r s_r, \lambda in the simplex, and u = \sum_r \lambda_r u_r^{\mathrm{safe}}. Convexity of \mathcal U: u is a convex combination of admissible inputs, so u \in \mathcal U. Linearity: Ax + Bu = \sum_r \lambda_r (A s_r + B u_r^{\mathrm{safe}}) = \sum_r \lambda_r s_r^+. Convexity of the hull: each s_r^+ \in SS^j \subseteq CS^j, so their convex combination is in CS^j. Convexity of \mathcal X is needed too: the hull of admissible states must consist of admissible states, which holds since SS^j \subseteq \mathcal X and \mathcal X is convex.

  3. Barycentric LP. Compute V_c^1(2.5) by hand in the one-dimensional example.
    Hint

    In one dimension the cheapest representation of a point between two consecutive samples uses those two samples, provided the stored values are convex in x.

    Solution

    The stored pairs are (2, 5.2) and (3, 14.3), and the sequence of values 0, 1.1, 5.2, 14.3, 30.4 has increasing increments, so it is convex and no farther pair can do better. 2.5 = 0.5 \cdot 2 + 0.5 \cdot 3 gives V_c^1(2.5) = 0.5 \cdot 5.2 + 0.5 \cdot 14.3 = 9.75, the notebook's output with \lambda = (0.5, 0.5).

  4. Dominated data. Add a worse trajectory through an already sampled state and explain how the sampled minimum and the convex envelope treat it.
    Hint

    Try the widget of Part 3: its button adds a run 2 \to 1.6 \to 1.0 \to 0.4 \to 0.

    Solution

    The slow run stores J(2) = 4.016 + 2.596 + 1.036 + 0.176 = 7.824 (stage costs x^2 + 0.1u^2 with inputs -0.4, -0.6, -0.6, -0.4), worse than the existing 5.2 at x = 2. The sampled value function keeps the minimum, 5.2. The convex extension ignores the dominated pairs: (1.6, 3.808) lies above the chord from (1, 1.1) to (2, 5.2), which has value 3.56 there, and (1.0, 1.212) is above the existing 1.1. But the run's last pair (0.4, 0.176) lies below the chord from (0, 0) to (1, 1.1), whose value there is 0.44, so the envelope drops near x = 0.4. A worse run overall can still contain a better partial continuation, and the envelope keeps exactly the parts that help: worse data never raise the terminal value, and the LP picks out whatever is cheaper.

  5. Stage cost by hand. For x = (-2, 1) and u = 0.5, compute the stage cost of Part 6.
    Hint

    Three terms: quadratic in x, quadratic in u, and \ell_1 in x.

    Solution

    x^\top Q x = 4 + 1 = 5, u^\top R u = 0.25, \|Q_1 x\|_1 = 0.01(2 + 1) = 0.03. Total h = 5.28, which the code's stage cost confirms.

  6. Epigraph. Prove the epigraph representation of \|z\|_1.
    Hint

    Show that the feasible set in e is e_i \ge |z_i| and that minimising makes it tight.

    Solution

    For fixed z, the constraints z_i \le e_i and -z_i \le e_i are equivalent to e_i \ge |z_i|, which also implies e_i \ge 0. Hence \min_e \{ \sum_i e_i : e_i \ge |z_i| \} = \sum_i |z_i| = \|z\|_1, attained at e_i = |z_i|. Inside a larger minimisation over (z, e) the same holds for whatever z is chosen, so replacing \|z\|_1 by \sum_i e_i with these linear constraints does not change the optimal value or the optimal z, and the problem stays a QP.

  7. Horizon. Repeat the seed MPC experiment with N = 2, 3, 5 and compare complete closed-loop task costs.
    Hint

    Set the seed horizon in the demo. With N = 2 look at what the two-step objective can see.

    Solution

    N = 2: the controller never reaches the target. Its objective contains the stage costs at x_0 (a constant) and x_1 = (-15, u_0), whose position does not depend on u_0, so the cheapest input is u_0 = 0 and the cart stays at (-15, 0) for ever: there is no seed at all, and LMPC cannot start. N = 3: cost 693.992, gap 20.316. N = 5: cost 673.677379, gap 7 \times 10^{-4}, already within a hair of the reference. The short horizon is deliberately chosen so that there is something for LMPC to learn; with N = 5 plain MPC is essentially optimal on this task.

  8. Different feasible seed. Generate another successful seed and compare the LMPC learning curve. Does the experiment prove initialisation independence?
    Hint

    A saturated LQR, u = \operatorname{sat}(-Kx), is another feasible seed on this task; so is the N = 5 MPC.

    Solution

    From the N = 5 seed (cost 673.677379) nine LMPC iterations give 673.676796, 673.676745, 673.676702, 673.676684, 673.676719, 673.676690, 673.676682, 673.676671, 673.676692. From a saturated-LQR seed, u = \operatorname{sat}(-Kx) with the LQR gain of chapter 00 (21 steps, cost 673.676906), the nine costs stay between 673.67667 and 673.67679, in an order that changes from run to run. Both curves are flat at the reference level within 5 \times 10^{-5}, and both contain increases of order 10^{-5}: those are the QP solver's tolerance, not violations of the non-increase result, which is a statement about exact solutions. All three seeds end at the same cost to five decimals. That is evidence of initialisation independence for this convex task and this formulation, not a proof: the theory guarantees non-increase from each seed, and nothing in it says that different seeds must meet.

  9. Database size. Compare all-data against recent-trajectory safe sets; record solve time and iteration cost.
    Hint

    Set the window slider to 0 in the demo and watch the solve time in the status text.

    Solution

    With every stored trajectory active, the nine iteration costs agree with the window-4 run to within 3 \times 10^{-5} (the first four are identical, because until then the window holds every trajectory). The mean solve time per QP in the notebook grows from 5.5 ms to 85 ms with all data, against 5.5 ms to about 10 ms with the window, because the number of barycentric variables grows from 27 to 213 instead of staying below 90. Same cost, eight times the computation by iteration 9: the window costs nothing here and bounds the online problem.

  10. Model mismatch. If the real system is x^+ = (A + \Delta A)x + Bu, which line of the convex-invariance proof fails?
    Hint

    The stored successors were produced by the real plant, but the proof multiplies by the nominal A.

    Solution

    The line x^+ = \sum_r \lambda_r (A s_r + B u_r) = \sum_r \lambda_r s_r^+. Replaying the mixture of stored inputs on the true plant gives \sum_r \lambda_r ((A + \Delta A) s_r + B u_r); if the stored successors came from the true plant this still equals \sum_r \lambda_r s_r^+, but the online QP predicts x_N with the nominal A, so the state that actually arrives at time N is not the S^\top \lambda the optimiser planned, and the continuation argument breaks. If instead the successors were simulated with the nominal model, the equality fails already at the first replay. Either way the certificate rests on the identity between model and plant.

  11. Nonlinear counter-example. Give a nonlinear f(x, u) for which convex combinations do not propagate linearly.
    Hint

    Anything with a square.

    Solution

    Take f(x, u) = x^2 + u in one dimension, safe states s_1 = 0, s_2 = 2 with inputs u_1 = u_2 = 0, so s_1^+ = 0, s_2^+ = 4. The midpoint x = 1 with the mixed input u = 0 goes to f(1, 0) = 1, whereas the mixture of successors is 2. Convex combinations of safe states need not have safe successors under mixed inputs, so the hull of stored states is not control invariant without further argument.

  12. Classical against learned terminal ingredients. Compare (\mathcal X_f, p) with (CS^j, V_c^j): which roles are analogous, and where does the information come from?
    Hint

    Part 5's table.

    Solution

    \mathcal X_f and CS^j are both control-invariant terminal sets that make the shifted sequence feasible; p and V_c^j are both terminal costs satisfying a one-step decrease, p(x^+) - p(x) \le -\ell from the Riccati construction and V_c^j(x^+) - V_c^j(x) \le -h from convexity and the stored data recursion; \kappa_f = -Kx and \sum_r \lambda_r u_r^{\mathrm{safe}} are the terminal controllers that realise the decrease. The classical pair is computed from the model offline by the designer; the learned pair is computed from the model and from successful closed-loop data, and it improves as data accumulate. Both need the model: LMPC in this form is not model-free.

Part 13

The chapter on one page

  1. Repetition: the same task from x_S every time; successful runs end in \mathcal O = \{0\} and respect the constraints.
  2. Sampled safe set: all visited states of successful runs plus the target; control invariant by replaying the stored input.
  3. Convex safe set: its hull, x = S^\top \lambda on the simplex; invariant for linear dynamics and convex constraints by mixing the stored inputs.
  4. Learned value: stored costs-to-go, extended by the barycentric LP to the lower convex envelope; V_c^1(2.5) = 9.75 in the scalar example.
  5. Decrease: V_c^j(x^+) - V_c^j(x) \le -h(x, u), the terminal-cost condition of chapter 03 obtained from data.
  6. LMPC problem: chapter 01's CFTOC plus x_N = S^\top \lambda, the simplex, and \lambda^\top V in the cost; one QP, recursively feasible by the shifted sequence.
  7. Task: double integrator from (-15, 0), boxes 15 and 5, cost x^\top x + u^2 + 0.01\|x\|_1 via the epigraph trick; reference 673.6766534 at N = 20.
  8. Seed: three-step MPC, first input 4.285, cost 693.992, gap 20.3; 27 stored samples.
  9. Learning: first LMPC input 5, two active weights; nine iterations 673.9316 → 673.6767, never increasing, final gap 5 \times 10^{-5}.
  10. Anatomy: hull growth stalls after a few runs while values keep improving; the recursion residual is round-off.
  11. Meaning: the model is known, not learned; not DQN, not ILC; non-increase is guaranteed, global optimality is not; a window of four trajectories bounds the QP at equal cost.

Scope. A deterministic repeated task with known linear dynamics, convex box constraints and a convex stage cost, which is the setting in which the convex constructions are justified. Only the terminal ingredients are learned. The experiment is reproduced in your browser with an interior-point QP solver; the notebook uses SciPy's SLSQP, whose 10^{-8} tolerance explains the differences in the fifth decimal of the costs and the different step counts near the target.
