Polytopes and set operations

A state constraint such as "the position stays within four units and the speed within three" is not a pair of limits but a set, and once dynamics enter, every question about constraints becomes a question about sets: where a set is mapped to, which states are mapped into it, what two sets have in common. For linear inequalities all of these sets are polytopes, and every operation on them is finite. Below, the four operations the course needs are computed exactly in your browser.

Part 1

Two representations of a polytope

The central idea of this chapter and the two that follow is

\boxed{\text{constraints} + \text{dynamics} \ \Longrightarrow\ \text{geometry in state space}}.

What is a polytope?

In plain words: a flat-sided, bounded region, like a box, a diamond or a cut-off box. It can be described from the outside, as the region on the correct side of a few lines, or from the inside, as everything between a few corner points.

More precisely: a polyhedron is an intersection of finitely many closed half-spaces, \mathcal P = \{x \in \mathbb R^n : Hx \le h\}, with one row of H per half-space; a polytope is a bounded polyhedron. Equivalently (the Minkowski–Weyl theorem [4]), every polytope is the convex hull of finitely many vertices, \mathcal P = \mathrm{conv}\{v_1, \dots, v_M\}. These are the two representations:

\boxed{\mathcal P = \{x : Hx \le h\}} \ \ (\text{H, half-spaces}), \qquad \boxed{\mathcal P = \mathrm{conv}\{v_1, \dots, v_M\}} \ \ (\text{V, vertices}).
H-representation
Rows H_i^\top x \le h_i; the language of constraints and solvers.
V-representation
A convex combination x = \sum_i \lambda_i v_i, \lambda_i \ge 0, \sum_i \lambda_i = 1; the language of geometry and plotting.
Facet, vertex
Where the set touches one boundary; where two (in 2-D) boundaries meet inside the set.
Full-dimensional
The polytope has an interior; everything in this course is.

Why keep both. The H-form is what constraints look like: the course's state box |p| \le 4, |v| \le 3 is

\begin{pmatrix} 1 & 0 \\ 0 & 1 \\ -1 & 0 \\ 0 & -1 \end{pmatrix} x \le \begin{pmatrix} 4 \\ 3 \\ 4 \\ 3 \end{pmatrix},

exactly the format a solver takes, and chapter A5 stacks rows like these over a whole horizon. The V-form is what pictures look like, and what convex combinations want: chapter A12 builds a safe set as the hull of visited states and represents a point in it by its weights \lambda_i. Converting is conceptually simple and computationally expensive in high dimension: H to V is vertex enumeration, V to H a convex-hull computation. The widget builds a five-sided polygon from its vertices, recovers five half-spaces with unit normals, and recovers the vertices again from those.

Part 2

Membership, and rows that do nothing

Membership. For an H-polytope, x \in \mathcal P \iff Hx \le h componentwise: a few inner products, one per row, and the first failed row decides. It is the operation the course uses most, to check a simulated state against its constraints, to check whether one set's vertices lie in another, and to detect that a set iteration has stopped changing (chapter A10). For the probe (1.5, 0) of the widget all five rows hold with room to spare; for (2, 1) the first row fails by 0.358 and the point is outside.

Redundant inequalities. Some rows of Hx \le h may be implied by the others: x_1 \le 1 already implies x_1 \le 2. To test row i, solve the linear program

\max_x\ H_i^\top x \quad \text{subject to the other rows};

if the maximum is at most h_i, row i changes nothing and can be dropped. The unit box with a fifth row x_1 \le 2 reduces from 5 rows to 4. Redundancy reduction matters because repeated intersections and predecessor operations breed unnecessary half-spaces; chapter A9's Fourier–Motzkin elimination creates 9 rows for a target with 4, of which 3 are redundant already in two dimensions.

One care the test must take. A row is tested against the rows still kept and the rows not yet tested, never against a row already dropped. Otherwise two identical rows would each be implied by the other and both would be dropped, enlarging the set. The numbers script shows the trap on the unit box with its first row written twice: tested naively, 5 rows become 3 and the box loses a side; tested properly, 5 become 4. The course package had exactly this bug until this chapter was written, and the code walk below shows the fix.

Part 3

Basic set operations

Each operation favours one representation; the hero shows all four.

Intersection. If \mathcal P_1 = \{x : H_1 x \le h_1\} and \mathcal P_2 = \{x : H_2 x \le h_2\}, then

\boxed{\mathcal P_1 \cap \mathcal P_2 = \Big\{ x : \begin{pmatrix} H_1 \\ H_2 \end{pmatrix} x \le \begin{pmatrix} h_1 \\ h_2 \end{pmatrix} \Big\}} :

stack the inequalities. This is why H-representations are so natural in constrained control: "satisfy the state constraints and land in the target" is one stacked system. For the box and diamond of the hero, 8 stacked rows of which 6 survive, and a 6-vertex result.

Affine images. M\mathcal X + c = \{Mx + c : x \in \mathcal X\} is again a polytope, and in V-form it is immediate: \mathrm{conv}\{v_i\} \mapsto \mathrm{conv}\{Mv_i + c\}. It is how a set is propagated forward through linear dynamics; the area scales by |\det M|, 1.52 for the hero's matrix.

Linear preimages. The preimage of \mathcal S under x \mapsto Ax is A^{-1}(\mathcal S) = \{x : Ax \in \mathcal S\}, an inverse image of a set that does not require A to be invertible. If \mathcal S = \{y : H_S y \le h_S\}, then Ax \in \mathcal S means H_S A x \le h_S, so

\boxed{A^{-1}(\mathcal S) = \{x : (H_S A)\, x \le h_S\}},

the basic autonomous predecessor operation of chapter A10: multiply the rows, keep the right-hand sides. For the hero's box and A = \begin{pmatrix} 1 & 0.7 \\ 0 & 0.85 \end{pmatrix} the rows become (1, 0.7), (0, 0.85) and their negatives, and the box becomes a parallelogram with the vertices (\pm 1.576, \mp 0.824) and (\pm 0.424, \pm 0.824).

Minkowski sum. \mathcal X \oplus \mathcal Y = \{x + y : x \in \mathcal X,\ y \in \mathcal Y\}. In low dimension: enumerate both vertex sets, form all pairwise sums, take the hull. Intuitive, and scaling poorly, since the candidate pairs multiply: 16 sums for two quadrilaterals, 8 of them on the hull. Minkowski sums appear in forward reachable sets (A\mathcal S \oplus B\,\mathcal U in chapter A9), in disturbance propagation, and in the tubes of robust MPC.

Part 4

Projection: eliminating a variable

Suppose a set is described in an augmented variable z = (x, u) by \mathcal Z = \{(x, u) : G_x x + G_u u \le g\}. Its projection onto x is

\boxed{\mathrm{Proj}_x(\mathcal Z) = \{x : \exists u \text{ such that } (x, u) \in \mathcal Z\}}.

The \exists u is exactly what makes projection the key operation of set-based control: keep the state if at least one admissible input satisfies the required inequalities. Chapter A9 builds the controlled predecessor this way, and eliminates u by pairing its lower and upper bounds, Fourier–Motzkin elimination. Conceptually simple; eliminating variables from a polyhedron can generate many rows, most of them redundant.

Part 5

Why exact set computations get expensive

Representation switching is not cosmetic. A set-based algorithm switches repeatedly between the two forms, and the conversions can dominate the cost. A polytope may have many vertices even with a compact H-form (vertex enumeration grows combinatorially with the dimension); intersections and elimination generate many inequalities (facet growth); a naive Minkowski sum considers N_{\mathcal X} N_{\mathcal Y} vertex pairs; Fourier–Motzkin elimination is notoriously prone to redundant rows; and reachability and invariance apply all of these many times over. Exact explicit polytopes are excellent teaching tools and practical for many low-dimensional systems, which is why this course keeps the state two-dimensional and the input scalar so that every set can be drawn; higher-dimensional problems need implicit, approximate or optimisation-based representations [2].

Numerical equality of polytopes. Two H-representations can describe the same set with completely different rows: scaled duplicates, redundant facets, a different order. Comparing H_1 and H_2 is not a set-equality test. In two dimensions the course checks equality geometrically: every vertex of each set lies in the other. That is the test that stops the fixed-point iterations of chapter A10.

Part 6

The code behind it

The package's HPolytope holds an H-representation and the operations above; the hero's browser version replaces its linear programs by vertex tests, which is fine in 2-D and would not be in 20-D.

advanced_mpc_lmpc/polytopes.py · HPolytope

@dataclass
class HPolytope:
    """Bounded convex polytope P={x | Hx<=h}, with utilities focused on 2-D examples."""
    H: np.ndarray
    h: np.ndarray

    def __post_init__(self):
        self.H = np.asarray(self.H, float)
        self.h = np.asarray(self.h, float).reshape(-1)
        if self.H.ndim != 2 or self.H.shape[0] != self.h.size:
            raise ValueError("Inconsistent H/h dimensions")

    @classmethod
    def box(cls, lower, upper):
        lower = np.asarray(lower, float); upper = np.asarray(upper, float)
        n = lower.size
        H = np.vstack([np.eye(n), -np.eye(n)])
        h = np.r_[upper, -lower]
        return cls(H, h)

    @classmethod
    def from_vertices_2d(cls, V):
        V = np.asarray(V, float)
        hull = ConvexHull(V)
        # scipy hull.equations: normal*x + offset <= 0
        H = hull.equations[:, :2]
        h = -hull.equations[:, 2]
        return cls(H, h).remove_redundancy()

    def contains(self, x, tol=1e-8):
        x = np.asarray(x, float)
        return bool(np.all(self.H @ x <= self.h + tol))

    def intersect(self, other: "HPolytope"):
        return HPolytope(np.vstack([self.H, other.H]), np.r_[self.h, other.h]).remove_redundancy()

    def vertices_2d(self, tol=1e-8):
        if self.H.shape[1] != 2:
            raise ValueError("vertices_2d only supports 2D")
        pts = []
        for i, j in itertools.combinations(range(len(self.h)), 2):
            M = self.H[[i, j]]
            if abs(np.linalg.det(M)) < 1e-10:
                continue
            x = np.linalg.solve(M, self.h[[i, j]])
            if np.all(self.H @ x <= self.h + tol):
                pts.append(x)
        if len(pts) < 3:
            return np.asarray(pts)
        pts = np.unique(np.round(np.asarray(pts), 10), axis=0)
        if len(pts) < 3:
            return pts
        hull = ConvexHull(pts)
        return pts[hull.vertices]

    def remove_redundancy(self, tol=1e-8):
        """Drop every row implied by the others, one linear program per row.

        Row i is redundant if max H_i x over the other rows is at most h_i.  Each row
        is tested against the rows still kept plus the rows not yet tested, never
        against a row already dropped: two identical rows would otherwise each be
        implied by the other and both be dropped, enlarging the set.
        """
        H, h = self.H, self.h
        keep = []
        n = H.shape[1]
        for i in range(H.shape[0]):
            idx = keep + list(range(i + 1, H.shape[0]))
            if not idx:
                keep.append(i); continue
            res = linprog(-H[i], A_ub=H[idx], b_ub=h[idx], bounds=[(None, None)]*n,
                          method="highs")
            if (not res.success) or (-res.fun > h[i] + tol):
                keep.append(i)
        return HPolytope(H[keep], h[keep])

    def approximately_equal(self, other: "HPolytope", tol=1e-6):
        if self.H.shape[1] != 2 or other.H.shape[1] != 2:
            return False
        V1, V2 = self.vertices_2d(), other.vertices_2d()
        if len(V1) == 0 or len(V2) == 0: return len(V1) == len(V2)
        return all(other.contains(v, tol) for v in V1) and all(self.contains(v, tol) for v in V2)

Four methods to read. box writes bounds as the rows \pm I with right-hand sides (\text{upper}, -\text{lower}): a lower bound x_i \ge l_i is the row -x_i \le -l_i. contains is the membership test, with a tolerance because a vertex computed in floating point sits a few 10^{-16} off its facets. vertices_2d intersects every pair of rows by solving a 2 \times 2 system, keeps the intersection if it satisfies all rows, removes duplicates, and orders the survivors with a convex hull; parallel rows are skipped by the determinant test. remove_redundancy is the LP test of Part 2: for row i, linprog maximises H_i^\top x over the rows in idx, which are the rows kept so far plus the rows after i, never a row already dropped. The sign flip, -H[i], is because linprog minimises.

advanced_mpc_lmpc/polytopes.py · minkowski_sum_2d

def minkowski_sum_2d(P: HPolytope, Q: HPolytope):
    """Minkowski sum P (+) Q using vertex enumeration in 2-D."""
    VP = P.vertices_2d()
    VQ = Q.vertices_2d()
    Vsum = np.asarray([p + q for p in VP for q in VQ])
    return HPolytope.from_vertices_2d(Vsum)

Three lines of geometry: both vertex lists, every pairwise sum, and from_vertices_2d, which takes a convex hull with SciPy and converts its facet equations normal * x + offset <= 0 to the course's Hx \le h convention by negating the offset. The hull is what discards the interior sums; for the hero's two quadrilaterals, 8 of the 16.

Part 7

Common pitfalls

  1. "A^{-1}(\mathcal S) means matrix inversion." Not necessarily. It is the set preimage \{x : Ax \in \mathcal S\}, computed as H_S A, defined for singular A too.
  2. "The same rows mean the same set, and different rows mean different sets." The second is false: compare vertices, not matrices.
  3. "A redundant row is harmless." It is harmless for membership and costly for everything else: each extra row multiplies the pairs an elimination or a vertex enumeration must consider.
  4. "Test each row against all the others." That drops both copies of a duplicated row. Test against the rows still kept.
  5. "Polytope operations scale." In two dimensions everything here is instant; the vertex count of a box is 2^n, and projection and Minkowski sums grow faster still.
Part 8

Check your understanding

Try to answer each question before opening it.

1. What is the difference between a polyhedron and a polytope?

A polyhedron is an intersection of finitely many half-spaces and may be unbounded. A polytope is a bounded polyhedron, equivalently the convex hull of finitely many vertices.

2. Why is the H-representation convenient in constrained control?

State and input constraints are naturally linear inequalities, intersections are obtained by stacking rows, membership is the evaluation of Hx \le h, and solvers take constraints in exactly this form.

3. How is a redundant row detected?

Maximise H_i^\top x subject to the other rows; if the maximum is at most h_i, the row never binds. One linear program per row, each against the rows still kept.

4. Write the intersection of \{H_1 x \le h_1\} and \{H_2 x \le h_2\}.

\{x : \begin{pmatrix} H_1 \\ H_2 \end{pmatrix} x \le \begin{pmatrix} h_1 \\ h_2 \end{pmatrix}\}: the stacked rows, followed by redundancy removal if the representation is to stay small.

5. What is the H-representation of A^{-1}(\mathcal S)?

\{x : (H_S A)\, x \le h_S\}: the rows multiplied by A, the right-hand sides unchanged; no inverse is needed.

6. How is a Minkowski sum computed in two dimensions?

All pairwise sums of the two vertex sets, then their convex hull; N_{\mathcal X} N_{\mathcal Y} candidates, of which only the hull's vertices survive.

7. What does projection onto x mean, and why does it matter for control?

Keeping the x for which some u makes (x, u) feasible: the "there exists an admissible input" that defines predecessors and control invariance.

8. Why can exact polytope calculations become expensive?

Vertex and facet counts grow under conversion, Minkowski sums, projection and repeated recursion, and variable elimination generates many redundant inequalities that must be removed one linear program at a time.

Part 9

Exercises

Each exercise has a hint and a solution; the code runs with the course package installed. Try first, then peek.

  1. H-representation. Write -2 \le x_1 \le 3, -1 \le x_2 \le 4 as Hx \le h.

    Hint

    Each lower bound becomes a row with a minus sign.

    Solution

    H = \begin{pmatrix} 1 & 0 \\ 0 & 1 \\ -1 & 0 \\ 0 & -1 \end{pmatrix}, h = (3, 4, 2, 1), which is HPolytope.box([-2, -1], [3, 4]), rows in this order.

  2. Redundant facet. Add x_1 \le 5 to the previous set and prove it redundant by solving the corresponding linear program by hand.

    Hint

    Maximise x_1 over the other four rows.

    Solution

    The LP \max x_1 subject to the four box rows attains 3, at the right edge, and 3 \le 5, so the new row is implied; remove_redundancy drops it, 5 rows to 4.

    from advanced_mpc_lmpc.polytopes import HPolytope
P = HPolytope.box([-2, -1], [3, 4])
P5 = HPolytope(np.vstack([P.H, [[1.0, 0.0]]]), np.r_[P.h, 5.0])
print(len(P5.h), "->", len(P5.remove_redundancy().h))   # 5 -> 4

  3. Affine image. With M = \begin{pmatrix} 1 & 1 \\ 0 & 2 \end{pmatrix} and \mathcal X the unit square [0, 1]^2, compute the transformed vertices of M\mathcal X and its area.

    Hint

    Map the four corners; the area scales by |\det M|.

    Solution

    (0,0) \mapsto (0,0), (1,0) \mapsto (1,0), (1,1) \mapsto (2,2), (0,1) \mapsto (1,2): a parallelogram of area |\det M| = 2.

    from advanced_mpc_lmpc.polytopes import HPolytope, affine_image_2d
print(affine_image_2d(HPolytope.box([0, 0], [1, 1]), np.array([[1.0, 1.0], [0.0, 2.0]])).vertices_2d())
# (0,0), (1,0), (2,2), (1,2) in hull order

  4. Minkowski sum. For the intervals \mathcal A = [-2, 1] and \mathcal B = [-1, 3], compute \mathcal A \oplus \mathcal B, then generalise to axis-aligned boxes and check on [0, 1] \times [0, 2] plus [-1, 1] \times [1, 1.5].

    Hint

    Smallest possible sum, largest possible sum.

    Solution

    [-2, 1] \oplus [-1, 3] = [-3, 4]: lower bounds add and upper bounds add. For boxes the same happens coordinate by coordinate, because a box is a product of intervals: [l_1, u_1] \times [l_2, u_2] \oplus [l_1', u_1'] \times [l_2', u_2'] = [l_1 + l_1', u_1 + u_1'] \times [l_2 + l_2', u_2 + u_2']. The two boxes give [-1, 2] \times [1, 3.5], which minkowski_sum_2d returns as the four corners (-1, 1), (2, 1), (2, 3.5), (-1, 3.5).

  5. Build it: vertex enumeration. Write your own vertices(H, h) for a 2-D polytope: intersect every pair of rows, keep the feasible intersections, remove duplicates. Compare with vertices_2d on the five-sided polygon.

    Hint

    np.linalg.solve on the 2 \times 2 system of rows i and j; skip pairs whose determinant is zero; keep x if np.all(H @ x <= h + 1e-8).

    Solution

    Ten pairs of rows, five of them feasible, and those five are the vertices; the package finds the same five, ordered around the hull.

    H, h = P5.H, P5.h
pts = []
for i in range(len(h)):
    for j in range(i + 1, len(h)):
        M = H[[i, j]]
        if abs(np.linalg.det(M)) < 1e-10:
            continue
        x = np.linalg.solve(M, h[[i, j]])
        if np.all(H @ x <= h + 1e-8):
            pts.append(x)
pts = np.unique(np.round(pts, 10), axis=0)
print(len(pts), np.allclose(np.sort(pts, axis=0), np.sort(P5.vertices_2d(), axis=0)))   # 5 True

  6. Equality of sets. Give two different H-representations of the unit box, and explain why comparing their matrices fails while comparing vertices works.

    Hint

    Scale a row, add a redundant one, reorder.

    Solution

    \{x : \pm x_1 \le 1, \pm x_2 \le 1\} and \{x : \pm 2x_1 \le 2, \pm x_2 \le 1, x_1 \le 3\} with the rows in another order describe the same set; their matrices differ in scale, count and order. Every vertex of each lies in the other, so approximately_equal says they agree; that is the test chapter A10 uses to stop its iterations.

Part 10

The chapter on one page

  1. Two faces of a polytope: \{x : Hx \le h\} for constraints and membership, \mathrm{conv}\{v_i\} for geometry; converting is the expensive part.
  2. Membership is one inner product per row; redundancy is one linear program per row, tested against the rows still kept.
  3. Operations: intersection stacks rows; images map vertices; preimages multiply rows by A with the same right-hand sides; Minkowski sums add vertex pairs and take the hull.
  4. Projection is the "there exists": the key operation behind predecessors and invariance.
  5. The numbers: 8 stacked rows, 6 kept; |\det M| = 1.52; a parallelogram with vertices (\pm 1.576, \mp 0.824), (\pm 0.424, \pm 0.824); 16 sums, 8 on the hull.
  6. The cost: vertex and facet counts explode with the dimension; the course stays in 2-D so that every set can be drawn.
