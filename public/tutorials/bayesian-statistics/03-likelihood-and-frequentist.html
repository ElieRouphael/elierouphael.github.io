Likelihood and frequentist inference

A basketball player makes 13 of 20 free throws. A statistics textbook would say: her success rate is 0.65, with a 95% confidence interval from 0.44 to 0.86. But what does "95%" mean? Almost everyone, including many scientists, reads it the wrong way. Below, the player's true skill is fixed and known. Repeat her 20 throws as often as you like, compute the interval each time, and count how often it catches the truth.

Part 1

The likelihood

A statistical model says how likely each possible data set is, for each value of the unknown parameter \theta ("theta"). For the free throws: if each throw goes in with probability \theta, independently, the number made out of 20 is Binomial(20, \theta), and the probability of exactly 13 is

f(13 \mid \theta) = \binom{20}{13}\,\theta^{13} (1-\theta)^{7}.

Before the throws, you would read this as a function of the data: fix \theta, and it gives the probability of 0, 1, …, 20 makes. After the throws, the data are fixed at 13, and the interesting unknown is \theta. Read the same formula as a function of \theta, and it is called the likelihood:

L(\theta) = f(y \mid \theta), \qquad \text{with the data } y \text{ held fixed.}

Move \theta below. On the left, the probability of every possible number of makes; on the right, the likelihood. They share one number: the height of the orange bar is the height of the dot.

Fix θ: probability of each number of makes

Fix the data: the likelihood of each θ

For independent observations y_1, \dots, y_n, the likelihood is a product, and its logarithm, the log-likelihood \ell, is a sum:

L(\theta) = \prod_{i=1}^{n} f(y_i \mid \theta), \qquad \ell(\theta) = \log L(\theta) = \sum_{i=1}^{n} \log f(y_i \mid \theta).

What is a likelihood?

In plain words: a score for each possible value of the unknown: how probable the data you actually saw would have been, if that value were true.

More precisely: the likelihood is the probability (or density) of the observed data, f(y \mid \theta), viewed as a function of the parameter \theta with the data held fixed.

Model
A rule f(y \mid \theta) giving the probability of any data set for each value of the parameter.
Parameter \theta
The unknown number the model depends on, such as the success rate.
Likelihood L(\theta)
The same formula, read as a function of \theta once the data are known.
Log-likelihood \ell(\theta)
Its logarithm: a sum instead of a product, and much safer to compute.

The likelihood is not a probability distribution for \theta. The bars on the left always add up to 1, but the area under the curve on the right is \frac{1}{n+1} for this model, not 1. And constants that don't involve \theta, such as \binom{20}{13}, can be dropped without changing anything that matters: L(\theta) \propto \theta^{13}(1-\theta)^7. Turning the likelihood into a distribution for \theta takes one more ingredient, a prior, and that is chapter 04.

For the curious: why always work with the log (optional)

A product of many probabilities is astronomically small. With 1,000 observations that each have probability 0.2, the likelihood is 0.2^{1000} \approx 10^{-699}. A computer's floating-point numbers stop at about 10^{-308}, so 0.2 ** 1000 in Python returns exactly 0.0: every value of \theta would look equally (im)possible. Its logarithm, 1000 \log 0.2 \approx -1609, is a perfectly ordinary number.

The logarithm is increasing, so L and \ell peak at the same \theta; and the log turns products into sums, which are much easier to differentiate. Every serious statistics code works with log-likelihoods, and the Metropolis sampler of chapter 09 will too.

Part 2

Maximum likelihood

A natural single answer is the value of \theta that makes the observed data most probable: the top of the likelihood curve. It is the maximum likelihood estimate (MLE), written \hat\theta ("theta hat"):

\hat\theta = \arg\max_\theta \ell(\theta).

At the top of a smooth hill the slope is zero, so the recipe is: write \ell, differentiate, set to zero, solve. For the free throws, with y makes in n throws, \ell(\theta) = y \log\theta + (n - y)\log(1 - \theta) plus a constant, and

\frac{y}{\theta} - \frac{n - y}{1 - \theta} = 0 \quad \Longrightarrow \quad \hat\theta = \frac{y}{n} = \frac{13}{20} = 0.65.

The same recipe gives the obvious answers for two other standard models (the derivations are in the box below):

  • Waiting times, Exponential(\lambda): \hat\lambda = \frac{1}{\bar y}, one over the average wait.
  • Measurements, Normal(\mu, \sigma^2): \hat\mu = \bar y, the average, and \hat\sigma^2 = \frac{1}{n}\sum_i (y_i - \bar y)^2.

Each is what intuition suggests. The recipe earns its keep on harder models, where intuition has nothing to say but the steps are the same. The notebook also finds the free-throw maximum numerically:

n, y = 20, 13
loglik = lambda t: y * np.log(t) + (n - y) * np.log(1 - t)
res = optimize.minimize_scalar(lambda t: -loglik(t), bounds=(1e-9, 1 - 1e-9), method="bounded")
print(f"numerical MLE = {res.x:.4f},   y/n = {y / n:.4f}")
numerical MLE = 0.6500,   y/n = 0.6500
For the curious: the exponential and normal derivations (optional)

Exponential. The density of one wait is \lambda e^{-\lambda y_i}, so

\ell(\lambda) = n \log\lambda - \lambda \sum_i y_i, \qquad \ell'(\lambda) = \frac{n}{\lambda} - \sum_i y_i = 0 \quad \Longrightarrow \quad \hat\lambda = \frac{1}{\bar y}.

Normal mean, with \sigma known. Dropping constants,

\ell(\mu) = -\frac{1}{2\sigma^2} \sum_i (y_i - \mu)^2, \qquad \ell'(\mu) = \frac{1}{\sigma^2} \sum_i (y_i - \mu) = 0 \quad \Longrightarrow \quad \hat\mu = \bar y.

Normal variance. If \sigma^2 is unknown too, the same steps give \hat\sigma^2 = \frac{1}{n}\sum_i (y_i - \bar y)^2. It is slightly too small on average: \mathbb{E}[\hat\sigma^2] = \frac{n-1}{n}\sigma^2, because the data sit closer to their own average \bar y than to the true \mu. That is why the usual "sample variance" divides by n - 1 instead. With n = 5 the MLE underestimates by 20% on average; with n = 100, by 1%.

Part 3

How sure are we?

An estimate without an error bar is half an answer. The shape of the log-likelihood near its peak tells us how sure to be. A sharp peak means that values of \theta away from \hat\theta make the data much less probable, so they are effectively ruled out. A flat top means the data can't tell nearby values apart.

Sharpness is measured by the second derivative, the curvature. The observed information is J(\hat\theta) = -\ell''(\hat\theta), and for a large sample the MLE is approximately normal, with a standard error (SE) of one over the square root of the information [1], [3]:

\hat\theta \;\dot\sim\; \text{Normal}\Big(\theta,\ \frac{1}{J(\hat\theta)}\Big), \qquad \text{SE}(\hat\theta) = \frac{1}{\sqrt{J(\hat\theta)}}.

For the binomial, the information at the peak works out to J(\hat\theta) = \frac{n}{\hat\theta(1 - \hat\theta)}, so

\text{SE}(\hat\theta) = \sqrt{\frac{\hat\theta(1-\hat\theta)}{n}} = \sqrt{\frac{0.65 \times 0.35}{20}} \approx 0.107.

Below, keep the success rate at 65% and give the player more throws. The log-likelihood gets sharper; the dashed parabola is the normal approximation, matched to its curvature at the peak.

More data means more curvature, and the standard error shrinks like 1/√n: four times the data, half the error.

For the curious: the curvature of the binomial, and why a parabola (optional)

Differentiate the log-likelihood twice:

\ell''(\theta) = -\frac{y}{\theta^2} - \frac{n - y}{(1 - \theta)^2}.

At \hat\theta = \frac{y}{n}, substitute y = n\hat\theta: the two terms become \frac{n}{\hat\theta} + \frac{n}{1 - \hat\theta} = \frac{n}{\hat\theta(1 - \hat\theta)}. For 13 of 20 that is about 87.9, and \frac{1}{\sqrt{87.9}} \approx 0.107.

Why does the curvature give the spread? The log of a normal density with standard deviation s is a parabola, -\frac{(\theta - \hat\theta)^2}{2s^2} plus a constant, whose second derivative is -\frac{1}{s^2}. Near its peak, any smooth log-likelihood looks like a parabola (that is a second-order Taylor expansion), so it looks like the log of a normal with s^2 = \frac{1}{J}. The approximation is good when the curve really is close to a parabola, which the widget shows happens as n grows.

Part 4

Confidence intervals

If the estimate is approximately normal with standard error SE, it lands within 1.96 standard errors of the truth 95% of the time. Turning that around gives the familiar 95% confidence interval, called the Wald interval:

\hat\theta \pm 1.96\,\text{SE}(\hat\theta) = 0.65 \pm 1.96 \times 0.107 \approx (0.44,\ 0.86).

Now the crucial question: what does "95%" mean? In frequentist statistics, \theta is a fixed number, not a random variable. It is not inside any interval "with probability 0.95": it either is or it isn't. What is random is the data, and so the interval. The 95% is a promise about the procedure [4]:

If you repeated the experiment many times and computed an interval each time, about 95% of those intervals would contain the true θ.

That is exactly what the demo at the top does. Each repetition gives a new interval; most catch the true rate, a few miss, and in the long run the share that catches it settles near the promised level. Any single interval, such as (0.44, 0.86), either contains the truth or doesn't, and you never know which.

def wald(y, n, z=1.96):
    t = y / n
    se = np.sqrt(t * (1 - t) / n)
    return t - z * se, t + z * se
For the curious: where 1.96 comes from (optional)

For a standard normal Z, P(-1.96 \le Z \le 1.96) = 0.95: the 2.5% in each tail is cut at \pm 1.96. Other levels use other cut-offs: 1.28 for 80%, 1.64 for 90%, 2.58 for 99%. If \hat\theta \sim \text{Normal}(\theta, \text{SE}^2), then

P\big(|\hat\theta - \theta| \le 1.96\,\text{SE}\big) = 0.95 \quad \Longleftrightarrow \quad P\big(\theta \in [\hat\theta - 1.96\,\text{SE},\ \hat\theta + 1.96\,\text{SE}]\big) = 0.95.

Read the second statement carefully: the random things are \hat\theta and SE, so the random thing is the interval, and \theta sits still. Once the data are in, nothing random is left, and the probability statement no longer applies to the one interval you computed. This shift of meaning was set out by Jerzy Neyman in 1937 [2].

Part 5

When the promise breaks

The 95% promise rests on the normal approximation, which needs a large sample. For a binomial with a small n, or a \theta near 0 or 1, it can be badly wrong [5]. Try it in the demo: set the true rate to 5% and repeat 100 times.

We don't even need a simulation. With n throws there are only n + 1 possible outcomes, so the true long-run share of intervals that catch \theta, the coverage, can be computed exactly: for each possible y, check whether its interval contains \theta, and add up the probabilities of the y values for which it does:

\text{coverage}(\theta) = \sum_{y=0}^{n} \binom{n}{y} \theta^y (1-\theta)^{n-y}\; I_{\{\theta \,\in\, \text{CI}(y)\}}.

def coverage(theta, n, interval):
    ys = np.arange(n + 1)
    lo, hi = interval(ys, n)
    inside = (lo <= theta) & (theta <= hi)
    return stats.binom.pmf(ys, n, theta)[inside].sum()

print(f"coverage at θ = 0.05, n = 20: {coverage(0.05, 20, wald):.3f}")
coverage at θ = 0.05, n = 20: 0.639

At \theta = 0.05 with n = 20, the "95%" interval catches the truth only about two times in three, and closer to the edges it is worse still. The main culprit: when y = 0, the estimated SE is \sqrt{\frac{0 \times 1}{20}} = 0, and the interval collapses to the single point \{0\}, which can never contain a \theta above zero. And y = 0 happens 36% of the time when \theta = 0.05.

Better frequentist intervals exist. The Wilson interval [5], [6] is centred a little towards \frac{1}{2} and never collapses; tick it above and it stays close to 95% almost everywhere. Chapter 05 shows that a simple Bayesian interval behaves just as well.

Part 6

What the likelihood can't answer

Frequentist inference answers questions about the procedure: how often would this method be right, over many repetitions of the experiment? It deliberately gives no probabilities to \theta. So three very natural questions have no direct frequentist answer:

  • Given these 20 throws, what is the probability that \theta > 0.5, that she makes more than half her throws?
  • What range of \theta values is 95% probable, given what we saw?
  • Years of data on similar players say \theta is usually near 0.75. How should that change the conclusion from only 20 throws?

All three are questions about \theta given the data, and they need a probability distribution for \theta. Combine the likelihood with a prior, and Bayes' theorem gives exactly that: the posterior. Here is a preview of chapters 04 and 05.

prior likelihood (rescaled) posterior

With no prior opinion, the posterior says that \theta > 0.5 with probability 0.905, and that \theta is between 0.43 and 0.82 with probability 95%. Those are direct answers to the first two questions. The third is answered by changing the prior: years of data on similar players pull the estimate towards 0.75 and narrow the range. Chapter 04 builds this from the ground up.

Part 7

The chapter on one page

  1. The likelihood is the probability of the observed data, read as a function of the parameter. It is not a distribution for the parameter. Work with its logarithm.
  2. The MLE maximises it: differentiate the log-likelihood, set to zero. Binomial \frac{y}{n}, exponential \frac{1}{\bar y}, normal mean \bar y.
  3. Curvature gives precision: \text{SE} = \frac{1}{\sqrt{J(\hat\theta)}}, shrinking like \frac{1}{\sqrt{n}}.
  4. A 95% confidence interval promises that 95% of intervals from repeated experiments contain the true value. It says nothing about the one interval you computed.
  5. The promise can fail for small samples or parameters near a boundary (Wald at \theta = 0.05, n = 20: 64%). Probabilities about θ need a prior.

Part 8

Exercises

Each exercise has a hint and a solution. Try first, then peek. The notebook has a code cell ready for each of them.

  1. Counts. For y_i \sim Poisson(\lambda), derive the MLE \hat\lambda and its standard error from the observed information.
    Hint

    Drop the \log y_i! terms: they don't involve \lambda. Then differentiate twice.

    Solution
    \ell(\lambda) = \Big(\sum_i y_i\Big) \log\lambda - n\lambda, \qquad \ell'(\lambda) = \frac{\sum_i y_i}{\lambda} - n = 0 \;\Longrightarrow\; \hat\lambda = \bar y.

    Then \ell''(\lambda) = -\frac{\sum_i y_i}{\lambda^2}, so J(\hat\lambda) = \frac{n\bar y}{\bar y^2} = \frac{n}{\hat\lambda} and \text{SE}(\hat\lambda) = \sqrt{\frac{\hat\lambda}{n}}. It matches the Poisson's variance of \lambda: the average of n counts has variance \frac{\lambda}{n}.

  2. A known mean. Derive the MLE of \sigma^2 for normal data with a known mean \mu.
    Hint

    Treat v = \sigma^2 as the unknown, and keep the -\frac{n}{2}\log v term: it involves v.

    Solution
    \ell(v) = -\frac{n}{2}\log v - \frac{1}{2v}\sum_i (y_i - \mu)^2, \qquad \ell'(v) = -\frac{n}{2v} + \frac{1}{2v^2}\sum_i (y_i - \mu)^2 = 0.

    So \hat\sigma^2 = \frac{1}{n}\sum_i (y_i - \mu)^2. Unlike the case of Part 2, this one is unbiased: with the true mean known, no degree of freedom is spent estimating it.

  3. A positive parameter. For the exponential model, show that J(\hat\lambda) = \frac{n}{\hat\lambda^2} and write the Wald interval for \lambda. Is the interval symmetric? Is that sensible for a positive parameter?
    Hint

    Start from \ell(\lambda) = n\log\lambda - \lambda\sum_i y_i (Part 2). Then try n = 3.

    Solution

    \ell''(\lambda) = -\frac{n}{\lambda^2}, so J(\hat\lambda) = \frac{n}{\hat\lambda^2}, \text{SE} = \frac{\hat\lambda}{\sqrt{n}}, and the Wald interval is \hat\lambda\Big(1 \pm \frac{1.96}{\sqrt{n}}\Big). It is symmetric, and that is not sensible: a rate can't be negative, yet for n \le 3 the lower end is below zero (for n = 3, 1 - \frac{1.96}{\sqrt{3}} \approx -0.13). A better interval works on the log scale, \hat\lambda\,e^{\pm 1.96/\sqrt{n}}: always positive, and longer on the right, as the uncertainty about a rate should be.

  4. A better interval. Implement the Wilson interval (see [5]) and add its coverage curve to the plot. How does it compare with the Wald interval for n = 20?
    Hint

    The Wilson interval is centred at \frac{2y + z^2}{2(n + z^2)}, with half-width \frac{z}{n + z^2}\sqrt{\frac{y(n - y)}{n} + \frac{z^2}{4}}, where z = 1.96. Reuse coverage().

    Solution 
    def wilson(y, n, z=1.96):
    centre = (y + z**2 / 2) / (n + z**2)
    half = z / (n + z**2) * np.sqrt(y * (n - y) / n + z**2 / 4)
    return centre - half, centre + half

    Over a fine grid of \theta with n = 20, the Wald interval's coverage averages 85% and drops as low as 10% near the edges; it is below 90% for 41% of the grid. The Wilson interval averages 95%, never drops below 85%, and is below 90% for less than 1% of the grid. At \theta = 0.05: Wald 0.639, Wilson 0.925. Tick both boxes in the widget of Part 5 to see the two curves.

  5. A common misreading. A colleague says: "the 95% confidence interval is (0.44, 0.86), so there is a 95% chance that θ is between 0.44 and 0.86." Explain precisely what is wrong, then explain what additional ingredient would make a statement of that form valid.
    Hint

    In the frequentist view, which of these is random: \theta, or the interval? After the data are in, is anything random left?

    Solution

    In the frequentist framework \theta is fixed. The 95% describes the procedure over hypothetical repeated experiments: 95% of the intervals it would produce contain \theta. The particular interval (0.44, 0.86) is no longer random, so it contains \theta with "probability" 1 or 0, and we don't know which. To say "θ is in this range with probability 95%", you must treat \theta as uncertain and give it a probability distribution: a prior. Bayes' theorem then gives the posterior, and a 95% credible interval does mean exactly what your colleague said. With a flat prior it is (0.43, 0.82), close to the Wilson interval (0.43, 0.82) and a little narrower and lower than the Wald interval.
