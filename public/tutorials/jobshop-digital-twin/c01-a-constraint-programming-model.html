A constraint-programming model of the shop

A dispatching rule says what to do; a model says what is allowed and what is wanted, and leaves the search to a solver. This chapter writes the course's shop as a constraint-programming model, as the repository's solve_snapshot does: optional intervals with exactly-one routing, NoOverlap, a circuit whose arcs carry the changeovers, precedence with transport lags, tardiness made linear. Then it writes the same problem as a big-M MILP, to see why the formulation matters.

Part 1

Describe the rules, let the solver search

The dispatching rules of chapter B2 are procedures: when a machine frees, rank the waiting jobs and start the best. They cannot look ahead: on the paint machine of chapter A2 every rule loses to A, B, D, C, which accepts an early colour change to rescue the urgent red B, then runs the other red order before going back to blue.

Constraint programming turns the question around: write down what a schedule is and what makes one better, and let a general-purpose solver search. For the paint machine the description is four sentences.

  1. Each order occupies the machine for its painting time, from a start to an end.
  2. Two orders never occupy the machine at the same time.
  3. When an order directly follows one of the other colour, a 10-minute changeover separates them; the first order needs one if it is red, since the machine is set up for blue.
  4. Among all such schedules, find one with the smallest total tardiness.

Searching, and proving that nothing better exists, are the solver's job (chapter C2). This chapter is about the description, for the paint machine and for the five-machine workshop that Optimiser re-planning (CP-SAT) re-plans at every event (chapter C3).

What is a constraint-programming model?

In plain words: a precise description of the choices to make, the rules every acceptable choice obeys, and the number that says how good it is. A solver reads it and searches; nobody writes the search.

More precisely: decision variables with finite integer domains, constraints (relations a full assignment must satisfy), and an integer objective to minimise. A solution satisfies every constraint; an optimal one has the smallest objective. Constraint programming (CP) allows constraints that are not linear inequalities, such as NoOverlap and Circuit below.

Decision variable
An unknown with a finite set of allowed integer values.
Feasible
Satisfying every constraint.
Global constraint
One constraint over many variables, with its own reasoning inside the solver.

In the hero you play the solver: choose who follows whom and when each order starts, and the page checks every constraint. The opening state forgets the changeovers; its total tardiness, 5, beats the optimum's 40, but two rows fail: it is not a schedule.

Part 2

Starts, ends, intervals and presence literals

Plain words. A schedule says, for every operation, where (which machine), when (start and end) and in which order on its machine: a variable for each answer.

When. Every operation (j, k) still to plan has integer variables S_{jk} and E_{jk} in [t_0, H]: t_0 is the time of the snapshot, the frozen picture of the running shop that chapter C3 builds, and H is a horizon derived in Part 6.

Where. The routing \mu(j, k) \in \mathcal M_{jk} is the machine chosen for (j, k). For each eligible machine m (one to three in the workshop), a Boolean variable, a literal, says whether \mu(j, k) = m, and exactly one does:

x_{jkm} = 1 \iff \mu(j, k) = m, \qquad \sum_{m \in \mathcal M_{jk}} x_{jkm} = 1 .

This exactly-one constraint is routing written as a constraint. The duration depends on the machine, so E_{jk} = S_{jk} + p_{jkm} must hold for the chosen m only. CP-SAT has an object for that.

What is an interval variable, and an optional one?

In plain words: a block of time with a start, a length and an end that agree. An optional interval is a block that may or may not exist; a yes-or-no switch decides, and when it is off every rule ignores the block.

More precisely: an interval I = (S, p, E) imposes E = S + p. An optional interval (S, p, E, x) adds a presence literal x [1]. In CP-SAT, if x = 1 it imposes E = S + p and takes part in the constraints over it; if x = 0 it is absent: S and E keep values, but the size equation is not enforced and constraints such as NoOverlap ignore it [2].

Presence literal
The Boolean that says whether an optional interval exists.
Absent
Presence 0; the interval constrains nothing.

So operation (j, k) gets one optional interval per eligible machine, all sharing its start and end, I_{jkm} = (S_{jk}, p_{jkm}, E_{jk}, x_{jkm}). Exactly one is present, so exactly one size equation holds. The first operation of a family-0 job runs on machine 1 in 6 minutes or on machine 2 in 10 (notation): the model holds S, E, x_1, x_2, the intervals (S, 6, E, x_1) and (S, 10, E, x_2), and x_1 + x_2 = 1. With x_1 = 1, E = S + 6 and machine 2 never hears of the operation.

On the paint machine. One machine, so no routing choice: order A gets S_A, E_A \in [0, 110] and the always-present interval I_A = (S_A, 20, E_A); likewise B, C and D.

Part 3

One job at a time on a machine

Plain words. A machine paints one order at a time: either A ends before B starts, or B ends before A starts. Written as one constraint over all four blocks, that is NoOverlap.

What does NoOverlap mean?

In plain words: on one machine's calendar, the blocks that exist share no minute.

More precisely: \mathrm{NoOverlap}(I_1, \dots, I_n) holds when every pair of present intervals a \ne b satisfies E_a \le S_b or E_b \le S_a. Absent intervals are ignored; intervals are half-open, [S, E).

Disjunction
An "or" of two constraints: a before b, or b before a.

The model posts one NoOverlap per machine over every optional interval that could land on it. It is the disjunctive graph of chapter A3 for that machine, handed over as one global constraint, so the solver reasons on all pairs together: three present operations of 20, 25 and 30 minutes cannot all fit between minutes 0 and 60, although every pair fits, and a NoOverlap propagator (the routine that removes impossible values, chapter C2) sees it without trying the six orders.

"Or" is not linear (two half-planes of (S_a, S_b), a non-convex set), so the MILP of Part 8 needs a binary per pair. NoOverlap is even implied by the circuit of Part 4, which chains direct successors with S_b \ge E_a; the repository keeps it as a redundant constraint, a standard CP device that gives the solver a global view of each machine.

On the paint machine. One constraint, \mathrm{NoOverlap}(I_A, I_B, I_C, I_D), stands for six disjunctions, among them S_B \ge E_A or S_A \ge E_B.

Part 4

Who directly follows whom, and the changeover

Plain words. The changeover depends on the order just before: red after blue costs 10 minutes, red after red nothing. NoOverlap does not know who comes directly next, so the model needs a variable for it.

Arc literals. For machine m, take a graph whose node 0 is the machine in its current state (free from \phi_m, set up for family g_m) and whose other nodes are the operations that could run on m. For each ordered pair,

z^m_{uv} = 1 \iff \text{on machine } m,\ v \text{ directly follows } u .

The arc 0 \to v means "v runs first", u \to 0 means "u runs last". On the paint machine the plan A, B, D, C is z_{0A} = z_{AB} = z_{BD} = z_{DC} = z_{C0} = 1, every other arc 0.

What is the circuit constraint?

In plain words: the arcs switched on form one loop that leaves the machine, visits every operation placed on it once, and comes back. Operations placed elsewhere are skipped by looping onto themselves.

More precisely: \mathrm{Circuit}(\{(u, v, z_{uv})\}) holds when the arcs with z_{uv} = 1 form a single loop through every node that does not take its self-loop, each visited exactly once (a Hamiltonian circuit of those nodes); a node with z_{vv} = 1 is outside it [2].

Node 0
The machine's current state, start and end of the tour.
Self-loop
z^m_{vv} = \neg x_{vm} (\neg x, "not x", is 1 - x): an operation routed elsewhere loops on itself, one routed to m must be visited; the idle loop z^m_{00} = 1 closes the empty tour of an unused machine.
Subtour
A cycle avoiding node 0; forbidden.

How many arcs. With n_m candidates: one idle loop, n_m first arcs, n_m last arcs, n_m self-loops and n_m(n_m - 1) successions, in all

1 + 3 n_m + n_m(n_m - 1) = (n_m + 1)^2 ,

every ordered pair of nodes, loops included. Knowing the direct successor costs quadratic growth: 25 arcs for the paint machine in solve_snapshot's form (20 in the hand-written model of Part 7), 196 for a machine with 13 candidates (Part 9).

The changeover sits on the arcs. Each arc literal is the enforcement literal of two timing constraints, written \Rightarrow: they must hold when z = 1 and are ignored when z = 0. With \alpha_b = \alpha_{jk} the time the job of b = (j, k) reaches the machine (Part 5),

z^m_{ab} \Rightarrow S_b \ge E_a + s_m(f(a), f(b)) \ \text{ and } \ S_b \ge \alpha_b + s_m(f(a), f(b)),

that is S_b \ge \max(E_a, \alpha_b) + s_m(f(a), f(b)): the changeover starts once the machine is free and the job is there, as in the simulator of chapter B1. The second constraint is posted only for a positive changeover, since S_b \ge \alpha_b holds anyway. The first arc uses the machine's state: z^m_{0b} \Rightarrow S_b \ge \max(\phi_m, \alpha_b) + s_m(g_m, f(b)), with no changeover for a machine that has run nothing (notation). The last arc carries nothing.

Why only between direct successors. Three reasons.

  1. Physics. A machine changes over from the family it is set up for, the one just before.
  2. Sums of changeovers are not changeovers. Imposing S_b \ge E_a + s(f(a), f(b)) for every a anywhere before b is safe only when a detour never saves changeover time, the triangle inequality of chapter A2; the workshop breaks it on 4 of 120 triples.
  3. The arrival rule is wrong for non-adjacent pairs: a blue order two places back would hold a red one 10 minutes after its arrival, though its direct predecessor is red and no changeover happens (Exercise 2).

The circuit gives each operation one predecessor, so exactly the true changeover applies. On the paint machine, z_{AB} \Rightarrow S_B \ge E_A + 10 (blue to red) and z_{BD} \Rightarrow S_D \ge E_B (red to red).

Part 5

Inside a job, with the transport lag

Plain words. A job's operations run in order, and between two machines a cart must come, load, drive and unload. So each operation gets one more integer, \alpha_{jk}, the time the job reaches the chosen machine, with S_{jk} \ge \alpha_{jk}. A family-0 job that ends operation 0 on machine 1 at minute 30 is at machine 3 at minute 35.

First operation. The snapshot gives a ready time R_{jm} for each machine m the job may go to next (chapter C3). The model posts x_{jkm} \Rightarrow \alpha_{jk} \ge R_{jm}.

Later operations. If (j, k-1) runs on m' and (j, k) on m, the job arrives after the transport lag

\ell(m', m) = \begin{cases} 0, & m' = m, \\ \delta + \tau\bigl(\mathrm{st}(m'), \mathrm{st}(m)\bigr), & m' \ne m, \end{cases}

with \tau the loaded travel time between the stations (machine m at station m + 1) and \delta = 2 minutes for a cart to come (notation). The lag depends on two decisions, so it is enforced by two literals at once (\wedge, "and": both are 1),

x_{j,k-1,m'} \wedge x_{jkm} \Rightarrow \alpha_{jk} \ge E_{j,k-1} + \ell(m', m),

one constraint per pair (m', m), at most 9 per pair of consecutive operations. Exactly one pair of literals is true, so exactly one lag applies: 4 or 5 minutes between two machines of the workshop.

What this costs. A move is a fixed lag, but the simulated shop's two carts may be busy, so the plan drifts from reality until the next re-plan. No method of the course optimises the carts.

On the paint machine. Every order waits at the machine from minute 0: \alpha_j = 0, no lag.

Part 6

Tardiness made linear, the weight 10, the horizon

Plain words. Order A is due at minute 30. Finished at 40, it is 10 minutes late; finished at 25, its tardiness is 0, not -5. Tardiness is a maximum, T_j = \max(0, C_j - d_j) with C_j = E_{j, K_j - 1} (chapter A1), and a maximum is not linear, so the model does not write one. It posts T_j \ge C_j - d_j and T_j \ge 0 (the domain), which only say that T_j is at least the tardiness; minimisation does the rest. On the paint machine: T_B \ge E_B - 25, T_B \ge 0.

Claim. In every optimal solution, T_j = \max(0, C_j - d_j).

Proof. T_j appears only in its two lower bounds and in the objective, with weight 10 > 0. If T_j > \max(0, C_j - d_j), lower it to that value: both bounds still hold, no other constraint mentions T_j, and the objective drops by 10\,(T_j - \max(0, C_j - d_j)) > 0. So the solution was not optimal. \square

At a FEASIBLE, non-optimal solution T_j may exceed the true tardiness. On the snapshot of Part 9 the reported objective equals plan_cost, which recomputes it from the plan's end times (7940 = 7940).

The objective is \min \sum_j (10\, T_j + C_j) over the jobs of the snapshot. The completion term breaks ties: when many plans have zero tardiness it makes the solver finish early, which keeps machines free for jobs not yet arrived (chapter C3).

What the weight does. It is an exchange rate, one minute of tardiness for ten of total completion, not a lexicographic priority (tardiness strictly first, completion only to break ties). On the paint machine, minimising w \sum T_j + \sum C_j over every sequence:

Weight w Best sequence \sum T_j \sum C_j Objective
0 CABD 55 185 185
2 ACBD 50 190 290
10 ABDC 40 215 615

From w = 3 on, the minimum-tardiness plan wins. In a large shop the trade can bite, so "CP-SAT minimises tardiness" approximates what the model says; 10 is the repository's choice, not a proven best.

The horizon. Every variable needs a finite domain. The repository takes

H = \max\bigl(t_0, \max_m \phi_m, \max_{j,m} R_{jm}\bigr) + \sum_{(j,k)} \bigl(\max_m p_{jkm} + s_{\max} + \ell_{\max}\bigr),

with \ell_{\max} = \delta + \max_{a,b} \tau(a, b), 5 minutes in the workshop: the latest moment anything is available plus, per operation, its slowest processing time, the longest changeover and the longest lag. For the hand-written paint model of Part 7, with no transport term, H = 70 + 4 \times 10 = 110.

Why it cuts off no optimal plan. The objective is regular, so by the left-shift theorem of chapter A1 some optimal plan is semi-active [5]: no operation can start earlier without changing a routing or an order. Exercise 3 proves that such a plan ends every operation by H.

Part 7

The paint machine, written out and solved

Parts 2 to 6 built the pieces; here they are assembled. All four orders wait at minute 0, so the arrival lines vanish; with one machine every interval is present and there is no self-loop. With H = 110:

Variables. S_j, E_j, T_j \in \{0, \dots, 110\} for j \in \{A, B, C, D\}; intervals (S_j, p_j, E_j) with p = (20, 10, 15, 25); arc literals z_{0j}, z_{j0} and z_{ab} (a \ne b): 20 Booleans.

Constraints and objective.

\mathrm{NoOverlap}(I_A, I_B, I_C, I_D), \qquad \mathrm{Circuit}(\{0, A, B, C, D\},\ 20 \text{ arcs}),
z_{0B} \Rightarrow S_B \ge 10, \qquad z_{0D} \Rightarrow S_D \ge 10,
z_{ab} \Rightarrow S_b \ge E_a + 10 \cdot [\text{colour}(a) \ne \text{colour}(b)] \qquad (a \ne b),
T_j \ge E_j - d_j \quad (d = 30, 25, 70, 60), \qquad \min \textstyle\sum_j T_j .

The first arcs into A and C carry only S \ge 0; 12 arcs join two orders. In all: 32 variables (12 integers, 20 Booleans), 4 intervals, one NoOverlap, one circuit of 20 arcs, 16 conditional and 4 plain linear constraints.

CP-SAT's answer (numbers script): status OPTIMAL, objective 40, best bound 40: a plan of total tardiness 40, and a proof that none is better.

Order Arc into it S_j E_j d_j T_j
A 0 \to A 0 20 30 0
B A \to B 30 40 25 15
D B \to D 40 65 60 5
C D \to C 75 90 70 20

With C \to 0 the arcs form one tour; the binding constraints are S_B = E_A + 10, S_D = E_B, S_C = E_D + 10. It is chapter A2's optimum over all 24 sequences. With the objective 10 \sum T_j + \sum C_j: same sequence, 615.

The repository's own function agrees. On a one-machine workshop with one family per order, set up for A's family, solve_snapshot returns OPTIMAL, 615, A, B, D, C. Its 25 arcs add four self-loops and the idle loop, all forced to 0.

Part 8

The same problem with big-M constraints

A mixed-integer linear program (MILP) allows only linear constraints over continuous and integer variables. The classic scheduling MILP is Manne's disjunctive formulation [3]: one binary and two big-M constraints per pair.

What is a big-M constraint?

In plain words: a rule with an off switch made of a huge number: when a binary is 1 the rule holds; when it is 0, a large constant makes it true whatever happens.

More precisely: g(x) \ge -M(1 - y) with y binary and M at least the largest violation -g(x) on the domain, the MILP version of y \Rightarrow g(x) \ge 0. A linear program (LP) has only continuous variables; the LP relaxation of a MILP lets every binary take any value in [0, 1], and its optimum is a lower bound.

The paint machine as a MILP. With y_{ab} = 1 when a comes before b (not necessarily directly), for each of the 6 pairs

S_b \ge S_a + p_a + s(a, b) - M(1 - y_{ab}), \qquad S_a \ge S_b + p_b + s(b, a) - M y_{ab},

plus S_j \ge s(\text{blue}, \text{colour}(j)) for every order (binding only for the first), T_j \ge S_j + p_j - d_j, and \min \sum T_j, over the domains S_j \in [0, H - p_j], T_j \ge 0. Pairwise changeovers are correct here because the paint machine's changeovers satisfy the triangle inequality. The switched-off line needs M at least the largest S_b + p_b + s - S_a, which on these domains is at most H + s_{\max}, so M = 120: 14 variables (6 binary), 20 constraints.

Same optimum, useless bound. SCIP (a MILP solver shipped with OR-Tools) finds 40, A, B, D, C, after 6 branch-and-bound nodes. But the plain LP relaxation (before SCIP's presolve, cuts and branching), solved by GLOP, OR-Tools' LP solver, gives a bound of 0, with starts (0, 10, 0, 10) for A, B, C, D and fractional binaries such as y_{AB} = 0.25: half-switched big-M lines let the orders overlap freely. With M = 1000 the bound is still 0.

Why so weak. Take A and B alone and write d = S_B - S_A. "A before B" is d \ge 30 (20 minutes of A, 10 of changeover); "B before A" is d \le -20: two half-planes, blue in the widget. Relaxed, the lines read d \ge 30 - M(1 - y) and d \le -20 + My, that is

\frac{d + 20}{M} \le y \le 1 - \frac{30 - d}{M} .

A y \in [0, 1] exists when the lower end is at most the upper end (d + 20 \le M - 30 + d, that is M \ge 50), the lower end is at most 1 (d \le M - 20) and the upper end is at least 0 (d \ge 30 - M):

30 - M \le S_B - S_A \le M - 20 \qquad (M \ge 50).

For M = 120, -90 \le S_B - S_A \le 100: nearly the whole square. For y between 20/M and 1 - 30/M (1/6 and 0.75 at M = 120) the band contains d = 0, where A and B start together. The relaxation has forgotten the disjunction, a larger M widens the band, and branching must recover what the formulation lost. On four orders that is cheap; this chapter does not measure how it scales. CP reasons on NoOverlap and the circuit directly (and CP-SAT adds linear relaxations where they help, chapter C2).

The flexible shop as a MILP needs assignment binaries and successor binaries with one-in-one-out equalities, the circuit rewritten with every switch weakened by an M the size of the horizon: for the snapshot of Part 9, 42 assignment and 170 order binaries for the pairwise part alone.

Per machine: add_no_overlap (redundant, Part 3); the idle loop; for candidate i the first arc with two bounds, the last arc, the self-loop lit_i.Not() (no new variable), and a follows literal per other candidate with s_j >= e_i + setup and, for a positive changeover, s_j >= a_j + setup. order and successor only compute hints.

Part 10

Common pitfalls

  1. "NoOverlap orders the operations." It forbids overlaps but does not say who is directly next, so it cannot carry a sequence-dependent changeover; the circuit does.
  2. "T_j \ge C_j - d_j makes T_j the tardiness." Only with T_j \ge 0, a positive weight in a minimisation, and at an optimal solution; otherwise impose the maximum as an equality (add_max_equality in CP-SAT).
  3. "A big enough M is safe." Too small cuts off schedules; too large is valid but weakens the relaxation further.
Part 11

Check your understanding

Try to answer each question before opening it.

1. Why one optional interval per eligible machine rather than a single interval?

The duration p_{jkm} depends on the machine and NoOverlap is posted per machine. Exactly one interval is present, so one size equation holds and the operation sits on one calendar.

2. A machine has 3 candidate operations. How many arc literals does its circuit have, and how many new Booleans?

(3 + 1)^2 = 16 arcs. The 3 self-loops reuse negated presence literals, so 1 + 2 \times 3 + 3 \times 2 = 13 new Booleans.

3. What do z^m_{ab} = 1 and z^m_{aa} = 1 mean?

b starts directly after a on machine m; and a is not on machine m (z^m_{aa} = \neg x_{am}).

4. Why is node 0 needed?

It is the machine's state, free time \phi_m and family g_m: the arc 0 \to b carries the first changeover, and the tour starts and ends there. With nothing to run, z^m_{00} = 1.

5. Write the two arc constraints of z_{DC} on the paint machine.

Red to blue, changeover 10: z_{DC} \Rightarrow S_C \ge E_D + 10 and z_{DC} \Rightarrow S_C \ge \alpha_C + 10 = 10, since C is there from minute 0. The second is implied by the first, and Part 7 drops it.

6. Order A completes at 25. Which values may T_A take, and which does the optimum pick?

Any integer in [0, 110]: T_A \ge -5 and the domain say nothing more. The optimum picks 0: T_A has a positive weight and appears only in its two lower bounds, so any larger value can be lowered.

7. Both the CP model and the big-M MILP give 40. Why prefer CP?

The MILP's LP bound is 0: with fractional y_{ab} the orders overlap freely, so the proof of 40 rests on branching. CP reasons on NoOverlap and the circuit directly.

Part 12

Exercises

The code runs in the repository's environment, from its root. Try first, then peek.

  1. The start times forbid subtours. Show that if every operation has a positive duration, the constraints z_{ab} \Rightarrow S_b \ge E_a + s(f(a), f(b)) alone make infeasible any cycle of length at least 2, of chosen arcs that are not self-loops, avoiding node 0. What does the circuit add?

    Hint

    Add up the constraints along a cycle a_1 \to \dots \to a_r \to a_1, r \ge 2.

    Solution

    Along the cycle S_{a_{i+1}} \ge S_{a_i} + p_{a_i} + s_i with s_i \ge 0 (indices mod r). Summing, the starts cancel: 0 \ge \sum_i (p_{a_i} + s_i) > 0, a contradiction. The times act as the potentials of Miller, Tucker and Zemlin [4]. A self-loop carries no timing constraint, which is why it is excluded. The circuit adds the degree structure (one predecessor and one successor per present operation, none for absent ones), the passage through node 0 that charges the first changeover, and reasoning on the whole tour at once.

  2. A changeover charged to the wrong predecessor. On the paint machine, order D arrives at minute 50; the others wait at 0. In the plan A, C, B, D, find B's and D's earliest starts under the model's rule, then under a pairwise rule that also imposes, for every earlier order a, S_b \ge E_a + s(a, b) and S_b \ge \alpha_b + s(a, b). Does the pairwise rule change which plan looks best?

    Hint

    A and C are blue, B and D red. C ends at 35.

    Solution

    Model: B follows C, S_B \ge \max(35, 0) + 10 = 45, ends 55; D follows B (red to red), S_D \ge \max(55, 50) + 0 = 55. Total tardiness 50. Pairwise: B still starts at 45 (from A E_A + 10 = 30, from C 45), but D from the blue A and C needs \alpha_D + 10 = 60, so it runs 60 to 85 and the plan scores 55. Over all 24 orders the pairwise rule's best is 55, by A, B, C, D and A, C, B, D: it overstates A, C, B, D (truly 50, the optimum of Exercise 4) and may return A, B, C, D, truly 55.

  3. The horizon is safe. Prove that some optimal plan has every end at most H, and compute H for the hand-written paint model.

    Hint

    Left-shift an optimal plan, then follow from any operation the lower bound that is tight at its start.

    Solution

    By the left-shift theorem of chapter A1, a semi-active optimal plan exists. In it each start equals one of its lower bounds: t_0; \max(R_{jm}, \phi_m) + s (first arc); R_{jm} + s or E_q + s for the machine predecessor q; or E_q + \ell (+ s) for the job predecessor q. In the last two cases S_o \le S_q + p_q + s_{\max} + \ell_{\max} with S_q < S_o. Repeating, starts strictly decrease, so the chain has distinct operations and ends at a snapshot bound B = \max(t_0, \phi_m, R_{jm}) plus at most one changeover. Summing, E_o \le B + \sum_{q \in \text{chain}} (p_q + s_{\max} + \ell_{\max}) \le H. Also T_j = \max(0, C_j - d_j) \le C_j \le H, because d_j \ge 0, so the domain [0, H] of T_j is safe too. Paint: B = 0, processing 70, no lag, s_{\max} = 10: H = 110 (the code's 118 adds max_lag = 2 per operation).

  4. Model a release time with CP-SAT. Let order D arrive at minute 50, with the rule that a changeover starts once the order is there. Solve with CP-SAT and compare with the old optimum A, B, D, C.

    Hint

    Add S_j \ge r_j, and on each arc with a positive changeover S_b \ge r_b + s.

    Solution 
    from ortools.sat.python import cp_model

N, node = "ABCD", "0ABCD".index                      # node 0: the machine, set up for blue
P = dict(A=20, B=10, C=15, D=25); DUE = dict(A=30, B=25, C=70, D=60); R = dict(A=0, B=0, C=0, D=50)
s = lambda a, b: 10 * ((a in "0AC") != (b in "0AC"))  # A, C blue; B, D red
m = cp_model.CpModel()
S, E, T = ({n: m.new_int_var(0, 200, x + n) for n in N} for x in "SET")
m.add_no_overlap([m.new_interval_var(S[n], P[n], E[n], "") for n in N])
arcs = []
for a in N:
    m.add(S[a] >= R[a]); m.add(T[a] >= E[a] - DUE[a])
    arcs.append((node(a), 0, m.new_bool_var("")))     # a runs last
    for b in "0" + N:                                 # b directly before a
        if b != a:
            z = m.new_bool_var(""); arcs.append((node(b), node(a), z))
            if b != "0": m.add(S[a] >= E[b] + s(b, a)).only_enforce_if(z)
            if s(b, a): m.add(S[a] >= R[a] + s(b, a)).only_enforce_if(z)
m.add_circuit(arcs); m.minimize(sum(T.values()))
sol = cp_model.CpSolver(); print(sol.status_name(sol.solve(m)), sol.objective_value,
                                 "".join(sorted(N, key=lambda n: sol.value(S[n]))))   # OPTIMAL 50.0 ACBD

    The optimum is 50 with A, C, B, D, confirmed by trying all 24 orders; A, B, D, C now gives 60, since D cannot start before 50 and C ends at 100.

  5. The flexible instance of chapter A3. Chapter A3 has three jobs on three machines (J0: M0 2, M1 7, M2 7 minutes; J1: M1 7, M2 4, M0 5; J2: M2 2, M0 6, M1 2) and makes three operations flexible: J0.1 and J1.0 may also run on M2 in 6 minutes, J2.2 on M0 in 3. Model it in CP-SAT with optional intervals, add_exactly_one and one add_no_overlap per machine, minimise the makespan, and recover chapter A3's optima: 21 with the classical routing, 19 with flexibility.

    Going further. Put J0 and J1 in family 0, J2 in family 1: on any machine, an operation directly after one of the other family needs a 2-minute changeover, which starts once the machine is free and the job is there (none on a machine that has run nothing). Add one add_circuit per machine and compare the optima again.

    Hint

    As in Part 2, one optional interval per eligible machine, sharing the operation's start and end; S_{jk} \ge E_{j,k-1} along each route; the makespan by add_max_equality. Going further: Part 4's circuit per machine (idle loop, first and last arcs, self-loop x.Not(), and per ordered pair of candidates an arc literal enforcing S_b \ge \max(E_a, \alpha_b) + c, c the changeover).

    Solution 
    from ortools.sat.python import cp_model

JOBS = [[{0: 2}, {1: 7}, {2: 7}], [{1: 7}, {2: 4}, {0: 5}], [{2: 2}, {0: 6}, {1: 2}]]   # {machine: minutes}
FLEX = {(0, 1): {2: 6}, (1, 0): {2: 6}, (2, 2): {0: 3}}
FAM = [0, 0, 1]                                                   # family of J0, J1, J2

def solve(flexible, setup=0):
    m = cp_model.CpModel()
    elig = {(j, k): {**op, **(FLEX.get((j, k), {}) if flexible else {})}
            for j, job in enumerate(JOBS) for k, op in enumerate(job)}
    S, E, x, on = {}, {}, {}, {0: [], 1: [], 2: []}
    for (j, k), e in elig.items():
        S[j, k], E[j, k] = m.new_int_var(0, 60, ""), m.new_int_var(0, 60, "")   # 60 > all the work
        x[j, k] = {i: m.new_bool_var("") for i in e}             # x[j, k][i] = 1 iff mu(j, k) = i
        for i, p in e.items():
            on[i].append(m.new_optional_interval_var(S[j, k], p, E[j, k], x[j, k][i], ""))
        m.add_exactly_one(x[j, k].values())
        if k:
            m.add(S[j, k] >= E[j, k - 1])
    for i, ivs in on.items():
        m.add_no_overlap(ivs)
        if not setup:
            continue
        cand = [o for o in elig if i in elig[o]]                  # nodes 1, 2, ... of machine i
        arcs = [(0, 0, m.new_bool_var(""))]                       # the idle loop
        for u, a in enumerate(cand, 1):
            arcs += [(0, u, m.new_bool_var("")), (u, 0, m.new_bool_var("")), (u, u, x[a][i].Not())]
            for v, b in enumerate(cand, 1):
                if v != u:
                    z, c = m.new_bool_var(""), setup * (FAM[a[0]] != FAM[b[0]])
                    arcs.append((u, v, z))
                    m.add(S[b] >= E[a] + c).only_enforce_if(z)
                    if c and b[1]:                                # alpha_b = end of the job's previous step
                        m.add(S[b] >= E[b[0], b[1] - 1] + c).only_enforce_if(z)
        m.add_circuit(arcs)
    cmax = m.new_int_var(0, 60, "")
    m.add_max_equality(cmax, [E[j, 2] for j in range(3)])
    m.minimize(cmax)
    sol = cp_model.CpSolver()
    return sol.status_name(sol.solve(m)), sol.value(cmax)

print(solve(False), solve(True))          # ('OPTIMAL', 21) ('OPTIMAL', 19)
print(solve(False, 2), solve(True, 2))    # ('OPTIMAL', 21) ('OPTIMAL', 21)

    All four are proven optimal. The solver returns one of the 4 flexible assignments reaching 19; each sends exactly one of J0.1 and J1.0 to M2, as chapter A3's proof requires. With changeovers (flexible circuits of 25, 16 and 36 arcs on M0, M1, M2) both optima are 21, confirmed by trying every assignment and machine order: the changeovers eat flexibility's 2 minutes. With 1-minute changeovers: 21 and 20.

Part 13

The chapter on one page

  1. A model, not a procedure: variables, constraints, an objective; the solver searches and proves.
  2. Variables: S, E, \alpha per operation, one optional interval per eligible machine with \sum_m x_{jkm} = 1 (the routing \mu), T_j per job.
  3. Circuit per machine, (n_m + 1)^2 arcs: z^m_{ab} enforces S_b \ge \max(E_a, \alpha_b) + s_m(f(a), f(b)); NoOverlap is kept as redundant.
  4. Precedence under two literals, lag \ell = \delta + \tau; tardiness as two lower bounds, exact at the optimum; the weight 10 an exchange rate.
  5. Paint machine: OPTIMAL 40 by A, B, D, C. Big-M MILP: the same 40, an LP bound of 0.

The vocabulary, in one table

Word Meaning
Decision variable, domain An unknown the solver sets, and its finite set of allowed values.
Global constraint One constraint over many variables, with its own reasoning in the solver.
Exactly-one Of a set of literals, exactly one is 1: here, the routing.
Optional interval, presence literal A block (S, p, E) that exists only if its Boolean is 1.
NoOverlap, disjunction Present blocks of one machine share no minute; "a before b or b before a".
Circuit, arc literal, self-loop One tour over the present nodes; z_{ab} = 1 if b directly follows a; z_{vv} = \neg x_v.
Enforcement literal A Boolean that switches a constraint on.
Transport lag \ell(m', m): minutes between ending on m' and being at m, 0 if m' = m.
Horizon H, the upper end of every time domain, large enough to cut off no optimal plan.
Redundant constraint Implied by the others, added to help the solver.
Big-M, LP relaxation A switched inequality with a large constant; binaries relaxed to [0, 1].

Scope. One snapshot's jobs, deterministic durations, transport as a fixed lag, no carts as resources, no knowledge of future arrivals or breakdowns. Chapter C3 turns the model into a controller.
